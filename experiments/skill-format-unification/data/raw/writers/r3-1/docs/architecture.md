# 아키텍처

saturn은 4개 구성 요소로 이루어진다. 화면과 명령은 엔진과 Unix 소켓 위 JSON-RPC 2.0으로 통신한다.

## 맥락

| 외부 요소 | 종류 | 주고받는 것 |
|---|---|---|
| Codex CLI | 외부 프로그램 | 입력과 응답 |
| Claude Code CLI | 외부 프로그램 | 입력과 응답 |

## 구성 요소

| 구성 요소 | 식별자 | 하는 일 | 기술 | 위치 |
|---|---|---|---|---|
| 엔진 | `engine` | 공급자 프로세스 실행, 입력 대기열, JSON-RPC 서버 | Rust, `tokio` | `crates/saturn-engine` |
| 화면 | `tui` | 채팅 화면과 입력 | Rust, `ratatui` | `crates/saturn-tui` |
| 명령 | `cli` | 엔진과 화면을 시작하는 바이너리 `saturn` | Rust, `clap` | `crates/saturn-cli` |
| 기록 저장소 | `store` | 모든 입력과 응답 저장 | SQLite | `~/.local/share/saturn/saturn.db` |

## 실행 흐름

### 세션 시작

1. 명령: 엔진 시작
2. 화면: 엔진 연결
3. 엔진: 공급자 실행

### 입력 전송

1. 화면: 엔진에 입력 전송
2. 엔진: 입력 대기열에 추가
3. 엔진: 기록 저장소에 입력 저장
4. 엔진: 공급자에 입력 전송

### 공급자 비정상 종료

1. 엔진: 공급자 종료 감지
2. 엔진: 작업 보류
3. 화면: 공급자 비정상 종료 표시

## 배치

| 프로세스 | 시작 주체 | 수명 |
|---|---|---|
| `saturn` 명령 프로세스 | 사용자 | 화면을 닫을 때까지 |
| 엔진 프로세스 | `saturn` 명령 | 마지막 화면이 닫히고 작업이 없을 때까지 |
| 공급자 프로세스 | 엔진 | 세션 중지까지 |

## 공통 규칙

### 저장

기록 저장소는 엔진만 쓴다. 여러 프로세스가 같은 SQLite 파일에 쓸 때 나는 잠금 충돌을 막기 위해서다.

## 기술 선택

| 영역 | 선택 | 고른 이유 |
|---|---|---|
| 비동기 런타임 | `tokio` | 프로세스와 소켓을 한 런타임에서 다룬다. |
| 화면 | `ratatui` | 터미널 화면 표준 라이브러리다. |
| 저장 | SQLite | 단일 파일이고 트랜잭션을 제공한다. |
| 통신 | JSON-RPC 2.0 | 언어 무관 표준이다. |
| 공급자 통신 | stdio | 두 공급자가 모두 지원하는 유일한 통로다([결정 기록](decisions/2026-09-20-provider-stdio.md)). |
