# 스킬 형식 통일과 조건부 로드: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | 해당 없음(비공개 기록) |
| 관련 설계 | [스킬 폴더 안내](../../README.md) |
| 사전 데이터 | 있음. 이 설계는 측정과 스킬 수정 뒤 작성. 가설과 채택 기준도 결과를 본 뒤 기록 |

## 질문

스킬 22개의 형식을 맞추고 참조를 기반 줄과 조건부 줄로 바꾼 뒤 규칙 누락 없이 로드 토큰이 줄었는지 잰다. 요청에 맞는 스킬 선택과 두 에이전트 산출 문서의 일치도 잰다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 조건부 스킬이 필요 없는 요청 9개는 모두 불러오는 o200k 토큰이 20% 이상 준다. | 시나리오 s01, s03, s05, s07, s09, s10, s11, s13, s14 |
| H2 | 조건부 스킬이 필요한 요청 5개는 불러오는 o200k 토큰 증가가 모두 10% 이하다. | 시나리오 s02, s04, s06, s08, s12 |
| H3 | 요청 14개의 o200k 토큰 합은 10% 이상 준다. | 시나리오 14개 전부 |
| H4 | 누락 대조에서 찾은 소실과 뜻 변경은 수정 뒤 재대조에서 모두 반영돼 있다. | 옛 스킬 21개 대비 새 스킬 22개 |
| H5 | 카탈로그만 보고 고른 스킬에 기반 줄을 따라가면 요청 30개가 모두 적중하고 과선택은 1개 이하다. | 새 카탈로그 실행 3개 |
| H6 | 같은 사실로 두 에이전트가 만든 문서 5개의 줄 차이 비율은 10% 이하다. | 마지막 라운드 r4 |
| H7 | 형식 검사 위반은 0개다. | 새 스킬 22개 |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | 기준 조건: 옛 스킬(`before`). 비교 조건: 새 스킬(`after`). 중간 버전 `r1`, `r2`, `r3`는 결정성 라운드용 |
| 배정 | 해당 없음 |
| 눈가림 | 트리거, 작성, 대조 에이전트에게 기대 답과 다른 에이전트 결과 비공개 |
| 환경 | [env.json](env.json). 에이전트 모델 claude-opus-5-5 설정값, 샘플링 고정 불가 |

## 변수

| 변수 | 종류 | 정의 | 단위 |
|---|---|---|---|
| `version` | 조작 | 스킬 버전 | 없음 |
| `o200k`, `claude_legacy` | 측정 | 시나리오에서 불러오는 SKILL.md 전체의 토큰 합. 옛 버전은 description에 이름이 나온 스킬까지, 새 버전은 기반 줄과 조건이 참인 조건부 스킬까지 | 토큰 |
| `hit_after_base` | 파생 | 기대 스킬 집합이 고른 스킬과 그 기반 스킬 집합에 포함되면 1 | 없음 |
| `over_selection` | 파생 | 기대 밖 스킬을 고른 요청 수 | 개 |
| `diff_ratio` | 파생 | 두 작성자 문서 5개의 `diff` 다른 줄 수 합 / 첫 작성자 빈 줄 아닌 줄 수 합 | % |
| `style_violations` | 측정 | `scripts/skill_check.py` 위반 수 | 개 |
| `audit_fixed` | 측정 | 누락 대조 발견 중 수정 반영 수 | 개 |

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 스킬 폴더 스냅숏, 설계자가 작성한 요청 30개와 기대 스킬, 공개할 저장소의 설계 사실 |
| 크기 | 스킬 전수, 요청 30개, 시나리오 14개, 작성 라운드 4개 × 작성자 2명 |
| 크기 근거 | 전수(스킬). 요청과 라운드는 예산 |
| 중단 규칙 | 라운드 사이 결정성 차이의 원인을 스킬 규칙으로 고칠 수 없을 때 중단 |
| 반복과 예열 | 트리거 새 버전 3회, 옛 버전 1회. 예열 없음 |

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | `o200k` | 시나리오별 변화율 | 9개 모두 -20% 이하 |
| H2 | `o200k` | 시나리오별 변화율 | 5개 모두 +10% 이하 |
| H3 | `o200k` | 14개 합의 변화율 | -10% 이하 |
| H4 | `audit_fixed` | 새 에이전트 재대조 | 수정 대상 발견 전부 반영 |
| H5 | `hit_after_base`, `over_selection` | 실행별 적중 수, 95% Wilson 신뢰구간 | 실행마다 30/30, 과선택 1 이하 |
| H6 | `diff_ratio` | 비율과 95% Wilson 신뢰구간 | 신뢰구간 상한 ≤ 10% |
| H7 | `style_violations` | 검사 스크립트 | 0개 |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | 없음 |
| 실패한 실행 | 산출물이 없는 실행은 실패로 기록, 비율에서 제외 |
| 다중 비교 | 해당 없음(검정 없이 기준 비교) |

## 판정

| 결과 | 설계에 반영 |
|---|---|
| 채택 | 새 형식을 스킬 폴더 안내의 작성 규칙으로 고정 |
| 기각 | 늘어난 시나리오의 원인 스킬을 줄이는 후속 수정 |
| 보류 | 라운드 추가, 남은 차이의 원인 규칙 보강 |

## 탐색 분석

- 스킬 전체 바이트와 토큰의 변화
- 옛 카탈로그와 새 카탈로그의 카탈로그 적중 차이
- 작성 에이전트가 읽은 스킬 순서

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | 가설과 기준을 결과를 본 뒤 정해 유리한 기준을 고를 수 있다. | 모든 가설의 판정을 기각 포함 그대로 보고한다. |
| 내적 | 라운드마다 여러 규칙을 함께 바꿔 어떤 규칙이 차이를 줄였는지 가를 수 없다. | 라운드별 스킬 스냅숏을 남기고 바꾼 규칙을 보고서에 적는다. |
| 구성 | 로드량은 규칙대로 불러온다는 가정의 계산값이고 실제 에이전트가 읽은 양이 아니다. | 작성 에이전트의 읽은 스킬 기록과 계산 집합을 대조한다. |
| 구성 | Claude 토큰은 공개된 구 토크나이저의 근사치다. | o200k를 주 지표로 하고 Claude 값은 함께 적는다. |
| 외적 | 사실 파일 하나, 요청 30개로 다른 저장소에 일반화하기 어렵다. | 적용 범위를 이 스킬 폴더로 한정한다. |
