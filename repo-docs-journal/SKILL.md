# Repo Docs Journal

- 저장소 안에 같은 역할의 규칙이 있으면 그것 우선. 없으면 이 스킬이 다른 규칙보다 우선
- 기반: repo-docs 먼저 적용. 이 스킬 범위: 비공개 판단, 서사, 원칙 템플릿, 표시, 놓친 것 분류, 작성 시점
- 필요할 때만 읽기: 판단이 공개 설계를 정했을 때 → repo-docs-decision

- 비공개 기록. 공개 문서, 이슈, PR, 커밋에 링크나 문장 옮기기 금지
- 공개할 가치가 있는 판단: 공개 결정 기록으로 재작성, 그 뒤 이 기록 `관련` 칸에 그 경로 추가
- 저장 전 `git check-ignore .local`로 git 제외 확인. 제외되지 않으면 저장 금지, 보고

## 종류

| 종류 | 쓰는 때 | 파일 |
|---|---|---|
| 판단 | 선택지 중 하나 결정 | `.local/journal/{YYYY-MM-DD}-{주제}.md` |
| 판단 변경 | 이전 판단 변경 | `.local/journal/{YYYY-MM-DD}-{주제}.md` |
| 서사 | 큰 작업(마일스톤, 설계 문서 둘 이상 변경, 공개 계약 변경)의 처음부터 끝까지 | `.local/stories/{작업}.md` |
| 원칙 | 판단 변경에서 얻은 교훈 | `.local/principles.md` |

- `{주제}`, `{작업}`: 영어 소문자 kebab-case 2~5단어
- 목록: `.local/journal/README.md` 표 하나

## 표시

위치: 문장 끝. 비공개 기록 전용

| 표시 | 뜻 |
|---|---|
| `[근거: {출처}]` | 확인한 사실. 출처는 이슈, 파일 경로, 명령, 링크 |
| `[가정]` | 당시 확인하지 않고 전제한 것 |
| `[미확인]` | 몰랐거나 확인하지 못한 것 |
| `[추정]` | 사용자가 말하지 않은 동기나 이유를 기록자가 짐작한 것 |

- 사용자의 판단과 이유: 사용자가 말한 것만 표시 없이, 나머지는 `[추정]`
- `[추정]`: 사용자가 확인하면 삭제

## journal/README.md

```text
# 판단 기록

| 날짜 | 기록 | 종류 | 이전 판단 |
|---|---|---|---|
| {YYYY-MM-DD} | [{제목}]({파일}) | {판단, 판단 변경} | {링크, 또는 없음} |
```

- 날짜 오름차순

## 판단

```text
# {정한 것, 결론 문장}

| 항목 | 값 |
|---|---|
| 날짜 | {YYYY-MM-DD} |
| 관련 | {이슈, 공개 문서, 서사 링크} |

## 문제

{무엇을 정해야 했고 잘못 정하면 무엇을 잃는지 한 문단}

## 알던 것과 모르던 것

- {사실} [근거: {출처}]
- {모르던 것} [미확인]

## 선택지

| 선택지 | 얻는 것 | 잃는 것 |
|---|---|---|
| {선택지} | {얻는 것} | {잃는 것} |

## 판단

{고른 선택지와 가른 기준 한 문단}

| 확신 | 이유 |
|---|---|
| {높음, 중간, 낮음} | {이유} |

## 틀렸다는 신호

- {이 판단이 틀렸다고 알려 줄 관측}
```

## 판단 변경

```text
# {바꾼 판단, 결론 문장}

| 항목 | 값 |
|---|---|
| 날짜 | {YYYY-MM-DD} |
| 이전 판단 | [{제목}]({파일}) |
| 관련 | {이슈, 공개 문서, 서사 링크} |

## 이전 판단

{한두 문장}

## 드러난 것

{무엇이 어디서 새로 보였는지 한 문단. 어디서는 구현, 실험, 버그, 검토, 조사 중 하나}

## 놓친 것

| 분류 | 원인 | 당시 신호 |
|---|---|---|
| {분류} | {왜 놓쳤는지} | {있었던 신호, 또는 없음} |

## 새 판단

{고른 것과 기준 한 문단}

## 교훈

{원칙 한 문장}. principles.md에 반영했다.
```

| 분류 | 뜻 |
|---|---|
| 사실 부족 | 확인할 수 있었는데 하지 않은 확인 |
| 잘못된 가정 | 틀린 전제 |
| 범위 착오 | 잘못 그은 대상의 경계 |
| 추론 오류 | 맞는 사실에서 잘못 끌어낸 결론 |
| 원칙 충돌 | 이미 정한 원칙과의 충돌을 못 본 경우 |
| 환경 변화 | 당시엔 맞았으나 도구, 버전, 요구가 바뀐 경우 |

- 놓친 것 표: 한 행이 기본. 원인이 둘이면 두 행, 주된 것 먼저

## 서사

```text
# {작업 이름}

| 항목 | 값 |
|---|---|
| 기간 | {YYYY-MM-DD}~{YYYY-MM-DD, 또는 진행 중} |
| 마일스톤 | {링크} |

## 시작한 이유

{한 문단}

## 목표와 성공 기준

| 목표 | 성공 기준 |
|---|---|
| {목표} | {측정할 수 있는 기준} |

## 처음 생각

{처음 판단과 그때의 전제 한 문단}

## 설계

{확정한 설계 한 문단과 공개 설계 문서 경로}

## 진행 기록

| 날짜 | 드러난 것 | 판단 | 기록 |
|---|---|---|---|
| {YYYY-MM-DD} | {드러난 것} | {판단} | {링크, 또는 없음} |

## 바뀐 판단과 놓친 것

- {이전 판단} → {새 판단}: {분류}

## 결과

| 목표 | 결과 | 근거 |
|---|---|---|
| {목표} | {달성, 일부, 미달} | {지표나 링크} |

## 돌아보며

- {다시 한다면 먼저 할 것}
```

- 시작 시 `시작한 이유`~`설계`, 진행 중 `진행 기록` 행만 추가, 끝날 때 나머지
- 기간의 `진행 중`: 끝날 때 날짜로 교체

## principles.md

```text
# 원칙

## {원칙 한 문장}

{어떤 판단 변경에서 나왔는지 한두 문장}

- [{기록 제목}]({파일})
```

- 같은 교훈 재등장: 새 절 대신 링크 한 줄. 링크 수 = 되풀이 횟수
- 절 순서: 링크 수 내림차순

## 문장

- 당시 판단은 당시 알던 것으로. 나중에 안 근거를 당시 이유로 사용 금지
- 놓친 것은 분류와 사실로. 자책, 변명 문장 금지
- 제목 `#`: 결론 문장, 마침표 없음

## 작성 시점

- 세션 종료 시 그 세션에 판단이 있었을 때만 초안 작성
- 작성 전 `journal/README.md`로 이전 판단 변경 여부 확인. 바꾸면 판단 변경 템플릿
- 기간을 받으면 `gh`로 그 기간의 닫힌 `design` 이슈 결정 댓글, `bug` 이슈 원인, PR 본문을 재료로 수집
- 서사에 속한 기록이면 서사의 진행 기록에 한 행 추가
- 판단이 공개 설계(아키텍처, 프로토콜, 데이터, 기술 선택, 라이선스)를 정하면 공개 결정 기록 초안도 작성
- 보고: 저장한 경로와 남은 `[추정]` 수만
