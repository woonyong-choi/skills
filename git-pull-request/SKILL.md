# Git Pull Request

- 저장소 안에 같은 역할의 규칙이 있으면 그것 우선. 없으면 이 스킬이 다른 규칙보다 우선
- 범위: PR 종류, 본문, 계약 검토, 문서 동반, 검토 댓글, 머지 조건. 제목, 브랜치, 머지 절차(git-branch)와 제목 형식(git-commit) 제외
- 필요할 때만 읽기: 테스트 변경 근거 확인 → code-style

## 종류

| 종류 | 담는 것 | 올리는 방식 |
|---|---|---|
| 설계 | docs만: 설계 이슈 결정 반영, 실험 사전 등록, 실험 결과 | 바로 검토 |
| 계약 | 여러 이슈가 함께 쓰는 trait·공유 타입·오류 타입과 문서 주석. 본문이 필요한 함수 제외, 구현할 이슈는 문서 주석에 `TODO(#번호)` | 바로 검토. 머지 뒤 구현 이슈 시작 |
| 구현 | 구현, 테스트, 설계 문서 갱신 | 계약이 이 이슈 안에서만 쓰이면 초안(draft)으로 열고 첫 커밋에 시그니처와 문서 주석만. 계약 승인 뒤 같은 PR에서 구현 |

- 초안 PR의 미완성 표시(언어별 스킬이 허용한 것): 준비 완료(ready) 전에 0개

## 본문

- 섹션 이름, 순서 그대로. 빈 섹션은 `없음`
- 본문, 댓글의 문장, 목록, 표: 평서 문체 (repo-docs 문체)

```text
Closes: #{번호}

## 변경
- {결과 중심, 3~7줄. 파일 나열 금지}

## 문서
- {고친 문서와 절} 또는 `없음: {이유}`

## 검증
- `{실제로 실행한 명령}`: {결과}
- 테스트 변경: {추가·삭제한 테스트 이름과 각각의 근거} 또는 `없음`

## 가정
- {이슈·설계에 없어서 작성자가 정한 것} 또는 `없음`

## 확인할 곳
- {사람이 직접 볼 파일과 이유: 보안, 데이터 손실, 동시성, 공개 계약} 또는 `없음`
```

- 첫 줄: `Closes: #{번호}` (git-branch PR). `experiment` 사전 등록 PR은 `Refs: #{번호}`
- 검증: 실제로 실행한 것만. 실행하지 못한 것은 `실행 안 함: {이유}`
- 테스트 변경 근거: (code-style 테스트). 삭제는 근거 폐기·중복 병합 등 삭제 이유 포함
- 가정: 작은 선택도 기록(기본값, 오류 메시지, 이름). 설계를 바꾸는 선택이면 PR 중단, 설계 이슈 생성

## 문서 동반

- 동작, 계약, 설정을 바꾸는 PR: 같은 PR에서 설계 문서 수정. 고칠 것이 없으면 문서 절에 이유
- 계약 PR: 설계 문서의 인터페이스 절을 코드 위치로 교체 (repo-docs-design)
- 실험 결과가 설계를 바꾸면 실험 문서와 설계 문서를 같은 PR에서
- 결정 기록 대상 표에 맞는 `design` 이슈 결정: 같은 PR에 결정 기록 (repo-docs-decision 대상)
- 그림 원본(`.d2`, `.vl.json`, `.tape`)을 고치면 만든 그림도 같은 PR에서 (repo-docs-figures)
- README나 `docs/` 문서가 바뀌면 `llms.txt`, `llms-full.txt`도 같은 PR에서 (repo-docs-llms)
- 릴리스 PR: `CHANGELOG.md`를 같은 PR에서 (repo-docs-root)

## 크기

- 바뀐 줄 400줄 안팎. 생성 파일, 잠금 파일 제외. 넘으면 이슈 분할
- 계약 PR: 사람이 한 번에 읽을 수 있는 크기

## 검토

검토자: 작성한 도구, 세션과 다른 도구나 새 세션. 두 축을 따로 검토.

| 축 | 기준 | 보는 것 |
|---|---|---|
| 규칙 | 저장소 규칙, code-style과 언어별 스킬 | 이름, 구조, 에러 처리, 테스트, 금지 항목 |
| 설계 | 이슈 완료 조건, 설계 문서 | 빠진 조건, 범위 밖 변경, 설계와 다른 동작, 문서 동반, 가정 절 |

검토 댓글

```text
## 규칙 검토
- 필수 · {파일·항목}: {문제} ({근거 규칙})
- 제안 · {파일·항목}: {문제}

## 설계 검토
- 필수 · {완료 조건·설계 절}: {문제}
```

- 발견이 없으면 그 절에 `발견 없음`
- `필수`만 머지 차단. `제안`은 작성자 판단
- 취향, 근거 규칙을 댈 수 없는 지적 기록 금지

## 머지 조건

- CI 통과
- 검토 `필수` 0개
- 완료 조건 모두 체크
- 계약이 있으면 사람이 계약 승인
- 머지 주체: 요청이 있을 때만 AI 머지 (git-branch 머지)

## 금지

- 본문, 댓글에 AI 흔적: 모델 이름, 생성 문구, 세션 링크
- 실행하지 않은 검증 기록
- 비공개 기록 링크나 내용
- 섹션 빼기, 빈 섹션 두기
