# Repo Docs Decision

- 저장소 안에 같은 역할의 규칙이 있으면 그것 우선. 없으면 이 스킬이 다른 규칙보다 우선
- 기반: repo-docs 먼저 적용. 이 스킬 범위: 공개 결정 기록 대상, 파일, 템플릿, 판단 기록 옮기기, 절차
- 필요할 때만 읽기: 비공개 판단 기록에서 옮길 때 → repo-docs-journal

- 결정 기록: 설계 선택지 중 하나를 고른 이유의 공개 기록. 현재 설계는 설계 문서, 판단 과정과 놓친 것은 비공개 판단 기록 담당
- 비공개 기록 문장 복사 금지(판단 기록에서 옮기기 표가 정한 제목, 선택지 글자 제외), 확인된 사실만 골라 새로 작성

## 대상

| 기록하는 결정 | 기록하지 않는 결정 |
|---|---|
| 아키텍처, 프로토콜, 데이터 구조, 기술 선택, 라이선스 결정 | 이름, 서식, 코드 스타일 |
| 선택지 둘 이상, 버린 선택지에도 장점 | 선택지가 하나뿐인 결정 |
| 되돌리려면 여러 구성 요소나 공개 계약 수정 필요 | 한 PR로 되돌릴 수 있는 결정 |

## 파일

- 경로: `docs/decisions/{YYYY-MM-DD}-{주제}.md`. 날짜는 결정한 날, `{주제}`는 영어 소문자 kebab-case 2~5단어
- 목록: `docs/decisions/README.md`
- 머지된 기록: 상태, 대체 칸만 수정. 결정이 바뀌면 새 기록

## docs/decisions/README.md

```text
# 결정 기록

설계를 정한 이유와 버린 선택지를 결정한 순서대로 남긴다.

| 날짜 | 결정 | 상태 |
|---|---|---|
| {YYYY-MM-DD} | [{제목}]({파일}) | {채택, 대체됨} |
```

- 날짜 오름차순

## 템플릿

```text
# {정한 것, 결론 문장}

| 항목 | 값 |
|---|---|
| 날짜 | {YYYY-MM-DD} |
| 상태 | {채택, 대체됨} |
| 대체 | {없음, 대체한 결정 링크, 대체된 결정 링크} |
| 관련 문서 | [{문서 제목}](../{파일}) |

## 배경

{무엇을 정해야 했는지, 어떤 제약과 요구가 있었는지 한 문단}

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| {선택지} | {장점} | {단점} |

## 결정

{고른 선택지와 가른 기준 한 문단}

## 결과

- {이 결정으로 얻는 것}
- {이 결정으로 치르는 것}

## 다시 볼 조건

- {이 결정을 다시 검토하게 만드는 관측}
```

| 자리 | 규칙 |
|---|---|
| 제목 | 고른 것이 보이는 결론 문장, 마침표 없음: `플러그인과 표준 입출력으로 통신한다`. 판단 기록에서 옮기면 그 제목에서 용어만 설계 문서 이름으로 교체 |
| 대체 | 새 기록 `대체한 결정: [{제목}]({파일})`, 옛 기록 `대체된 결정: [{제목}]({파일})`. 둘 다 아니면 `없음` |
| 관련 문서 | 이 결정을 반영한 설계 문서. 여럿이면 `, `로 연결 |
| 배경 | 과거형. 당시 확인한 사실만 |
| 선택지 | 2~4행. 고른 선택지를 첫 행에. 문장 열 없음. 판단 기록이 있으면 선택지 이름, 얻는 것, 잃는 것 글자를 명사구 끝만 바꿔 옮기기 |
| 결정 | 과거형 두 문장: `{선택지}를 골랐다. {가른 기준}이 기준이었다.` 기준이 둘이면 `, `로 연결 |
| 결과 | 얻는 것, 치르는 것 한 항목 이상씩, 명사구 |
| 다시 볼 조건 | 관측할 수 있는 조건: `플러그인 실행기가 소켓만 제공` |

## 판단 기록에서 옮기기

| 비공개 판단 기록 | 공개 결정 기록 |
|---|---|
| 제목 | 제목 |
| 문제 | 배경. 잃는 것 대신 제약과 요구로 |
| 알던 것과 모르던 것 | `[근거: ...]` 문장의 사실만 배경에. 출처가 `docs/archive`면 제외 |
| 선택지 | 선택지. 얻는 것은 장점, 잃는 것은 단점 |
| 판단 | 결정. 확신 표 제외 |
| 틀렸다는 신호 | 다시 볼 조건 |
| 판단 변경의 놓친 것, 교훈 | 제외 |

- `[가정]`, `[미확인]`, `[추정]`이 붙은 문장 제외
- 사람 이름, 비용, 일정, 내부 경로, 다른 판단 기록 링크 금지
- 판단 변경이 공개 결정을 바꾸면 새 결정 기록, 옛 기록 상태는 `대체됨`

## 작성 절차

1. 대상 표로 기록 여부 판정. 아니면 중단
2. 판단 기록이 있으면 옮기기 표대로. 없으면 재료는 `design` 이슈 결정 댓글과 PR 본문
3. 채울 사실이 없는 칸이 있으면 저장 금지, 보고(repo-docs 템플릿 사용)
4. 관련 설계 문서의 기술 선택 표나 해당 절에 이 기록 링크 추가(repo-docs-design)
5. `docs/decisions/README.md`에 행 추가
6. 저장 전 검사 실행(repo-docs)
