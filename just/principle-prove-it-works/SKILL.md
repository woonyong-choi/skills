# 동작 증명(Prove It Works)

모든 작업 결과는 실제 대상을 직접 확인해서 검증한다. 대리 지표, 자기 보고, "컴파일된다"에서 추론하지 않는다.

**이유.** 검증하지 않은 작업은 올바른지 알 수 없다. 간접 검증(파일 수정 시각, 출력이 새것인지, 에이전트의 자기 보고, 캐시된 스크린샷)은 직접 관측보다 싸게 느껴진다. 잘못된 추론에 따라 행동하는 비용은 원본을 확인하는 비용보다 훨씬 크다.

대리 지표가 아니라 실제 대상을 확인한다.

- 프로세스가 살아 있는지는 파생 상태로 간접 확인하지 말고 직접 확인한다.
- 캐시되거나 파생된 표현이 아니라 실제 값을 읽는다.
- 검증이 실패하면 시스템보다 관측 방법을 먼저 의심한다.
- 0이나 빈 결과는 정상 입력으로 먼저 확인한다. 결과가 나와야 하는 입력을 넣어 입력, 필터, 기간, 권한, 읽기, 계측이 실제로 값을 잡는지 본 뒤에야 "없다"고 판단한다. 일부 검색에서 못 찾은 것을 전체에 없다고 넓히지 않는다.
- 확인한 범위를 나눠 적는다. 호출, 응답, 효과, 영속화, 재시작과 구현, 실사용, 배포, 복구는 저마다 따로 확인한다. 모의 성공, 형식 통과, 검사 개수, 검토자 동의는 확인을 대신하지 못한다.
- 모델의 검토 결과도 원래 요구와 직접 근거로 다시 확인한다. 확신, 요약, 해시를 서로 인용해 근거로 삼지 않는다.

## 기대 결과는 독립된 근거에서 가져온다

기대 결과를 구현 코드, 같은 계산식, 모델 답변에서 베끼지 않는다. 그렇게 만든 기대값은 구현이 틀려도 같이 틀린다. 요구사항, 공식 계약, 사용자가 정한 값처럼 구현과 독립된 근거에서 가져온다. 독립된 근거가 없으면 그 항목은 미검증으로 보고한다.

## 필수 검사를 끝까지 돌린다

저장소와 언어가 요구하는 빌드, 테스트, 포맷, 린트를 돌린다. 해결하지 않은 실패나 경고가 남아 있으면 완료로 보고하지 않는다.

## 가능하면 확인을 스크립트로 만든다

가장 강한 증명은 한 번 눈으로 보는 것이 아니라 같은 비교를 다시 돌리는 결정적인 스크립트다. 스크립트를 쓰고, 돌리고, 그 출력을 산출물로 남긴다. 리뷰어는 내 말을 믿는 대신 그것을 다시 돌려 볼 수 있다.

확인 스크립트와 출력을 어디에 둘지는 [도구부터 만들기](../principle-build-the-lever/SKILL.md)의 도구 파일 기준을 따른다. 나중에 기록을 점검해야 하는 크고 복잡한 작업은 **show-me-your-work** 스킬로 결정 기록도 남긴다.
