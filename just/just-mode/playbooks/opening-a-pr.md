### PR 열기

다른 모든 플레이북의 끝에서 부른다.

**워크트리.** main에서 딴 git 워크트리에서 일한다. 서브에이전트도 그것을 물려받는다. 같은 브랜치에서 서브에이전트를 여러 개 띄우면 각자 자기 워크트리를 받거나, 그 사이마다 `git fetch && git reset --hard origin/<branch>`를 한다. 브랜치에 무관한 작업이 섞여 있으면 변경을 패치로 빼고, 새 워크트리를 만들어 적용한다. 워크트리가 엉켰으면 main에서 리셋하고 필요한 것만 다시 한다.

**커밋.** 커밋은 자주 한다. PR을 열기 전에 작고 순서 있는 커밋으로 리베이스한다. 커밋 하나하나가 미래의 PR이다. 따로 머지할 수 있어야 하고, 차례로 읽으면 변경 흐름이 이해되게 순서를 정한다. 방금 만든 커밋에 속하는 수정이면 amend한다. 따로 떼어 낼 수 있는 변경이면 새 커밋을 만든다. 커밋 본문에 제목을 되풀이하지 않는다.

**PR.** 커밋 전에 **unslop** 스킬로 diff의 AI 티 나는 군더더기를 지우고, 리뷰 전에 **no-comments** 스킬을 돌린다. 모든 PR 제목, 설명, 커밋 본문은 **technical-writing** 스킬로 쓰고, 그다음 **unslop**을 적용한다. technical-writing은 Diátaxis를 뺀 모든 계층을 적용한다.

**제목과 커밋.** 커밋 메시지와 PR 제목은 **git-commit** 스킬의 `type(scope): 한글 설명` 형식을 따른다. 커밋·PR·이슈 본문은 "~다"로 끝내지 않고 "확인", "결정", "구현"처럼 명사로 끝낸다.

**설명.** PR 본문은 diff를 보고 있는 리뷰어가 1분 안에 읽을 요약이지 실험 노트가 아니다. 틀과 절 순서는 **git-pull-request** 스킬의 PR 본문 틀을 따르고 할 말이 없는 절은 뺀다. 본문은 squash 커밋 본문이 되므로 약 40줄을 넘지 않게 한다. 각 절에는 변경 이유, 일부러 뺀 것, 깨뜨릴 수 있는 것, 실제로 돌린 검증과 결과가 드러나야 한다. 성능이면 대표 숫자 하나를 단위와 함께 `이전 → 이후`로 쓰고, 나머지는 arena나 swarm 폴더 링크로 둔다.

절 다음에는 주장을 증명하는 영상이나 스크린샷이 있으면 붙인다. 전체 SHA, swarm이나 arena 검증 항목 나열, 만든 도구를 고친 경위 설명, 파일별 체크리스트, "CLEAN" 판정은 본문이 아니라 링크한 별도 결과물에 둔다.

**PR 도구.** PR 생성, 수정, 보기, 감시, 머지는 GitHub CLI(`gh`)로 한다. Graphite(`gt`)를 요구하지 않는다.

**내장 PR 도구.** 실행 환경에 내장 PR 도구가 있으면 생성, 수정, 기준 브랜치 변경, 준비 표시는 그 도구로 하고 CLI로 하지 않는다. CLI로 만든 PR은 그 도구가 추적하는 정보를 놓친다. 그 도구가 다루지 않는 일과, 그런 도구가 없을 때의 모든 PR 작업은 `gh`로 한다.

**크기와 스택.** 큰 PR 하나보다 좁은 PR 다섯이 낫다. 스택은 기준 브랜치가 줄줄이 이어진 구조다. 맨 아래 PR은 trunk를 대상으로 한다. 각 자식 브랜치는 부모의 정확한 끝 커밋 위로 리베이스하고, 그 PR은 부모 브랜치를 대상으로 한다. 부모가 머지되면 `playbooks/shipping.md` 4단계에 따라 자식을 trunk로 옮긴다. 내장 PR 도구가 없으면 자식은 `gh pr create --base <parent-branch>`로 만들고, 기준 변경은 `gh pr edit <pr> --base <parent-branch>`로 한다. 독립된 작업일 때만 trunk에서 분기한다. 스택에서 큰 작업을 하기 전에 trunk로 리베이스한다.

**준비 상태로 열기.** 모든 PR은 초안(draft)이 아니라 리뷰 준비 상태(ready)로 연다. 내장 PR 도구는 기본이 초안일 수 있으므로 그 도구로 만들 때마다 `draft: false`를 준다. `gh`에서는 `--draft`를 뺀다. 그래도 초안으로 열리면 PR 도구로 준비 표시를 하거나 `gh pr ready <number>`를 실행한다. PR 상태를 말하기 전에 `gh pr view <number>`를 실행한다.

**PR 돌보기.** PR을 연다고 PR 돌보기가 시작되지 않는다. URL을 올리고 작업을 계속한다. 단계나 스택을 먼저 끝낸다. 스택 전체가 생긴 뒤 사용자가 요청할 때만 따로 PR 돌보기를 돌린다. 새 PR마다 돌보면 작업이 멈추고, 다음 push 웨이브가 어차피 다시 돌릴 커밋에 CI를 낭비한다. 리뷰 피드백이 원래 의도에서 벗어나면 반박한다.

PR을 연 서브에이전트는 `interrogate`, **unslop**, **no-comments**를 돌리고 URL을 올린다. 오토파일럿 전체나 오토파일럿 스택의 담당자가 아니면 PR 돌보기 없이 부모에게 돌아간다. 그 담당자가 받은 지시에는 PR 돌보기 루프가 들어 있고, 그 지시가 바로 `playbooks/babysit.md`가 기다리는 요청이다. 담당자는 코드 준비 보고 뒤에 루프를 시작하고, 자기 플레이북에 따라 머지 준비나 STACK-READY를 보고한다. 스택 전체가 만들어질 때까지 PR 돌보기를 미루라는 이 문서와 `playbooks/babysit.md`의 규칙은 담당자에게 적용하지 않는다.
