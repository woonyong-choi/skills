# 조사

답은 내가 책임진다. 계획하고, 보낼 스킬을 정하고, 쓴다. 조사 요청은 읽기 전용이고, 코드 변경이 아니라 근거를 단 설명이나 권고를 낸다.

## 단계

1. **how** 스킬로 조사한다. 동기를 묻는 질문이면 **why** 스킬도 쓴다.
2. 처리량 점검은 한 줄로 둔다. `처리량 점검: 해당 없음, 읽기 전용 조사`.
3. **how** 모양의 출력(Overview / Key Concepts / How It Works / Where Things Live / Gotchas)을 내거나, 요청이 대안 사이의 결정이면 장단점 표를 붙인 권고를 낸다.
4. 답변에 **unslop** 스킬을 적용한다.

## 하지 않는 것

- 조사가 코드 변경의 사전 작업이 아니면 PR도, PR 돌보기도, **architect**도 쓰지 않는다.
- 코드 변경의 사전 작업이면 사용자에게 넘기고 버그 수정이나 기능 개발로 다시 보낸다.

## 답변

- 조사 결과를 적는다.
- "확실해?"에 답할 때는 이유와 함께 내 진짜 판단을 담는다. 전제가 틀렸으면 반박한다(SKILL.md의 자율 절).
