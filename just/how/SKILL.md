# 동작 방식 설명

코드베이스를 탐색해 "X는 어떻게 동작하나?" 질문에 답한다. 하위 시스템을 처음 맡는 시니어 엔지니어 수준의 아키텍처 설명을 만든다. 쓸 만한 머릿속 모델을 세울 만큼은 자세하고, 주석 달린 소스 코드처럼 읽힐 만큼 자세하지는 않다.

모든 서브에이전트는 읽기 전용으로 띄운다([호스트 대응표](../just/references/hosts.md)). 탐색자는 `code` 역할, 설명자는 `judgment` 역할 모델을 쓴다([역할별 모델](../just/references/models.md)). 지정한 모델이 거부될 때의 처리도 역할별 모델을 따른다. 서브에이전트마다 추론 수준은 [서브에이전트](../just/references/subagents.md#추론-수준과-속도-고르기)에 따라 일에 맞게 고른다.

## 1. 복잡도 판단

범위가 모호하면 내가 어떻게 해석했는지 밝히고 탐색한다. 방향이 틀렸으면 사용자가 바로잡을 수 있다.

- **단순**(모듈 하나, 작은 유틸리티, "함수 X는 어떻게 동작하나" 같은 좁은 질문)하면 탐색자를 띄우지 않는다. 탐색과 설명을 한 번에 하는 설명자 하나를 띄운다. 프롬프트는 `references/explainer-prompt.md`에서 탐색자 결과 절을 빼고 만든다. 4단계로 간다.
- **복잡**(여러 파일이나 서비스에 걸친 하위 시스템, 여러 곳을 가로지르는 기능, 전체 아키텍처 개요)하면 2단계로 간다.

애매하면 단순 경로를 택한다.

## 2. 탐색(복잡한 경우만)

질문을 2~4개 관점으로 나눈다. 각 관점은 하위 시스템의 서로 다른 단면이다. 탐색자를 모두 동시에 띄운다. 각자 `references/explorer-prompt.md`에 자기 관점을 채워 받는다.

## 3. 종합(복잡한 경우만)

탐색자가 모두 돌아오면 설명자 하나를 띄운다. 프롬프트는 `references/explainer-prompt.md`에 모든 탐색자 결과를 채워 만든다.

## 4. 전달

설명자의 결과를 전달한다. 명확하게 다듬거나 대화 맥락을 덧붙이는 정도의 가벼운 수정은 괜찮다. 크게 다시 쓰지 않는다.

## 답변

설명은 `references/explainer-prompt.md`가 정한 절(개요, 핵심 개념, 동작 방식, 코드 위치, 주의할 점)을 쓰고, 해당 없는 절은 뺀다.
