# 세션 이어받기

재개 지점을 맡는다. 결정 기록을 먼저 읽고, 끝난 일을 다시 하지 않는다. 이 플레이북은 읽기 전용이고 5단계에서 끝난다. 남은 일은 5단계에서 보낸 순서표가 맡는다.

## 단계

1. 이전 기록을 찾는다.
   - 먼저 결정 기록 `.local/decisions/<과업>.tsv`의 마지막 줄들(특히 phase `다음`과 `결정 필요`), 연결된 이슈 본문과 판 상태, push된 브랜치와 작업 중 저장 커밋(`작업 중 변경 추가`)을 읽는다.
   - 그것으로 재개 지점이 부족할 때만 대화 기록을 읽는다. 대화 기록은 **recall** 스킬로 찾거나 현재 프로젝트의 대화 기록([호스트 대응표](../references/hosts.md)의 대화 기록 위치)을 직접 읽는다.
   - 대화 기록은 현재 프로젝트 폴더 안에서만 찾는다. 다른 프로젝트 폴더까지 glob으로 훑지 않는다. 그러면 작업 공간 경계를 넘어 관계없는 프로젝트의 비공개 대화까지 읽게 된다.
   - 메타데이터 개요와 마지막 메시지를 먼저 읽고, 거슬러 올라가며 결정 지점을 훑는다. 긴 대화 기록은 서브에이전트에서 파싱하고 줄인 시간순 정리만 주 대화에 둔다(**principle-guard-the-context-window** 스킬).
2. 작업 상태를 다시 세운다. 브랜치와 워크트리, 이미 들어간 것(`git log`, base 대비 `git diff`), 열린 할 일, 내려진 결정을 확인한다. 결정 기록과 이전 기록은 믿고 쓸 입력이다. 처음부터 다시 도출하려 하지 않는다.
3. 끝난 것과 남은 것을 비교한다. 배포된 것과 계획된 것을 비교하고, 재개 지점을 밝힌다. 이전 재현을 다시 돌리거나 끝난 일을 다시 하지 않는다. "처음부터 검증해 보자"는 믿고 써야 할 기록을 못 믿을 것으로 대한다는 뜻이다.
4. 물려받은 "끝났다"는 주장만 실제 결과물에서 확인한다(**principle-prove-it-works** 스킬). 확인은 이미 있는 결과물을 읽는 일이다. PR과 CI 상태, 장부와 판정 줄, 커밋된 파일, 남은 산출물을 본다. 일을 다시 하거나 재현을 다시 돌리는 것이 아니다. 이전 에이전트가 통과했다고 스스로 보고했을 뿐 결과물이 없으면 끝나지 않은 일로 남은 일에 넣는다.
5. 재개 지점을 결정 기록에 phase `start` 줄로 남기고, 남은 일을 맞는 플레이북으로 보내고 판정을 고른다. 판정은 실행을 이어 가기, 완성된 추천을 내놓기, 이전 결론을 승인하거나 뒤집기, 실패한 실행을 사후 분석하기 중 하나다. 세션 이어받기 플레이북은 여기서 끝난다.

## 답변

- 이전 에이전트가 멈춘 곳, 물려받은 것과 다시 한 것(다시 한 것은 없을수록 좋다), 재개 지점, 결과를 적는다.
