# HTML Report

- 저장소 안에 같은 역할의 규칙이 있으면 그것 우선. 없으면 이 스킬이 다른 규칙보다 우선
- 범위: 사용자가 그림으로 결정하거나 결과를 확인하는 보고서 HTML 한 장의 구성, 모형 표시, 생성 스크립트, 확인 절차

## 사용 조건

쓸 때:

- 차이가 눈으로만 보이는 선택지 결정(레이아웃, 차트 모양, 색, UI 배치 A/B)
- 화면이 바뀌는 작업의 머지 전 확인(스크린샷 전/후)
- 그림 3장 이상, 또는 그림, 코드, 실행 출력을 함께 봐야 하는 경우
- 사용자 요청 낱말: 보여줘, 눈으로, 그림으로 정리, 비교해서, 보고서로, 스크린샷으로

| 상황 | 대신 |
|---|---|
| 글로 고를 수 있는 결정 | 채팅 또는 질문 선택지 |
| 그림 1~2장 | 채팅에 바로 |
| 저장소에 커밋할 문서 | (repo-docs 문서 목록) |
| 데모 GIF, 홍보 영상 | (repo-docs-figures 도구), (repo-docs-promo 촬영 순서) |

## 구성

섹션 하나가 질문 하나 또는 확인 대상 하나. 순서 고정. 입력 최상위 `kind`로 종류 선택(기본 `decision`)

| 칸 | 결정 보고서 `decision` | 결과 보고서 `result` |
|---|---|---|
| 제목 | 질문 번호와 한 줄 제목 | 확인 대상 번호와 한 줄 제목 |
| 설명 | `무슨 질문인가`: 2~3문장, 낱말 풀이 포함 | `무엇이 바뀌었나`: 요청한 것과 반영한 것, 낱말 풀이 포함 |
| 그림 | 지금 그림을 선택지 앞에 같은 크기로. 선택지 A, B, C 같은 크기로 나란히 | 전과 후를 같은 크기로 나란히. 단계, 다크 모드 그림은 `extra` |
| 표 | `좋은 점`, `나쁜 점` | `좋은 점`, `남은 문제` |
| 확인할 점 | 선택(`check`) | 선택(`check`): 사용자가 직접 볼 것 |
| 마지막 줄 | `추천`: 추천 선택지와 이유 한 문장 | `판단`: `머지 권장` 또는 `다듬기 필요`와 이유 한 문장 |

- 선택지 열 제목: 기호와 이름(`A. 몸통을 길게`). 지금 상태가 선택지 중 하나면 제목에 `지금 =` 표기. 결과 보고서 열 제목은 `전 (main)`, `후 (PR #11)`
- 열 최대 4개(초과 시 스크립트 오류), 그림 2개 이상이면 열 안에 세로로
- 맨 위: 제목, 모형 표시 규칙 설명, 번호 링크
- 표 칸 정렬 `align`: 짧은 값(통과, 오류, 숫자)은 `center`, 숫자만 있는 칸은 `right`, 글은 `left`. 열 너비는 `widths`
- 열마다 `max_height`로 그림 높이 상한만 지정

## 그림

- 그림 색 변경 금지
- 라이트와 다크를 둘 다 보여야 하면 각각 고정해 찍은 PNG로 넣기. 브라우저 테마를 따르는 SVG를 직접 넣으면 다크 브라우저에서 다크로만 보임. 캡처는 색 구성표를 고정한 브라우저로

## 모형 표시

- 흉내 낸 그림은 `"mock": true`와 그림 안 `모형` 문구. 시험 코드로 실제 그린 그림은 모형 아님
- 지어낸 경고·수치는 `[모형]` 표기

## 저장 위치

프로젝트 보고서: 해당 저장소 `.local/reports/{YYYY-MM-DD}-{주제}/`. 저장 전 `git check-ignore .local`로 git 제외 확인. 제외되지 않으면 저장 금지, 보고

프로젝트가 없는 보고서: 워크스페이스 규칙의 작업 기록 폴더. 없으면 사용자에게 확인. 임시 폴더 금지

`index.html`(결과), `choices.json`(입력), `index.png`(전체 캡처), `svg/`(그림 SVG, PNG), `sources/`(그림을 만든 시험 코드와 원본 입력)

그림 경로: 입력 JSON 폴더 기준 상대 경로

## 문장 규칙

- 쉬운 한국어. 전문 낱말은 처음 나올 때 풀이 한 번
- 좋은 점, 나쁜 점은 근거(시험 결과, 그림에서 보이는 것) 포함. 추정이면 추정이라고 표기

## 생성

```sh
python3 <이 스킬 폴더>/scripts/build_report.py <입력.json> [출력.html]
```

- 출력 기본값: 입력 파일 옆 `index.html`
- 결과 보고서의 `effect`는 `["후", "좋은 점", "남은 문제"]`, `rec`는 `["머지 권장", "이유"]`

입력 JSON(필수는 `*`, 나머지 선택):

```json
{
  "kind": "decision | result",
  "title*": "제목", "intro*": "맨 위 설명. 모형 표시 규칙 포함",
  "questions*": [{
    "title*": "", "what*": "",
    "options*": [
      {"label*": "A", "images": [{"src*": "svg/a.svg", "alt": "", "max_height": 300}], "mock": true, "text": ""},
      {"label*": "B", "table": {"head*": ["항목"], "rows*": [["x"]], "align": ["left"], "widths": ["70%"]}}
    ],
    "effect*": [["A", "좋은 점", "나쁜 점"]],
    "rec*": ["A", "이유 한 문장"],
    "check": [""], "note": "",
    "extra": [{"title*": "", "options*": []}]
  }]
}
```

## 확인 절차

1. 생성 스크립트 오류 없이 종료
2. 브라우저로 열어 깨진 이미지 0개 확인(모든 `img`의 `naturalWidth` > 0)
3. 화면 캡처로 확인: 표 칸 정렬, 그림 위 여백, 모형 테두리 굵기. 전체 캡처가 브라우저 높이 제한(약 8000px)에서 잘리면 섹션 단위로 나눠 찍어 확인
4. 질문마다 구성 칸이 빠짐없이 있고, 모형 그림에 표시가 있는지 확인
5. 확인용 캡처 삭제, `index.png`(전체 캡처) 하나만 보존
