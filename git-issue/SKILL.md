# Git Issue

- 저장소 안에 같은 역할의 규칙이 있으면 그것 우선. 없으면 이 스킬이 다른 규칙보다 우선
- 범위: 이슈 종류, 라벨, 제목, 본문 틀, 묶음, 상태, 닫기. 브랜치와 PR 흐름(git-branch), PR 본문(git-pull-request), 커밋 형식(git-commit) 제외
- 필요할 때만 읽기: build, docs 제목의 끝말이나 영역 라벨의 scope 단어 → git-commit

## 종류

한 이슈에 종류 하나. 라벨: 종류 라벨 하나, 영역 라벨 하나.

| 종류 라벨 | 쓰는 때 | 제목 | 예 |
|---|---|---|---|
| `design` | 정해야 할 질문 | `~할지`, `~을 무엇으로 할지` | `연결이 끊긴 요청을 다시 보낼지` |
| `build` | 만들 것 확정 | 대상 + 끝말 (git-commit 설명) | `토큰 만료 시 자동 재발급 추가` |
| `bug` | 설계·기대와 다른 동작 | `~할 때 ~하는 문제` | `재연결 뒤 대기 요청이 두 번 전송되는 문제` |
| `experiment` | 측정·실측 필요 | 대상 + `측정` | `한국어 입력의 분류 오류율 측정` |
| `docs` | 문서만 수정 | 대상 + 끝말 | `설치 방법 갱신` |

- 영역 라벨: `area:{scope}`. scope는 커밋 scope 단어 (`area:core`, `area:tui`, `area:repo`)
- 제목: 한글, 50자 이내, 마침표·물음표 없음. 라벨 이름, 번호 금지

## 본문

- 종류별 틀. 섹션 이름, 순서 그대로. 내용 없으면 빼는 절: `원인`, `범위 밖`, `관련`만
- 틀 파일: `.github/ISSUE_TEMPLATE/{종류 라벨}.md`. 파일 머리 `---` 사이에 GitHub 틀 머리말 `name: {종류 라벨}`, `about: {쓰는 때}`, `labels: [{종류 라벨}]`
- 문장, 목록, 표: 평서 문체 (repo-docs 문체)
- 저장소 파일 링크: 전체 URL `https://github.com/{소유자}/{저장소}/blob/main/{경로}`. 이유: 이슈에서 상대 경로 열기 불가

design

```text
## 질문

{정할 것, `~할지`로 끝나는 명사절}

## 배경

{왜 지금 정해야 하는지 한두 문장}. 관련 설계: [{문서 제목}]({전체 URL})

## 선택지

| 선택지 | 얻는 것 | 잃는 것 |
|---|---|---|
| {선택지} | {얻는 것} | {잃는 것} |

## 정하는 기준

- {기준}

## 관련

- {이슈나 문서 링크}
```

build

```text
## 목표

{끝나면 무엇을 할 수 있는지 한두 문장}

## 따르는 설계

- [{문서 제목}]({전체 URL}#{절})

## 계약

{공개 타입과 함수 시그니처 초안. 계약이 코드에 들어가면 코드 위치로 바꾼다}

## 완료 조건

- [ ] {검증할 수 있는 조건} (확인: `{테스트 이름이나 명령}`)

## 범위 밖

- {하지 않는 것}

## 관련

- {이슈나 문서 링크}
```

bug

```text
## 증상

{무엇이 잘못 보이는지 한 문장}

## 재현

1. {단계}

## 기대 동작

{설계 문서 링크와 해당 규칙}

## 실제 동작

{관측한 동작}

## 환경

| 항목 | 값 |
|---|---|
| 운영체제 | {운영체제} |
| 버전 | {버전} |
| 커밋 | `{커밋}` |

## 원인

{찾은 뒤 채운다}
```

experiment

```text
## 확인할 것

{측정할 것 한 문장}

## 실험 문서

- [{실험}]({design.md 전체 URL})

## 관련

- {이슈나 문서 링크}
```

- `docs` 이슈: build 틀에서 `계약` 절 제외
- 관련 절: 막는 이슈, 막히는 이슈, 상위 이슈, 설계 문서 링크
- 완료 조건: 확인 방법까지. `잘 동작함` 같은 조건 금지

## 묶음과 순서

- 큰 작업(설계 문서 둘 이상 변경, 공개 계약 변경, 이슈 셋 이상): 마일스톤 하나(설명: 목표 한 문장, 성공 기준)
- 나눈 작업: GitHub 하위 이슈. 순서 제약: GitHub 막힘 관계, 기능이 없으면 관련 절에 `막힘: #번호`
- 한 이슈 = 한 세션에 끝낼 분량. 크면 하위 이슈로 분할 (git-branch 작업 단위)

## 상태

상태 표시: GitHub로만. 이슈 본문, 문서에 상태 기록 금지.

| 상태 | 표시 |
|---|---|
| 할 일 | 열림, 담당자 없음 |
| 진행 중 | 담당자 지정 + 작업 브랜치 (git-branch) |
| 막힘 | 막힘 관계 |
| 끝 | 닫힌 이슈(completed) |
| 안 함 | 닫힌 이슈(not planned) + 이유 댓글 |

## 닫기

| 종류 | 닫는 방법 |
|---|---|
| build, bug, docs | PR의 `Closes: #번호`로만. 손으로 닫기 금지 |
| design | 결정 댓글 뒤 설계 문서 PR의 `Closes: #번호` |
| experiment | 결론 한두 줄 댓글 뒤 결과 PR의 `Closes: #번호`. 사전 등록 PR은 `Refs: #번호` |
| 안 함 | 이유 한 문장. 중복이면 `#번호와 중복` |

결정 댓글

```text
## 결정

{고른 선택지 한 문장}

## 이유

{정하는 기준에 비춰 한두 문장}

## 반영

- {설계 문서 PR}
- {후속 이슈}
```

- 닫은 이슈 재오픈 금지. 같은 문제 재발 시 새 이슈에 이전 이슈 링크

## 금지

- 한 이슈에 종류 둘 이상, 다른 이슈 작업 섞기
- 결정 댓글 없이 design 닫기
- 본문, 댓글에 비공개 기록 링크나 내용
- AI 흔적: 모델 이름, 생성 문구, 세션 링크
