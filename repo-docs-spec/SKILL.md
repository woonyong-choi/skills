# Repo Docs Spec

- 저장소 안에 같은 역할의 규칙이 있으면 그것 우선. 없으면 이 스킬이 다른 규칙보다 우선
- 기반: repo-docs 먼저 적용. 이 스킬 범위: 인터페이스 문서 템플릿과 항목 규칙
- 필요할 때만 읽기: 데이터 그림을 만들거나 바꿀 때 → repo-docs-figures; 요구·검증 범위, 생성표 의미, 호환성 확인 → repo-docs-design
- 문서 생성 여부: 만드는 조건(repo-docs 문서 목록). 인터페이스가 `main` 코드에 들어간 뒤에만. 그 전에는 `docs/design/{주제}.md` 상세 설계(repo-docs-design)
- 인터페이스 문서: 찾아보는 문서. 설명과 이유 없이 항목만. 이유: 설계 문서에
- 코드에서 만들 수 있는 내용(명령 도움말, 스키마, 기본값): 코드와 같은 글자. 코드가 바뀌면 같은 PR에서 수정
- 항목 순서: 문서마다 정한 순서. 정하지 않은 곳은 알파벳순

## 요구사항

- 요구·검증 범위, 생성표 의미, 기능 생략 시 호환 사례: (repo-docs-design 요구사항)

## protocol.md

````text
# 프로토콜

{보내는 쪽}과 {받는 쪽}은 {방식}으로 {형식} 메시지를 주고받는다.

## 전송

| 항목 | 값 |
|---|---|
| 방식 | {stdio, Unix 소켓 등} |
| 형식 | {JSON-RPC 2.0 등} |
| 메시지 구분 | {줄 단위, 길이 헤더 등} |
| 인코딩 | UTF-8 |

## 연결 수명

1. {주체}: {동작}

## 요청

### `{메서드}`

{하는 일 한 문장}

| 항목 | 값 |
|---|---|
| 방향 | {보내는 쪽} → {받는 쪽} |
| 부작용 | {바뀌는 것} |
| 순서 | {다른 메시지와의 순서 조건} |

#### 매개변수

| 이름 | 타입 | 필수 | 뜻 |
|---|---|---|---|
| `{이름}` | `{타입}` | {예, 아니오} | {뜻} |

#### 결과

| 이름 | 타입 | 뜻 |
|---|---|---|
| `{이름}` | `{타입}` | {뜻} |

#### 오류

| 코드 | 조건 |
|---|---|
| `{코드}` | {조건} |

#### 예

```json
{요청 JSON}
```

```json
{응답 JSON}
```

## 알림

### `{메서드}`

{요청 형식에서 결과 절을 뺀 것}

## 호환성

- {버전 규칙}
````

- 알림: 요청과 같은 형식, `#### 결과`만 제외
- 요청과 알림: 도메인 접두사로 묶고 `{도메인}/{동작}` 알파벳순: `session/start`, `session/stop`
- 부작용이 없으면 `없음`, 순서 조건이 없으면 `없음`
- 오류 코드의 뜻: `errors.md`에만. 여기는 조건만
- 예: 실제로 주고받을 수 있는 값. 한 메서드에 요청 하나, 응답 하나

````text
{도움말의 Usage 줄 그대로}
```

### 인자

| 인자 | 필수 | 뜻 |
|---|---|---|
| `{인자}` | {예, 아니오} | {뜻} |

### 옵션

| 옵션 | 값 | 기본값 | 뜻 |
|---|---|---|---|
| `{--옵션}` | `{값 형식}` | `{기본값}` | {뜻} |

### 예

```sh
{명령}
```

## 종료 코드

| 코드 | 뜻 |
|---|---|
| `{코드}` | {뜻} |
````

- 하위 명령 순서: 명령 표 순서. 명령 표: 처음 쓰는 순서
- 인자, 옵션이 없으면 그 절 삭제. 값을 받지 않는 옵션의 `값`, `기본값`: `없음`
- 전역 옵션 절: 모든 하위 명령에 적용되는 옵션이 있을 때만
- 종료 코드: 문서 끝에 한 번. 명령마다 다르면 `### 종료 코드`를 그 명령 절에

## configuration.md

````text
# 설정

## 우선순위

1. 명령 옵션
2. 환경 변수
3. 프로젝트 설정 파일 `{경로}`
4. 사용자 설정 파일 `{경로}`
5. 기본값

## 항목

### `[{표 이름}]`

| 키 | 타입 | 기본값 | 환경 변수 | 뜻 |
|---|---|---|---|---|
| `{키}` | `{타입}` | `{기본값}` | `{환경 변수}` | {뜻} |

## 전체 예

```toml
{기본값을 모두 적은 설정 파일}
```
````

- 우선순위에서 해당하지 않는 단계: 삭제 후 번호 재부여
- 표 이름 순서: 설정 파일에 나오는 순서. 키: 알파벳순
- 환경 변수가 없으면 `없음`
- 전체 예: 기본값과 같은 값만

## errors.md

```text
# 오류

프로세스 종료 코드는 [명령](cli.md)에 있다.

## 오류 코드

| 코드 | 이름 | 메시지 | 원인 | 대응 |
|---|---|---|---|---|
| `{코드}` | `{이름}` | `{메시지}` | {원인} | {대응} |
```

- 종료 코드 문장: `cli.md`가 있을 때만
- 코드 오름차순
- 메시지: 코드의 메시지 문자열 그대로
- 문장 열: `원인`, `대응`
- 없앤 코드: 행 삭제 대신 `이름`을 `폐기`로 변경. 없앤 코드 재사용 금지
