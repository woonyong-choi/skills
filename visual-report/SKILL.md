# Visual Report

- 저장소 안에 같은 역할의 규칙이 있으면 그것 우선. 없으면 이 스킬이 다른 규칙보다 우선
- 범위: 사용자가 그림으로 결정하거나 결과를 확인하는 보고서 HTML 한 장의 구성, 모형 표시, 생성 스크립트, 확인 절차

## 사용 조건

- 사용자가 그림, 스크린샷, 코드, 실행 출력을 보고 선택지를 고르는 보고서(결정 보고서)
- 사용자가 작업 결과를 전/후 그림으로 확인하고 머지 여부를 판단하는 보고서(결과 보고서)
- 글만으로 고를 수 있는 결정, 저장소에 남길 문서: 제외(repo-docs 계열)

## 구성

섹션 하나가 질문 하나 또는 확인 대상 하나. 순서 고정. 입력 JSON 최상위 `kind`로 종류 선택(기본 `decision`)

| 칸 | 결정 보고서 `decision` | 결과 보고서 `result` |
|---|---|---|
| 제목 | 질문 번호와 한 줄 제목 | 확인 대상 번호와 한 줄 제목(PR 번호 포함 가능) |
| 설명 | `무슨 질문인가`: 2~3문장, 낱말 풀이 포함 | `무엇이 바뀌었나`: 요청한 것과 반영한 것, 낱말 풀이 포함 |
| 그림 | 지금 그림을 선택지 앞에 같은 크기로. 선택지 A, B, C 같은 크기로 나란히 | 전과 후를 같은 크기로 나란히. 단계, 다크 모드 그림은 `extra` |
| 표 | `좋은 점`, `나쁜 점` | `좋은 점`, `남은 문제` |
| 확인할 점 | 선택(`check`) | 선택(`check`): 사용자가 직접 볼 것 |
| 마지막 줄 | `추천`: 추천 선택지와 이유 한 문장 | `판단`: `머지 권장` 또는 `다듬기 필요`와 이유 한 문장 |

- 선택지 열 제목: 기호와 이름(`A. 몸통을 길게`). 지금 상태가 선택지 중 하나면 제목에 `지금 =` 표기. 결과 보고서 열 제목은 `전 (main)`, `후 (PR #11)`
- 열 최대 4개, 그림 2개 이상이면 열 안에 세로로
- 맨 위: 제목, 모형 표시 규칙 설명, 번호 링크
- 표 칸 정렬: 짧은 값(통과, 오류, 숫자)은 `center`, 숫자만 있는 칸은 `right`, 글은 `left`. 열 너비는 `widths`로 지정
- 그림 위 여백 금지: 그림 칸은 그림 높이에 맞춤. 열마다 `max_height`로 상한만 지정
- 그림 칸: 옅은 회색 바탕과 1px 테두리. 흰 그림 가장자리가 보이게 함. 그림 색 변경 금지
- 카드와 표 선: 옅은 회색 계열 한두 단계 진하게, 표 머리 행 아래 선은 더 진하게

## 모형 표시

- 모형: 실제 동작이 아닌 흉내 그림. 선택지에 `"mock": true`
- 그림 안에 `모형`이나 `실제 동작 아님` 문구 필수
- 모형 선택지 칸은 굵은 주황 점선 테두리(4px)로 자동 표시. 실제 렌더 그림은 일반 테두리
- 시험 코드로 실제 렌더한 그림: 모형 아님, 그림 아래 주석에 시험 렌더라고 표기
- 지어낸 문구(경고, 수치): 앞에 `[모형]` 표기

## 저장 위치

- 작업 기록 폴더 안에만 저장. 그림과 입력 JSON, 결과 `index.html`이 같은 폴더 트리
- 저장소 안 커밋 금지, 임시 폴더와 `/tmp` 금지

```text
<작업 기록 폴더>/
├── index.html      생성 결과
├── choices.json    입력 JSON
├── index.png       확인용 전체 캡처
├── svg/            보고서에 넣는 그림(SVG, PNG)
└── sources/        그림을 만든 시험 코드와 원본 입력
```

## 문장 규칙

- 쉬운 한국어. 전문 낱말은 처음 나올 때 풀이 한 번
- 이모지 금지
- 좋은 점, 나쁜 점은 근거(시험 결과, 그림에서 보이는 것) 포함. 추정이면 추정이라고 표기

## 생성

```sh
python3 <이 스킬 폴더>/scripts/build_report.py <입력.json> [출력.html]
```

- 출력 기본값: 입력 파일 옆 `index.html`. 입력과 같은 폴더만 허용
- 그림 경로: 입력 파일 폴더 기준 상대 경로. 파일이 없으면 실패
- CSS 내장, 외부 파일 불필요. Python 3.9 이상 표준 라이브러리만
- 글은 모두 이스케이프. 백틱 안 글만 코드 서식
- `kind`: `decision`(기본) 또는 `result`. 결과 보고서의 `effect`는 `["후", "좋은 점", "남은 문제"]`, `rec`는 `["머지 권장", "이유"]`

입력 JSON 형식:

```json
{
  "kind": "decision",
  "title": "보고서 제목",
  "intro": "맨 위 설명. 모형 표시 규칙 포함",
  "questions": [
    {
      "title": "질문 제목",
      "what": "무슨 질문인가 2~3문장",
      "options": [
        {"label": "지금", "images": [{"src": "svg/now.svg", "alt": "설명", "max_height": 300}],
         "text": "실제 출력 문구(선택)"},
        {"label": "A. 이름", "images": [{"src": "svg/a.svg", "alt": "설명 (모형)"}], "mock": true},
        {"label": "B. 표", "table": {"head": ["항목", "결과"], "rows": [["x", "통과"]],
         "align": ["left", "center"], "widths": ["70%", "30%"]}}
      ],
      "effect": [["A", "좋은 점", "나쁜 점"], ["B", "좋은 점", "나쁜 점"]],
      "check": ["사용자가 직접 볼 것(선택)"],
      "rec": ["A", "이유 한 문장"],
      "note": "그림 아래 주석(선택)",
      "extra": [{"title": "추가 그림 제목", "options": []}]
    }
  ]
}
```

## 확인 절차

1. 생성 스크립트 오류 없이 종료
2. 브라우저로 열어 깨진 이미지 0개 확인(모든 `img`의 `naturalWidth` > 0)
3. 화면 캡처로 확인: 표 칸 정렬, 그림 위 여백, 모형 테두리 굵기
4. 질문마다 구성 칸이 빠짐없이 있고, 모형 그림에 표시가 있는지 확인
5. 확인한 캡처 파일도 같은 작업 기록 폴더에만 저장
