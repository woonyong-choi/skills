# 구매, 구축, 인프라

SaaS 도입, 구매와 구축, 호스팅을 고르거나 바꿀 때 같은 사용자 과업을 끝내는 구성끼리 비교한다. 먼저 지금의 [스펙](requirements.md)을 확인하고, 공급자 이름이 아니라 구성으로 비교한다.

## 후보

| 후보 | 먼저 확인할 적합 조건 | 비교할 대가 |
|---|---|---|
| 기존 SaaS 설정 | 필요한 업무, 권한, 데이터 입출력을 기본 기능으로 채운다 | 바꿀 수 있는 범위, 반출, 종속 |
| SaaS와 API 연동 | 필요한 차이를 확장이나 연동으로 채운다 | API 한도, 동기화, 인증, 중복과 실패 처리 |
| 관리형 서비스 조합 | 고유 화면과 업무 규칙은 구현하고 실행, DB, 인증 등은 맡긴다 | 남는 개발, 보안, 운영 책임과 서비스별 한도 |
| 직접 구축과 운영 | 계약, 통제, 운영에서 얻는 이점과 운영할 수 있다는 근거가 있다 | 개발, 배포, 패치, 관측, 복구, 인력, 이전 책임 |

- 위 후보는 차례로 반드시 거치는 목록이 아니라 비교 후보다. 지금 구성을 다시 쓰거나 섞어도 된다. 모두 조건을 채우지 못하면 제약 조정안을 설명하고 고르기 전까지 구현을 미룬다.
- 클라우드 공급자 하나에도 관리형 구성과 직접 운영 구성이 함께 있다. 공급자 이름과 SaaS라는 범주를 같은 급의 후보로 놓고 점수를 매기지 않는다.

## 후보 비교

| 정할 것 | 후보마다 확인할 것 | 탈락과 보류 기준 |
|---|---|---|
| 필요한 기능 | 같은 사용자 과업, 권한, 바꿀 수 있는 정도, 연동, 내보내기. 필요한 실행, DB, 파일, 인증, 큐, 관측이 포함되는 범위 | 요청하지 않은 기능을 필요한 것으로 만들어 후보를 고르지 않는다 |
| 실행 계약 | 지원 언어, 배경 작업, 시간 제한, 연결 수, 영속성, 리전, 네트워크 | 필수 계약을 어기는 후보는 근거와 함께 뺀다. 확인하지 않은 것은 확인 전에 정하지 않는다 |
| 운영 책임 | 설치, 패치, 배포, 백업, 복원, 모니터링, 장애 대응의 담당자와 작업 시간 | 관리형도 남는 책임을 밝힌다. 담당자가 정해지지 않은 것을 운영할 수 있다고 보지 않는다 |
| 보존과 철수 | 내보내기 형식, 이전 경로, 인증과 파일과 DB 의존, 중단 시간, 나가는 트래픽 | 코드만 바꿨다고 데이터와 권한 이전이 끝났다고 판정하지 않는다 |

- 스펙에 맞는 실제 후보만 비교하고 후보 수를 채우지 않는다. 필수 조건마다 근거와 충족, 위반, 미확인을 대조한다. 확인하지 않은 조건이 남은 후보에 전체 통과를 표시하지 않는다.
- 특정 공급자에게 관리형 서비스가 없다고 가정하는 기울어진 비교를 하지 않는다. 축을 가르는 법과 공식 한도 조회는 [구조 경계](../SKILL.md#구조-경계)와 [선택](../SKILL.md#선택)을 따른다.
- 결론에는 채우는 스펙, 남는 책임, 추천이 바뀌는 조건을 쓴다. 검증 상태와 채택, 구현 권한을 나눈다.
