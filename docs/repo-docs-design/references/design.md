# design/{주제}.md

`docs/design/{주제}.md`를 쓰거나 갱신하거나 검토할 때 이 상태, 절 목록, 틀을 쓴다.

## 독자와 파일

- 독자는 기여자와 검토자다. 왜 필요한가, 어떻게 동작하나, 무엇이 아직 미정인가에 답한다.
- 파일 이름은 기능 주제의 영어 소문자 kebab-case다(`input-handling.md`).
- 주제는 사용자가 알아볼 수 있는 기능 단위다. 모듈 설명을 어디에 둘지는 architecture.md의 세부 분리 기준을 따른다.

## 상태

| 상태 | 뜻 |
|---|---|
| 제안 | 검토 중이다. 요구사항 표의 필수 동작에 미해결 항목이 있다 |
| 결정 | 요구사항 표의 필수 동작에 모두 승인 근거가 있다. 구현 근거는 아직 없다 |
| 구현 | 요구사항 표의 필수 동작이 모두 repo-docs 사실 상태의 구현 근거를 채운다 |

- 사용 가능은 따로 실제 실행 근거가 반드시 있어야 한다(repo-docs 사실 상태).

## 절

| 순서 | 한국어 절 | 영어 절 | 필수 | 내용 |
|---|---|---|---|---|
| 1 | `요약` | `Summary` | 필수 | 무엇을 하는 기능인지 한 문단. 해당하면 아래에 `하지 않는 것`(영어 `Non-goals`) 목록 |
| 2 | `해결하는 문제` | `Motivation` | 필수 | 누가 어떤 상황에서 무엇이 어려운지, 이 기능이 없으면 생기는 일 |
| 3 | `사용 예` | `Examples` | 필수 | 요구사항별 동작 차이가 드러나는 사용 장면. 현재형 |
| 4 | `작동 방식` | `Design` | 필수 | 규칙, 상태, 흐름, 오류 처리, 요구사항 |
| 5 | `단점` | `Drawbacks` | 선택 | 이 설계가 치르는 비용 |
| 6 | `대안` | `Alternatives` | 선택 | 버린 방법 한 줄씩과 공개 결정 기록 링크 |
| 7 | `미해결` | `Unresolved questions` | 미정이 있으면 필수 | 질문과 추적 링크 |

## 틀

````text
# {주제 이름}

| 항목 | 값 |
|---|---|
| 상태 | {제안, 결정, 구현} |
| 관련 결정 | [{결정 제목}](../decisions/{결정 파일}.md) |

## 요약

{무엇을 하는 기능인지 한 문단}

### 하지 않는 것

- {하지 않는 일}: {이유 한 문장 또는 옮긴 곳 링크}

## 해결하는 문제

{누가 어떤 상황에서 무엇이 어려운지, 이 기능이 없으면 생기는 일}

## 사용 예

### {장면 이름}

1. {사용자가 보는 것 또는 시스템이 하는 일 한 문장}

## 작동 방식

### {규칙, 상태, 흐름, 오류 처리 중 하나의 이름}

{내용}

### 요구사항

| 요구사항 | 검증 계획 |
|---|---|
| {요구사항 문장} | {테스트나 실험이 확인할 내용} |

## 단점

- {이 설계가 치르는 비용}

## 대안

- {버린 방법}: {버린 이유 한 문장} [결정 기록](../decisions/{결정 파일}.md)

## 미해결

- {질문과 선택지} ([#{번호}]({이슈 URL}))
````

## 자리 규칙

| 자리 | 규칙 |
|---|---|
| 하지 않는 것 | 요약 아래 선택적 `###` 소제목이다. 이 기능에 붙어 기대할 만한 일만 5개까지 쓴다. 항목마다 이유나 옮긴 곳(설계 문서, 이슈 링크)을 반드시 쓴다. 해당이 없으면 소제목까지 뺀다. 대안, 단점, 미해결과 섞지 않는다 |
| 사용 예 | `###` 하나가 장면 하나다. 단계마다 한 문장이다 |
| 작동 방식 | `###`으로 나눈다. 단계 목록은 문장이다. 수치 근거는 repo-docs `references/writing.md`를 따른다. 상태 전이가 있으면 `상태`, `뜻`, `다음 상태` 표를 쓴다 |
| 요구사항 | 작동 방식의 마지막 `###`이다. 시험이 생기면 검증 계획을 `{파일 경로}`의 `{테스트 이름}`으로 바꾼다 |
| 미해결 | 추적기가 없으면 `- {질문 ID}: {질문} ({결정 근거 링크})`로 쓴다 |
| 설정 값, 메시지 형식, 테이블 구조 | 코드에 들어간 뒤 spec 문서로 옮기고 여기에는 링크만 둔다 |
