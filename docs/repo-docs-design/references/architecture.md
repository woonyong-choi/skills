# architecture.md

`docs/architecture.md`를 쓰거나 갱신하거나 검토할 때 이 절 목록과 틀을 쓴다.

## 독자

- 독자는 거듭 기여하는 사람이다. 코드가 어떻게 나뉘나, 무엇이 어디서 일어나나, 깨면 안 되는 조건은 무엇인가에 답한다.
- 특정 기능을 바꿀 때 함께 바뀌는 설명은 그 `design/` 문서에 두고 링크한다. 기능과 상관없는 구조 설명은 architecture에 둔다. 이것이 세부 분리 기준이다.

## 절

| 순서 | 한국어 절 | 영어 절 | 필수 | 내용 |
|---|---|---|---|---|
| 1 | `외부 연결` | `Context` | 선택 | 외부 요소 그림과 표 |
| 2 | `구성 요소` | `Code map` | 필수 | 구성 요소 그림과 표 |
| 3 | `처리 흐름` | `Flows` | 선택 | 요구사항별 입력, 처리, 결과의 차이가 드러나는 구성 요소 사이 흐름 |
| 4 | `지켜야 할 규칙` | `Invariants` | 필수 | 깨면 안 되는 조건과 이유 |
| 5 | `배포` | `Deployment` | 선택 | 프로세스 수명과 파일 위치 |
| 6 | `기술 선택` | `Technology choices` | 선택 | 영역별 기술과 고른 이유 |

## 자리 규칙

| 자리 | 규칙 |
|---|---|
| 외부 연결 표 | 종류는 `외부 프로그램`, `외부 서비스`, `운영체제`, `파일` 중 하나다 |
| 구성 요소 표 | `구성 요소`는 코드 식별자를 인라인 코드로 쓴다. 실행 단위나 저장소 단위로 나누고, 모듈 내부는 세부 분리 기준을 따른다 |
| 구성 요소 그림 | repo-docs-figures를 따른다 |
| 처리 흐름 | `###` 하나가 흐름 하나다. 단계는 문장으로 쓰고 주어는 구성 요소 이름이다 |
| 지켜야 할 규칙 | 항목마다 조건과 이유를 한 문장씩 쓴다. `없다`, `하지 않는다`처럼 없음으로 정한 조건도 넣는다(`엔진만 기록 저장소에 쓴다. 쓰기 충돌을 막기 위해서다.`) |
| 배포 | 채울 사실이 있는 표만 둔다 |
| 기술 선택 | 이유는 한 문장이다. 공개 결정 기록이 없으면 링크를 뺀다 |
| 선택 절 | 채울 사실이 없으면 절째 뺀다 |
| 코드 링크 | 경로와 식별자 이름만 쓴다. 줄 번호와 코드 줄 링크를 쓰지 않는다 |
