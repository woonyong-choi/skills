# AGENTS.md

`AGENTS.md`를 쓰거나 갱신하거나 검토할 때 이 틀과 절 규칙을 쓴다. 기존 지침을 옮길 때는 조건, 범위, 예외를 그대로 지킨다.

````text
# {이름}

{한 줄 소개}

설계 문서는 [docs/README.md](docs/README.md)에 있다.

## 구성

| 경로 | 내용 |
|---|---|
| `{경로}` | {내용} |

## 명령

```sh
{빌드 명령}
{테스트 명령}
{린트 명령}
{포맷 검사 명령}
```

## 규칙

- 커밋 전 명령 절의 명령 모두 통과
- 동작, 계약, 설정 변경은 같은 PR에서 설계 문서 갱신
- 새 문서는 `docs/README.md` 문서 목록 안에서만 추가
- {저장소 규칙}
````

## 절 규칙

| 절 | 규칙 |
|---|---|
| 한 줄 소개 | `AGENTS.md` 언어의 README 한 줄 소개를 작업 언어로 줄여 쓴다 |
| 구성 | 처음 들어올 때 필요한 모듈 경계만 줄여 쓰고 architecture.md 구성 요소 절을 링크한다. 저장소 밖 경로(`~/`, 절대 경로) 행은 넣지 않는다 |
| 명령 | CI나 저장소 검사 스크립트에 실제로 있는 명령만 빌드, 시험, 린트, 포맷 검사 순서로 쓴다. README 개발 절이 있으면 같은 명령을 같은 순서로 쓴다. 명령이 하나도 없으면(설계 단계 포함) 명령 절과 규칙의 첫째 항목을 지운다 |
| 설계 문서 문장 | `docs/README.md`가 있을 때만 쓴다. 없으면 규칙의 셋째 항목도 지운다 |
| 규칙 | 앞 세 항목은 고정이다(첫째와 셋째는 위 조건을 따른다). `{저장소 규칙}`은 들어올 때 지킬 핵심 경계만 줄여 쓰고 architecture.md 지켜야 할 규칙 절을 링크한다. 없으면 그 줄을 뺀다 |

## 지킬 것

- 정본의 경계나 명령이 바뀌는 PR에서 진입 요약도 함께 맞춘다. 상세 규칙을 베끼지 않는다.
- 필요한 명령, 경로, 규칙은 남기고, 다른 문서가 정의한 내용을 되풀이한 부분은 그 문서의 해당 절 링크로 바꾼다.
- 도구별 설정(모델, 권한, 훅)을 쓰지 않는다.
- 에이전트 이름이나 도구 이름으로 규칙을 나누지 않는다.
