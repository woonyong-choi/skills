# JD 분석

SPEC에서 경력 원본을 읽기 전 적용. 고정 길이 보고서·다른 스킬 의존 없음

## 경계

- 시작은 사용자가 준 JD 원문. 회사 추측·검색 결과·이전 지원·지원자 정보로 시작 금지
- 회사·직무·팀·공고 확정 전 경력 원본 사용 금지. JD 분석 단계의 지원자 경험 선택·순위·추천 금지
- 기존 분석 파일의 후보 추천은 신뢰하지 않는 제안, 선택은 PLAN에서
- 직무 사실의 정본: JD 원문과 회사 공식 자료. 분석 파일은 해석. 최근 맥락은 가설 보강만, JD 문구 무효화·지원자 사실 생성 금지

## 출처와 최신성

`jd.md`에 기록:

- 원문 URL·파일, 캡처 시각(절대 날짜·시간대), 수집 경로(`direct`, `official-api`, `embedded-data`, `detail-iframe`, `official-html`, `user-supplied-text`), 공고 ID 또는 본문 해시
- 회사, 직무, 팀, 근무지·방식, 고용·연차 조건, 식별 신뢰도와 남은 신원 문제

기존 분석 재사용 조건(모두 충족):

1. 원문 출처와 캡처 시각 기재
2. 같은 공고·회사·직무
3. 이번 실행에서 동적 공고 재확인, 불가하면 이유 기록
4. 명시 사실·최근 근거·추정·불확실 구분
5. 출처 접근 가능 또는 관련 내용 보존

하나라도 실패하면 새로 분석. 분석 파일만 있고 원문 복구·확인 불가면 원문 요청 후 중단

## 수집 순서

1. 사용자가 준 JD URL·본문·파일
2. 같은 공고의 공식 채용 페이지·공식 엔드포인트
3. 공식 API, JSON-LD, 내장 데이터(`__NEXT_DATA__` 등), 상세 iframe, 공식 HTML
4. 직무 해석에 의미 있는 공식 회사·제품·뉴스룸·기술 블로그
5. 더 강한 출처가 없을 때만 신뢰할 만한 2차 보도

- 검색 요약·숫자 ID·채용 플랫폼 요약만으로 공고·회사·직무 추정 금지. 막힌 화면 대신 공식 데이터 경로 사용

## 근거 표시와 신뢰도

- `[명시]` JD에 직접 기재, `[최근근거]` 날짜 있는 JD 밖 출처, `[추정]` 이유를 적은 해석, `[확인필요]` 미확인
- 최근 주장은 출처·날짜·직무 해석을 바꾸는 이유 함께. 추정을 회사 사실로 쓰기 금지
- 신원 신뢰도: `high` JD나 공식 연결이 회사·직무 하나를 확정, `medium` 신원은 하나지만 공식 연결 일부 부족(맥락 주장 낮춰 진행), `low` 후보 여럿(중단)

## jd.md 내용

1. 출처 기록과 조사 한계
2. 신원과 신뢰도
3. 채용 이유: 이 직무로 풀려는 문제
4. 명시 요구: 업무, 필수·우대, 기술·도메인 제약, 협업, 반복 신호
5. 추정 요구: 결과를 바꾸는 소수만, 근거·이유·신뢰도와 함께
6. 최근 맥락: 직무 해석을 바꾸는 날짜 있는 신호만
7. 열린 질문: 모순, 빠진 정보, 중단·질문 조건

- 회사 연혁·칭찬·문화 추측·면접 질문 목록 금지(요청 시만). 최근 근거가 없으면 `JD 기반`으로 표시하고 실패한 확인 기록
