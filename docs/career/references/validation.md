# 검증

VERIFY·실패 수정 때 적용

## 내용

경력 원본·SPEC과 대조:

- 신원·시기·직무·회사·프로젝트·수치·링크 정확
- 주장마다 담당·상태·조건·증명 범위 보존, 지원하지 않는 요구는 공백
- 진행 중·제안을 완료로 쓰지 않음, 이력서와 포트폴리오 사이 모순 없음
- 자리 글 `{}`, 양식 예시, 내부 표시, 중복 결론 없음
- 제출 문장마다 대응하는 원본 사실 줄 또는 사례 문장 존재. 없으면 삭제

## 기계 검사

지원 폴더에서 실행:

```bash
shasum -a 256 career.typ <이 스킬 폴더>/assets/typst/career.typ
typst compile 이력서.typ 이력서.pdf
typst compile 포트폴리오.typ 포트폴리오.pdf
pdfinfo 이력서.pdf
pdffonts 이력서.pdf
pdftotext -layout 이력서.pdf 이력서.txt
shasum -a 256 이력서.pdf 포트폴리오.pdf
```

- `career.typ` 해시 불일치면 원본으로 다시 복사
- 포트폴리오도 `pdfinfo`·`pdffonts`·`pdftotext` 같은 검사. A4, 쪽 수, 한국어 글꼴, 의미 있는 텍스트 추출 확인
- 원본·추출 텍스트에서 `{`, `·`, 유니코드 대시 검색 0건
- 컴파일 성공만으로 완료 판정 금지. 추출 텍스트는 검사 뒤 삭제

## 화면 검사

- 모든 쪽 250 DPI 렌더 후 전부 확인. 한국어 줄바꿈, 목록 간격, 절 구분, 여백, 쪽 균형, 외톨이 제목, 겹침·잘림, 작은 글자, 읽는 순서
- `facts` 표 행 정렬, 그림 글자 판독 가능, 그림과 캡션이 같은 쪽
- 검토한 PDF 해시 = 전달 PDF 해시. 원본·PDF 수정 뒤 해당 문서의 컴파일·추출·글꼴·쪽·화면 검사 반복

## 기록

`전략.md` `# VERIFY`에 실행한 명령, 쪽 수, 화면 결과와 개별 확인 쪽, PDF SHA-256, 남은 공백·근거 보강 제안, 최종 경로. 실행하지 않은 검사·ATS 통과·합격 가능성 주장 금지
