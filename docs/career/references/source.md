# 경력 원본 사용

공고 분석 전 원본 확인, 구성 계획, 작성 때 적용. 원본은 사실 정본, 제출본은 원본에서 고른 편집본

- 형식 정본: career-record `references/format.md`(폴더, master.md, 소속.md, 이력서.md 줄 8칸, 포트폴리오.md 짝 묶음, 등급). 이 스킬에서 형식 정의·원본 수정 금지
- 원본 추가·병합·수정·초안: career-record

## 읽기 범위

- 공고 분석: `master.md`, 모든 `소속.md`·`팀.md`, 모든 `이력서.md`의 속성과 줄 전체
- 구성 계획: 고른 줄의 짝 묶음(`포트폴리오.md`의 같은 제목 `##` 묶음)만
- 작성 재검토: 고른 줄과 그 짝 묶음 전체
- 공고 폴더(`{마감일}-{회사명}-{직군명}/`): 원본 제외

## 양식 대응

템플릿 자리 → 원본:

- `profile`·`intro` → `master.md` 기본
- Career `entry` → 구분 재직 `소속.md`. `meta` = 역할 변화·근거, `items` = 그 소속 아래 프로젝트의 고른 줄
- Education `compact` → 구분 교육 `소속.md`, `master.md` 기타
- Projects `entry` → 프로젝트 폴더. 제목 = 폴더 이름, `meta` = 소속 폴더 이름·저장소(공개: 비공개면 저장소 삭제), 기간·인원·역할·기술 = `이력서.md` 속성, `items` = 고른 줄
- 이력서 한 줄(`items` 한 항목) → 원본 줄 첫 줄 + 결과(끝 괄호)
- Skills `compact` → `master.md` 기술, 수준별 한 줄
- 포트폴리오 사례(`case`부터 `callout`까지) → 고른 줄의 짝 묶음. 묶음 없는 줄은 이력서에만
  - `case` 리드·`facts` 내 담당 → 맡은 일. `facts` 기간·역할·기술·저장소 → `이력서.md` 속성, 검증 → 줄의 확인
  - 문제 정의 및 기술적 제약 → 해결한 문제
  - 기술적 의사결정 및 아키텍처 → 설계 결정
  - 구현 및 해결 과정 → 구현
  - 성과 및 배운 점 → 줄의 결과 + 묶음의 결과·남은 과제
- 그림 → 프로젝트 `figures/{그림}.thinkflow`를 공고 폴더 `figures/{프로젝트}-{그림}.thinkflow`로 복사, 문서 경로 `/figures/{프로젝트}-{그림}.png`
