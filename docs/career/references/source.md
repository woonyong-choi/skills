# 경력 원본

공고 분석 전 원본 확인, 원본 초안 작성·보완 요청 때 적용. 원본은 사실 정본, 제출본은 원본에서 고른 편집본

## 위치

- `<Vault>/career/master.md`: 경력 전체 한 파일. 이력서 항목의 원천
- `<Vault>/career/cases/{사례}.md`: 사례마다 한 파일. 포트폴리오의 원천. 그림 원본은 `cases/figures/{사례}-{그림}.thinkflow`
- 원본 없음: 사용자에게 요청
- 받은 기존 이력서·포트폴리오·저장소, 또는 이 형식과 다른 원본: 이 형식의 초안을 지원 폴더 `원본-초안.md`로 작성, 사용자 확인 뒤에만 원본으로 사용·원본 위치로 이동

## master.md

```markdown
# 기본
이름: / 직무: / 이메일: / GitHub: / 전화: (선택) / 사진: (선택, 파일 경로)

# 소속
## {소속 id}
이름: / 구분: 재직|교육|학력 / 기간: YYYY.MM - YYYY.MM / 역할 변화: / 근거: (링크)
요약: (조직과 맡은 범위 한 문장)

# 프로젝트
## {프로젝트 id}
이름: / 소속: {소속 id} / 기간: / 인원: / 역할: / 공개: 공개|비공개 / 저장소: / 사례: cases/{사례}.md (있을 때)
소개: (무엇을 왜 만들었는지 한 문장)
기술: (실제 사용한 것만)
- (사실 줄)

# 기술
- {기술}: 실무|프로젝트|학습 (근거 프로젝트 id)

# 기타
- 병역·어학·자격·수상: 이름, 시기, 근거
```

- 짧은 요약 대신 빠짐없는 기록. 제출 길이 제한은 원본에 미적용
- 기간·인원·역할·공개 범위는 확인한 값만. 모르면 `미확인`

## 사실 줄 요건

사실 줄 하나는 한 행동과 그 결과. 다음을 모두 담음, 없는 요소는 `미확인`

- 주체: 본인 또는 팀(본인 몫 명시)
- 상황·제약: 왜 필요했는지, 무엇이 막았는지
- 행동·방법: 무엇을 어떤 기술·구조로
- 확인: 시험·측정·리뷰·운영 관찰 중 무엇으로
- 결과: 수치는 전 → 후, 측정 조건(데이터 크기·횟수·환경). 수치 없으면 관찰된 변화
- 상태: 완료·진행 중·제안(채택 여부)
- 근거: 저장소·커밋·PR·문서 링크 또는 파일 경로

예: `본인. 100만 행 조회가 전체 스캔이라 느림. C로 B+ 트리 색인 구현. 같은 데이터 3회 중앙값 측정. 조회 시간 215배 단축(학습 엔진 내부 비교, 운영 아님). 완료. {측정 문서 링크}`

## cases/{사례}.md

```markdown
# {사례 이름}
(무엇을 하는 시스템인지와 본인 역할 2문장)

기간: / 역할: / 기술: / 저장소: / 검증: / 내 담당: / 팀원: (혼자면 생략) / 원칙: (선택, 판단 원칙 한 문장)

## 개요 및 역할
## 문제 정의 및 기술적 제약
## 기술적 의사결정 및 아키텍처
## 구현 및 해결 과정
## 성과 및 배운 점
```

- 절마다 사실 줄 요건을 문단으로. 대안과 고르지 않은 이유, 실패·예외 처리, 한계와 후속 포함
- 그림: 실제 구조·흐름만 `.thinkflow`로, 결론 한 문장 캡션
- 코드: 저장소 경로와 커밋 기준 핵심 몇 줄, 직접 쓴 부분만

## 사용

- 읽기 범위: 공고 분석은 master 전체와 사례 파일 머리(제목·리드·머리 항목), 구성 계획은 고른 사례 파일 전체, 작성 재검토는 원본 전체
- 구성 계획: 사실 줄 단위로 선택, 사례는 파일 단위로 선택. 원본 문장 수정 금지
- 작성 양식 대응(템플릿 자리 이름 = 원본 항목 이름):
  - 기본 → `profile`·`intro`
  - 소속 재직 → Career `entry`. `meta` = 역할 변화·근거, `items` = 그 소속 프로젝트의 고른 사실 줄
  - 소속 교육·학력, `# 기타` → Education `compact`
  - 프로젝트 → Projects `entry`. `meta` = 소속 이름·저장소(비공개면 저장소 삭제), `items` = 고른 사실 줄
  - `# 기술` → Skills `compact`, 수준별 한 줄
  - 사례 머리 → `case`·`facts` 같은 이름 행, 원칙 → `callout`. 절 → `part`와 문단
  - 그림 원본 → 공고 폴더 `figures/`로 복사
