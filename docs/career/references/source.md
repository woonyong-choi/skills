# 경력 원본 사용

공고 분석 전 원본 확인, 구성 계획, 작성 때 경력 원본을 어떻게 읽고 양식에 대응시키는지 정한다. 원본은 사실의 정본이고, 제출본은 원본에서 고른 편집본이다.

## 읽는 방법

- 경력 원본은 Hanger closet의 `career/` 아래 Markdown이다. `search_documents`(`folders: ["career"]`)로 찾고, 목록에만 나온 문서는 `read_document`로 읽는다. closet 고르기와 오류 메시지 전달은 hanger 규칙을 따른다.
- 원본 파일에 직접 쓰거나 Hanger 변경 요청(`request_change`, `collect`)을 하지 않는다. 이 스킬은 읽기만 한다.
- 그림 원본(`.torso`)은 Hanger가 색인하지 않는다. `list_closets`가 알려 준 closet 경로 아래 파일을 공고 폴더로 복사한다(읽기만 한다).
- 원본이 비었거나 필요한 칸이 `미확인`이면 그대로 빈 곳으로 보고한다. 원본을 채우는 일은 사용자에게 hanger 요청으로 안내한다.

## 읽기 범위

| 단계 | 읽는 것 |
|---|---|
| 공고 분석 | `master.md`, 모든 `소속.md`와 `팀.md`, 모든 `이력서.md`의 속성과 줄 전체 |
| 구성 계획 | 고른 줄의 짝 묶음(`포트폴리오.md`의 같은 제목 `##` 묶음)만 |
| 작성 재검토 | 고른 줄과 그 짝 묶음 전체 |

- 공고 폴더(`{마감일}-{회사명}-{직군명}/`)는 원본으로 읽지 않는다.

## 원본 형식

읽을 때 필요한 형식만 적는다. 형식을 바꾸거나 줄을 더하고 합치는 일은 이 스킬이 맡지 않는다.

```text
career/
  master.md                    # 기본, 기술, 기타
  {소속}/
    소속.md                    # 구분(재직|교육|개인), 기간, 역할 변화, 근거
    [{팀}/팀.md]               # 기간, 역할
    {프로젝트}/
      이력서.md
      포트폴리오.md
      figures/{그림}.torso
  개인/{프로젝트}/...
```

- 상위 소속과 팀은 폴더 위치로 정해진다. 파일 안에는 소속과 팀 이름이 없다.
- `이력서.md`의 속성은 기간, 인원, 역할, 공개(공개, 비공개), 저장소(목록), 기술(목록)이다. 모르면 `미확인`이다.
- `이력서.md`의 줄은 첫 줄과 고정 순서의 8칸(등급, 주체, 상황, 행동, 확인, 결과, 상태, 근거)으로 이루어진다. 칸 값 `미확인`은 사실이 없다는 뜻이다.
- 주체는 `본인(맡은 부분), 팀 N명`으로 쓰고, 혼자면 `본인`, 단순 참여면 `참여(맡은 부분)`로 쓴다.
- 결과는 전과 후, 측정 조건으로 쓴다. 측정이 여러 번이면 `6시간 → 30분(1차) → 5분(2차)`처럼 쓴다.
- 등급(상, 중, 하)은 운영 결과 수치, 근거 링크, 본인 주도를 얼마나 채우는지 나타내는 참고 값이다. 선택 점수로 쓰지 않는다.
- `포트폴리오.md`에는 줄 하나마다 짝 묶음 `## {줄 첫 줄}`과 절 6개(맡은 일, 해결한 문제, 설계 결정, 구현, 결과, 남은 과제)가 있다. 짝 묶음이 없는 줄은 이력서에만 쓴다.
- 옛 형식(`master.md`의 `# 프로젝트` 절 사실 줄, `cases/{사례}.md`, `cases/figures/`)도 같은 대응으로 읽는다. 프로젝트 절은 프로젝트 폴더의 `이력서.md`, 사실 줄은 줄, `cases/` 사례는 짝 묶음에 대응한다.

## 양식 대응

| 템플릿 자리 | 원본 |
|---|---|
| `profile`, `intro` | `master.md` 기본 |
| Career `entry` | 구분이 재직인 `소속.md`. `meta`는 역할 변화와 근거, `items`는 그 소속 아래 프로젝트의 고른 줄 |
| Education `compact` | 구분이 교육인 `소속.md`, `master.md` 기타 |
| Projects `entry` | 프로젝트 폴더. 제목은 폴더 이름, `meta`는 소속 폴더 이름과 저장소(공개가 비공개면 저장소를 지운다), 기간, 인원, 역할, 기술은 `이력서.md` 속성, `items`는 고른 줄 |
| 이력서 한 줄(`items` 한 항목) | 원본 줄의 첫 줄과 결과(끝 괄호) |
| Skills `compact` | `master.md` 기술. 수준마다 한 줄 |
| 포트폴리오 사례(`case`부터 `callout`까지) | 고른 줄의 짝 묶음. 묶음이 없는 줄은 이력서에만 쓴다 |
| `case` 리드, `facts`의 담당 | 맡은 일 |
| `facts`의 기간, 역할, 기술, 저장소 | `이력서.md` 속성 |
| `facts`의 검증 | 줄의 확인 |
| 문제 정의 및 기술적 제약 | 해결한 문제 |
| 기술적 의사결정 및 아키텍처 | 설계 결정 |
| 구현 및 해결 과정 | 구현 |
| 성과 및 배운 점 | 줄의 결과와 묶음의 결과, 남은 과제 |
| 그림 | 프로젝트 `figures/{그림}.torso`를 공고 폴더 `figures/{프로젝트}-{그림}.torso`로 복사한다. 문서 경로는 `/figures/{프로젝트}-{그림}.png`다 |
