# 경력 원본 사용

공고 분석 전 원본 확인, 구성 계획, 작성 때 적용. 원본은 사실 정본, 제출본은 원본에서 고른 편집본

## 읽는 방법

- 경력 원본: Hanger closet의 `career/` 아래 Markdown. 찾기는 `search_documents`(`folders: ["career"]`), 목록에만 나온 문서는 `read_document`. closet 고르기·오류 메시지 전달은 hanger 규칙
- 원본 파일 직접 쓰기·Hanger 변경 요청(`request_change`, `collect`) 금지. 이 스킬은 읽기만
- 그림 원본(`.thinkflow`)은 Hanger가 색인하지 않는 파일. `list_closets`의 closet 경로 아래 파일을 공고 폴더로 복사(읽기만)
- 원본이 비었거나 필요한 칸이 `미확인`이면 그대로 빈 곳 보고. 원본을 채우는 일은 사용자에게 hanger 요청으로 안내

## 읽기 범위

- 공고 분석: `master.md`, 모든 `소속.md`·`팀.md`, 모든 `이력서.md`의 속성과 줄 전체
- 구성 계획: 고른 줄의 짝 묶음(`포트폴리오.md`의 같은 제목 `##` 묶음)만
- 작성 재검토: 고른 줄과 그 짝 묶음 전체
- 공고 폴더(`{마감일}-{회사명}-{직군명}/`): 원본 제외

## 원본 형식

읽을 때 필요한 형식만. 형식 바꾸기와 줄 추가·병합은 이 스킬 범위 밖

```text
career/
  master.md                    # 기본, 기술, 기타
  {소속}/
    소속.md                    # 구분(재직|교육|개인), 기간, 역할 변화, 근거
    [{팀}/팀.md]               # 기간, 역할
    {프로젝트}/
      이력서.md
      포트폴리오.md
      figures/{그림}.thinkflow
  개인/{프로젝트}/...
```

- 상위 소속·팀 = 폴더 위치. 파일 안 소속·팀 이름 없음
- `이력서.md` 속성: 기간, 인원, 역할, 공개(공개|비공개), 저장소(목록), 기술(목록). 모르면 `미확인`
- `이력서.md` 줄: 첫 줄 + 8칸 고정 순서(등급, 주체, 상황, 행동, 확인, 결과, 상태, 근거). 칸 값 `미확인`은 사실 없음
- 주체: `본인(맡은 부분), 팀 N명`, 혼자면 `본인`, 단순 참여면 `참여(맡은 부분)`
- 결과: 전 → 후와 측정 조건, 측정이 여러 번이면 `6시간 → 30분(1차) → 5분(2차)`
- 등급(상·중·하): 운영 결과 수치·근거 링크·본인 주도의 충족 정도를 나타내는 참고 값. 선택 점수 사용 금지
- `포트폴리오.md`: 줄 하나의 짝 묶음 `## {줄 첫 줄}`과 절 6개(맡은 일, 해결한 문제, 설계 결정, 구현, 결과, 남은 과제). 짝 묶음이 없는 줄은 이력서에만
- 옛 형식(`master.md`의 `# 프로젝트` 절 사실 줄, `cases/{사례}.md`, `cases/figures/`): 프로젝트 절 = 프로젝트 폴더의 `이력서.md`, 사실 줄 = 줄, `cases/` 사례 = 짝 묶음으로 같은 대응 적용

## 양식 대응

템플릿 자리 → 원본:

- `profile`·`intro` → `master.md` 기본
- Career `entry` → 구분 재직 `소속.md`. `meta` = 역할 변화·근거, `items` = 그 소속 아래 프로젝트의 고른 줄
- Education `compact` → 구분 교육 `소속.md`, `master.md` 기타
- Projects `entry` → 프로젝트 폴더. 제목 = 폴더 이름, `meta` = 소속 폴더 이름·저장소(공개: 비공개면 저장소 삭제), 기간·인원·역할·기술 = `이력서.md` 속성, `items` = 고른 줄
- 이력서 한 줄(`items` 한 항목) → 원본 줄 첫 줄 + 결과(끝 괄호)
- Skills `compact` → `master.md` 기술, 수준별 한 줄
- 포트폴리오 사례(`case`부터 `callout`까지) → 고른 줄의 짝 묶음. 묶음 없는 줄은 이력서에만
  - `case` 리드·`facts` 내 담당 → 맡은 일. `facts` 기간·역할·기술·저장소 → `이력서.md` 속성, 검증 → 줄의 확인
  - 문제 정의 및 기술적 제약 → 해결한 문제
  - 기술적 의사결정 및 아키텍처 → 설계 결정
  - 구현 및 해결 과정 → 구현
  - 성과 및 배운 점 → 줄의 결과 + 묶음의 결과·남은 과제
- 그림 → 프로젝트 `figures/{그림}.thinkflow`를 공고 폴더 `figures/{프로젝트}-{그림}.thinkflow`로 복사, 문서 경로 `/figures/{프로젝트}-{그림}.png`
