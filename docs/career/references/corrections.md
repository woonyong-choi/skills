# 교정 기록

사용자가 사실, 선호, 작업 방식을 바로잡을 때 무엇을 어디에 남기고 언제 승격 후보로 올리는지 정한다.

## 이번 작업

교정마다 다음을 적는다.

- 고정 교정 키와 틀린 내용, 고친 내용을 적는다.
- 종류 하나를 고른다. `applicant-fact`, `personal-preference`, `workspace-convention`, `public-skill-candidate`, `run-only` 중 하나다.
- 출처(사용자, 문서), 범위, 민감도, 영향받은 산출물, 이번 작업에서 되풀이된 횟수를 적는다.
- 무효가 된 검증과 다시 실행한 결과를 적는다.

다음을 지킨다.

- 사실이나 근거를 바로잡으면 선택, 문장, 컴파일, 추출, 화면 검사, 해시, 완료 주장이 모두 무효가 된다. 끝내기 전에 다시 실행한다.
- 교정이 있으면 `전략.md` 확인 절에 `## 교정과 기억 전달` 절을 두고 저장 위치나 대체 출력, 누적 횟수, 승격 후보, 경력 원본 변경 여부를 적는다.

## 저장 위치

- 교정 기록 하나는 파일 하나 `<산출물 폴더>/corrections/{YYYYMMDD-HHMMSS}-career-feedback.md`다. 산출물 폴더는 [지원 폴더 절](../SKILL.md#지원-폴더)을 따른다.
- 저장할 수 없으면 최종 응답에 같은 블록을 출력하고 저장되지 않았다고 밝힌다.
- 비밀이나 민감한 원래 값을 저장하지 않는다. 실수를 막을 규칙만 남긴다.

## 승격

끝내기 전에 같은 키의 기존 기록을 찾는다. 한 작업 안에서 여러 번 나온 교정은 작업을 넘나드는 승격에서 한 번으로 세고, 되풀이 횟수는 따로 적는다.

- 한 작업에서만 나왔으면 `observed`다.
- 서로 다른 작업에서 2회 이상 나왔으면 선호와 작업 방식은 `durable-memory-candidate`로 두고 답변 맨 앞 할 일 줄에 "작업 규칙으로 저장할지" 한 줄을 넣는다. 사실과 근거는 `career-master-candidate`로 둔다. 되풀이만으로 사실을 확정하지 않고, 사용자의 명시 승인과 출처가 있을 때만 원본을 고친다.
- 한 작업에서 같은 키를 2회 이상 바로잡았으면 작업 횟수와 상관없이 `public-skill-candidate`를 더하고, 사적 정보 없는 일반 교훈을 따로 적는다.
- 지원 작업 중에는 이 스킬을 고치지 않는다. 따로 요청받았을 때만 고친다. 특정 회사에만 해당하거나, 모순되거나, 근거가 없는 항목은 `run-only`나 `needs-review`로 둔다.
- 원본 수정이 승인되면 hanger 요청으로 원본을 바꾼다. 이 스킬에서 직접 고치지 않는다. 출처를 적고, 원본 전체를 다시 읽고, 무효가 된 단계를 모두 다시 실행한다.
