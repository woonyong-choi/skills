# Repo Docs Decision

- 사용자 지시를 먼저 적용. 해당 주제의 사용자 지시가 없으면 작업 대상 저장소의 같은 주제 규칙 파일(예: `AGENTS.md`, `CONTRIBUTING.md`) 적용. 둘 다 없으면 이 스킬 적용. 다른 스킬과 겹치는 규칙은 머리의 연결에 적힌 스킬 중 그 규칙을 정한 스킬 적용
- 기반: repo-docs 먼저 적용. 이 스킬 범위: 공개 결정 기록 대상, 파일, 템플릿, 판단 기록 옮기기, 절차
- 필요할 때만 읽기: 비공개 판단 기록에서 옮길 때 → repo-docs-journal; 관련 설계에 결정 링크를 반영할 때 → repo-docs-design

- 결정 기록: 설계 선택지 중 하나를 고른 이유의 공개 기록. 현재 설계는 설계 문서, 판단 과정과 놓친 것은 비공개 판단 기록 담당
- 공개 전환: (repo-docs 문서 목록). 공개 근거로 확인한 사실·식별자만 사용, 비공개 문장은 재작성
- 독자: 미래의 기여자. 답할 질문: 무엇을 정했나, 왜 그것인가, 무엇을 버렸나, 언제 다시 보나
- 언어: `docs/` 작업 언어(repo-docs 언어). 문체: 현재형, 능동태, 완결된 문장(결과 목록 제외)

## 대상

- 판정: 사용자나 연동 개발자에게 약속한 동작·형식, 또는 아키텍처를 선택할 때 적용. 그 선택의 대안별 장단점과 다시 검토할 조건을 남겨야 하는 경우 기록
- 이름·서식·코드 스타일만의 변경, 대안 선택이 없는 작업은 제외

## 파일

- 경로: `docs/decisions/{YYYY-MM-DD}-{주제}.md`. 날짜는 결정한 날, `{주제}`는 영어 소문자 kebab-case
- 목록: `docs/decisions/README.md`
- 머지된 기록: 상태, 대체 칸만 수정. 결정이 바뀌면 새 기록
- 영어 작업 언어의 절 이름: `Context`, `Options`, `Decision`, `Consequences`, `Revisit when`

## docs/decisions/README.md

```text
# 결정 기록

설계를 정한 이유와 버린 선택지를 결정한 순서대로 남긴다.

| 날짜 | 결정 | 상태 |
|---|---|---|
| {YYYY-MM-DD} | [{제목}]({파일}) | {제안, 채택, 대체됨} |
```

- 날짜 오름차순

## 템플릿

```text
# {정한 것, 결론 문장}

| 항목 | 값 |
|---|---|
| 날짜 | {YYYY-MM-DD} |
| 상태 | {제안, 채택, 대체됨} |
| 대체 | {없음, 대체한 결정 링크, 대체된 결정 링크} |
| 관련 문서 | [{문서 제목}](../{파일}) |

## 배경

{무엇을 정해야 하는지, 어떤 제약과 요구가 있는지 한 문단}

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| {선택지} | {장점} | {단점} |

## 결정

{고른 선택지와 가른 기준 한 문단}

## 결과

- {이 결정으로 얻는 것}
- {이 결정으로 치르는 것}

## 다시 볼 조건

- {이 결정을 다시 검토하게 만드는 관측}
```

| 자리 | 규칙 |
|---|---|
| 상태 | 제안: 검토 중인 결정. 채택: 머지된 결정. 대체됨: 새 결정으로 바뀐 결정 |
| 제목 | 고른 것이 보이는 결론 문장, 마침표 없음: `플러그인과 표준 입출력으로 통신한다`. 판단 기록의 제목도 공개 근거에 맞춰 재작성 |
| 대체 | 새 기록 `대체한 결정: [{제목}]({파일})`, 옛 기록 `대체된 결정: [{제목}]({파일})`. 둘 다 아니면 `없음` |
| 관련 문서 | 이 결정을 반영한 설계 문서. 여럿이면 `, `로 연결 |
| 배경 | 현재형. 결정 시점에 확인한 사실만. 외부 도구 동작은 확인 날짜(repo-docs 사실 상태) |
| 선택지 | 검토한 대안 모두 기록, 고른 선택지를 첫 행에. 문장 열 없음. 비공개 표현은 복사하지 않고 공개 근거로 재작성 |
| 결정 | 고른 선택지·선택 기준·치르는 손실 포함 |
| 결과 | 얻는 것, 치르는 것 한 항목 이상씩, 명사구 |
| 다시 볼 조건 | 관측할 수 있는 조건: `플러그인 실행기가 소켓만 제공` |

## 판단 기록에서 옮기기

| 비공개 판단 기록 | 공개 결정 기록 |
|---|---|
| 제목 | 공개 근거로 재작성한 제목 |
| 문제 | 배경. 잃는 것 대신 제약과 요구로 |
| 알던 것과 모르던 것 | `[근거: ...]` 문장의 사실만 배경에. 출처가 `.local`이면 제외 |
| 선택지 | 공개 근거로 확인한 대안의 장점과 단점을 재작성 |
| 판단 | 결정. 확신 표 제외 |
| 틀렸다는 신호 | 다시 볼 조건 |
| 판단 변경의 놓친 것, 교훈 | 제외 |

- `[가정]`, `[미확인]`, `[추정]`이 붙은 문장 제외
- 비공개 인물 정보·협상 비용·내부 일정·내부 경로·판단 기록 링크 금지. 공개 근거와 결정 관련성이 있는 정보는 허용
- 판단 변경이 공개 결정을 바꾸면 새 결정 기록, 옛 기록 상태는 `대체됨`

## 작성 절차

1. 대상 표로 기록 여부 판정. 아니면 중단
2. 판단 기록이 있으면 옮기기 표대로. 없으면 재료는 `design` 이슈 결정 댓글과 PR 본문
3. 채울 사실이 없는 칸이 있으면 저장 금지, 보고([repo-docs 절 구성](../repo-docs/SKILL.md#절-구성))
4. 관련 설계 문서의 기술 선택 표나 해당 절에 이 기록 링크 추가(repo-docs-design)
5. `docs/decisions/README.md`에 행 추가
6. 저장 전 검사 실행(repo-docs)
