# Torso 그림 품질

요청한 항목을 빠짐없이 담고, 가로형으로 읽히고, 무엇이 중요한지 바로 보이는 Torso 그림을 만든다. 문법과 정본 고르기는 [그림 작성](syntax.md), 명령은 [설치와 실행](execution.md)과 [검사](validation.md)가 맡는다. 편집 규칙은 [Diagram Design](https://github.com/cathrynlavery/diagram-design)(MIT)의 "더 뺄 것이 없을 때 끝난다", 종류 꼬리표, 초점 1~2개, 기술 글만 고정폭, 복잡도 상한을 Torso 문법으로 옮긴 것이다. 아래 수치는 Torso `3d2d6af`에서 쟀다.

## 가로형 원칙

모든 그림은 가로형이다. 정지 SVG의 높이가 폭보다 크면 오류로 보고 원본을 고친다. 그래서 구조, 상태, 순서 그림은 머리에 `width wide`를 적는다. 생략하면 Torso는 680px 안에 가로로 들지 않는 배치를 세로로 돌린다(카드 5개짜리 블로그 요청 경로가 395x648). `width wide`를 적으면 1440px까지 가로로 놓는다(같은 원본이 1126x408). 차트는 머리와 상관없이 680px 폭이다. 실측한 한도는 이렇다.

| 그림 | `width wide`에서 가로형이 되는 한도 | 넘으면 |
|---|---|---|
| 구조 그림 사슬 | 짧은 이름 카드 8개(1391x79), 선 글이 없으면 9개(1266x103) | `aspect 1.6`으로 접는다(9개가 538x263). 접기는 갈래와 그룹이 없는 사슬에만 쓴다 |
| 갈래 있는 구성도 | 층 5개(결제 서비스 구성도 1373x277) | 늘 함께 다니는 카드(서비스와 그 전용 DB)를 부제로 합치고, 그래도 넘으면 전체 그림과 자세한 그림으로 나눈다 |
| 상태 그림 | 정상 흐름 한 줄(6상태 1139x79)과 예외 전이 한두 개 | 예외 전이가 셋 이상이면 넓은 캔버스에서도 세로가 된다(8상태 281x913). 정상 흐름과 예외 흐름을 그림 둘로 나눈다 |
| 단계가 많은 순서도 | 단계 카드 6개 안팎(1341x205) | 하위 단계는 단계 카드 안 `text "1 린트"` 줄로 쓰고, 그래도 넘으면 `aspect 2`(957x344) |
| 순서 그림 | 메시지 수가 참여자 수의 두 배 빼기 하나 이하(3명 5개, 4명 7개). 폭은 참여자 수가 정하고 높이는 메시지마다 44px씩 늘어 `width wide`가 바꾸지 못한다 | 단계(로그인, 갱신)마다 그림 하나로 나누고, 같은 흐름 안의 선택 경로만 `fragment`로 담는다 |

넓은 그림은 넣는 자리에서 다르게 보인다. Markdown 이미지는 칸 폭에 맞춰 줄어(1126px 그림이 680px 칸에서 0.6배) 글자가 작아지고, HTML 그림 틀은 본문 폭이라 넘치는 부분을 그림 안에서 가로로 스크롤하거나 전체화면으로 본다. 그림 폭은 내용 폭을 따르므로 그림마다 다르다.

## 품질이 무너지는 원인

아래는 원본을 직접 그려 재현한 증상이다. 모두 `check --strict`를 통과했으므로 검사 통과만으로 품질을 판단하지 않는다. 고치는 법의 자세한 규칙은 가리킨 절에 있다.

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| 모든 카드가 같아 무엇이 중요한지 안 보인다 | 종류, 기술 값, 초점이 글자로도 색으로도 드러나지 않는다 | 2절 편집 위계 |
| 세로 한 줄이나 세로로 긴 그림이 된다 | `width wide`가 없거나 넓은 캔버스에도 가로로 들지 않는다. 꼬리표는 카드 폭을 약 40px 늘린다 | 가로형 원칙의 한도대로 줄이거나 나눈다 |
| 그룹이 계단처럼 내려간다 | 그룹을 앞 그룹 마지막 카드에서 다음 그룹 첫 카드로 차례로 잇는다 | 4절 격자 만들기 |
| 접힌 선이 그림을 가로지르고 번호 라벨이 모서리로 떨어진다 | 갈래나 그룹이 있는 그림에 `aspect`를 적었다(블로그 요청 경로가 702x489) | `aspect`는 갈래와 그룹이 없는 사슬에만 쓴다 |
| 선이 엉킨다 | 같은 역할 카드 여럿이 각자 같은 대상으로 선을 긋는다 | 4절 같은 역할 |
| 카드 폭이 들쭉날쭉하고 이름이 두 줄로 접힌다 | 이름과 선 글에 문장을 쓴다(카드 폭 169~186px) | 4절 이름 길이 |
| 요청한 메시지가 정지 이미지에 없다 | 순서 그림의 정지 SVG는 고른 장면 하나의 메시지만 그린다 | 한 장에 보일 메시지는 첫 장면에 두고 선택 경로는 `fragment` |
| 지표 카드가 흩어지고 순서가 바뀐다 | 선 없는 카드는 선언 순서와 다르게 쌓인다 | 지표는 카드 하나의 `value` 줄로 모은다. 값 이름은 한글 4자, 값은 6자 안팎 |
| 차트 합계가 뜻 없는 값이 된다 | 매출과 비용을 `stacked`로 쌓았다 | 3절 아래 줄 |
| 그래프 그림에 제목과 설명이 없다 | 구조, 상태, 순서 그림은 `title`을 그리지 않고 `subtitle`은 HTML에만 나온다 | 그림 안에 보일 말은 카드, 꼬리표, 선 글, 보기 라벨로 쓰고 나머지는 본문과 대체 글에 쓴다 |

## 1. 요구 항목 뽑기

1. 그릴지부터 정한다. 표나 문단 하나로 같은 것을 전할 수 있으면 그리지 않는다. 카드 하나뿐인 그림, 속성만 나열하는 그림은 문장이나 표로 쓴다.
2. 요청과 글에서 그릴 것을 다섯 종류로 나눠 목록을 만든다. 구성 요소(카드), 단계와 메시지(선, 순서), 상태와 전이, 관계(키, 호출, 소속), 수치(값, 계열, 단위)다.
3. 목록 한 줄에 항목 하나를 원본에 쓸 표시 이름으로 적어 `.local/runs/figures-<그림 이름>/items.txt`로 둔다. 같은 뜻의 다른 이름은 `|`로 잇는다(`토큰 갱신|/refresh`). "3대", "포함" 같은 수량과 조건도 항목으로 적는다.
4. 항목마다 그림에서 맡을 자리를 정한다. 카드, 부제, 꼬리표, 선 글, 값 줄, 차트 행, 장면 가운데 하나다. 자리가 정해지지 않은 항목은 본문에 쓸 항목으로 따로 표시한다.
5. 한 그림의 양을 정한다. 카드는 9개를 목표로 하고 12개, 선은 12개를 넘기지 않는다. 가로형 원칙의 한도도 함께 지킨다. 넘으면 그룹이나 `count=`로 합치고, 그래도 넘으면 전체 그림과 자세한 그림으로 나눈다.
6. 장면을 나눌지 정한다. 장면은 같은 구조 위의 다른 경로나 변화를 보일 때만 나눈다. 정지 이미지 한 장에 모두 보여야 하는 항목은 첫 장면에 둔다.
7. 그리기 전에 답변에 한 줄로 계획을 적는다. 그림 종류, 쓰임(본문 단, Obsidian, 포트폴리오), 상한 때문에 빼거나 합칠 항목이다. 사용자가 있으면 고칠 기회를 주고, 없으면 그 줄을 가정으로 남기고 진행한다.

## 2. 편집 위계

그림은 "더 뺄 것이 없을 때" 끝난다. 카드는 서로 다른 생각 하나씩이고, 선은 배치만으로 알 수 없는 정보를 하나씩 싣는다. 그 위에 아래 다섯 가지로 위계를 세운다.

- **종류 꼬리표.** 갈래가 있는 구성도는 모든 카드에 `badge="글"`을 단다. 순서도, 상태도, 시퀀스에는 달지 않는다. 카드가 모두 단계나 상태라서 꼬리표가 모두 같아지고 아무것도 가르지 않는다. 꼬리표는 이름이 아니라 종류를 말하므로 다섯 낱말 가운데서 고른다. `EXT`(우리가 운영하지 않는 바깥), `EDGE`(요청을 받아 넘기는 경계, 로드밸런서와 CDN), `APP`(우리 코드가 도는 서버와 서비스), `DATA`(DB, 캐시, 파일 같은 저장), `ASYNC`(큐 뒤의 워커와 배치)다. 같은 종류는 같은 글이다. 꼬리표 글이 범례 노릇을 하므로 흑백에서도 종류가 남는다. 일부 카드에만 달지 않는다. `queue`는 꼬리표를 받지 않고 칸이 종류를 대신한다. `person`은 꼬리표를 받지만 사람 아이콘이 이미 종류를 말하므로 달지 않는다. 이름을 되풀이하는 꼬리표(`DB` 카드의 `DB`, `캐시` 카드의 `CACHE`)를 쓰지 않는다.
- **이름과 부제.** 이름은 사람이 읽는 명사(`Astro 오리진`)이고 일반 글꼴로 쓴다. 경로, 포트, 명령, 프로토콜 같은 기술 값은 부제에 백틱으로 쓴다(``"`src/content/*.mdx`"``). 백틱 구간만 고정폭으로 그려진다. 이름 전체를 백틱으로 감싸지 않는다.
- **초점.** 독자가 먼저 볼 카드 1~2개에만 `tone=blue appearance=filled`를 준다. 나머지는 색을 주지 않는다. 셋 이상 칠하고 싶으면 아직 무엇이 중심인지 정하지 않은 것이다. 색만으로 뜻을 전하지 않고 꼬리표와 이름이 같은 뜻을 글로 갖는다.
- **경로 번호와 선 모양.** 주 경로의 선에 `no=1`부터 차례로 번호를 단다. 정지 이미지에서도 순서가 읽힌다. 응답, 비동기, 선택, 실패 경로는 `dashed`로 두고 번호를 달지 않는다. 배치만으로 뻔한 관계의 선과 선 글은 지운다.
- **경계.** 신뢰 경계, 배포 단위, 소유 묶음처럼 "안과 밖"이 뜻인 묶음은 `group id "이름" dashed`로 두른다. 묶음 이름은 한글 5자 안으로 쓴다. 평평한 묶음은 한 그림에 3개 이하로 둔다.

Torso에는 구조 그림의 범례 띠, 카드 위 큰 단계 숫자, 그림 안 제목 글꼴 선택이 없다. 범례는 꼬리표로, 단계 숫자는 `no=`로, 제목은 본문 머리로 대신하고, 카드나 그룹을 꾸며 흉내 내지 않는다. 범례 카드를 따로 두면 선 없는 카드라서 흩어진다.

## 3. 그림 종류 고르기

| 전할 내용 | Torso 그림 | 주로 쓰는 문법 |
|---|---|---|
| 구성 요소와 요청이 지나는 길(아키텍처) | 구조 그림, 구성도 | `box`, `store`, `queue`, `external`, `group`, `badge=`, `icon=`, `count=`, `no=` |
| 처리 단계의 차례(순서도) | 구조 그림 | 갈래가 있으면 `decision`, 갈래 없는 5단계 이상이면 `aspect 1.6`, 하위 단계가 있으면 단계 카드 안 `text` 줄 |
| 참여자 사이 메시지 차례(시퀀스) | 순서 그림 | `view sequence`, `dashed` 응답, `fragment alt`, `opt`, `loop`, `par`, `note` |
| 대상의 생애 주기 | 상태 그림 | `state`, `start`, `final`, 전이마다 사건 글, 예외 전이는 `dashed` |
| 테이블, 키, 참조 | 데이터 관계 그림 | `table`, `pk`, `fk=` |
| API 요청과 응답 칸 | 구조 그림의 API 카드 | `api`, `카드.칸` 연결 |
| 클래스와 인터페이스 | 구조 그림의 클래스 카드 | `class`, `interface`, `relation=` |
| 배열, 비트, 메모리, 스택 | 칸 격자 | `grid`, `item` |
| 측정한 시간 구간 | 시간 보기 | `trace`, `span`, `view time` |
| 큐와 병목 | 구조 그림의 흐름 장면 | `queue slots=N`, `track`, `every`, `wait`. 용량과 속도는 단위로 적는다(`8건/분`) |
| 항목별 값, 두 조건 비교 | 차트 | `bar`, `dumbbell`, `difference` |
| 구성과 비율 | 차트 | `stacked`, `percent`, `pie`, `donut` |
| 시간에 따른 변화 | 차트 | `line`, `step`, `area` |
| 분포 | 차트 | `histogram`, `box`, `ecdf` |
| 두 변수 관계, 교차표 | 차트 | `scatter`, `heatmap` |
| 증감이 합계에 주는 영향 | 차트 | `waterfall` |
| 구조와 핵심 수치 한 장 | 구조 그림 보기 둘 | `view graph "구조"`, `view graph "성과"`와 값 줄 카드 |

- 메시지 차례를 구조 그림의 번호 선으로 대신하지 않는다. 같은 두 참여자 사이를 여러 번 오가면 순서 그림을 쓴다.
- 합계가 뜻 없는 두 값을 `stacked`로 쌓지 않는다. 비교는 `bar`, 차이 자체가 결론이면 `difference`를 쓴다.
- 두 종류가 다 맞아 보이면 독자가 따라갈 축 하나(시간, 구성, 상태)로 고르고 나머지는 다른 그림으로 나눈다.

## 4. 배치 규칙

- **이름 길이.** 카드 이름은 한글 5자와 띄어쓰기 하나, 영문 10자 이하로 쓴다. 이 안이면 카드 폭이 같아 줄과 열이 맞는다. 설명은 부제(`box id "이름" "부제"`)나 카드 안 `text`로 옮긴다. 선 글과 메시지 글은 한글 10자 이하로 쓴다.
- **방향.** 방향을 적지 않는다. `view graph`는 보기를 둘 이상 둘 때만 이름과 함께 쓰고(`view graph "구조"`), `down`은 위아래에 뜻이 있을 때만 적는다. 캔버스를 넘는 가로 배치는 Torso가 돌리므로 `right`를 적어도 효과가 없다.
- **격자 만들기.** 갈래와 그룹이 없는 사슬은 `aspect 1.6`으로 접고 카드 수를 한 줄 칸 수의 배수(9개면 3x3)로 맞춘다. 갈래가 있는 그림은 같은 층에 올 카드를 `direction=down` 그룹으로 묶어 한 출발 카드에서 갈라지게 잇는다. 그룹끼리 사슬로 잇지 않는다.
- **같은 역할.** 복제 서버나 워커는 `count=N` 카드 하나로 그리고 대상은 그룹으로 묶는다. 개별 서버마다 다른 선이나 값이 있을 때만 카드를 나눈다.
- **예외 경로.** 정상 경로는 실선으로 한 줄을 이루게 두고, 실패, 취소, 재시도는 `dashed`로 옆에 둔다. 예외가 셋 이상이면 가로형 원칙대로 그림을 나눈다.

## 5. 쓰임별 기준

| 쓰임 | 넣는 방식 | 기준 |
|---|---|---|
| HTML로 넣는 블로그 글 | 본문의 `torso` 블록을 빌드가 HTML 그림으로 넣는다 | 틀보다 넓은 그림은 그림 안에서 가로로 스크롤한다. 장면 탭을 쓸 수 있다. 삽입 빌드가 파일을 읽지 않으면 `data` 파일과 파일 아이콘 세트를 쓰지 않는다 |
| Markdown 노트, GitHub 문서 | `torso` 블록과 `torso md`가 넣는 SVG 이미지 줄([Markdown과 CI](markdown.md)) | SVG가 칸 폭에 맞춰 줄어든다. 가장 작은 글은 11 × 칸 폭 / SVG 폭 px이다. 둘째 장면부터는 `<details>` 안에 있어 접혀 보인다 |
| 포트폴리오 한 장 이미지 | `render --static` SVG를 2배 PNG로 바꾼다 | A4 폭에서는 넓은 그림의 글자가 읽히지 않으므로 `width wide`를 쓰지 않고, 가로형을 지키도록 그림을 나눈다. 장면 없이 읽혀야 한다. 모든 항목을 첫 장면에 담는다. 그래프 그림의 제목은 그려지지 않으므로 보기 라벨이나 포트폴리오 쪽 제목으로 보탠다. 수치는 값 줄 카드 하나로 모으고 짧게 쓴다. 인쇄용이라 라이트 PNG 한 장을 만든다(career `scripts/figures.py`) |

- 실제 표시는 넣을 환경에서 따로 확인한다. Markdown 앱이 SVG 안 움직임을 재생하는지는 확인하지 않았다.

## 6. 나쁜 예와 좋은 예

아래 짝은 모두 `check --strict`를 통과하고 Chromium으로 렌더해 눈으로 비교했다. 머리 한 줄만 보인 좋은 예는 나쁜 예 원본에 그 줄을 더한 것이고, `scene`으로 시작하는 예는 원본의 해당 장면만 보인다.

**위계 없는 구성도.** 나쁜 예는 카드 다섯이 모두 같은 모양이고, 이름에 기술 값이 섞여 `Astro 오리진 서버 SSR과 MDX`가 두 줄로 접히고, 응답이 요청과 같은 실선이다.

```text
torso
width wide
title "블로그 요청 경로"
person reader "독자 브라우저"
box edge "Cloudflare Pages 캐시"
box origin "Astro 오리진 서버 SSR과 MDX"
box bundle "MDX 번들"
store cms "콘텐츠 CMS"
reader -> edge "HTTPS 요청"
edge -> reader "응답"
edge -> origin "SSR 요청"
origin -> bundle "MDX 읽기"
origin -> cms "조회"
```

좋은 예는 같은 카드 다섯에 꼬리표, 고정폭 부제, 초점 하나, 주 경로 번호, 점선 응답과 경계를 단다. 1126x408 가로형이고, 꼬리표만 읽어도 바깥, 경계, 우리 서버, 저장이 구분된다.

```text
torso
width wide
title "블로그 요청 경로"
external reader "독자" "브라우저" badge="EXT"
box edge "Cloudflare" "Pages · 캐시" badge="EDGE" icon=cloud
box origin "오리진" "Astro `SSR` + `MDX`" badge="APP" icon=server tone=blue appearance=filled
group content "콘텐츠" dashed direction=down {
  box bundle "MDX 번들" "`src/content/*.mdx`" badge="DATA"
  store cms "콘텐츠 CMS" "자산 · OG 이미지" badge="DATA"
}
reader -> edge "HTTPS" no=1
edge -> origin "SSR" no=2
origin -> bundle "MDX 읽기" no=3
origin -> cms "조회" no=4
edge -> reader "응답" dashed
```

`width wide`를 빼면 395x648 세로형이 되고, 대신 `aspect 1.6`을 적으면 702x489로 접히지만 2번 선이 그림을 가로질러 되돌아오고 번호 라벨이 왼쪽 위로 떨어진다. 갈래와 그룹이 있으므로 접지 않는다.

**갈래 없는 단계 사슬.** 나쁜 예는 `width wide`가 없어 폭 144px, 높이 819px의 세로 한 줄이 된다.

```text
torso
title "요청 처리 경로"
person user "사용자"
box dns "DNS"
box cdn "CDN"
box lb "로드밸런서"
box api "API 서버"
box cache "캐시"
store db "DB"
queue mq "메시지 큐" slots=4
box worker "워커"
user -> dns
dns -> cdn
cdn -> lb
lb -> api
api -> cache
cache -> db
db -> mq
mq -> worker
```

좋은 예는 머리에 `width wide`를 더해 1266x103의 한 줄이 된다. 넓은 캔버스도 넘는 사슬이면 `aspect 1.6`을 더해 격자로 접는다(같은 원본이 538x263의 3x3). 단계를 그룹으로 묶고 그룹끼리 이으면 계단이 되므로 그룹으로 고치지 않는다.

```text
torso
width wide
title "요청 처리 경로"
```

**같은 역할의 서버 여럿.** 나쁜 예는 `api1`, `api2`, `api3`를 따로 두고 각자 캐시, DB, 큐로 선 9개를 그어 선이 엉킨다. 좋은 예는 카드 하나와 그룹 둘로 선을 5개로 줄이고, 요청이 모이는 API 서버를 초점으로 칠한다.

```text
box lb "로드밸런서" badge="EDGE" icon=lb
box api "API 서버" badge="APP" icon=server count=3 tone=blue appearance=filled
group data "데이터" direction=down {
  box cache "캐시" badge="DATA" icon=redis
  store db "DB" badge="DATA" icon=db
}
group async "비동기 처리" direction=down {
  queue mq "메시지 큐" slots=4
  box worker "워커" badge="ASYNC" icon=server
}
lb -> api "분산"
api -> cache "조회"
api -> db "저장"
api -> mq "발행"
mq -> worker "소비"
```

**문장 이름.** 나쁜 예는 카드 이름과 선 글에 문장을 써 카드 폭이 169~186px로 갈리고 이름이 두 줄로 접힌다.

```text
box a "사용자가 웹 브라우저에서 주문 버튼을 누름"
box b "주문 API가 요청을 받아 검증함"
box c "주문 서비스가 재고를 확인하고 결제 요청을 보냄"
a -> b "HTTPS POST 요청으로 주문 내용을 전달"
b -> c "검증한 주문을 넘김"
```

좋은 예는 이름을 명사로 줄이고 기술 값은 부제로, 설명은 카드 안으로 옮긴다.

```text
person a "사용자"
box b "주문 API" "`POST /orders`" badge="APP"
box c "주문 서비스" badge="APP" {
  text "재고 확인 뒤 결제 요청"
}
a -> b "주문"
b -> c "검증 통과"
```

**두 장면으로 나눈 시퀀스.** 나쁜 예는 로그인과 토큰 갱신을 `scene` 둘로 나눠 정지 SVG에 토큰 갱신이 없다. 좋은 예는 한 장면 안에 `fragment opt`로 담는다.

```text
scene "로그인과 갱신"
  front -> browser "로그인 완료" dashed
  fragment opt "액세스 토큰 만료 시" run=on {
    front -> auth "POST /refresh"
    auth -> front "새 액세스 토큰" dashed
  }
```

**흩어진 지표 카드.** 나쁜 예는 선 없는 지표 카드 셋이 2+1로 쌓이고 순서가 바뀐다. 좋은 예는 값 줄 카드 하나를 둘째 보기에 둔다.

```text
box kpi "기존 대비" icon=chart {
  value latency "p95 지연" from=-85%
  value throughput "처리량" from=5배
  value cost "월 비용" from=-40%
}
view graph "구조" {
  user api db jobs worker push
}
view graph "성과" {
  kpi
}
```

## 7. 완료 전 확인

1. 원본 검사와 정지 SVG, HTML 렌더는 [설치와 실행](execution.md)의 명령으로 한다. 검사 출력이 없고 종료 코드가 0이어야 한다.
2. 항목과 배치 위험을 대조한다. `누락:`과 `경고` 줄이 없어야 한다. 경고를 남길 때는 그 이유를 답변에 적는다. 이 스크립트는 글과 크기로 잴 수 있는 위험(이름과 선 글 길이, 카드와 선 수, 사슬, 계단, 꼬리표, 초점 수, `aspect` 오용, 흩어진 카드, 세로형, `width wide` 누락, 순서 그림의 메시지 수)만 보므로, 경고가 없어도 4번과 5번을 건너뛰지 않는다.

   ```sh
   python3 <이 스킬 폴더>/scripts/figure_audit.py <원본>.torso --items .local/runs/figures-<그림 이름>/items.txt --svg <출력 폴더>/<원본>.svg
   ```

3. PNG로 찍어 직접 본다. Torso 소스 작업본의 `scripts/shoot.mjs`(npm 패키지에는 없다)는 Mac의 Chrome을 기본으로 쓰고, 다른 곳에서는 `CHROME_PATH`에 Chrome이나 Chromium 경로를 준다. 정지 SVG를 라이트와 다크로, HTML을 390px로 찍는다.

   ```sh
   node <Torso 경로>/scripts/shoot.mjs <출력 폴더>/<원본>.svg <이름>-light.png
   node <Torso 경로>/scripts/shoot.mjs <출력 폴더>/<원본>.svg <이름>-dark.png --dark
   node <Torso 경로>/scripts/shoot.mjs <출력 폴더>/<원본>.html <이름>-390.png --width 390
   ```

4. PNG에서 빼기 점검을 한다. 하나라도 "예"면 원본을 고치고 1번부터 다시 한다.
   - 지워도 독자가 이해하는 카드가 있는가.
   - 늘 함께 다니는 두 카드가 있는가. 있으면 하나로 합친다.
   - 배치만으로 뻔한 선이나 꼬리표와 같은 말을 되풀이하는 선 글이 있는가.
5. PNG에서 아래를 하나씩 확인한다. 하나라도 어긋나면 원본을 고치고 1번부터 다시 한다.
   - 카드가 줄과 열에 맞고 폭이 같은 역할끼리 같다.
   - 가로형이고(높이가 폭 이하) 세로 한 줄, 계단, 엉킨 선, 그림을 가로지르는 되돌아오는 선이 없다.
   - 글이 잘리거나 겹치지 않고 두 줄로 접힌 이름이 없다.
   - 초점 색이 1~2개이고, 꼬리표는 같은 종류에 같은 글이며 모든 카드에 있거나 없다.
   - 주 경로 번호가 차례대로 읽히고 응답과 예외 경로는 점선이다.
   - `items.txt`의 모든 항목이 그림에 보인다. 장면 탭에만 있는 항목은 정지 이미지에서 빠진 것으로 본다.
   - 구조, 상태, 순서 그림의 머리에 `width wide`가 있다. 390px HTML에서 첫 카드가 잘리지 않는다.
   - 라이트와 다크에서 글자, 선, 아이콘, 꼬리표가 면 위에 보인다.
