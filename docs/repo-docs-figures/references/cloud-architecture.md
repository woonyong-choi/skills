# 클라우드 구성도 규칙

어느 클라우드든 구성도의 아이콘 종류, 서비스 경계, 하위 리소스와 경로를 같은 원칙으로 표현한다. 공급자마다 다른 아이콘 이름, 경계 선 모양, 사용 조건은 [세트별 규칙](#세트별-규칙)의 문서가 정한다. 문법과 자산 이름은 설치한 DiagramPlay와 design-tokens 카탈로그에서 확인한다.

## 적용 범위

- 클라우드 구성도를 만들거나 검수할 때 이 문서를 읽는다. 데이터 관계도·상태 전이·일반 업무 흐름에 클라우드 배포 의미를 억지로 넣지 않는다.
- 공급자의 공식 아키텍처 아이콘 가이드를 근거로 삼는다. 가이드에 없는 크기·선 굵기·개수 한도를 규칙으로 만들지 않는다.

## 아이콘 세트

- 한 그림에는 공급자의 공식 세트 하나를 쓴다. 다른 일반 세트나 임시로 그린 SVG와 섞지 않고, 없는 로고를 비슷하게 그려 대체하지 않는다.
- 설치한 카탈로그에 세트와 이름이 있는지 먼저 확인한다. 없으면 공통 정본에 원본·버전·해시·권리 고지를 함께 추가한다. 소비자 저장소에 SVG를 복제하거나 이름을 지어내지 않는다.
- 원본 도형과 서비스·리소스·그룹의 고유색을 보존한다. 무채색 일반 아이콘은 테마의 글자색을 상속한다. 표시 크기와 정렬은 공통 토큰과 렌더러가 정한다.
- 공급자가 밝힌 사용 목적과 권리 조건을 따른다. 출처와 고지를 보존하고 공급자 자산을 도구의 라이선스로 재라이선스하지 않는다.

## 종류와 자리

| 종류 | 쓰는 자리 | 피할 표현 |
|---|---|---|
| 서비스 아이콘 | 서비스 자체를 아이콘과 이름이 있는 독립 리소스 타일로 표시한다. | 업무 카드 안에 로고를 반복하지 않는다. |
| 리소스 아이콘 | 해당 서비스에 속하는 하위 리소스를 독립 타일로 표시한다. | 다른 제품의 자원처럼 표시하지 않는다. |
| 일반 아이콘 | 서비스에 종속되지 않는 참여자·기기를 식별한다. | 이름만으로 충분한 동작의 장식으로 쓰지 않는다. |
| 그룹 아이콘 | 그룹 제목 줄에서 리전·계정·프로젝트·네트워크 같은 영역을 식별한다. | 노드 카드 안에 넣거나 이름 없이 쓰지 않는다. |

- 세트가 종류를 나누지 않으면 아이콘이 나타내는 대상에 맞춰 위 자리를 고른다.
- 모든 요소에 아이콘을 붙이지 않는다. 주문 접수·검증·재고 예약처럼 이름으로 충분하면 기본 도형과 글만 쓴다.
- 독립 리소스는 `shape=tile`을 기본으로 쓴다. 아이콘은 위, 이름은 아래에 놓고 카드 면과 좌우 여백이 모든 재생 상태에서 보이게 한다. 업무 카드 머리의 장식 로고와 구분한다. 실행 상태는 `status`를 우선한다.

## 그룹과 중첩

- 그룹 아이콘과 명시적 이름을 그룹 제목 줄에 함께 둔다. 선과 부딪히면 제목 덩어리를 옮길 수 있다.
- 중첩은 실제 포함 관계를 나타낸다. 리전·계정·프로젝트·네트워크·서비스와 하위 리소스를 자료에 맞게 묶는다. 처리 순서를 꾸미려고 포함 관계를 만들지 않는다.
- 일반 도메인 그룹의 자동 헤더 표식은 공급자 아이콘과 다르다. 자동 표식에서 리전 같은 경계 의미나 선 모양을 추론하지 않는다.
- 맞는 그룹 아이콘이 없는 영역은 이름과 경계로만 표시한다. 다른 서비스 아이콘을 대신 붙이지 않는다.
- 배포 정보가 없으면 구성 모형이라고 밝힌다. 예시를 실제 운영 구성이나 성능·복구 보장으로 설명하지 않는다.

### 영역 외곽선

- 영역마다 실선과 점선은 공급자 가이드를 따른다. 모든 영역을 같은 실선이나 점선으로 통일하지 않는다.
- 카탈로그가 영역 종류의 기본 선 모양을 갖고 렌더러가 이를 적용하면 그대로 쓴다. 자동 적용을 확인하지 못했으면 점선 영역의 `group`에 `dashed`를 명시하고 결과를 확인한다. 확인하지 않고 적용됐다고 보고하지 않는다.
- 선 색은 정본의 의미 토큰과 테마 대비를 따른다. 가이드의 밝은 배경용 색을 다크 화면에 그대로 옮기지 않는다.

## 경로와 상태

- 주 경로는 실선, 보조 경로는 점선으로 구분한다. 가이드가 다르게 정하면 가이드를 따른다.
- 성공은 정상 역할, 실패는 오류 역할로 표현하고 상태 글을 함께 둔다. 점선을 항상 실패와 같은 뜻으로 보지 않는다.
- 비동기라는 이유만으로 모든 주 흐름을 보조 경로로 만들지 않는다. 같은 선을 호출과 응답에 겸용하지 않는다.
- 선 모양과 글만으로도 관계를 읽을 수 있게 한다. 관계를 설명하지 않는 장식용 이동을 넣지 않는다.

## 배치와 검수

- 읽는 순서와 짧은 연결을 우선한다. 고정 본문 폭에 맞추려고 사슬을 접어 긴 우회를 만들지 않는다.
- 복잡한 설계의 요소와 연결을 수량 목표 때문에 지우지 않는다. 전체 구조를 보존하고, 상세 보기가 필요하면 같은 항목을 이어서 볼 수 있게 나눈다.
- 라이트와 다크에서 아이콘·이름·경계·선을 실제로 확인한다. 같은 바이트라는 사실을 두 배경의 가독성 합격으로 대신하지 않는다.
- 그룹 아이콘의 노드 사용, 서비스·리소스의 장식 카드 사용, 이름 없는 그룹과 잘못된 중첩을 검사한다.
- 교차 마스킹, 선 끝과 도형 경계, 긴 우회, 잘림, 가로 넘침을 확인한다. 정지 SVG와 재생 장면이 같은 요소·경로를 전달해야 한다.
