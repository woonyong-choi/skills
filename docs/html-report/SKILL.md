# HTML Report

- 우선순위: 사용자 지시 → 저장소 규칙 → 이 스킬. 범위 밖은 명시한 소유 스킬 적용
- 범위: 브라우저로 보는 HTML 한 장. 설명 페이지(`explain`)와 비교 보고서(`decision`·`result`)의 구성, 생성 스크립트, 확인 절차
- 고정 양식: HTML은 `build_report.py`만 생성, AI는 입력 JSON만 작성. HTML·CSS·생성물 직접 작성·수정 금지. 두 종류 모두 공통 테마의 같은 블로그 틀(제목·요약·테마 전환·글꼴·색), 설명은 본문 폭, 비교는 넓은 폭
- 필요할 때만 읽기: 저장소 문서 그림 → repo-docs-figures; 저장·사실 상태·자리표시 → repo-docs

## 사용 조건

- `explain`: 개념·로직·흐름·아키텍처를 "그려서/웹으로/브라우저에 보여 줘"라고 요청할 때, 실험 블로그 글(repo-docs-experiment 흐름). 채팅 설명이나 갤러리로 대체 금지
- `decision`: 차이가 눈으로만 보이는 선택지 결정(레이아웃, 차트 모양, 색, UI 배치)
- `result`: 화면이 바뀌는 작업의 전/후 확인, 그림·코드·실행 결과의 공통 기준 판정
- 대신: 글로 고를 수 있는 결정 → 채팅 선택지; 저장소에 커밋할 문서 → (repo-docs 문서 목록); 데모 GIF·홍보 영상 → repo-docs-figures, repo-docs-promo

## 설명 페이지

ThinkFlow 공통 테마(`src/vendor/theme`)와 기본 재생기 호스트를 그대로 사용, 스타일·높이 조정·테마 전환 재구현 금지. 그림 폭은 자기 캔버스 폭까지 본문 밖으로 확장

1. 의미 단위로 나누기: 맨 앞 전체 흐름, 이어서 단계·분기·실패 처리 등 한 절에 한 의미
2. 절마다 제목, 핵심 문단 1~3개(한 문단 2문장 이내), ThinkFlow 그림 하나. 쉬운 말, 전문 낱말은 처음에 풀이. 그림이 말하는 것을 글로 반복 금지
3. 그림 원본 `.thinkflow`: 가로로 화면을 채우는 배치 기본(`view graph` 생략). 한 줄 카드 4개 이하는 기본 캔버스(폭 약 970px 화면부터 전체), 5~6개는 머리에 `width wide`(5개 약 1230px, 6개 약 1490px 화면부터 전체, 좁으면 그림 안 가로 스크롤). 7개 이상은 ThinkFlow가 세로로 돌리므로 의미 단위로 나눔. 선 라벨 2~4자, `view graph down`은 위아래 의미가 있을 때만
4. 순서·변화가 이해를 돕는 그림만 `scene` 추가. 문법: ThinkFlow `docs/usage.md`, `docs/reference/`
5. 생성 뒤 확인 절차 2·3 실행, 사용자에게 `index.html` 경로 전달

## 비교 보고서

절 하나가 질문 하나 또는 확인 대상 하나. 순서 고정

칸 → `decision` → `result`:

- 설명 → `무슨 질문인가` 2~3문장 → `무엇이 바뀌었나`: 요청한 것과 반영한 것
- 그림 → 지금 그림과 선택지 A·B·C를 같은 크기로 나란히 → 전·후 같은 크기로 나란히. 단계·다크 모드 그림은 `extra`
- 표 → `좋은 점`, `나쁜 점` → `좋은 점`, `남은 문제`. 근거(시험 결과, 그림에서 보이는 것) 포함, 추정은 추정 표기
- 마지막 줄 → `추천`: 선택지와 이유 한 문장 → `판단`: 수용 조건 충족 여부와 근거. Git 검토만 머지 판정

- 열 제목: 기호와 이름(`A. 몸통을 길게`), 현재 상태면 `지금 =`. 결과 열은 실제 대상·버전(`전 ({기본 브랜치})`, `후 (PR #{번호})`)
- 열 4개 이하, 그림 2개 이상이면 열 안에 세로로. 맨 위 고정 탐색 칩(글자 대비 4.5:1 이상, 한 줄 가로 스크롤)
- 표 `align`: 상태 `center`, 수치 `right`, 설명 `left`. 이미지 `max_height`: 래스터 높이 상한, iframe은 초기 높이
- 시각 차이가 결정에 필요하면 설명만으로 그림 대체 금지, 실제와 모형 구분
- 선택 기능(`review`): 후보마다 그림·선택 버튼·의견 하나, 결과는 복사 가능한 JSON. 자동 전송·제품 변경 금지, 미판정·보류·재작업을 승인으로 해석 금지, 새 후보에 이전 승인 승계 금지. 사용 전 [입력 형식](references/input-format.md) 필수 확인

## 그림과 모형 표시

- 입력: `.thinkflow` 원본, 미리 만든 SVG·HTML(`inline`), 스크린샷(`src`). 렌더 실패는 생성 실패, 이전 산출물을 새 성공으로 간주 금지
- 색·글꼴·아이콘 변경 금지. 정본은 ThinkFlow 공통 테마. 스크린샷은 검증 테마 고정 후 테마명 표시
- 모형 표시: (repo-docs 자리표시). 흉내 낸 그림은 `"mock": true`와 그림 안 `모형`, 지어낸 경고·수치는 `[모형]`. 렌더 성공과 실제 구현 여부는 별도 판정

## 저장 위치

- 프로젝트: repo-docs 문서 목록의 `.local/reports/{YYYY-MM-DD}-{주제}/` 위치·비공개 규칙(등록 Vault 위치, git 제외 확인)
- 프로젝트 밖: 사용자·워크스페이스 지정 폴더, 없으면 현재 폴더의 git 제외된 `.local/reports/`. 제외를 확인할 수 없으면 저장 중단
- 폴더 내용: `index.html`, 입력 JSON, 그림 원본, `theme/`, `explain`의 `figures/`, 비교 보고서의 `index.png`(테마 명시 캡처)

## 생성

```sh
python3 <이 스킬 폴더>/scripts/build_report.py <입력.json> [출력.html] --thinkflow <ThinkFlow 경로>
```

- `--thinkflow`: 체크아웃 루트 또는 `src/cli.js`. 없으면 `THINKFLOW_PATH`, PATH의 `thinkflow`. 공통 테마 출처라 필수
- 출력은 입력 JSON과 같은 폴더만, 기본 `index.html`. 그림 경로는 입력 폴더 기준
- `--static`: 비교 보고서의 `.thinkflow`를 멈춘 SVG로
- 입력 JSON 작성 전 [입력 형식](references/input-format.md) 필수 확인

## 확인 절차

1. 생성 스크립트 오류 없이 종료
2. 브라우저로 열어 그림 수 일치·0개 아님, iframe마다 재생기 로드, 가로 넘침 없음 확인. 데스크톱과 폭 390에서 각각 확인
3. `시스템 / 라이트 / 다크`를 눌러 페이지와 모든 그림이 함께 바뀌는지 확인
4. 비교 보고서: 질문마다 구성 칸·모형 표시, 표 정렬 확인. 움직임은 탭·시간 변화 직접 관찰. 선택 기능은 선택·의견·필터·새로고침 복원·복사 대안 확인
5. 판정에 쓴 캡처 보존. 직접 보지 못한 범위는 미확인으로 보고
