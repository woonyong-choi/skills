# HTML Report

- 우선순위: 사용자 지시 → 저장소 규칙 → 이 스킬. 범위 밖은 명시한 소유 스킬 적용
- 범위: 브라우저로 보는 보고서 폴더 하나. 설명 페이지(`explain`), 선택 비교(`decision`), 전후 확인(`result`)의 원문 형식, 생성, 확인, 전달
- 고정 양식: AI는 원문 Markdown만 작성. HTML은 `build_report.mjs`만 생성, HTML·CSS·생성물 직접 작성·수정 금지
- 디자인: 홈페이지 문서 페이지와 같은 정본(design-tokens) 상속. 보고서에만 있는 배치·상단 막대·판정 조작은 `assets/report.css`, `assets/report.js`가 소유
- 필요할 때만 읽기: `.thinkflow` 원문 작성·변경 → repo-docs-figures `references/syntax.md` 필수 확인; 스크린샷 촬영 → repo-docs-figures 스크린샷 규칙(촬영 스크립트), 비교용은 배경 프레임 없이 앱 영역만; 저장·사실 상태·자리표시 → repo-docs

## 사용 조건

요청이 없어도 아래 조건이 맞으면 AI가 보고서 띄우기. 판단 문구 없이 아래 조건만 사용

띄우는 조건(하나라도 맞으면):

- 설명 페이지
  1. 답에 순서가 있는 단계 5개 이상
  2. 답에 서로 연결된 구성 요소 5개 이상
  3. 답에 조건에 따라 갈리는 경로 2개 이상
  4. 사용자가 같은 설명을 다시 묻거나 "무슨 말이야", "모르겠어"라는 반응
  5. 사용자가 "그려서", "웹으로", "브라우저에" 보여 달라는 요청
- 선택 비교: 후보 2개 이상이고 후보끼리 다른 점이 배치·색·크기·간격·글꼴·아이콘·차트 종류·움직임 중 하나 이상
- 전후 확인: PR 변경에 CSS·HTML·화면 구성 요소 코드, `docs/assets` 이미지·GIF, README 이미지, `.thinkflow` 원본 중 하나 이상 포함. 띄우는 시점은 PR 열기 전

띄우지 않는 조건(띄우는 조건보다 우선, 설명 페이지 5번 요청은 예외):

1. 후보끼리 다른 점이 글자뿐(이름, 문구, 설정값) → 채팅 선택지
2. 확인할 화면이 한 장뿐 → 채팅에 스크린샷 한 장
3. 같은 주제 보고서가 이미 있음 → 새로 만들지 않고 그 보고서를 고쳐 다시 띄우기

띄운 뒤:

- 순서: 채팅에 핵심 답을 먼저 짧게, 이어서 보고서. 보고서로 답 대체 금지
- 사용자 컴퓨터 Chrome으로 열기(전달 절)
- 선택 비교·전후 확인: 판정 결과(결과 복사 글)를 받을 때까지 다음 단계 진행 금지. 미판정·보류 항목은 진행 금지
- 설명 페이지: 띄운 뒤 하던 작업 계속

## 원문 형식

세 종류 모두 같은 뼈대: 머리(제목, 요약 한 문장) → `##` 절 반복 → `## 정리`

작성 전 종류별 틀 필수 확인: [설명 페이지](references/explain.md), [선택 비교](references/decision.md), [전후 확인](references/result.md). 틀의 칸 이름이 채울 질문

자리 → 규칙:

- `kind` → `explain`, `decision`, `result` 중 하나
- `version` → 비교 보고서만 필수. 판정 저장 키. 버전이 바뀌면 이전 판정 승계 없음
- `related` → 생략 가능. `- title:`·`href:` 목록, 오른쪽 목차 아래 관련 보고서 목록
- 첫 문단 → 요약 한 문장
- 그림 → 정본 문법 `ui:figure-grid`(`columns: 2`), 이미지 파일은 원문 옆 `assets/`에 두고 `src`에 파일 이름만
- 도표 → `thinkflow` 펜스
- 판단·추천 상자 → `:::note[추천]` 또는 `:::note[판단]`. 주의 상자(`:::warning`) 사용 금지
- 제목 → 번호 없음
- 판정 대상 → 비교 보고서에서 그림 격자가 있는 `##` 절. 정리 절은 판정 대상 제외
- 그 밖의 문법 → document-engine이 그리는 정본 문법
- 별도 런타임이 필요한 구성 요소(탭 등) → 원문에서 사용 금지. 보고서 런타임은 `report.js` 하나
- 문체 → 설명 페이지 합쇼체, 선택 비교·전후 확인 개조식 명사 끝
- 금지 → 인사, 필자 소개, "여러분", 이모지

## 작성 규칙

세 종류 공통. 규칙 → 나쁜 예 → 좋은 예:

1. 결론과 할 일을 맨 앞에. 요약 문장은 "그래서 무엇이 어떻게 되나", 선택 비교는 무엇을 고르면 되는지까지 → `목차 위치를 비교한 보고서` → `질문 1개. 목차 위치는 A를 추천. 버튼으로 고른 뒤 결과 복사`
2. 한 문장에 한 가지, 새 개념은 문장마다 최대 하나 → `훅이 상태를 모아 체크포인트로 게시하고 새 세션은 그것을 복구` → `세션을 닫기 전에 지금 상태를 이슈 댓글로 남깁니다.`
3. 모르는 말은 쓰지 않거나 바로 풀이. 작업 중 붙인 이름(파일명, 함수명, 내부 용어)은 본문에서 제외, 꼭 필요하면 처음 나올 때 무엇인지와 예 → `정본 토큰` → `디자인 저장소에 정해 둔 색·간격 값(예: 본문 글자색, 버튼 곡률)`
4. 추상적인 설명 바로 뒤에 실제 이름·값·화면의 예 하나 → `찾는 속도가 느림` → `토픽이 40개면 order.paid를 찾으려고 표를 끝까지 내려야 함`
5. 숫자에는 비교 대상 → `680px` → `680px(1920px 화면의 3분의 1 정도)`
6. 왜와 안 하면 생기는 일 한 줄 → `그림 격자 여백을 0으로` → `지금은 이미지 양옆에 빈칸이 생겨 그림이 칸보다 작게 보임`
7. 선택지는 사용자가 겪을 결과로. 비교 기준은 기술 속성이 아니라 사용자 행동(찾기, 읽기, 고치기, 기다리기) → `정렬 순서 유지` → `화면을 다시 봤을 때 같은 토픽이 같은 자리에 있음`
8. 바뀌는 것은 전·후를 나란히. "바뀝니다" 한 줄 대신 바뀌기 전과 후를 그림이나 짧은 예로 → `간격이 넓어집니다` → `전 16px(본문 글자 높이) · 후 24px(글자 높이의 1.5배)`
9. 보내기 전 스스로 세 가지 확인 → 처음 보는 말 → 풀이하거나 빼기; 추상적인 문장 → 예 붙이기; 다 읽고 할 일 → 한 문장으로 말할 수 있는지

- 낯선 말 목록: [unfamiliar-words.md](references/unfamiliar-words.md). 사용자가 어떤 말에 "무슨 말이야"라고 하면 그 말을 목록에 추가
- 설명 페이지 도표 원문: 배치·폭·세로 전환은 그림 작성 문서(머리 참조) 적용, 선 라벨 2~4자. 순서·변화가 이해를 돕는 도표만 `scene` 추가(ThinkFlow `docs/usage.md`, `docs/reference/`)
- 비교 보고서: 그림 캡션은 후보 이름 또는 실제 대상·버전. 순서 표시(A·B·C·D, 전·후)는 런타임 담당. 시각 차이가 결정에 필요하면 글만으로 그림 대체 금지, 실제와 모형 구분. 전후 확인의 Git 검토만 머지 판정

## 생성 순서

1. 읽는 사람이 얻을 것을 한 문장으로 정하기. 그대로 요약. 한 문장으로 안 써지면 보고서 나누기
2. 예로 쓸 재료(실제 이름, 값, 화면, 명령 출력) 먼저 모으기. 이후 모든 "예:" 칸은 여기서만, 지어낸 값은 "(모형)"
3. 절 나누기: 설명은 흐름 단계를 3~6개로, 선택 비교는 고를 것 하나가 절 하나, 전후 확인은 수용 조건 하나가 절 하나
4. 선택 비교만: 그 화면에서 사용자가 하는 행동 2~4개를 비교 기준으로
5. 틀의 칸을 위에서부터 채우기. 재료가 없는 칸은 "확인 못 함"으로 쓰고 보고
6. 낯선 말 목록과 대조해 쉬운 말로 바꾸거나 처음 나올 때 풀이. 작업 중 붙인 이름은 본문에서 제외
7. 그림 넣기
8. 작성 규칙 9번 스스로 확인
9. 자동 검사(생성기) 통과. 걸린 줄은 5~6번으로 돌아가 수정
10. 읽기 검토 통과
11. 띄우기: 채팅에 1번 문장과 할 일 한 줄 먼저

## 자동 검사

생성기가 걸린 줄 번호와 이유를 출력하고 생성 중단. 코드 블록·front matter 제외:

- 빈 칸, 남은 `{...}` 자리
- "예:"·"예를 들면:"·"근거:" 칸에 숫자, 고유 이름(영문), 코드 표기, 따옴표가 하나도 없음
- 괄호 풀이 없이 처음 나온 낯선 말 목록의 말이나 스크립트 파일명
- 한 문장 80자 초과
- 단위 숫자(px, ms, %, KB, MB)에 비교 대상(바로 뒤 괄호 설명, "~보다", "~의") 없음

## 읽기 검토

- 작성하지 않은 새 세션에 보고서 원문만 전달(작성 대화·재료 제외)하고 세 질문: 처음 보는 말과 그 줄, 예 없이 추상적인 문장과 그 줄, 다 읽고 할 일 한 문장
- 3번 답이 요약과 같은 뜻인지 작성 세션이 대조
- 모델: 공급자마다 가장 저렴한 모델(Claude `haiku`, Codex는 `read_review.mjs`의 `CHEAPEST` 상수). 더 비싼 모델로 올려 통과 금지
- 실행: `node <이 스킬 폴더>/scripts/read_review.mjs <보고서 폴더>/report.md --host claude`
- 하나라도 걸리면 고쳐서 다시 읽히기, 최대 2번. 그래도 걸리면 걸린 줄을 표시한 채 띄우고 보고
- 1번 답에 나온 말은 낯선 말 목록에 추가
- 연결 예정: #91 교차 리뷰의 호스트 어댑터가 머지되면 그 실행 명령에 모델 지정만 더해 교체(후속 이슈)

## 그림과 모형 표시

- 렌더 실패는 생성 실패, 이전 산출물을 새 성공으로 간주 금지
- 색·글꼴·아이콘 변경 금지. 스크린샷은 검증 테마 고정 후 테마명을 그림 `caption`에 기재
- 모형 표시: (repo-docs 자리표시). 흉내 낸 그림은 그림 안과 캡션에 `모형`, 지어낸 경고·수치는 `[모형]`. 렌더 성공과 실제 구현 여부는 별도 판정

## 화면

- 배치: 문서 배치에서 왼쪽 목록 열 없이 본문 + 오른쪽 목차. 본문은 남는 폭 전부, 좁은 화면은 목차가 위
- 상단 막대: 왼쪽 비움, 가운데 판정 조작(비교 보고서만), 오른쪽 테마 전환(시스템·라이트·다크). 개수가 고정된 조작만, 다른 보고서 연결은 관련 보고서 목록
- 판정: 선택 비교 A·B·C·재작업·보류, 전후 확인 승인·재작업·보류. 같은 버튼 다시 누르면 해제, 의견 칸은 버튼 줄 아래
- 버튼: 판정·필터·결과 복사·테마 모두 디자인 저장소 분할 버튼(`app-tablist is-segmented`). 보고서 전용 버튼 모양 금지, 배치만 `report.css`
- 순서 표시: 그림 왼쪽 위 모서리 바깥 원(그림자 포함), 고른 후보 그림에 강조 테두리
- 상단 가운데: 진행 수, 필터(전체·선택·미선택·재작업·보류), 결과 복사
- 저장: 보고서 대상·버전별 키로 브라우저에만, 외부 전송 없음. 미판정·보류를 승인으로 해석 금지
- 결과 복사: `{ target, version, questions: [{ title, choice, note }] }` JSON. 클립보드 실패 시 본문 끝 읽기 전용 글 상자
- 테마 전환: html-report 전용, 홈페이지에 추가 금지

## 저장 위치

- 등록 프로젝트: `<Vault>/worktree/<프로젝트>/docs/reports/{YYYY-MM-DD}-{주제}/`
- 프로젝트 무관: `<Vault>/legacy/reports/{YYYY-MM-DD}-{주제}/`
- Vault 미등록·접근 불가: 저장 중단. 사용자에게 Vault 절대 경로 요청 → git-issue `project_context.py --register-vault <경로>`
- 저장소 안 저장 금지(git 제외 여부와 무관)
- 생성기 검사: 파일을 쓰기 전에 git-issue `project_context.py`의 Vault 해석·쓰기 검사로 출력 폴더 확인. 위 두 위치가 아니면 HTML·그림·도표 포함 어떤 파일도 쓰지 않고 종료 1. 출력 폴더 인자가 없으면 원문 폴더가 검사 대상
- 폴더 내용: `report.md`(원문), `assets/`(그림), 생성물 `index.html`, `report.css`, `report.js`, `theme/`(정본 CSS·글꼴), `diagrams/`(도표). 외부 네트워크 없이 열기 가능

## 생성

```sh
cd <이 스킬 폴더>/scripts && npm ci
node <이 스킬 폴더>/scripts/build_report.mjs <보고서 폴더>/report.md
```

- 첫 실행 전 `npm ci`. 의존성은 `package.json`에 고정 commit의 Git 의존성(design-tokens, document-engine, ThinkFlow), `node_modules` 커밋 금지
- 출력: 기본은 원문 폴더, 둘째 인자로 다른 폴더 지정
- 실패(원문 규칙 위반, 자동 검사, 원문 오류, 도표 실패): 종료 1, 기존 출력 파일 유지

4. 판정에 쓴 캡처는 보고서 폴더에 보존, 직접 보지 못한 범위는 미확인으로 보고

## 전달

- 열기 위치: 사용자 컴퓨터의 위 Vault 보고서 폴더. 원격·클라우드 세션이면 사용자 컴퓨터의 같은 Vault 경로에 폴더 전체 저장 후 그 경로 사용. 저장 불가하면 미저장으로 보고
- 결과에 열기 명령 그대로 제공, 경로는 따옴표로 감싼 절대 경로: macOS `open -a "Google Chrome" "<폴더>/index.html"`, Linux `google-chrome "<폴더>/index.html"`, Windows `start chrome "<폴더>\index.html"`
- 사용자 컴퓨터에서 명령 실행 가능하면 직접 실행. 앱 실행이 막힌 실행 환경(Codex 기본 보호 모드 등)이면 명령만 제공, 권한 우회 금지

## 금지

- 보고서를 git에 커밋
- 보고서 산출물의 저장 위치 밖(임시 폴더, `/tmp`) 저장. 확인 중 캡처만 세션 작업 폴더 허용
