# 글 유형

독자가 가져갈 답으로 주 유형을 고르고 해당 파일만 읽는다. 학습 구현만 작성 기준이 있으며 나머지 파일은 제목만 둔다. 빈 유형은 첫 글을 함께 쓰면서 채운다.

| 유형 | 독자가 가져갈 답과 전개 | 증거와 그림 | 피할 패턴 |
|---|---|---|---|
| [기술 원리 설명](technical-principles.md) | 익숙한 예를 따라 동작·조건·경계를 이해한다. 같은 값이나 대상을 유지하며 필요한 개념을 소개한다. | 단계별 상태·값의 변화·대응 관계·경계 사례 | 용어부터 쌓기, 운영 사고를 억지로 도입하기 |
| [학습 구현](learning-implementation.md) | 배운 원리가 실제 코드와 저장·실행 과정으로 어떻게 연결되는지 이해한다. 궁금했던 것·제약·선택·확인한 동작을 잇는다. | 실제 코드·실행 화면·저장 형식·동일 입력의 전체 경로 | 기능 목록·교과서 요약, 허구의 시행착오 |
| [아키텍처·설계 선택](architecture-decisions.md) | 해당 조건에서 왜 그 구조를 골랐는지 판단한다. 요구·제약·유효한 대안·책임·데이터 흐름·감수한 비용을 연결한다. | 전후 구조·계약·제약·구현과 검증 | 구성 요소와 장점 나열, 모든 조건에서 같은 선택이라고 단정 |
| [운영·장애 개선](incident-improvement.md) | 관측에서 원인을 좁히고 대응한 과정을 이해한다. 당시 관측·가설·확인·조치·남은 위험을 구분한다. | 시간축·로그·지표·재현·변경 전후 | 결과를 미리 알았던 듯 꾸미기, 사람 탓, 없는 장애 만들기 |
| [성능 실험·리포트](performance-report.md) | 어떤 조건에서 무엇이 달라졌는지 해석한다. 질문·환경·방법·결과·해석의 범위를 중심으로 전개한다. 표·목록과 보고서 리듬을 허용한다. | 원자료·반복·분포·단위·프로파일·비교 조건 | 최고값 선별, 다른 조건의 배수 비교, 관측 차이를 원인으로 단정 |
| [도구 전환·선정](tool-selection.md) | 자신의 환경에 맞는 선택을 판단한다. 필요한 작업·평가 기준·실제 사용 차이·호환성·전환과 운영 비용을 연결한다. | 같은 작업의 비교·현재 화면·설정·제약 | 유행·기능표만으로 추천, 시도하지 않은 대안을 과거 경험으로 쓰기 |
| [회고·성장](retrospective.md) | 사건이 생각과 행동을 어떻게 바꿨는지 이해한다. 실제 장면·당시 생각·이후 해석·바뀐 행동을 잇고 개인의 목소리를 남긴다. | 당시 기록·결과물·피드백·행동 변화 | 성장 상투어, 억지 교훈, 과거 미화, 감정 창작 |
| [인터뷰](interview.md) | 실제 인물의 관점과 선택을 만난다. 답에서 생긴 궁금증을 다음 질문으로 잇고 화자의 말뜻과 말투를 보존한다. | 동의한 발언·맥락 있는 인용·확인된 작업 사례 | 없는 대화, 유도 질문, 모든 답을 같은 말투로 교정 |
| [사용 가이드](usage-guide.md) | 실제 작업을 완료한다. 시작 조건·행동·확인할 결과·막혔을 때의 해결을 행동 순서로 설명한다. | 재현한 명령·입력·화면·기대 결과 | 기능 둘러보기, 절차를 가리는 배경 설명 |
| [제품·팀 소개](product-team.md) | 무엇을 누구와 왜 만드는지 이해한다. 실제 사용·협업 장면에서 제품과 팀의 특징을 드러낸다. | 사용 화면·작업 방식·구성원이 확인한 사례 | 다른 팀 이름으로도 성립하는 문화 구호와 홍보 수식어 |
| [기술 제안·로드맵](proposal-roadmap.md) | 문제와 선택지를 이해하고 다음 결정을 판단한다. 현재 제약·대안·기대·비용·위험·필요한 검증을 구분한다. | 비교·POC·현재 제약·미확인 항목 | 계획을 구현이나 성과로 표현, 가능성을 보장으로 쓰기 |
| [발표·소식 안내](announcement.md) | 무엇이 공개됐고 어디까지 확인할 수 있는지 안다. 짧은 소개와 항목으로 핵심 내용·대상·현재 상태를 알린다. | 실제 발표·공개 자료·확인한 범위 | 소개문만 읽고 발표 전체를 검토했다고 주장, 안내를 억지 서사로 늘리기 |
