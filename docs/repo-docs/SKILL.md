# 저장소 문서

저장소 문서가 정해진 독자의 질문에 사실대로 답하도록 문서 목록, 언어, 위치, 사실 상태, 저장 전 검사를 정한다.

## 언제 쓰나

- 문서 공통 규칙이 필요할 때 쓴다. 종류별 스킬(`repo-docs-*`)은 절 구성, 필수 절, 그 스킬에 명시한 종류별 예외를 맡고, 그 밖의 규칙은 이 스킬을 따른다.

## 원칙

1. **독자.** 문서마다 독자와 답할 질문이 정해져 있다(문서 목록 표). 형식을 지켜도 질문에 답하지 못하면 실패다.
2. **예시.** 개념을 설명하기 전에 동작 장면이나 예시를 먼저 보인다.
3. **정직한 상태.** 없는 파일, 시험, 명령, 화면을 있는 것처럼 쓰지 않는다. 정하지 않은 것은 미정으로 표시한다.
4. **적고 정확하게.** 같은 사실은 한 파일에만 쓴다. 낡은 문서는 지우고, 만드는 조건이 되지 않은 문서는 만들지 않는다.
5. **이름과 자리.** 같은 내용이면 같은 절 이름, 같은 순서, 같은 용어, 같은 상태 표기를 쓴다. 절의 유무, 길이, 예시 수는 문서마다 다를 수 있다.
6. **절 이름.** 독자가 찾는 것을 일상어 명사구로 짓는다. 영어 절 이름을 직역하지 않는다. 같은 뜻이면 README, 이슈, docs에서 같은 말을 쓴다.

## 언어

- 저장소 문서는 작업 언어 하나로 쓴다. 한국어 저장소의 기본은 한국어다. `docs/README.md` 첫 문단에 작업 언어를 밝힌다.
- 번역판은 README 하나만 둔다. `README.md`가 작업 언어 정본이고 `README.en.md`가 영어판이다(repo-docs-readme의 영어판 절). docs 전체, `AGENTS.md`, `CHANGELOG.md`, CONTRIBUTING, SECURITY의 번역판은 만들지 않는다.
- 작업 언어가 영어인 저장소는 각 틀의 `영어 작업 언어의 절 이름` 줄을 쓴다.
- `LICENSE`는 공식 원문 그대로 둔다. 저장소 `.local/`의 비공개 작업 파일은 한국어로 쓴다.

## 파일과 폴더 이름

- 공개 Git 저장소의 파일과 폴더(코드, `docs/`, 그림)는 영어 소문자 kebab-case로 짓는다. 언어가 강제하는 표기(Python `test_*.py`, Rust 모듈 snake_case 등)가 있으면 그 표기를 따른다.
- 여러 기록이 한곳에 모이는 시스템 파일(색인, 설정, 모아 두는 정본)은 영어로 짓는다. 예는 `principles.md`, `master.md`, 설정 파일이다.
- 그 밖의 문서와 폴더는 한국어로 지을 수 있고 공백은 `-`로 쓴다.
- `.local/` 아래 정해진 폴더(`decisions/`, `plans/`, `orch/`, `runs/`, `media/`, `tmp/`)는 이름을 그대로 둔다. 그 아래 새로 만드는 이름부터 이 규칙을 적용한다.

- repo-docs-llms는 저장소 안에 `docs/`를 둔 저장소에만 적용한다.
- `docs/README.md` 목록의 분류와 순서는 repo-docs-design `references/index.md`를 따른다.

## 새 문서

새 공개 문서 승인 규칙의 정본은 이 절이다. 다른 스킬은 이 절을 가리킨다.

- 저장소에 없던 문서 종류나 위치의 새 파일은 만들기 전에 사용자 승인을 받는다.
- 이미 정해진 폴더에 쌓는 새 기록(`docs/decisions/`, `docs/notes/`, `docs/experiments/` 아래)은 승인 없이 만든다. 기존 문서를 고치는 일도 승인 없이 한다.
- 기존 정본에 맞는 절이 있으면 새 문서 대신 그 절을 고친다.
- 자율 실행 중에는 승인이 필요한 새 문서를 만들지 않는다. 내용은 기존 문서나 PR 본문에 넣고, 결정 기록에 단계 `결정 필요`로 한 줄 남긴다.
- 작업용 파일은 비공개 작업 파일 절의 `.local/`에 두고 승인받지 않는다.

## 비공개 작업 파일

`.local/` 배치의 정본은 이 절이다.

- 비공개 작업 파일, 보존 원자료와 유일한 실행 증거는 작업 저장소의 `.local/`(git 무시 대상)에 둔다. 같은 호출 안에서만 쓰고 정리하는 재생성 가능한 중간물만 OS 임시 폴더를 쓸 수 있다. 보존 자료를 `archive/`나 저장소 밖 개인 폴더에 두지 않는다.
- 결정 기록과 과업 연결은 워크트리가 아니라 기본 체크아웃의 `.local/`에 둔다. 기본 체크아웃은 `git rev-parse --git-common-dir`가 가리키는 폴더의 상위다. 워크트리를 지워도 기록이 남는다. 그 밖의 파일은 지금 작업하는 체크아웃의 `.local/`에 둔다.
- 공개 문서, 이슈, PR, 커밋에 정책상 비공개인 경로를 링크하거나 그 내용을 옮겨 싣지 않는다.
- 비공개 설계서를 공개 문서로 옮길 때는 확인된 사실만 새로 쓴다. 원문 문장과 내부 기호를 복사하지 않는다.

| `.local/` 위치 | 내용 |
|---|---|
| `decisions/<과업>.tsv` | 결정 기록. 형식은 **show-me-your-work** 스킬이 맡는다 |
| `plans/` | 계획 파일 |
| `orch/<이름>/` | 오케스트레이션 장부 |
| `runs/<종류>-<이름>/` | 실행 산출물(arena, swarm, prototype, eval, trace, visual-parity, 스크린샷) |
| `media/` | 그림과 영상 작업 파일 |
| `tmp/` | 그 밖의 임시 파일 |

## 작성

1. 산출물을 만들기 전에 독자, 답할 질문, 기존 정본, 소비 경로를 확인한다.
2. 문서 문장, 언어, 절 구성, 용어, 서식을 쓰거나 교정하기 전에 [references/writing.md](references/writing.md)를 반드시 읽는다.
3. 사람이 읽는 설명(보고서, 답변, 질문, 비공개 기록)을 쓰기 전에 [references/plain-language.md](references/plain-language.md)를 반드시 읽는다.
4. 새 문서 전체를 쓸 때는 그 종류의 템플릿을 반드시 읽는다. 필수 절을 채울 사실이 없으면 저장하지 않고 빠진 사실을 보고한다.
5. 문서를 쓰거나 고친 뒤 **unslop** 스킬의 `SKILL.md`를 읽고 그 패턴으로 AI 티를 지운다. 새 문서의 갈래와 문장 층은 **technical-writing** 스킬의 `SKILL.md`를 따른다. 두 스킬과 이 스킬이 부딪히는 자리는 [references/writing.md](references/writing.md)의 문체 절이 정한다.
6. 기존 문서 목록이나 마지막 응답에 산출물의 경로, 용도, 정본과 생성물의 구분, 다시 만드는 방법, 지울 때의 영향을 적는다. 이를 위한 관리 문서를 따로 만들지 않는다.
7. 작업을 끝낼 때 중간 출력, 캐시, 중복 사본이 아직 필요한지 다시 따진다. 유일한 근거, 아직 보내지 않은 기록, 실행 중에 참조하는 파일은 남긴다. 필요 없는 파일도 사용자의 삭제 지시나 저장소 정리 정책이 있을 때만 지운다. 둘 다 없으면 남기고 답변에 목록을 적는다.
8. 사용자가 지운 선택적 보고서와 기록은 그것을 만들라는 요청이나 반드시 소비하는 조건이 없으면 다시 만들지 않는다. 지우기 전에 들어오는 링크, 생성 명령, 사용처를 확인하고 같은 범위에서 참조도 고친다.

## 사실 상태

기능, 동작, 수치를 쓰기 전에 상태를 정한다. 상태마다 쓸 수 있는 자리는 종류별 스킬이 정한다.

| 상태 | 근거 | 표시 |
|---|---|---|
| 미정 | 선택지가 남은 추적 항목이나 문서 안 질문 식별자 | 설계 문서 `미해결` 절의 추적 링크나 질문 식별자 |
| 결정 | 저장소 정책에 따른 승인 기록이 있고 `구현` 근거는 아직 없다 | 설계 문서 상태 `결정`, README 상태의 다음 할 것 |
| 구현 | 저장소에서 확인한 기본 브랜치에 코드와 통과한 시험이 있다 | 설계 문서 상태 `구현`, README 기능 |
| 사용 가능 | 사용자가 실행하는 명령을 실제로 실행해 기대 출력을 확인했다 | README 설치, 사용법 |

- 해야 할 동작은 승인된 요구와 계약으로, 실제 동작은 그 버전의 관측으로 판정한다.
- 둘이 다르면 불일치로 기록한다. 구현 결과로 요구를 바꾸거나 결정 기록으로 실행 성공을 대신하지 않는다.
- 수치는 실험 결과(`results/summary.json`)나 실행 출력이 있을 때만 쓴다. 설계로 정한 값은 근거 링크와 함께 쓴다.
- 버전에 따라 달라지는 지원 여부와 측정 결과에는 적용 버전을 밝힌다. 확인 날짜와 상세 검증 기록은 근거 문서에 남긴다. 본문에는 결과를 이해하는 데 필요한 조건을 쓰며, 작성자가 무엇을 확인했는지 나열하는 작업 기록은 넣지 않는다. 근거 문서가 따로 없으면 필요한 버전·조건·확인 날짜를 해당 설명에 짧게 붙인다.
- 근거를 찾지 못한 주장은 쓰지 않는다.

## 자리표시

- 데이터 출처와 구현 여부는 따로 따진다. 실제 동작에 합성 입력을 넣었으면 `합성 데이터`, 구현하지 않은 동작을 보이면 `모형`으로 표시하고, 둘 다 해당하면 두 표시를 모두 단다. 화면과 대체 글에 같은 표시를 단다.
- 접두사는 영어 `Synthetic data:`, `Mock:`, 한국어 `합성 데이터:`, `모형:`이다. 다른 스킬도 이 글자를 쓴다.
- 아직 없는 것은 아래 표의 것으로만 대신한다. 가짜 수치나 화면을 실제처럼 보이지 않는다.

| 아직 없는 것 | 대신 두는 것 | 표시 |
|---|---|---|
| 실행 화면 | 구조도나 흐름 그림 | 대체 글 앞 `Design:`, 한국어 `설계:` |
| 모든 기능이 동작하는 화면 | 구현 범위를 밝힌 데모나 구현하지 않은 모형 | 데이터 출처와 구현 여부 두 축에 맞는 화면과 대체 글 표시 |
| 측정값 | 값 칸을 `측정 전`으로 둔 표 | 표 바로 위 `> [!NOTE]` |
| 결과 차트 | 예시 데이터 차트 | 파일 이름 끝 `-illustrative`, 차트 부제 앞 `예시 데이터.`, 대체 글 앞 `예시 데이터:` |
| 벤치마크 결과 | 실험 `design.md`와 결과 칸이 `측정 전`인 표 | 표 바로 위 `> [!NOTE]` |

- 실제 값이 생기면 표시와 알림을 지우고 값으로 바꾼다.

알림 문장은 문체에 따라 다음 글자를 쓴다.

| 문체 | 알림 문장 |
|---|---|
| 평서 | `측정 전 값이다. 측정 방법은 [{실험 제목}]({design.md 경로})에 있다.` |
| 합쇼 | `측정 전 값입니다. 측정 방법은 [{실험 제목}]({design.md 경로})에 있습니다.` |
| 영어 | `Not measured yet. The method is in [{실험 제목}]({design.md 경로}).` |

## 저장 전 검사

독자, 질문, 필수 조건을 정한 뒤 기존 자료에서 확인 방법을 찾는다. 설정 문서나 검증 문서를 따로 요구하지 않는다. 저장한 파일마다 두 가지를 검사한다.

1. **기계 검사.** 저장소 루트에서 상대 경로로 아래 명령을 실행하고 출력이 없어질 때까지 고친다.
2. **독자 검사.** 문서 목록 표의 `답할 질문`에 이 문서만 읽고 답해 본다. 독립 검토자가 있으면 문서만 주고 묻는다. 없으면 질문마다 답과 근거 위치를 직접 대조한다. 답이 비거나 틀린 질문의 절을 고친다.

README 독자 검사에서는 제품의 역할, 대표 사용 흐름, 대안과의 차이, 현재 제약에 답할 수 있어야 한다. 성능 자료가 있으면 비교 대상, 작업, 수치와 조건을 찾을 수 있어야 한다. 기계 검사 통과로 이 검사를 대신하지 않는다.

```sh
python3 <이 스킬 폴더>/scripts/check_doc.py README.md README.en.md
```

- 스크립트를 실행하기 전에 skill-sync `references/execution.md`를 반드시 읽는다.
- Python 3.9 이상, 표준 라이브러리만 쓴다. 위반이 있으면 종료 코드 1, 인자 오류와 파일 읽기 실패는 2로 끝난다.
- 기계 검사 항목은 서식, 문장 끝, 쓰지 않는 말, 비공개 경로(`.local/` 고정. 저장소가 다른 비공개 폴더를 쓰면 손으로 확인한다), 절 이름 순서(종류별 스킬 목록에 있는 절끼리), 절 대응(`README.en.md`가 인자에 있을 때 `README.md`와)이다.
- 문체 신호 검사는 문장을 잇는 em dash, 이모지, 안내 말(영문 대소문자, 곧은 아포스트로피와 굽은 아포스트로피 포함), 굵게를 본다. 줄 첫머리의 굵은 머리말 `**이름.**`은 굵게로 보지 않는다.
- 문체 신호 검사는 코드 블록과 인라인 코드, 인용 블록(직접 쓰는 GitHub 알림 본문은 검사한다), 링크 대상, HTML 태그와 주석을 보지 않는다. 표의 빈 값 `—`, 범위의 en dash(`–`), 화살표 같은 일반 기호도 보지 않는다.
- 영어 파일 판정은 언어 절과 저장소의 선언이 먼저다. 검사기의 문자 비율 추정은 보조 신호이고, 선언과 다르면 손으로 확인한다.
- 합쇼로 검사하는 파일은 한국어 루트 `README.md`다. 그 밖의 한국어 파일은 평서로 검사한다.
- 스크립트가 보지 않아 손으로 확인하는 것은 문장 길이, 한 목록 안 문장과 명사구의 혼용, 명사형 어미 `-ㅁ`, `-기`, 번역본 문장의 뜻이다.
- 독자 검사에서는 셋씩 맞추려고 늘린 항목, 되풀이하는 마무리, 근거 없는 확신도 본다. 항목 수나 특정 단어만으로 위반을 자동 판정하지 않는다.
- `llms.txt`는 생성물이라 문체 검사에서 뺀다. 그림 원본은 사람이 쓰는 입력이라 도구 검사와 라벨, 대체 글의 문체 검사를 적용한다.
- 끝낼 때 조건마다 반영 위치, 근거, 확인하지 못한 연결을 적는다. 형식 검증과 내용 검증을 나눈다.
- 결론을 바꿀 때는 주장, 새 근거나 해석 오류, 영향 범위를 밝힌다. 질문을 받았다는 이유만으로 전체를 철회하지 않고, 반증된 주장만 바로잡는다.

## 교정

뜻은 그대로 두고 규칙에 어긋난 곳만 고친다. 다음은 바꾸지 않는다.

| 그대로 두는 것 | 예 |
|---|---|
| 사실, 수치, 날짜, 단위 | `171개`, `2026-09-29` |
| 조건과 부정의 범위 | `~일 때만`, `~는 아니다` |
| 인용, 코드, 명령, 출력, 링크 대상 | 해당 없음 |
| 사용자가 확정한 문장 | 해당 없음 |

1. 사실 상태를 다시 정하고, 상태와 맞지 않는 문장을 옮기거나 지운다.
2. 절 이름과 순서를 종류별 스킬 목록에 맞춘다.
3. 문체, 용어, 서식을 고친다.
4. 저장 전 검사를 실행한다.

## 답변

- 답변 형식은 **just-mode** 스킬 답변 절을 따른다.
- 근거를 들어 고친 파일 경로를 적는다.
- 사실 상태 때문에 옮기거나 지운 문장을 적는다.

## 구분

- 코드 주석의 허용 범위는 **just-mode** 스킬의 주석 절이 맡는다.
- 커밋, PR, 이슈, 브랜치는 **git-commit**, **git-pull-request**, **git-issue**, **git-branch** 스킬이 맡는다.
- 그림 파일과 대체 글은 [repo-docs-figures](../repo-docs-figures/SKILL.md)가 맡는다.
- 종류별 절 구성과 필수 절은 각 `repo-docs-*` 스킬이 맡는다.
