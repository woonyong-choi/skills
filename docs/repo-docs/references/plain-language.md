# 쉬운 설명

사람이 읽는 설명을 처음 보는 사람도 한 번에 이해하게 쓴다. 답변, 사용자에게 하는 질문, career 방향 제안과 확인 결과, 결정 기록의 이유 칸에 적용한다. 이 문서를 베끼지 않고 링크로만 가리킨다.

## 규칙

| 규칙 | 나쁜 예 | 좋은 예 |
|---|---|---|
| 1. 결론과 할 일을 맨 앞에 쓴다. 요약 문장은 "그래서 무엇이 어떻게 되나"에 답하고, 선택을 비교할 때는 무엇을 고르면 되는지까지 쓴다 | `목차 위치를 비교한 보고서` | `질문 1개. 목차 위치는 A를 추천. 버튼으로 고른 뒤 결과 복사` |
| 2. 한 문장에 한 가지를 쓰고, 새 개념은 문장마다 하나까지만 넣는다 | `훅이 결정 로그 tail을 주입하고 새 세션은 그것으로 resume` | `세션을 닫기 전에 결정을 결정 기록에 한 줄 남깁니다.` |
| 3. 모르는 말은 쓰지 않거나 바로 푼다. 작업 중 붙인 이름(파일 이름, 함수 이름, 내부 용어)은 본문에 쓰지 않는다. 꼭 필요하면 처음 나올 때 무엇인지와 예를 붙인다 | `정본 토큰` | `디자인 저장소에 정해 둔 색·간격 값(예: 본문 글자색, 버튼 곡률)` |
| 4. 추상적인 설명 바로 뒤에 실제 이름, 값, 화면의 예 하나를 붙인다 | `찾는 속도가 느림` | `토픽이 40개면 order.paid를 찾으려고 표를 끝까지 내려야 함` |
| 5. 숫자에는 비교 대상을 붙인다 | `680px` | `680px(1920px 화면의 3분의 1 정도)` |
| 6. 왜 하는지와 안 하면 생기는 일을 한 줄로 쓴다 | `그림 격자 여백을 0으로` | `지금은 이미지 양옆에 빈칸이 생겨 그림이 칸보다 작게 보임` |
| 7. 선택지는 사용자가 겪을 결과로 쓴다. 비교 기준은 기술 속성이 아니라 사용자 행동(찾기, 읽기, 고치기, 기다리기)이다 | `정렬 순서 유지` | `화면을 다시 봤을 때 같은 토픽이 같은 자리에 있음` |
| 8. 바뀌는 것은 전과 후를 나란히 보인다. "바뀝니다" 한 줄 대신 바뀌기 전과 후를 그림이나 짧은 예로 보인다 | `간격이 넓어집니다` | `전 16px(본문 글자 높이) · 후 24px(글자 높이의 1.5배)` |

## 보내기 전 확인

1. 처음 보는 말이 있으면 풀이하거나 뺀다.
2. 추상적인 문장이 있으면 예를 붙인다.
3. 다 읽은 사람이 할 일을 한 문장으로 말할 수 있는지 확인한다.

## 낯선 말

- [unfamiliar-words.md](unfamiliar-words.md)에 있는 말은 처음 나올 때 반드시 괄호로 푼다.
- 사용자가 어떤 말에 "무슨 말이야"라고 물으면 그 말을 목록에 더한다.
