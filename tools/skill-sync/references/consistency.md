# 일관성 검사 기준

`skill_check.py`가 모든 스킬에 같은 검사를 적용하는 기준이다. 문체 기준의 정본은 [스킬 작성 형식](authoring.md)이고, 이 문서는 그중 기계로 판정하는 부분과 판정하지 않는 부분을 적는다.

## 대상과 출력

- 대상은 `install.py`가 찾는 원본 스킬 전부다. 분류나 출처에 따른 예외 표시는 없다. 실험 스냅숏과 테스트 fixture는 대상이 아니다.
- 스킬마다 SKILL.md, `references/` 아래 Markdown, `playbooks/` 아래 Markdown, `scripts/`의 Python·JavaScript를 본다.
- 출력은 스킬별 위반 목록과 `total N`이다. `--json`은 종류별 개수와 `total`을 낸다. 종료 코드는 통과 0, 위반 1, 입력 오류 2다.

## 검사 항목

| 종류 | 판정 |
|---|---|
| `frontmatter` | 여는·닫는 `---`, 한 줄 값, 허용한 네 칸만, 호출 칸 값 `true`·`false`, `user-invocable: false`는 `disable-model-invocation: true`와 함께 |
| `name` | 영어 소문자·숫자·`-`, 폴더 이름과 같음 |
| `description` | 큰따옴표 한 줄, 1~1024자, 한글 포함, `쓴다.`로 끝나는 문장 포함, 마침표로 끝남, 꺾쇠(`<`, `>`) 없음(Claude 계정이 XML 태그로 보고 거절) |
| `본문 구조` | 본문 첫 줄이 `# 제목`, 그다음 줄이 목록·표·제목·코드·인용이 아닌 문단 |
| `agent` | `agents/openai.yaml`의 `display_name`·`short_description`·`default_prompt`, `$이름` 호출, `disable-model-invocation: true`와 `allow_implicit_invocation: false`가 함께 있음 |
| `절 구조` | 제목 단계 생략, 문서 안 `#` 둘 이상, 같은 `##` 절 이름 중복 |
| `목록 기호` | `*`, `+`, `1)` 목록 |
| `코드 울타리` | 여는 울타리에 언어 표기 없음 |
| `줄 끝 공백` | 줄 끝 공백. 코드 블록 안도 본다 |
| `엠 대시` | `—`, `―` |
| `굵은 머리말` | `**이름:**`처럼 콜론으로 끝나는 굵은 글. 큰따옴표로 인용한 예는 뺀다 |
| `참조 링크` | 상대 링크의 파일과 앵커, 스킬 이름 뒤 `references/…md`의 파일, 절대 경로와 `file://` 링크 |
| `참조 스킬` | `**이름** 스킬`, `**이름** 원칙 스킬`로 가리킨 스킬이 저장소에 있음 |
| `용어 불일치` | repo-docs `references/writing.md` 용어 절의 쓰지 않는 말과 제품 옛 이름(`Torso`, `ThinkFlow`, `띵스플로우`) |
| `규칙 복제` | 서로 다른 스킬의 같은 규칙 줄 |
| `스크립트 인자 형식`, `스크립트 출력 형식` | CLI 파일 머리의 `인자:`, `출력:` 설명 |

## 판정 세부

- 문체 검사(목록 기호, 엠 대시, 굵은 머리말, 용어, 절 구조)는 코드 블록과 인용 블록을 보지 않는다. 엠 대시, 굵은 머리말, 용어는 인라인 코드와 링크 대상도 보지 않는다.
- `참조 링크`는 외부 URL과 `{`가 든 자리표시 링크를 보지 않는다. 다른 분류로 가는 링크는 원본 경로로 푼다.
- `참조 스킬`은 `principle-` 접두사를 뗀 원칙 이름도 받는다. 저장소 밖 스킬 `skill-creator`는 검사하지 않는다.
- `용어 불일치`는 용어 표의 쓰지 않는 말과 정확히 같은 낱말, 또는 조사 `은·는·이·가·을·를·의·와·과·에·로·도·만·부터·에서·처럼·보다·마다·이면·라면`이 붙은 꼴만 잡는다. repo-docs가 대상에 없으면 용어 표 검사는 하지 않고 제품 이름만 본다. 용어 표의 정의 줄은 빼고, 합성어와 활용형은 사람이 본다.
- `규칙 복제`는 목록 항목을 공백 정리와 끝 마침표 제거 뒤 비교해 완전히 같을 때만 잡는다. 공백을 뺀 20글자 이상만 비교하고 뜻이 비슷한지는 보지 않는다. 표는 `금지`, `필수`, `우선`, `만 허용`, `만 사용`, `않는다`, `반드시`가 든 행만 비교한다. SKILL.md는 첫 `##` 절부터 보고, 링크나 스킬 출처 표시가 든 줄은 뺀다.

## 스크립트 형식

- 대상은 스킬 `scripts/`의 Python·JavaScript다. `test_` 파일과 캐시 폴더는 뺀다.
- Python은 모듈 최상위에 `__name__` 실행 분기가 있으면, JavaScript는 `process.argv`를 쓰면 CLI로 본다. 라이브러리 모듈은 검사하지 않는다.
- 설명 위치는 Python 모듈 docstring, JavaScript 첫 `import` 앞 주석이다.

```text
인자: 위치 인자, 선택 옵션, 환경 변수, 기본값, 실행 위치
출력: stdout 결과, stderr 진단, 생성·변경 파일, 종료 코드별 의미
실행 조건: 런타임 지원 범위, 외부 명령·패키지, 인증·권한
```

- 자동 검사는 `인자:`와 `출력:`이 비어 있지 않은지만 본다. `실행 조건`과 옵션·출력의 실제 일치는 CLI 시험과 검토로 확인한다.

## 검사하지 않는 것

- 문장 끝말과 개조식 여부, 짧은 문장, 번역투, 문장 중간 콜론, 굵게 쓴 자리, 표를 쓴 자리, 절 순서(답변, 구분 절 유무)는 기계로 판정하지 않는다. 사람이 [스킬 작성 형식](authoring.md)으로 읽고 고친다.
- 바꿔 쓴 중복 규칙, 뜻의 충돌, 절 사이 조건과 예외의 차이는 증명하지 못한다. PR에서 사람이 확인한다.
- 위반은 정본 하나를 남기고 나머지를 참조로 바꾸거나 형식을 고쳐 없앤다. 파일별 면제 목록은 두지 않는다.
