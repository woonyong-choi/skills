# 일관성 검사 기준

- 대상: 원본 스킬만. 탐색은 `install.py`와 같음, 실험 스냅숏·테스트 fixture 제외
- 출력: 스킬별 위반 목록과 `total N`, `--json`은 종류별 개수와 `total`. 종료 코드 통과 0, 위반 1, 입력 오류 2

검사 → 판정 기준 → 정본:

- 머리와 절 → 우선순위 문구 일치, 범위 또는 기반 줄, 존재하는 조건부 참조, 제목 단계 생략과 같은 2단계 절 중복 금지 → [스킬 작성 형식](authoring.md)
- description → 큰따옴표 한 줄, `때 … 사용.`의 사용 조건, 다른 스킬 이름과 함께 적용 표현 금지 → [스킬 작성 형식](authoring.md)
- 참조 링크 → 본문·references의 상대 링크 파일·앵커와 이름 기반 하위 문서 존재. 코드·인용·자리표시·외부 URL 제외 → [스킬 작성 형식](authoring.md)
- 용어 → 용어 표의 금지어와 정확히 일치하는 낱말 또는 열거한 한국어 조사 결합 → repo-docs references/writing.md 용어
- 규칙 복제 → 서로 다른 스킬의 본문·references 목록 항목이 공백 정리와 끝 마침표 제거 후 완전히 일치 → 공통 규칙의 정본 하나 원칙
- 스크립트 인자·출력 → CLI의 파일 머리에 비어 있지 않은 `인자:`와 `출력:` 설명 → 이 문서 스크립트 형식
- 비용 주석 → 기존 비용 검사기의 외부 호출 경계와 위치 검사, cost·vars·basis 형식 → code-style 비용 주석

- 규칙 복제: 공백 제외 20글자 이상만(규칙 아닌 항목명·짧은 정렬 지시 오판 방지), 의미 유사도 미사용. 표는 `금지`·`필수`·`우선`·`만 허용`·`만 사용`이 있는 전체 행만. 코드 블록, 인용, 스킬 출처 표기와 Markdown 링크가 있는 참조 항목, 머리 목록, 이름 기반 하위 문서 참조 제외. 제목 단계·상세 절 구성은 스킬별 차이 허용

- 용어: repo-docs `references/writing.md`의 `용어` 표 기준, repo-docs가 대상에 없으면 미적용. 코드 블록, 인라인 코드, 링크 대상, 인용, 금지어 정의 표 행 제외. 조사 `은·는·이·가·을·를·의·와·과·에·로·도·만·부터·에서·처럼·보다·마다·이면·라면`. 합성어·자유 활용은 수동 검토

## 스크립트 형식

- 대상: 스킬 `scripts/`의 Python·JavaScript, `test_` 파일·캐시 폴더 제외
- CLI 판정: Python 모듈 최상위 `__name__` 실행 분기, JavaScript `process.argv` 사용
- 위치: Python 모듈 docstring, JavaScript 첫 import 앞 줄 주석

```text
인자: 위치 인자, 선택 옵션, 환경 변수, 기본값, 실행 위치
출력: stdout 결과, stderr 진단, 생성·변경 파일, 종료 코드별 의미
실행 조건: 런타임 지원 범위, 외부 명령·패키지, 인증·권한
```

- `실행 조건`: 수동 대조, 자동 필수 키 제외. 자동 검사는 설명 누락만, 옵션·출력 일치는 CLI 시험과 검토로. 라이브러리 모듈 제외

- 비용 주석: `time O(…), heap O(…), stack O(…)` 순서와 0 아닌 `alloc·io·tokens` 선택 필드. 연속 주석 묶음의 `basis`는 `estimate` 또는 `measured {근거}`. O 식의 단일 영문 변수는 `vars`에 정의. 변수 정의 의무·비용 의미의 정본은 code-style 비용 주석. 여러 글자 변수·복잡도 정확성은 수동 검토. 시험 파일 제외는 검사 범위 한정, 기록 의무 유지. 탐색·위치 검사는 code-style 검사기 호출, 없으면 입력 오류

## 확인 범위

- 미증명: 바꿔 쓴 중복 규칙, 의미 충돌, 절 사이 조건·예외 차이, 비용 추산 정확성. PR 수동 확인으로 보완
- 위반 해소: 정본 하나 남기고 참조로 교체 또는 형식 수정. 파일별 면제 목록 금지
