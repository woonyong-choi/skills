# 스킬 작성 형식

스킬 원본 수정 시 작성 규약. 설치 절차 정본: [skill-sync](../SKILL.md)

## 공통 원칙

새 스킬 포함 모든 스킬에 적용

원칙 → 이유:

- 사용자 지시를 먼저 적용. 해당 주제의 사용자 지시가 없으면 작업 대상 저장소의 같은 주제 규칙 파일(예: `AGENTS.md`, `CONTRIBUTING.md`) 적용. 둘 다 없으면 이 스킬 적용. 다른 스킬과 겹치는 규칙은 머리의 연결에 적힌 스킬 중 그 규칙을 정한 스킬 적용 → 다른 프로젝트 관례 보존, 관례 부재 시 결과 고정
- 범용 규칙에 특정 프로젝트·제품·회사·글꼴 이름 금지. 실제 도구 의존은 선택 어댑터 절에 명시, 실제 명령의 이름·인자 유지 → 다른 저장소에서 그대로 사용
- 공통 규칙 정본은 공통 스킬 하나. 종류별·언어별 스킬은 맡긴 부분(템플릿, 그 종류에만 있는 규칙)만 → 같은 규칙의 두 곳 불일치 방지
- 스킬 지시는 조건별 목록, 실행 순서는 번호 목록. 표 금지. 산출물의 필수 표 양식은 코드 예제로 구분 → 선형 조회와 산출물 형식 보존
- 채울 사실이 없으면 저장 대신 빠진 칸 보고 → 지어낸 내용 방지
- 용어 선택: 설치 구조와 관계없이 이름으로 찾은 repo-docs의 `references/writing.md` 용어 절 → 읽는 사람의 즉시 이해
- 커밋, 작성자, 문서 어디에도 작성 표시 금지(git-commit 금지) → 공개 저장소 기록의 사용자 소유 유지
- 승인 전 설치·활성화 차단 방식은 저장소 배포 정책에 지정. 정책이 없으면 검토 전 설치·활성화와 기존 스킬 대체 금지 → 검토 전 규칙의 실제 작업 혼입 방지
- 스킬 수정 시 다른 스킬과 우선순위 문구, 용어, 서로 참조하는 규칙, 금지 항목 교차 확인 → 스킬 간 모순 방지
- 모든 스킬에 아래 작성 형식 적용 → 어느 스킬이든 같은 방식의 읽기와 검사 스크립트 확인

## 작성 형식

frontmatter:

```text
---
name: {이름}
description: "{대상 작업을 할 때} 사용."
---
```

- description: 사용·비사용 조건 보존 축약. 끝은 `사용.`만. 다른 스킬 이름과 `함께 적용` 금지
- description은 항상 올라가는 카탈로그라 짧게, 본문은 쓸 때만 올라가므로 규칙을 빠짐없이

`# 제목` 바로 아래 머리 목록(이 순서, 이 글자):

```text
- 우선순위: 사용자 지시 → 저장소 규칙 → 이 스킬. 범위 밖은 명시한 소유 스킬 적용
- 기반: {기반 스킬} 먼저 적용. 이 스킬 범위: {맡는 것}
- 필요할 때만 읽기: {조건} → {스킬}; {조건} → {스킬}
```

- 기반 스킬이 없는 스킬(repo-docs, code-style, git-*, folder-naming, design-tokens, skill-sync): 둘째 줄 `- 범위: {맡는 것}`
- 조건부 참조가 없으면 셋째 줄 생략
- 기반은 선행 적용 관계. 현재 문맥에서 확인한 같은 원문은 재조회하지 않고 해당 단계·절만 적용
- 본문에서 다른 스킬 규칙을 가리킬 때: `({스킬} {절 이름})` 출처 표시만. 읽어야 하는 참조는 셋째 줄 조건으로
- 목록 항목, 표 칸: 명사구 끝. 동작은 동작 명사(추가, 삭제, 저장), 금지는 `금지`, 필수는 `필수`
- 쓰지 않는 끝(줄 끝·칸 끝·줄 중간 문장 끝, SKILL.md·`references/*.md`): `-다`, `-한다`, `-함`, `-음`(없음, 다음 같은 명사 제외. 아님·않음은 서술 끝이라 금지), `-임`, `-됨`, `-ㅁ`형
- 템플릿 코드 블록과 백틱 안 예시는 문서에 그대로 나올 글자라 문체 규칙 밖
- 형식 검사: `python3 tools/skill-sync/scripts/skill_check.py .`, 출력 `total 0`까지 수정
- 실행 코드: `scripts/`. 본문: 실행 명령과 사용 조건. 런타임·버전·의존성은 해당 실행 명령 옆에 명시. Python은 표준 라이브러리 우선, 외부 도구는 공식 명령·패키지
- 스크립트 함수: code-style 비용 주석
- CLI 인자·출력 설명과 일관성 검사 범위: [일관성 검사 기준](consistency.md)

## 간결성

- 의미가 같은 가장 짧은 문장 사용. 대상·조건·의무·예외·실패 처리·근거 보존, 모호한 축약 금지
- 중복 설명·상투어 삭제, 공통 규칙은 정본 참조. 규칙 누락·무조건 분리로 길이 축소 금지

## 행동 검토

- 변경 전 요청·근거·응답으로 실패 조건 확정. 비공개 대화의 공개 시험 자료 전재 금지
- 변경 후 실패·미사용·적용 제외·기존 정상 사례 대조. 기대·관측·미확인은 기존 기록이나 응답에 기재
- 수동 대조·실행·독립 평가 구분. 정답 명시·형식 통과로 행동 개선 입증 금지
- 기존 설정·명령·자료로 검토. 시험용 프로젝트 지침 추가 금지
- 규칙은 소유 스킬 하나, 실행 순서·조회 선택은 developer-thinking 하나. 하위 스킬의 루트 재호출·절차 복제·추가 중계 스킬 금지

## 하위 문서

- 조건별 템플릿·설정·예·드문 절차: 해당 스킬의 `references/{역할}.md`. 실행 코드는 `scripts/`, 산출물에 넣는 자원은 `assets/`
- 이동한 규칙의 대상·조건·필수·금지·예외·실패 처리 보존. 매 작업의 핵심 규칙과 필수 검사·형식 정본은 본문 유지
- 읽기 조건: 작업·파일·단계를 특정하고 링크와 `필수 확인` 명시. 조건 없는 참고 링크로 의무 대체 금지
- 종류별 문서: 작성·갱신·검토 대상의 템플릿만 조회. 새 문서 전체 작성 시 해당 템플릿 필수 조회
- 같은 스킬 하위 문서 링크: 본문은 `references/{역할}.md`, 하위 문서끼리는 `{역할}.md`, 본문으로는 `../SKILL.md#{절}`
- 다른 스킬: 설치 구조와 관계없이 스킬 이름으로 폴더 탐색. 하위 문서만 필요한 조건은 `→ {스킬 이름} `에 상대 경로를 인라인 코드로 연결하고 `필수 확인` 명시. 예: `→ repo-docs` 뒤 `references/writing.md` 지정. 이 경우 그 하위 문서만 조회, SKILL.md 전체 로드 제외
- 같은 분류의 다른 스킬로 거는 Markdown 링크: 본문에서는 `../{스킬}/...`, 하위 문서에서는 `../../{스킬}/...`. 원본과 평탄한 설치본에서 모두 확인
- 다른 스킬의 상대 경로를 현재 스킬 기준 경로로 해석 금지. 이름으로 찾은 스킬 폴더 기준 해석
- 분리 후 원본·설치본의 링크·앵커, Claude zip의 하위 문서 포함과 `SKILL.md` 정확히 하나 확인
- 크기 표: 실제 스킬만, UTF-8 SKILL.md 전체 바이트(frontmatter·개행 포함), 기준 커밋과 스킬별 전후·합계. 하위 문서를 포함한 작업별 읽기량과 본문 합계 구별
