# 스킬 동기화

스킬 원본 저장소를 검사하고, 요청한 도구 폴더에 설치하고, 필요하면 Claude 계정까지 배포한 뒤 결과를 대조한다.

## 원본

- 스킬 원본은 스킬 폴더(`{분류}/{이름}/SKILL.md`나 `{이름}/SKILL.md`)가 모인 git 저장소 하나다. 도구 폴더의 설치본은 복사본이다.
- 제공 탐색기는 원본 루트 바로 아래 스킬과 다섯 분류 폴더 바로 아래 스킬만 찾는다. 분류 폴더는 `git`, `code`, `docs`, `design`, `tools`다. 다른 분류는 `--source`로 그 폴더를 지정한다. 실험과 시험 fixture는 찾지 않는다.
- 설치 대상에서는 분류 없이 기존 스킬 이름을 그대로 쓴다. 같은 이름의 원본이 둘 이상이면 오류다.
- 작성 규약은 대상 원본 저장소가 지정한 파일을 입력으로 확인한다. 이 저장소에서는 [스킬 작성 형식](references/authoring.md)을 따른다.

## 단계

1. 요청 범위를 정한다. 검사만 요청받았으면 읽기 전용으로 검사하고 결과를 보고한 뒤 끝낸다.
2. 수정을 요청받았으면 원본을 고치고 형식 검사를 돌려 출력이 `total 0`인지 확인한다.
3. 함께 읽는 스킬끼리 연결과 조건이 맞는지 교차 확인한다. 자동 생성 목록이 있으면 그 생성 절차로 갱신한다.
4. 설치를 요청받았으면 지정 도구에 설치하고, 대상별 성공, 충돌, 실패와 종료 코드를 확인한다.
5. 계정까지 배포하라는 요청이면 [선택 어댑터](#선택-어댑터)의 단일 명령을 실행한다. 검사, 설치, zip, 계정 반영, 대조까지 종료 코드를 확인한다.
6. 배포가 실패하면 막힌 단계, 원인, 복구 명령을 보고한다.
7. 원본을 바꿨으면 **git-branch** 스킬의 작업 중 절과 머지 절대로 커밋, push, PR, 머지까지 한다.

- 행동 규칙을 바꿀 때는 [행동 검토](references/authoring.md#행동-검토)를 반드시 읽는다. 형식 검사 통과와 실제 작업 효과를 구분한다.
- 스크립트를 실행하기 전에 [references/execution.md](references/execution.md)를 반드시 읽는다.

```sh
python3 <이 스킬 폴더>/scripts/skill_check.py <원본 저장소>
python3 <이 스킬 폴더>/scripts/install.py
```

## 검사

- skill_check는 모든 스킬에 같은 검사를 한다. frontmatter와 description 형식, 이름과 폴더 일치, 제목과 목표 문단, Markdown 형식, 참조 링크와 스킬 이름, 용어, 규칙 복제, 스크립트 인자와 출력, `agents/openai.yaml`의 필수 필드와 호출 이름과 암묵 호출 설정을 본다.
- 판정 기준과 자동 검사의 한계는 [일관성 검사 기준](references/consistency.md)에 있다. 문장 끝말은 검사하지 않는다.
- 종료 코드는 전체 통과 0, 위반 1, 입력 오류 2다.
- 참조 링크는 원본 형태와 평탄한 설치 형태 양쪽에서 확인한다.

## 설치

| 도구 | 위치 |
|---|---|
| Codex | `~/.codex/skills/` |
| Antigravity | `~/.gemini/config/skills/` |
| Claude Code | `~/.claude/skills/` |
| Claude 계정(웹, 데스크톱, 원격 세션) | 실행할 때 확인한 공식 배포 방식을 쓴다. 아래 UI 스크립트는 지원 환경에서만 쓴다 |

- 도구 폴더가 없는 도구에는 설치하지 않는다.
- 원본 저장소는 `--source`, 환경 변수 `SKILLS_SOURCE`, 스크립트가 든 git 저장소, 마지막으로 쓴 원본(`~/.config/skills/source`) 순서로 찾는다. 모두 없으면 사용자에게 원본 경로를 묻는다.
- 이 스크립트가 설치한 스킬만 관리한다(도구 폴더의 `.repo-skills.json`). manifest에 없는 같은 이름 폴더는 충돌로 남기고 설치하지 않는다. 원본에서 빠진 manifest 항목은 대상 폴더를 `~/.skill-trash/`로 옮기고, Claude 배포 zip과 manifest 항목도 정리한다.
- 스킬을 지울 때는 `install.py --remove {이름} [{이름} ...]`을 쓴다. manifest에 있는 스킬 이름만 받는다. 대상이 도구 설치 폴더 바로 아래이고 심볼릭 링크가 아닌지 확인한 뒤 휴지통으로 옮기고 목록을 갱신한다. 원본에 남아 있으면 다음 동기화 때 다시 설치된다.
- 바뀔 내용만 보려면 `install.py --dry-run`을 쓴다.
- Claude 계정에 올릴 zip은 `--dist {폴더}`에 만든다. 기본은 원본 저장소의 `dist/claude`다. 설치, 원본 포인터, 휴지통의 홈 경로는 `--target-home {폴더}`로 정하고, 생략하면 현재 사용자 홈을 쓴다.
- Claude 계정 zip에는 루트 스킬 폴더의 `SKILL.md` 하나만 넣는다. `SKILL.md`가 있는 하위 폴더는 그 안의 파일까지 뺀다. 나머지 보조 파일은 기존 제외 규칙에 따라 넣는다.
- 세 도구의 설치본과 zip에서 모두 `tests/`, `.claude-plugin/`, `.codex-plugin/`을 뺀다. 플러그인은 따로 설치해서 스킬 폴더의 중복 자동 로드를 막는다.
- 기존 zip은 파일 목록, 중복, 내용을 배포 대상 원본과 대조하고, 손상되거나 맞지 않으면 다시 만든다. 새 zip도 같은 검사를 거친 뒤 교체한다. 위반이 있으면 설치가 실패한다(종료 코드 1).
- zip 폴더의 `.repo-skills.json`은 생성에 쓴 원본 해시다. 계정 업로드 영수증으로 쓰지 않는다. `Claude 계정 zip 재생성: 없음`도 계정 상태를 확인한 것이 아니다. 변경 목록만 보고 배포가 끝났다고 판정하지 않는다.

### Claude Code와 Codex 설치

도구에 설치하기 전에 [references/installation.md](references/installation.md)를 반드시 읽는다.

## 선택 어댑터

Claude 계정에 올리거나 지우거나 교체하거나 UI를 탐색하기 전에 [references/claude-upload.md](references/claude-upload.md)를 반드시 읽는다.

## 하지 않는 것

- 설치본 폴더를 직접 고치지 않는다. 다음 설치 때 원본으로 덮어쓴다.
- `scripts/`가 있는 스킬을 Claude 저장 카드로 저장하지 않는다. 저장 카드는 SKILL.md만 저장한다.

## 답변

- 검사했으면 `total` 값과 남은 위반을 적는다.
- 설치했으면 도구별 성공, 충돌, 실패와 종료 코드를 적는다.
- 배포했으면 계정 대조 표의 결과를 적고, 실패했으면 막힌 단계, 원인, 복구 명령을 적는다.

## 구분

- 원본 저장소의 커밋 메시지는 **git-commit** 스킬이 맡는다.
- 브랜치, PR, 머지는 **git-branch** 스킬이 맡는다.
