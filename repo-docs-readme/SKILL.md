# Repo Docs Readme

- 저장소 안에 같은 역할의 규칙이 있으면 그것 우선. 없으면 이 스킬이 다른 규칙보다 우선
- 기반: repo-docs 먼저 적용. 이 스킬 범위: 루트 `README.md`의 템플릿과 절 규칙
- 필요할 때만 읽기: 대표 그림, 측정 결과 차트, 구성 그림 제작, 교체 → repo-docs-figures; README 재생성 뒤 `llms.txt` 재생성 → repo-docs-llms

- 문체: 문단은 합쇼체(repo-docs 문체), 제목, 목록, 표 칸은 명사형
- 길이: README 전체 200줄 이내, 세부는 `docs/` 링크
- 그림: 대표 그림, 측정 결과 차트, 구성 그림 각 하나까지

## 입력

작성 전 읽을 입력. 없는 파일은 생략

| 입력 | 쓰는 곳 |
|---|---|

| `docs/architecture.md`의 구성 요소 표와 구성 요소 그림 | 구성, 대표 그림 |
| `docs/experiments/README.md`와 채택 판정 보고서 | 측정 결과 |
| GitHub 릴리스 목록 `gh release list` | 단계 |
| 사용법 명령을 실제로 실행한 출력 | 사용법 |

## 절 규칙

### 제목

- 저장소 이름 그대로, 대소문자까지 동일

### 한 줄 소개

- 형식: `{하는 일} {범주}` 명사구, 50자 이내, 마침표 없음
- 범주는 하나만: `터미널 도구`, `CLI 도구`, `라이브러리`, `서버`, `MCP 서버`, `데스크톱 앱`, `웹 앱`, `플러그인`
- 프로젝트 이름 반복 금지
- GitHub 저장소 설명과 같은 글자
- 예: `여러 저장소의 할 일을 한 화면에 모아 보는 터미널 도구`

### 소개 문단

- 원본: `docs/requirements.md` 첫 문단 복사, 문장 끝만 합쇼체로 변경(repo-docs 문체). 그 파일이 없을 때만 아래 규칙으로 새로 작성
- 한 문단, 문장 셋. 비교 대상이 없으면 셋째 문장 제외

| 순서 | 형식 | 예 |
|---|---|---|
| 1 | `{누가} {무엇을 할 때} {무엇이 어렵습니다}.` | `여러 저장소를 함께 관리하면 할 일이 저장소마다 흩어집니다.` |
| 2 | `{이름}은/는 {무엇을} {어떻게} {합니다}.` | `{이름}은/는 모든 저장소의 이슈를 한 목록으로 모으고 로컬 데이터베이스에 저장합니다.` |
| 3 | `{비교 대상}과/와 달리 {차이}.` | `저장소별 이슈 화면과 달리 저장소를 오가지 않고 한 번에 봅니다.` |

- 기능 이름: 기능 표에 있는 것만
- 시제: 목적을 쓰는 문단이라 단계와 관계없이 현재형
- `{이름}`: 저장소 이름 그대로. 조사 `은/는`, `과/와`는 이름을 읽은 소리의 받침으로 선택

### 단계 알림

- `> [!NOTE]` 다음 줄에 단계별 고정 문장, 변경 금지

| 단계 | 문장 |
|---|---|
| 설계 | `설계 단계입니다. 실행할 수 있는 코드는 아직 없습니다.` |
| 개발 중 | `개발 중입니다. 실행할 수 있는 명령은 아직 없습니다.` |
| 실행 가능 | `개발 중입니다. 배포판은 없고 소스에서 빌드해 실행합니다.` |

### 대표 그림

| 단계 | 그림 | 경로 | 대체 글 |
|---|---|---|---|
| 설계, 개발 중 | 구성 요소 그림 | `docs/assets/architecture.svg` | `설계: {구성 요소 그림의 대체 글, 끝만 합쇼체}` |
| 실행 가능, 배포 | 데모 GIF | `docs/assets/demo.gif` | `{데모가 보여 주는 결론 문장}` |

- 데모 GIF: VHS로 제작(repo-docs-figures VHS)
- 데모에 로드맵 상태 기능이 보이면 합성 데이터로 녹화, 대체 글 앞에 `합성 데이터:` 추가(repo-docs 자리표시)
- 같은 그림 두 번 금지. 대표 그림이 구성 요소 그림이면 구성 절 그림 제외

### 설치

- 필요한 도구 문장: `{도구} {버전} 이상이 필요합니다.` 여럿이면 `{도구} {버전} 이상`을 `, `로 연결. 운영체제 제한이 있으면 `{운영체제}에서 동작하고 `로 시작. 필요한 도구가 없으면 문장 제외
- 실행 가능 단계: 소스 설치 명령 하나. Rust는 `cargo install --git https://github.com/{소유자}/{저장소} --locked`
- 배포 단계: 배포된 경로의 설치 명령만, 한 줄에 하나. 순서는 `cargo install`, `brew install`, 그 밖
- 실제로 실행해 확인한 명령만

### 사용법

- 사용 예 1~5개. 첫 예는 처음 실행하는 명령
- `###` 제목: `{대상} {동작}` 명사구. 예: `목록 보기`, `기록 검색`
- 명령 블록 하나, 출력 블록 하나. 출력은 실제 실행 결과 복사, 20줄 초과면 앞 20줄과 `...` 한 줄
- 화면이 뜨는 명령: 출력 블록 제외
- `전체 명령은` 문장: `docs/cli.md`가 있을 때만

### 기능과 로드맵

두 절의 원본: `docs/requirements.md`의 기능 표

1. 기능 표 행마다 상태 결정: 그 기능의 기능 요구사항이 모두 구현 상태면 구현, 하나라도 아니면 로드맵
2. 구현 행은 기능 절, 로드맵 행은 로드맵 절
3. 항목 글자: 기능 표의 `기능`, `하는 일` 칸 그대로 복사
4. 순서: 기능 표의 행 순서
5. 로드맵 항목 링크: 그 기능의 열린 `build` 이슈 중 번호가 가장 작은 것. URL은 `https://github.com/{소유자}/{저장소}/issues/{번호}`. 열린 이슈가 없으면 링크 제외

- 한 기능의 두 절 동시 기재 금지
- 구현되면 로드맵에서 삭제, 기능에 같은 글자로 추가. 이슈 링크만 제외
- 기능 표에 없는 기능 기재 금지

### 측정 결과

- README의 수치: 이 절에만
- 결과 문장 1~3개. 한 문장에 수치 하나와 보고서 링크: `{조건}에서 {지표}는 {값}입니다([{실험 제목}](docs/experiments/{실험}/report.md)).` 수치는 보고서의 `results/summary.json` 값 그대로
- 차트: 채택 판정 보고서의 `results/figures/` 그림 하나. 예시 데이터 차트 금지
- 보고서가 여럿이면 `docs/experiments/README.md` 표 순서의 처음 셋

### 구성

- 표 행: `docs/architecture.md` 구성 요소 표에서 `위치`가 `main`에 있는 코드 경로인 행만, 같은 순서. 데이터 파일 경로인 행 제외
- 세 칸 모두 아키텍처 표 글자 그대로 복사
- 그림: 대표 그림이 데모 GIF일 때만

### 문서

- 행: `docs/README.md` 표와 같은 행, 같은 순서, 같은 글자
- `docs/archive` 링크 금지

### 개발

- 명령: CI나 저장소 검사 스크립트에 실제로 있는 것만, 빌드, 테스트, 린트, 포맷 검사 순서
- 기여 문장: `.github/CONTRIBUTING.md`가 있을 때만

### 서비스

- 문장 둘: `{서비스 이름}은 {하는 일}을 제공합니다.`, `자세한 내용은 [{서비스 이름}]({URL})에 있습니다.`
- 가격, 할인, 비교 문구 금지

## 갱신
