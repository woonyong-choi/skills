# 검증

확인 단계와 실패를 고칠 때 이력서와 포트폴리오를 내용, 기계 검사, 화면으로 확인한다. 확인은 보내기 전과 수정을 반영한 뒤 두 번 하고, 두 번 모두 내용과 화면을 본다.

## 내용

경력 원본과 공고 분석에 대조한다.

- [사실 경계 절](../SKILL.md#사실-경계)과 대조한다. 신원, 시기, 직무, 회사, 프로젝트, 수치, 링크가 정확한지 본다.
- JD와 대조한다. 뒷받침하지 못하는 요구는 공백으로 두고, 진행 중인 일이나 제안을 끝난 일로 쓰지 않고, 이력서와 포트폴리오 사이에 모순이 없는지 본다.
- 자리 글 `{}`, 양식 예시, 내부 표시, 겹치는 결론이 남지 않았는지 본다.
- 제출 문장마다 대응하는 원본 줄이나 짝 묶음 문장이 있는지 본다. 없으면 지운다.
- 수정을 반영한 뒤에는 변경 표시가 의도한 곳에만 있는지 `versions.py marks` 개수를 요청과 대조한다.

## 기계 검사

공고 폴더에서 실행한다.

```sh
python3 <이 스킬 폴더>/scripts/versions.py check .
typst compile --root . 이력서/이력서.typ
typst compile --root . 포트폴리오/포트폴리오.typ
pdfinfo 이력서/이력서.pdf
pdffonts 이력서/이력서.pdf
pdftotext -layout 이력서/이력서.pdf 이력서/이력서.txt
awk '/```/{c=!c; next} !c' 이력서/이력서.typ 포트폴리오/포트폴리오.typ | grep -nE '\{|\}|·|‒|–|—|―|--'
shasum -a 256 이력서/이력서.pdf 포트폴리오/포트폴리오.pdf
```

- `versions.py check`는 양식 해시(`career.typ`가 스킬 원본과 같은지), 폴더 구조(공고 폴더 안 `이력서/`, `포트폴리오/`), 번호 파일 이름(`-NNNN` 4자리), `전략.md` 절 이름, 확정 버전에 남은 표시를 본다. 실패하면 원인을 고치고 다시 돌린다.
- 포트폴리오도 `pdfinfo`, `pdffonts`, `pdftotext`로 같이 검사한다. A4, 쪽 수, 한국어 글꼴, 뜻 있는 텍스트 추출을 확인한다.
- 자리 글과 금지 문자 검사(`awk`)는 출력이 0줄이어야 한다. 코드 블록 안은 보지 않는다. 변경 표시 함수 이름의 괄호도 보지 않는다.
- 컴파일이 성공했다는 것만으로 끝났다고 판정하지 않는다. 추출한 텍스트는 검사한 뒤 지운다.

## 화면 검사

- PDF를 PNG로 렌더링(`pdftoppm -r 150 -png`)한 뒤 쪽마다 직접 보고 잘림, 겹침, 빈 쪽, 간격을 확인한다.
- 한국어 줄바꿈, 목록 간격, 절 구분, 여백, 쪽 균형, 외톨이 제목, 작은 글자, 읽는 순서를 본다.
- `facts` 표의 행 정렬, 그림의 가로 배치, 그림 글자를 읽을 수 있는지, 그림과 캡션이 같은 쪽에 있는지 본다.
- 수정을 반영한 뒤에는 표시를 켠 것(기본)과 끈 것(`--input changes=off`) 두 벌을 모두 본다. 범례는 첫 쪽 위에 있어야 한다.
- 검토한 PDF의 해시가 전달하는 PDF의 해시와 같아야 한다. 원본이나 PDF를 고친 뒤에는 그 문서의 컴파일, 추출, 글꼴, 쪽, 화면 검사를 다시 한다.

## 기록

`전략.md`의 `# 확인`에 회차(보내기 전, 수정 반영 뒤), 실행한 명령, 쪽 수, 화면 결과와 따로 확인한 쪽, 변경 표시 개수, PDF SHA-256, 남은 공백과 근거 보강 제안, 최종 경로를 적는다. 실행하지 않은 검사, ATS 통과, 합격 가능성을 주장하지 않는다.
