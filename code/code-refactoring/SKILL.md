# 코드 리팩터링

문제 신호 하나를 골라 『리팩터링 2판』의 기법으로 동작을 유지한 채 구조를 고친다. [code-style](../code-style/SKILL.md)을 먼저 적용하고, 이 스킬은 신호별 기법 고르기와 기법 목록만 정한다. 그 밖에서 code-style과 다르면 code-style을 따른다.

## 단계

1. 책임, 의존, 쓰이지 않는 경로를 확인하고 문제 신호 하나를 고른다. 수치 기준 안에 들어도 신호를 판단한다.
2. 기법을 적용하기 전에 반드시 [기법 목록](references/techniques.md)을 읽는다.
3. 고른 기법을 적용하고 **principle-prove-it-works** 스킬대로 확인한다. 같은 값을 계산하는 생산 코드와 표시 코드는 계산 정본 하나를 함께 쓰게 한다.
4. 책임과 의존이 어떻게 바뀌었는지로 개선을 확인한다. 파일 수가 늘어난 것 자체를 구조 개선으로 세지 않는다.

- 모듈 경계는 도메인 지식 단위로 나눈다. 불러오기, 검증, 변환, 저장 같은 실행 순서로 모듈을 나누지 않는다. 처리 단계 분리는 함수 안에서만 한다.

## 문제 신호와 해결 기법

| 문제 신호 | 해결 기법 후보 |
|---|---|
| 이름만 보고 역할을 알 수 없다 | 함수 시그니처 변경, 변수 이름 변경, 필드 이름 변경 |
| 여러 곳에 같은 코드가 있다 | 함수 추출, 코드 순서 옮기기, 메서드 올리기 |
| 함수의 변경 이유가 둘 이상이거나 code-style 함수 길이 권장 최대를 넘는다 | 함수 추출, 임시 변수를 함수로, 매개변수 묶음 타입 도입, 객체 통째로 전달, 함수를 명령 객체로, 조건문을 함수로 분리, 분기를 다형성으로, 반복문 분리 |
| 서로 다른 책임의 입력이 섞이거나 code-style 매개변수 수 권장 최대를 넘는다 | 매개변수를 내부 조회로, 객체 통째로 전달, 매개변수 묶음 타입 도입, bool 플래그 인자 제거, 관련 함수를 타입으로 묶기 |
| 어디서나 바꿀 수 있는 전역 변수가 있다 | 변수 캡슐화 |
| 값을 바꾸는 코드가 여러 곳에 흩어져 있다 | 변수 캡슐화, 변수 분리, 코드 순서 옮기기, 함수 추출, 조회와 변경 분리, setter 제거, 계산 가능한 필드를 함수로, 관련 함수를 타입으로 묶기, 파생값 계산을 변환 함수로 묶기, 참조를 값으로 |
| 모듈이 서로 다른 이유로 자주 바뀐다 | 함수 이동, 함수 추출, 타입 분리 |
| 기능 하나를 바꾸려면 여러 모듈을 조금씩 고쳐야 한다 | 함수 이동, 필드 이동, 관련 함수를 타입으로 묶기, 파생값 계산을 변환 함수로 묶기, 함수 인라인, 타입 합치기 |
| 함수가 자기 모듈보다 다른 모듈의 데이터를 더 많이 쓴다 | 함수 이동, 함수 추출 |
| 같은 값 묶음이 여러 곳에 함께 나온다 | 타입 분리, 매개변수 묶음 타입 도입, 객체 통째로 전달 |
| 금액, 범위, 상태 코드를 기본 타입(int, string)으로 다룬다 | 기본 타입을 값 타입으로, 타입 코드를 하위 타입으로, 분기를 다형성으로, 타입 분리, 매개변수 묶음 타입 도입 |
| 같은 switch나 match 분기가 여러 곳에 되풀이된다 | 분기를 다형성으로 |
| 반복문이 의도를 가린다 | 반복문을 map·filter로 |
| 하는 일에 비해 구조가 과하다 | 함수 인라인, 타입 합치기, 계층 합치기 |
| 나중을 대비해 만든 코드를 쓰지 않는다 | 계층 합치기, 함수 인라인, 타입 합치기, 함수 시그니처 변경, 안 쓰는 코드 삭제 |
| 특정 상황에서만 값이 채워지는 필드가 있다 | 타입 분리, 함수 이동, 특수 케이스 객체 |
| `a.b().c().d()` 같은 긴 호출 체인이 있다 | 위임 숨기기, 함수 추출, 함수 이동 |
| 래퍼가 대부분 다른 객체에 넘기기만 한다 | 위임 래퍼 제거, 함수 인라인, 부모 클래스 상속을 위임으로, 하위 클래스 상속을 위임으로 |
| 모듈끼리 서로의 내부 데이터를 직접 주고받는다 | 함수 이동, 필드 이동, 위임 숨기기, 하위 클래스 상속을 위임으로, 부모 클래스 상속을 위임으로 |
| 클래스나 struct에 독립된 변경 이유가 둘 이상 있다 | 타입 분리, 부모 타입 추출, 타입 코드를 하위 타입으로 |
| 같은 일을 하는 타입들의 인터페이스가 다르다 | 함수 시그니처 변경, 함수 이동, 부모 타입 추출 |
| 타입에 데이터만 있고 관련 로직은 밖에 있다 | 레코드 캡슐화, setter 제거, 함수 이동, 함수 추출, 처리 단계 분리 |
| 상속받은 기능을 대부분 쓰지 않는다 | 메서드 내리기, 필드 내리기, 하위 클래스 상속을 위임으로, 부모 클래스 상속을 위임으로 |
| 주석이 코드가 하는 일을 설명한다 | 함수 추출, 함수 시그니처 변경, 단언 추가(언어별 형식) |

## 구분

- 함수 길이와 매개변수 수 같은 수치, 이름, 검증 방법은 [code-style](../code-style/SKILL.md)이 맡는다.
- 파일과 모듈 이름은 [folder-naming](../folder-naming/SKILL.md)이 맡는다.
