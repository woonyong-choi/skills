# 폴더 이름

새 폴더나 이름을 바꾸라고 요청받은 폴더의 구조와 이름을 정하고, 이름을 바꿀 때는 이력과 빌드를 지키며 옮긴다.

## 쓰지 않을 때

- 기존 폴더는 요청이 없으면 바꾸지 않는다.
- 파일과 모듈 이름에는 [금지](#금지) 절만 적용한다.

## 구조

기존 빌드와 패키지 관리자의 구조는 그대로 둔다. 아래 구조와 기술 종류 폴더 금지는 기존 제약이 없는 새 제품 폴더를 설계할 때만 적용한다.

```text
<프로젝트>/
├── assets/
├── docs/
├── <프로젝트>-<제품>/
│   ├── core/
│   └── cli/
└── <프로젝트>-protocol/
```

- 도구가 만들거나 요구하는 폴더(`target`, `node_modules`, `build`, `.idea`, `.vscode`, `.cargo` 등)에는 적용하지 않는다.
- 패키지나 모듈이 하나뿐인 저장소는 언어 기본 구조(`src/` 등)를 그대로 쓴다.

## 종류별 이름

| 종류 | 형식 | 예 |
|---|---|---|
| 루트 소스 | `<프로젝트>-<제품이나 실행 단위>` | `<프로젝트>-server`, `<프로젝트>-web`, `<프로젝트>-protocol` |
| 루트 비소스 | 예의 이름을 먼저 쓰고, 맞는 것이 없으면 언어나 도구의 관례 이름을 쓴다. 접두사는 붙이지 않는다 | `assets`, `docs`, `scripts`, `tools`, `examples`, `config`, `.github` |
| 모듈 | 역할이나 도메인 명사. 접두사는 붙이지 않는다 | `core`, `engine`, `cli`, `tui`, `api`, `auth`, `store` |
| 외부 서비스 | 연결 폴더 아래 실제 서비스 이름 | `providers/<service>`, `adapters/<service>` |

## 모듈 이름

모듈 안의 하위 폴더도 같은 규칙을 따른다.

| 규칙 | 예 |
|---|---|
| 같은 종류가 여럿이면 복수형을 쓴다 | `providers`, `sessions`, `judges` |
| 역할이 하나면 단수형을 쓴다 | `queue`, `store`, `config` |
| 외부 서비스 이름은 연결 폴더 안에서만 쓴다 | `<service>-handler`는 쓰지 않는다 |

## 금지

| 쓰지 않는 이름 | 이유 | 대신 |
|---|---|---|
| `utils`, `common`, `misc`, `helpers`, `etc` | 내용을 알 수 없다 | 역할 이름(`time`, `paths`) |
| `new`, `old`, `temp`, `v2`, `backup` | 상태는 git이 관리한다 | 지우거나 브랜치로 둔다 |
| `crates`, `packages`, `libs`, 루트 `src`(단일 패키지는 제외) | 기술 종류로 묶는다 | `<프로젝트>-<제품>` |
| 경로 안의 이름 반복(`<프로젝트>-server/<프로젝트>-core`) | 겹친다 | `<프로젝트>-server/core` |
| 대문자, 공백, 밑줄 | 표기가 섞인다 | **repo-docs** 스킬의 파일과 폴더 이름 절을 따른다. 공개 저장소는 영어 소문자 kebab-case이고, 언어가 강제하는 표기가 먼저다 |

## 배포 이름

패키지와 crate 이름은 폴더와 별개로 `<프로젝트>-<모듈>`로 쓴다. 언어와 레지스트리의 표기 관례가 먼저다(Python은 `<프로젝트>_<모듈>` 등).

| 폴더 | 패키지와 crate |
|---|---|
| `<프로젝트>-server/core` | `<프로젝트>-core` |
| `<프로젝트>-server/cli` | `<프로젝트>-cli` |

## 이름 바꿀 때

1. `git mv`로 옮겨 이력을 지킨다.
2. 빌드 설정(Cargo.toml, package.json, settings.gradle 등)의 경로를 고친다.
3. README와 문서의 경로를 고친다.
4. 빌드와 테스트가 통과하는지 확인한다.
5. 동작 변경과 섞지 않고 한 커밋으로 남긴다. 예: `refactor(repo): 소스 폴더 이름 변경`.

## 답변

- 정한 구조를 `text` 코드 블록의 트리로 적는다.
- 이름을 바꿨으면 바뀐 경로, 고친 설정 파일, 빌드와 테스트 결과, 커밋을 적는다.

## 구분

- 파일 이름과 문서 이름의 언어 규칙은 **repo-docs** 스킬이 맡는다.
- 커밋 메시지 형식은 **git-commit** 스킬이 맡는다.
