# 자원 · 성능

| 조건 | 필수 행동 | 검사·차단 |
|---|---|---|
| 예산·부하 | 평균/순간 최대·지속·동시 수·입력 분포·결과 크기·느린 소비자 확인 | 일일 건수·사용자 수만으로 용량·성능 충족 판정 금지. 과잉 구조 도입 근거 부재와 현재 구성의 성능 통과 구별 |
| 계측 범위 | 대기/초기화/처리/외부 호출/전송/전체, 요청/풀/프로세스/복제본/전체 구분 | 설정·예약·실사용·관측 최고 구분. 부분 개선을 전체 개선으로 확대 금지 |
| CPU | 실제 알고리즘·반복·직렬화·압축·복사·경합 경로 프로파일 | 입력 변화에 따른 비용 대조. 언어 탓 확정 전 아래 원인 분리 |
| 메모리 | 보관 값·버퍼·재할당 전후 공존·결과·캐시·관리 정보의 수명·동시 합산 | 요청 예산을 RSS나 RSS 증가분과 동일시 금지. 같은 계측 대상인지 먼저 확인 |
| I/O | 호출 수·묶음 크기·순차/임의 접근·왕복·재전송·bytes | 대상·전체 지연·완전성 대조 |
| 캐시 | 정본·키·범위·갱신/무효화·허용 오래됨·퇴출·민감 데이터 | 적중률 외 전체 지연·메모리·갱신·재시작·폭주 대조 |
| 동시 처리·stream | 직렬 구간·외부 한도·작업 수·생산/소비 속도·버퍼·취소·역압 | 처리량·긴 지연·실패율·누적 메모리·순서·완전성 대조 |

- 상한 초과 시 대기/거절/분할/외부 저장의 비용·업무 결과 선택. 조용한 잘림·부분 성공·무제한 재시도 금지
- 사용자 목적 밖 대규모 목표·안전 비율 강제 금지
- 캐시 도입은 반복 비용과 최신성 요구 확인 후 선택. 캐시 없음도 복제/snapshot/동시 갱신 때문에 최신성 미보장
- TTL은 항목 수명. 원본 대비 지연 보장은 채운 값의 시점·갱신·재삽입 경로까지 대조 후 판정
- 언어/컴파일러 옵션/런타임·할당기/자료 배치·알고리즘/OS·장치/계측 원인 분리. 같은 언어의 대안 확인 전 재작성 금지

## 측정 통과

1. 질문·예측·반증·고정 조건·반복·중단 기준 확정
2. 같은 의미·결과·내구성·자원·초기 상태의 기준 실행 확보. 차이가 있으면 비교 범위 제한
3. 변경한 비용 원인과 결과 대조. 여러 변경의 총효과를 개별 기여율로 창작 금지
4. 정확성·복구 보존과 병목 이동 확인. 다음 최적화를 시작할 관측 조건 제시

- 0/빈 지표는 양성 대조·필드·단위·집계·스키마부터 확인. 샘플링 최고를 절대 최고로 확정 금지
- CPU cache/DB buffer/OS page cache 구분. 재시작=전체 cold 상태 추정 금지
- 예상 밖 차이는 반복 원자료·실행 경로·동시 작업 조사. 근거 없이 잡음 처리 금지
- bytes/문자/토큰/요금, 누적/현재/최대, 직렬화/전송/저장 크기 구분. 비용 절감은 해당 과금 조건에서 별도 판정
