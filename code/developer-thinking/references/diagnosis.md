# G3 진단 · G4 완료 검사

## 실패 처리

| 순서 | 필수 실행 | 다음 단계 조건 |
|---|---|---|
| E1 피해 제한 | 현재 영향·진행 작업 확인, 허용 범위 확산 제한, 원본·미전송·근거 보존 | 복구 행동의 권한·효과 확인 |
| E2 현상 고정 | 버전·설정·입력·최근 변경·실행 경로, 기대/실제 결과 대조 | 실패와 결과 미확인 구분 |
| E3 원인 분리 | 원인 후보→배제할 관측→작고 정보가 큰 확인 실행 | 직접 원인 근거와 가설 구분 |
| E4 수정 | 깨진 가정·불변식·현재 계약 대조, 해당 원인의 국소 수정 | 새 요구·구조 선택이면 G0/G1 복귀 |
| E5 재검사 | 원실패·인접 경계·기존 정상·실패 후 다음 요청·복구 데이터 대조 | 의미·보존 조건 충족 |

- 새 근거 없는 동일 재시도 중단, 입력·권한·도구·환경·전제 재확인. 임의 횟수 뒤 해결 선언 금지
- timeout만으로 교착·효과 실패 확정 금지. 불확실한 외부 효과 재실행·무관한 변경 일괄 복귀 금지
- 긴급 복구와 장기 개선 분리. 현재 동작에서 당시 설계 의도·발견 주체 창작 금지

## 완료 차단 검사

각 요구에 `요구 ID → 구현 위치 → 독립 기대 결과 → 실행 입력·명령·환경·관측 → 통과/실패/미검증` 연결. 기존 검사·기록 재사용, 별도 보고서 생성 불필요.

| ID | 차단 조건 | 수정 위치 |
|---|---|---|
| V1 요구 누락 | 요구·보존 조건에 구현 또는 해당 실제 검사 근거 없음 | G2/G3 |
| V2 임의 추가 | 변경·거절 조건·기능·운영 의무에 합의 또는 위임 근거 없음 | G0/G1. 이미 만든 구현으로 선택 정당화 금지 |
| V3 자기 비교 | 구현값·같은 계산식·동일 모델 답변을 기대값으로 복제 | 요구의 예·공식 계약·신뢰할 참조·직접 계산으로 기대 결과 대조 |
| V4 잘못된 근거 | 호출/응답/효과/영속화/재시작 혼용, 파일·형식·검사 개수로 효과 판정 | 주장에 필요한 실제 경로 확인 |
| V5 범위 확대 | 모의/합성/일부 입력의 성공을 실제 연동·운영·전체 보장으로 표현 | 확인한 조건으로 주장 제한, 필요한 실행 추가 |
| V6 낡은 검사 | 관련 코드·입력·계약·환경 변경 뒤 기존 통과 재사용 | 영향 검사 재실행. 동일 조건의 유효 결과만 재사용 |
| V7 설명 모순 | 본문/표/코드/결론의 단위·주체·시점·예외 불일치, 미확인 계약을 위반/통과로 확정 | 해당 주장·구현 순서 수정 후 전체 재대조 |

- 변경 전 정상 기준 또는 재현 실패 확보. 기대 결과는 구현과 독립된 근거에서 도출; 독립 기준 부재는 미검증
- 빈 결과·0 지표는 입력·필터·기간·권한·읽기·계측의 양성 대조부터 확인. 일부 검색에서 미발견을 전체 부재로 확대 금지
- 분모·표본·버전·환경·미커밋 입력 보존. 누락·미실행을 성공 분모에서 제외 금지
- 새 규칙·수정은 원실패/새 사례/적용 제외/기존 정상 대조. 취향 변화와 결함 구분, 한 사례를 모든 작업의 금지로 일반화 금지
- 모델 재검토도 검증 대상. 합의·확신·해시·요약의 순환 인용을 사실 근거로 사용 금지
- 결과 보고는 해결·근거·남은 미검증·다음 행동. 구현/실사용/배포/복구를 각각 확인한 범위로 판정
