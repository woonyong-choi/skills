# 진단과 증거

| 적용 조건 | 해야 할 판단 | 예외 | 확인 방법 |
|---|---|---|---|
| DT-CAUSE: 장애·버그·병목·예상 밖 결과 | 현상 → 기대 계약 → 직접 원인 → 깨진 가정 → 불변식 → 수정 범위 | 국소 수정으로 계약 충족 시 전면 재설계 제외 | 원인 후보를 가르는 입력·관측·반증 |
| DT-EVIDENCE: 효과·보장·완료 주장 | 관측·추론·가설·결정과 근거 범위 분리 | 실행 불가 시 정적 분석 범위만 보고 | 실제 경로와 상태를 주장별로 대조 |
| DT-REVISE: 교정·판단 변경 | 요청·당시 정보·기존 결과·새 근거·선택 비교 | 선호 변경과 구현 결함을 같은 원인으로 취급 금지 | 원사례·새 사례·적용 제외·기존 정상 보존 |

## 장애에 대응하는 순서

1. 영향·손실 확대·현재 진행 작업 확인. 허용된 범위에서 확산 제한, 원본·미전송 기록·진단 근거 보존
2. 버전·설정·입력·최근 변경·실행 경로와 기대/실제 결과 특정. 실패와 아직 결과를 모르는 상태 분리
3. 가능한 원인과 각 원인을 배제할 관측 설정. 가장 작고 정보가 큰 확인부터 실행
4. 확인한 원인에 해당하는 최소 수정 또는 복구 수행. 불확실한 외부 효과를 무조건 재실행하거나 무관한 변경 일괄 되돌리기 금지
5. 원래 실패·인접 경계·기존 정상·실패 후 다음 요청·복구된 데이터 확인
6. 구조 가정이 깨졌으면 관련 선택만 재검토. 현재 해결과 재발 방지·장기 개선을 별도 완료 조건으로 구분

- 같은 실패를 새 근거 없이 반복하면 명령 재시도 중단, 입력·권한·도구·환경·전제 재확인. 임의 횟수로 무조건 해결 선언 금지
- timeout은 진행 실패의 관측. 원인·교착·장애 복구 성공은 별도 증거 필요
- 동작·당시 의도·발견 주체·현재 해석 구분. 코드에서 당시 동기를 창작하거나 나중에 찾은 대안을 당시 비교로 소급 금지

## 증거의 경계

- 원문·코드·실행·직접 설명으로 추적. 생성한 요약끼리의 순환 인용·해시·이관·형식 통과를 내용 검증으로 대체 금지
- 호출 시도·성공 응답·실제 효과·영속화·재시작 후 상태를 분리. 로그 존재와 로그가 원인을 입증하는지는 별도 판정
- 트랜잭션·백업·암호화·격리 기능의 존재와 현재 설정·실행 경로·장애 조건에서의 보장 구분. 제품 이름만으로 데이터 무손실·보안·복구를 확정 금지
- 빈 결과는 입력·필터·기간·권한·읽기 실패·저장 시점부터 확인. 기대한 대표 입력이 실제 경로를 통과하는지 대조
- 요구를 계산식·쿼리로 옮긴 정확성과 실행기의 계산 정확성 분리. 같은 잘못된 식의 일치로 업무 정답 판정 금지
- 수치의 분모·단위·표본·조건·버전·환경·미커밋 입력 보존. 누락·미실행을 성공 분모에서 조용히 제외 금지
- 모의·합성·오프라인·실제 연동·운영 관측 구분. 테스트 개수·반복 시간·샘플 성공으로 전체 정확성·장기 안정성 보장 금지
- 표본·일부 파일 검색에서 근거 미발견은 해당 범위 미확인. 전체 경험 부재·기능 없음·실패 증거로 확대 금지

## 검증과 교정

- 검사마다 요구 결과·보존 조건·원래 실패와 연결. 구현값을 그대로 기대값으로 읽는 자기 비교·형식만 검사하는 시험으로 행동 개선 판정 금지
- 영향받은 실제 경로·경계·동시성·실패 입력 우선. 조건이 같은 기존 결과 재사용, 입력·환경·계약 변경 시 해당 증거 무효화 후 재검사
- 단순 문장 교정으로 구현·증거·본인 이해를 해결한 것으로 처리 금지. 표현을 줄여도 의미를 결정하는 조건·주체·예외 유지
- 정정은 반증된 주장과 사용처에 적용. 모든 결론 철회 또는 최신 답변의 무조건 채택 금지, 원결과·중요한 판단 변경 근거 보존
- 새 규칙은 적용 대상·조건·의무·예외·검사로 표현. 한 번의 불만을 모든 작업의 영구 금지로 일반화 금지
- 완료 보고는 해결한 결과·근거·남은 실패/미검증·다음 행동 연결. 구현·사용 가능·배포·복구·이해 중 확인한 축만 완료
