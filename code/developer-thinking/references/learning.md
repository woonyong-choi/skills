# 이해와 전이

| 적용 조건 | 해야 할 판단 | 예외 | 확인 방법 |
|---|---|---|---|
| DT-LEARNING: 원리·아키텍처·선택을 이해하려는 요청 | 현재 결정에 필요한 개념과 실제 경로를 짧게 설명하고 조건 변경의 결과 연결 | 사용자의 무응답·질문 부재로 무지 추정 금지. 모든 작업에 시험·강의 강제 금지 | 본인 설명·작은 예측·다른 입력의 확인과 도움의 범위 구분 |

## 설명 순서

1. 이번에 결정할 문제와 잘못 선택했을 때의 실제 결과 설명
2. 실제 입력 하나가 어떤 구성 요소·상태·자원을 지나 결과가 되는지 추적
3. 용어의 원어와 구체적 동작 연결, 흐름에서 필요한 개념만 설명
4. 동시 요청·큰 입력·장애 등 선택을 바꾸는 조건 하나를 바꾸어 대안별 결과 비교
5. 사용자 선택·위임·남은 질문 확인. 필요하면 결과 예측이나 자기 말 설명으로 이해 확인

- 설명 부족이면 표현을 반복하기보다 작은 코드·전후 표·흐름·실제 실행으로 전환. 긴 교과서·용어 나열로 결정 지연 금지
- 예제는 같은 입력·단위·시점·초기 상태를 끝까지 추적해 산술·분기 직접 대조. 기간과 시각의 혼용, 설명 중 바뀐 만료·재시도 조건, 반례가 빠진 보장 문장 수정 후 제시
- 이해 확인은 현재 판단에 필요한 범위. 모든 구현 전에 사용자의 정답 제출을 승인 조건으로 강제 금지
- 사용자가 원리를 모르더라도 필수 구현 작업을 방치하지 않고 선택에 필요한 설명 제공. 학습을 원한 경로를 불필요한 시간으로 삭제 금지
- 간단한 확인에도 막히면 사실·원리·증거·조건 변경 중 어디가 미확인인지 구분. 사실은 자료, 원리는 값 추적, 원인은 실험, 전이는 반례로 확인

## 대화에서 배울 때

- 대화의 요청·당시 응답·사용자 교정·후속 결과를 함께 확인. 키워드 검색·요약만으로 전체 대화 검토·사용자 이해 부족 확정 금지
- 사용자 누락, 실행자의 누락, 취향 변경, 환경 차이, 조사 불가를 구분. 사용자가 여러 번 지적한 내용을 사용자의 능력 부족으로 귀속 금지
- 도구 출력·붙여 넣은 타인 사례·모의 사용자·이전 답변·분기된 대화 사본을 독립적인 사용자 경험으로 집계 금지
- 전체 기록 요청은 접근 가능한 활성·보관 범위와 검색/원문 왕복 검토/첨부 확인을 구분. 접근 실패·삭제·미확인 자료를 읽음 처리 금지
- 개인의 과거 지적은 관련 작업의 점검 우선순위로만 활용. 개인 성향·경력·본인 수행을 추정하거나 비공개 원문을 범용 스킬에 전재 금지

## 수행과 이해

- 도구가 작성한 코드의 성공과 본인의 판단·검토·설명 별도 확인. 제안 채택·거절 이유와 실제로 확인한 경로를 연결
- 개념 정의 암기·그림·문서 생성·문제 개수를 이해 증거로 대체 금지. 새로운 입력에서 달라지는 비용과 유지되는 계약 설명
- 다른 기술에 적용 시 공통 문제·새 계약·작은 확인 구분. 기존 경험을 새 도구의 실무·운영 능력으로 자동 승격 금지
- 학습용 직접 구현·비교와 제품의 납품 범위 분리. 실제 반영하지 않을 실습은 얻은 답과 적용 여부로 종료
- 설명 능력 미확인은 미확인으로 유지. 교정된 답변을 과거 최초 발견·개인 구현·성과로 소급 금지
