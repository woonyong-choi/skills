# 사용자와 인터페이스

| 적용 조건 | 해야 할 판단 | 예외 | 확인 방법 |
|---|---|---|---|
| DT-INTERFACE: UI·API·외부 입력·결과 전달 | 사용자 과업과 API·데이터·상태·복구 연결 | UI 없는 작업은 시각·모션 검사 제외, 외부 입력·계약 검사는 유지 | 실제 사용 크기·입력·권한·실패에서 완료 경로 대조 |

## 사용자 흐름

- 첫 사용·반복 사용·수정·취소·복구의 목표와 완료 신호 확인. 설명용 화면을 실제 제품 흐름으로 판정 금지
- 정상·로딩·빈 결과·오류·부분 결과·권한 없음·저장 중·성공 후 상태 연결. 빈 결과와 읽기 실패 구분
- 서버 정본·편집 중 값·일시적 UI 상태의 소유자 하나씩 지정. 파생값 중복 저장·오래된 응답 덮어쓰기·중복 제출 점검
- 낙관적 표시 시 실제 실패·재시도·충돌·되돌림의 사용자 결과 결정. 성공 표시와 영속화 성공 구분
- 기능 발견·입력 검증·오류 위치·복구 행동·용어와 단위의 의미 확인. 사용자가 개발 내부 구조를 알아야만 완료할 수 있는 흐름 점검

## API와 클라이언트

- 과업 → 사용자 행동 → 요청·권한 → 응답·오류 → 화면 상태 → 검사를 연결. 형식 일치와 업무 질문에 대한 정답 별도 확인
- 입력 검증·소유권·권한·오류 코드·재시도 가능성·페이지/정렬·버전·호환 소비자 확인
- HTTP 성공·호출 성공을 완전한 결과와 업무 완료로 대체 금지. 잘림·누락·전송 중 중단·연결 재개 상태 점검
- 네트워크 단절·재연결·오프라인 수정, 기기·런타임의 저장·권한·백그라운드 수명 제한 중 실제 지원 환경 확인. 개발 환경의 성공을 다른 배포 환경으로 확대 금지
- 공유 컴포넌트·토큰·역할별 변형을 먼저 사용. 새 역할인지 기존 역할의 상태인지 구분한 뒤 추가

## 시각과 동작

- 같은 역할의 표현·상태·모션 규약 일치와 실제 가독성을 별도 확인. 토큰 일치·빌드 성공만으로 품질 통과 금지
- 실제 작은 화면·확대·키보드·초점·대비·밝음/어두움·긴 내용 중 사용 조건 검사. 미확인 환경 명시
- 모션 목적·대상 속성·시간·곡선·중단·연속 입력·느린 로딩·모션 감소 설정 연결. 장식 효과 때문에 상태·초점·행동 차단 금지
- 시각 개선은 기존 의미·실루엣·정보 위계·색 역할의 보존 조건에서 시작. 대표 유형의 전후를 같은 크기·상태로 비교한 뒤 확대
- 통과: 이미지·시안·샘플이 아닌 실제 지원 입력과 처리 경로에서 사용자의 완료·복구 가능 확인. 시안 범위 요청이면 시안으로 명시
