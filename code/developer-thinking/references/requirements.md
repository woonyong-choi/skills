# 스펙 확정

적용: 신규 제품·기능, 규모·보장·비용 변경. 기존 요청·코드·운영 근거에서 추출하고 없는 값은 미확인으로 유지.

| 조건 | 필수 행동 | 통과·차단 |
|---|---|---|
| 모든 요구 | 사용자·입력·성공 결과·실패 결과·보존·제외와 검사 지정 | “좋게/빠르게/안전하게”만 있으면 요구 확정 전 보류 |
| 제약 추가 | 출처(요구/관측/공식 계약/가정)·적용 조건·위반 피해 확인 | 표준 요구/프로젝트 선택/가정 분리. 근거 없는 상한·정책 구현 금지 |
| 크기·사용량 관련 선택 | 평균/순간 최대·지속 시간·동시 수·입력 분포·읽기/쓰기 비중 확인 | 일일 건수로 작은 입력·순차 실행 추정 금지 |
| 성능·자원 보장 | 지연 구간·집계·허용 초과, CPU/메모리/디스크/네트워크/호출 예산의 적용 단위 확정 | 요청 예산과 프로세스/전체 상한 혼용 금지 |
| 데이터 보장 | 성장·보관·허용 손실·최신성·원자성·순서·중복의 정책 특정 | “무손실/최신/한 번”만 있으면 장애·시간 범위 구체화 |
| 운영·비용 | 환경·담당자·가용 시간·중단/복구 시간·월/실행 비용·개발/지원/이전 비용 확인 | 무료 한도=예산, 운영자 미확인=없음 처리 금지 |
| 조건 충돌 | 함께 만족 못 하는 근거와 범위/비용/보장의 조정안 제시 | 사용자 선택 없이 필수 조건 완화 금지 |

## 과잉·누락 설계 검사

1. 구성 요소·제약마다 현재 요구 또는 근거 있는 가까운 요구 연결
2. 생략·기존 기능·더 단순한 구성으로 같은 결과·보존·보안·복구 충족 여부 비교
3. 추가 코드·자원·배포 단위·장애 지점·운영·이전 비용과 얻는 효과 대조
4. 효과 근거가 없으면 도입 보류 후보. 다시 필요해지는 관측 조건 제시

- 기술 이름만으로 과잉 판정 금지. 작은 서비스도 중복 효과·권한 우회·데이터 손실 점검 필수
- 단일 사용자도 여러 탭·자동 저장·재전송 경로 확인. 재고 음수·부분 성공·오래된 값 허용은 업무 선택, 권장안을 필수 조건으로 승격 금지
- 수치마다 단위·대상·기간·환경·출처 표시. 관련 없는 축은 제외 이유와 생략, 모든 칸의 숫자 채우기 금지
- 미래 성장만을 근거로 미사용 계층·플러그인·분산 구조 추가 금지. 현재 요구를 만족하는 작은 구조와 변경 경계 우선
