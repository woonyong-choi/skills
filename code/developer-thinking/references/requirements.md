# 목적과 스펙

| 적용 조건 | 해야 할 판단 | 예외 | 확인 방법 |
|---|---|---|---|
| DT-PURPOSE: 작업 시작·목적 변경 | 사용자·업무 문제, 학습 질문, 사업 가설 구분. 누가 어떤 판단·처리를 할 수 있게 되는지 특정 | 학습을 위한 직접 구현은 납품 효율만으로 제외 금지 | 기대 결과와 입력·현재 불편·직접 근거 대조 |
| DT-SCOPE: 기능·규모·환경·보장 선택 | 아래 스펙에서 결정을 바꾸는 조건 확정, 미확인 전제 분리 | 오타 수정 등 영향이 고정된 작업은 해당 계약만 대조 | 완료·보존·제외 범위와 관측 방법 연결 |

## 요구의 근거

- 요청·현재 코드·운영 자료에서 먼저 추출, 사용자에게 이미 있는 정보 재작성 요구 금지
- 설명 순서: 사용자 → 처리할 객체 → 정상·실패 시 상태 변화 → 깨지면 안 되는 규칙 → 확인할 입력
- 업무 수혜·학습 결과·판매 가능성은 별도 판정. 경쟁사 인기·기술 구현·합성 시연을 고객의 선택·반복 사용·지불 근거로 대체 금지
- 기존 기능 사용·구현 생략·범위 축소를 후보로 포함. 학습의 비교 구현과 납품 기능은 따로 범위 지정

## 스펙의 최소 단위

| 축 | 필요한 정보 | 누락 시 행동 |
|---|---|---|
| 사용자·완료 | 누가, 어떤 입력, 어떤 결과, 허용 실패·보존 데이터 | 입력 하나의 전후 상태로 구체화 |
| 부하 | 평균·순간 최대·최대 지속 시간, 동시 실행 수, 입력 크기·분포, 읽기/쓰기 비중 | 현재 관측·예상·근거 없는 성장 가정을 분리 |
| 지연 | 사용자 대기 또는 백그라운드 마감, 대상 구간·집계 방식·허용 초과 | 임의의 응답 시간 목표 대신 사용 상황 확인 |
| 자원 | CPU·메모리·디스크·네트워크·외부 호출 예산, 요청/프로세스/전체 적용 단위 | 상한 범위와 초과 시 대기·거절·축소의 선택 제시 |
| 데이터 | 크기·증가·보관 기간, 허용 손실, 최신성, 원자성·순서·중복 정책 | 데이터 종류와 실패 영향부터 확인 |
| 운영 | 실행 장소, 담당자, 지원 환경, 중단·복구 시간, 설치·갱신·백업 | 누가 실제 운영할 수 있는지와 필요한 지원 확인 |
| 비용·일정 | 월·실행당 예산, 개발·지원 시간, 의존 작업, 이전 비용 | 가용 시간·현재 구현 없이 완성 시점 약속 금지 |

- 각 수치에 단위·대상·기간·출처와 확정/가정/측정 전 표시. 수치가 불필요한 요구에 가짜 정밀도 추가 금지
- 표준·계약의 요구값과 프로젝트 기본값·검증 가설 구분. 예산·일정·보장이 충돌하면 함께 만족할 수 없는 이유와 범위·비용·보장의 조정안을 설명, 필수 조건을 몰래 완화하는 선택 금지
- 사용량 미확인 상태에서 대규모 또는 소규모 확정 금지. 되돌릴 수 있는 최소 검증안을 제안하고 결과를 바꾸는 규모 선택은 사용자 확인
- 단일 사용자도 여러 탭·자동 저장·외부 재전송이 있으면 동시성 점검. 일일 총량과 순간 최대의 혼동 금지
- 권장 정책을 필수 조건으로 승격 금지. 재고 음수 허용·부분 성공·오래된 값 허용 같은 업무 선택은 현재 계약부터 확인, 미결정이면 선택안으로 표시

## 과잉 설계 판정

1. 제안한 구성 요소마다 해결할 현재 요구 또는 근거 있는 가까운 요구 연결
2. 더 단순한 안이 같은 완료·보존·보안·복구 조건을 충족하는지 대조
3. 추가 코드·배포 단위·장애 지점·자원·운영·이전 비용과 얻는 효과 비교
4. 요구 근거가 없고 단순한 안으로 충분하면 도입 보류 제안. 다시 검토할 관측 조건을 기존 결정에 연결

- 확장 여지는 변경하기 쉬운 경계부터 확보. 사용처 없는 계층·플러그인·분산 구조를 미래 대비라는 이유로 자동 추가 금지
- 작은 규모라도 데이터 손실·중복 효과·권한 우회 방지는 생략 금지. 성능 여유와 정확성 보장을 별도 판단
- 큐·캐시·색인·샤딩 등 이름만으로 과잉 판정 금지. 현재 문제·측정·실패 격리 필요성과 연결
- 통과: 현재 스펙을 만족하는 가장 작은 안과, 규모·지연·운영 조건이 바뀌면 재검토할 이유 설명 가능
