# 데이터와 동시성

| 적용 조건 | 해야 할 판단 | 예외 | 확인 방법 |
|---|---|---|---|
| DT-CONTRACT: 저장·경계·스키마 변경 | 단위·허용 범위·완전성·소유권·수명·실패 상태·호환성 합의 | 내부 값도 외부 의미·수명에 영향이 있으면 제외 금지 | 호출자·제공자의 같은 입력과 실패 후 상태 대조 |
| DT-CONCURRENCY: 겹치는 요청·재시도·공유 상태 | 식별자·순서·원자성·충돌·취소·복구의 실제 보장 선택 | 겹칠 경로가 없는 근거가 있을 때만 해당 조건 제외 | 순차·동시·응답 소실·중단 후 재개를 별도 확인 |

## 데이터 의미

- 스키마·타입·필수/NULL·기본값·정밀도·시간대·인코딩·길이 단위·직렬화 범위 확인. 문자 수·byte 수·저장 공간 혼용 금지
- 정본과 검색 색인·캐시·읽기 모델의 소유자 구분. 삭제·갱신 전파·재생성·최신성 조건 연결
- 데이터량·관계·접근 패턴·갱신·내구성·운영 조건으로 DB 후보 비교. 단순 저장 가능 여부만으로 제품 선택 금지
- 입력의 전체 유효성과 출력·저장 가능성 확인 전 부분 변경 가능성 점검. 실패 시 무변경·부분 성공·보상 중 의도한 계약 선택
- 결과의 길이·완전성·페이지 경계·종료 신호·오류 구분. 빈 결과·잘린 결과를 성공으로 합치기 금지
- 스키마 이전은 기존 데이터·배포 순서·신구 소비자 호환·되돌릴 수 없는 변환 확인. 백업 존재와 실제 복원 성공 별도 확인

## 중복과 순서

- 같은 이벤트 재전송과 의미가 같은 별도 요청 구분. 내용 해시만으로 정상 반복 요청 삭제 금지
- 중복 정책 후보: 매번 실행 / 동일 요청의 기존 결과 반환 / 중복 거절 / 대상 상태 갱신. 실제 업무 의미에 맞는 후보와 비용 설명 후 결정
- 식별자 생성 주체·범위·유효 기간·같은 키의 다른 내용·진행 중 중복·실패 후 재시도 정의
- 중복 확인과 효과 반영 사이의 경쟁 확인. 처리 기록과 효과의 원자성 경계, 외부 효과와 내부 기록 사이의 불확실 상태 명시
- 같은 ID의 실행권·내용 일치를 확인하기 전 공유 파일·외부 효과 변경 금지. 요청별 격리된 준비와 최종 반영 구분, 두 요청의 교차 실행으로 효과가 중복·덮어쓰기되지 않는 순서 확인
- 순서 범위는 전체·대상별·순서 무관 중 선택. 오래된 응답·버전 역전·시계 차이·누락 이벤트 처리 확인
- 한 번 호출과 한 번 효과를 구분. DB 제약·큐 전달 보장만으로 외부 효과까지 정확히 한 번이라고 주장 금지

## 공유 상태와 실패

| 경로 | 결정할 것 | 검사할 조건 |
|---|---|---|
| 읽기 뒤 갱신 | 충돌 검출·재시도·덮어쓰기 정책 | 두 요청이 같은 이전 값을 읽는 순서 |
| 잠금·트랜잭션 | 대상·보유 범위·획득 순서·해제 책임 | 대기·취소·오류·잠금 중 외부 I/O |
| 비동기 작업 | 상태 소유자·작업 수명·완료 전달 | 응답 역전·연속 입력·화면 이탈 |
| 재시도 | 안전한 효과·오류 분류·상한·지연·중단 | 성공 응답 소실·반복 실패·중복 효과 |
| 작업 큐 | 용량·동시 실행·밀림·소비 속도·재처리 | 과부하·느린 소비자·불량 항목·종료 |
| 다중 파일·외부 시스템 | 원자성 경계·보상·대조 방법 | 효과 반영 후 기록 전 중단 |

- timeout 관측만으로 교착 확정 금지. 잠금 소유자·대기 관계·진행 조건 확인
- 프로세스 내 보호를 다른 프로세스·다른 기기의 동시성 보장으로 확대 금지
- 작은 서비스의 정확성 문제와 대규모 처리량 문제 분리. 큐 도입은 처리량뿐 아니라 지연 허용·실패 격리·영속 대기 요구로 판단
- 예시: 결제 요청의 응답이 끊기면 재요청부터 하지 않고 실제 효과·요청 식별자·조회 가능성을 먼저 확인. 확인 불가 상태를 실패로 단정해 재실행 금지
