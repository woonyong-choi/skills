# G1 선택 · G2 아키텍처

| ID·조건 | 필수 행동 | 통과·차단 |
|---|---|---|
| D1 복수 기술·구조·정책 | 같은 입력·보장·환경·기간에서 실제 가능한 안 비교 | 필수 위반은 근거로 제외. 인기·가중 점수로 상쇄 금지 |
| D2 추천 | 충족 조건·이익·손해·개발/운영/이전 비용·추천 변경 조건 설명 | 보편적 최적 주장 금지. 동등하면 동등함과 실제 선호 명시 |
| D3 사실 미확인 | 코드·공식 계약·작은 실행으로 확인 | 사실을 취향 선택으로 전가, 미확인 후보를 불가능으로 제외 금지 |
| D4 제품 동작·보존·권한·비용·운영 차이 | 기존 결정 또는 사용자 선택·명시적 위임 범위 확인 | 추천만 하고 구현 시작 금지. 결정된 독립 범위는 계속 |
| D5 구조·경계 변경 | 아래 실제 입력 경로와 책임·실패 상태 작성 | 정본·상태 소유자 중복, 호출자/제공자 의미 불일치면 G2 대기 |
| D6 새 제약·실패 | 깨진 전제·영향 요구·대안·재검사 연결 | 전면 재설계 자동 시작 금지. 국소 수정으로 계약 충족 가능성 우선 |

## 비교의 정확성

- 구현 생략·기존 방식·표준 기능·관리형 구성·직접 구현 중 유효 후보만 제시. 안 개수 채우기 금지
- 제품/배치/기능 분리. 로컬/원격과 내장/별도 프로세스는 다른 축. 로컬 서버는 인터넷 없이 실행 가능, 원격 서버도 로컬 우선 구조의 일부로 사용 가능
- 실제 서비스 조합·요금제·책임끼리 비교. 한 공급자의 관리형 구성만 빼는 비대칭 금지
- 변화 가능한 기능·가격·제약·라이선스는 공식 버전·확인일 조회. 자료 조회와 실제 호환·복구 성공 별도 판정
- 성능·호환성이 선택을 바꾸면 제품 구현 전에 대표 입력의 최소 실행. 입력 개수만으로 크기·동시성 추정, 미요청 기능을 후보 선정 근거로 추가 금지
- 기존 결정의 확인 가능한 범위만 재사용. “로컬 DB”를 특정 제품 결정으로, 구현 위임을 데이터 보존 변경 위임으로 확대 금지

## 사용자와 합의할 경로

```text
입력 값 → 검증·권한 → 처리 → 정본 저장·외부 효과 → 응답·화면
각 경계: 실행 주체 / 입출력·단위 / 상태 소유자 / 실패 후 상태
같은 입력의 재전송·지연·취소·재시작 중 관련 조건 → 대안별 결과 차이
```

- 용어는 위 경로의 동작으로 설명. 추상 상자 나열 금지. 이해가 불명확하면 작은 코드·상태 표로 전환
- 같은 값·단위·시점을 유지하여 예제 계산·분기 대조. 사용자가 제약을 잘못 이해한 반응이면 핵심 차이 교정 후 선택 연결
- 사용자 설명·예측과 모델이 대신 작성한 답변 구분. 무응답을 무지로 추정하거나 모든 작업에 이해 시험 강제 금지
- 선택 근거는 선택·위임의 주체/범위와 보류 항목만 기존 기록에 유지. 긴 설계 문서 생성 불필요

## 구현 경계

- 책임은 변경 이유·계약·의존 방향으로 분리. 표현/업무 계산/데이터 접근과 정본/파생 화면/캐시 구별
- 새 계층은 실제 책임·변경·시험 경계가 있을 때만 도입 후보. 특정 패턴·프레임워크 강제 금지
- 교체는 읽기/쓰기 소비자·기존 데이터·혼합 버전·배포 순서·역변환 확인. 코드 롤백=데이터 복구 추정 금지
- 기존 선택 이유가 없으면 현재 해석으로 표시. 언어·제품 이름을 원인으로 단정하거나 나중의 비교를 과거 결정으로 소급 금지
