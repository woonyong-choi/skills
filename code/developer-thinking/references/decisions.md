# 선택과 아키텍처

| 적용 조건 | 해야 할 판단 | 예외 | 확인 방법 |
|---|---|---|---|
| DT-CHOICE: 복수 해결책·도구·기술 교체 | 목적에서 기준 도출 → 필수 조건으로 제외 → 남은 안의 비용·보장 비교 → 추천과 사용자 선택 | 동등하고 위임된 세부 구현은 이유를 밝히고 진행 | 왜 선택했는지·무엇을 포기했는지·언제 바꿀지 설명 |
| DT-ARCH: 책임·의존·실행 흐름 변화 | 요청 하나의 데이터·제어·상태·실패 경로와 소유자 대조 | 작은 수정은 영향받는 경계만 설명 | 실제 값·실패 하나를 끝까지 추적, 끊긴 책임·중복 정본 식별 |

## 대안 비교

- 도구 이름보다 요구 동작·제약 먼저 확인. 모호한 제품명은 정체 확인 전 지원 기능 추정 금지
- 제품·배치·기능을 분리. 로컬/원격, 내장/별도 프로세스, 온라인 전용/로컬 우선 동기화를 같은 축으로 취급 금지. 한 구성의 제약을 제품군 전체의 불가능으로 확대 금지
- 예: 같은 기기의 서버는 인터넷 없이 동작 가능, 원격 서버가 있어도 로컬 저장·동기화 구조는 오프라인 지원 가능. 현재 요구에서 서버 미도입 추천과 서버 자체의 오프라인 불가능 주장은 별개
- 필수 조건, 우선할 비교 조건, 선호, 미확인을 구분. 필수 위반 후보는 제외 이유 제시, 점수 합산으로 필수 위반 상쇄 금지
- 유효한 복수 대안은 같은 입력·보장·환경·기간으로 비교. 기존 방식 유지·표준 기능·관리형 서비스·직접 구현 중 실제 가능한 안만 선정, 개수 채우기 금지
- 비용: 개발·설치·운영·장애 대응·보안·성능·사용량 과금·데이터 이전·의존 종료 비용. 현재 중요하지 않은 차이는 그 이유와 함께 축소
- 변화 가능한 가격·지원·제약·라이선스는 공식 자료의 버전·확인일 조회. 벤더 설명·가설·직접 관측 구분, 자료 확인을 실제 호환·복구 검증으로 대체 금지
- 호환성·성능이 결정을 바꾸면 대표 입력의 최소 실행으로 확인. 전체 제품을 구현한 뒤 선택을 소급 정당화하는 방식 금지
- 요구하지 않은 편집·중복 삭제·이력·검색을 추천 근거로 추가 금지. 제안 기능은 선택적 가설로 구분하고 실제 과업 확인 후 비용 비교
- 입력 수만으로 각 입력이 메모리에 들어간다거나 순차 처리라고 가정 금지. 결정에 필요한 미확인 크기·겹침은 확인 전까지 미확인 유지
- 추천은 현재 조건과 우선 기준에 종속. 실질적 차이가 없으면 동등성·확인 범위를 밝히고 기존 환경·경험·유지 비용·학습 선호로 선택
- 선택 상태는 추천/선택/위임/미결정으로 구분. 사용자 선택 또는 명시적 위임 범위 밖의 중요한 결정을 코드로 기정사실화 금지
- 기존 결정을 확인할 수 없으면 그 결정으로 위임 범위를 확장 금지. 저장 기술·동기화·보존 정책을 단순 구현 세부값으로 낮추지 않고 미확인 부분만 조사·선택 연결

```text
안: 기존 방식 유지 / 후보 A / 후보 B
필수 충족: 조건별 충족·위반·미확인과 근거
비교: 현재 작업의 이익 / 부담·실패 조건 / 이전·철수 비용
추천: 우선 기준과 이유, 추천이 뒤집히는 조건
결정: 선택자·선택 범위·보류한 항목
```

## 흐름으로 이해하기

1. 실제 입력 하나와 사용자가 볼 완료·실패 결과 고정
2. 입력 → 검증·권한 → 처리 → 저장·외부 효과 → 응답의 현재 경로 설명
3. 각 경계의 실행 주체·상태 소유자·입출력·동기/비동기·실패 뒤 상태 확인
4. 중복·지연·취소·재시작 중 관련 조건 하나를 넣고 같은 경로 다시 추적
5. 대안마다 달라지는 지점·비용·보장을 흐름에 표시하고 사용자 판단 연결

- 추상 상자 이름만 나열 금지. 데이터 흐름과 제어 흐름, 저장된 사실과 파생 화면·캐시 구분
- 함수·파일 개수보다 바뀌는 이유·계약·의존 방향으로 경계 판정. 화면 표현·업무 규칙·데이터 접근의 책임 혼합과 같은 상태의 복수 소유 확인
- 새 계층은 현재 책임·변경·시험 경계가 필요한 경우만 후보. 기존 구조를 이해하기 전 특정 패턴·프레임워크·마이크로서비스 강제 금지
- 도식·코드가 이해를 돕는 경우 최소 예 사용. 그림에 없는 실패 경로를 구현돼 있다고 추정 금지
- 이해 확인 요청 또는 판단에 필요한 설명 부족 시 [이해와 전이](learning.md) 필수 조회. 사용자의 선택과 해당 선택의 결과 예측을 분리

## 구조 변경의 경계

- 직접 결함 수정과 구조 개선을 구분. 국소 수정으로 계약 충족 시 재설계하지 않는 이유 명시
- 기존 선택 이유가 없으면 현재 구조의 장단점 해석으로 표시. 언어·도구 이름으로 설계 실패의 원인 확정 금지
- 교체 시 읽는 쪽·쓰는 쪽·이전 데이터·혼합 버전·롤백 가능성 확인. 데이터 변환 뒤 코드만 되돌려 복구된다고 가정 금지
- 운영 사고 중 근거 없는 전면 교체 금지. 피해 제한·복구와 후속 구조 개선을 별도 단계로 처리
