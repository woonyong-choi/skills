# Developer Thinking

- 우선순위: 사용자 지시 → 저장소 규칙 → 이 스킬. 범위 밖은 명시한 소유 스킬 적용
- 범위: 개발 실행 순서·규칙 선택·재개 위치. 개인 업무·커리어 제외

## 실행 순서

1. 연결: 상위 지침·필수 링크 → git-issue 과업 연결·복구 → 요청·작업본 대조. 변경 전 경로 등록·작업 경계 기록도 git-issue 적용
2. 조회: 훅의 `--pending`으로 누락 보완 → 미조회 조건만 아래 분류 → 필수 참조 → 제안·변경. 대상 본문 선행 로드 금지
3. 결정·구현: 조회한 설계 선택 → 승인 범위 구현. 문서·Git·리팩터링은 해당 소유 스킬 추가
4. 검증: 출력의 검증 절로 요구·보존·근거 대조
5. 종료: git-issue의 최종 checkpoint·상태·완료 규칙 적용

- 산출물·쓰기 범위 준수. 읽기 전용은 stdout, 임시 파일 금지. 유효 결정·결과 재사용
- 실패·새 사실은 영향 단계로 복귀. 하위 스킬에서 루트 전체 재호출 금지

## 조회

`python3 <이 스킬 폴더>/scripts/read_rules.py <분류...>`

- Python 3.9+·표준 라이브러리. 선행 원문·검증 포함, 중복 제외. stdout 원문·stderr 진단, 성공 0·읽기 실패 1·입력 오류 2. 쓰기·네트워크 없음
- `spec`: 기능·규모·보장
- `choice`: 기술·구조·정책의 미확정 대안 제시 전 필수
- `infrastructure`: 구매·구축·호스팅
- `implement`: 구현 준비·변경·검토. 출력의 조건별 ID를 code-style 명령의 `--text --language <언어...>`로 조회, 후속 구현으로 연기 금지
- `failure`: 결함·장애 원인과 복구
- `data`: 데이터·공유 상태·비동기
- `resources`: 성능·자원·캐시·큐
- `interface`: 화면 상태·표현. 시각 변경은 design-tokens, CSS 변경은 code-style-css 추가
- `external`: API·외부 입력·권한
- `operations`: 신뢰 경계·외부 의존·배포·복구
- `review`: 주장·결과 대조
- `product`: 신규 제품·전체 설계 영역

- 같은 문맥·원문·단계의 완독 절·포함 참조 재사용, 파일·기반 스킬 재조회 금지
- 범위 확대·잘림은 미조회 부분만 확인. 원문 변경·압축·재개는 현재 단계 필수 원문 재조회. 검색 발췌·제목·해시·읽음 표시로 대체 금지
- 조회 실패는 해당 소유 원문(repo-docs-design: 설계, code-style: 구현·기술·검증) 직접 확인. 접근 실패는 영향 작업 보류
- 목록 밖 도메인·안전 계약은 공식 기준 확인. 읽음·형식 통과≠이해·실제 준수
