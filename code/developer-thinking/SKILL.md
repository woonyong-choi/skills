# Developer Thinking

- 우선순위: 해당 주제의 사용자 지시 → 저장소 규칙 → 이 스킬. 중복 규칙은 머리에 연결한 정본 스킬 적용
- 범위: IT 제품 개발의 요구·제약·선택·구현·검증 통과 기준. 개인 업무·커리어·대화 분석 제외
- 필요할 때만 읽기: 코드 작성·검사 → code-style; 시각 변경 → design-tokens; 이슈·기록 → git-issue; 요청된 문서 작성 → repo-docs

## 필수 실행

- 모든 개발 요청의 첫 조사·재개 전에 본문 적용. 명시 호출 불필요. 오타 수정도 요구·보존·결과 대조 필수
- 기존 요청·소스·결정·검사 근거 재사용. 아래 미통과 단계에 의존하는 변경·완료 선언 금지, 조사·독립 승인 작업 계속
- 분석 요청은 분석 범위 준수. 구현 요청은 설계 설명으로 종료 금지. 기록은 기존 이슈·작업 기록에 병합, 별도 문서 생성 금지

| 단계 | 실행 | 통과 조건·실패 경로 |
|---|---|---|
| G0 요구 | 결과·보존·제외 추출. 요구별 입력→기대 결과→검사 지정 | 관측 기준과 제약 출처 존재. 없으면 요구 구체화, 변경 보류 |
| G1 선택 | 실제 가능한 대안을 같은 스펙으로 비교. 이익·손해·추천 변경 조건 설명 | 결과를 바꾸는 결정의 기존 선택/사용자 선택/위임 근거 존재. 없으면 관련 구현 대기 |
| G2 경계 | 실제 입력의 정상·실패 경로, 상태 소유자·입출력·실패 후 상태·수정 범위 지정 | 요구→상태/API/데이터→컴포넌트→검사 연결. 새 결정이면 G1 |
| G3 구현 | 변경 전 기준 결과/재현 실패 확보. 관측 가능한 결과 단위로 변경·같은 입력 대조 | 요구·보존·실패 검사 일치. 실패면 원인 수정·재검사, 새 제약이면 G0/G1 |
| G4 완료 | 요구별 실제 결과와 전체 diff 대조. 누락·요청 밖 기능/제약 검사 | 필수 검사 통과, 미결정 구현·근거 없는 보장 없음. 실패·미검증은 영향 단계 복귀 |

- 분석 완료: 비교·결정 근거와 미확인 범위 대조. 결론에 필요한 검사는 요청 범위에서 수행; 요청하지 않은 납품 구현·배포 검사는 제외
- 환경·권한 차단: 현재 단계 대기·재개 조건 기록. 가능한 독립 작업 수행 후 미완료 범위 보고. 같은 차단의 무한 재시도 금지

## 결정 차단

- 결론 전 대조: 다음 행동을 바꾸는 항목만 `요청 구절/소스/관측 → 아직 구별되지 않은 해석·대안 → 구분할 확인 → 지금 가능한 행동`으로 짧게 제시. 판별 근거가 없으면 조건부 추천·미확인 유지
- 미결정 중 독립 구현: 남은 대안 각각에서 그 변경이 유효한지 대조. 특정 대안·미확인 처리 방식에 의존하면 공통 작업으로 간주 금지
- 제약마다 `출처=요구/관측/공식 계약/가정`, 수치마다 단위·대상·기간·환경 확인. 가정→필수 조건 승격 금지
- 제약의 필요성: `제거하면 현재 스펙의 어떤 실패가 생기는가?`. 근거 없으면 필수에서 제외한 후보로 표시; 작은 사용량을 정확성·보안 생략 근거로 사용 금지
- 결과·보존·권한·비용·운영 의무를 바꾸는 미결정은 설명 후 선택/위임 확보. 동등하고 가역적인 세부 구현은 승인 범위에서 이유와 함께 진행
- 사실은 코드·공식 계약·최소 실행으로 조사. 취향 선택으로 전가 금지
- 새 제약: `근거→깨지는 결정/요구→영향 코드/검사→대안`. 해당 범위만 재합의, 임의 완화·강화 금지
- 추천≠선택≠구현≠검증≠이해. 침묵·“알겠어”로 새 선택·이해 완료 추정 금지

## 필수 조회 조건

제안·분석·설계·수정·검토 모두 아래 표 적용. 해당 조건의 참조를 합집합으로 선택해 그 주장 제출·구현 전에 전부 필수 조회. G번호는 순서이며 분석·제안의 조회 생략 근거 아님. 아직 다루지 않는 경계만 착수 때까지 조회 보류.

| 시점·조건 | 조회 |
|---|---|
| 신규 제품·기능, 규모·보장·비용의 정의·적정성 판단 | [스펙](references/requirements.md) |
| 미결정·대안 추천/비교/선택, 구조·책임 검토 | [선택·구조](references/decisions.md) |
| 저장·공유 상태·비동기·재시도·스키마 | [데이터·동시성](references/data-and-concurrency.md) |
| 성능·자원·상한·병목·큰 입력·캐시·대기열 | [자원](references/resources.md) |
| UI·API·외부 입력·클라이언트 상태 | [인터페이스](references/interfaces.md) |
| 신뢰 경계의 파일/URL/쿼리/명령·권한·외부 의존·인프라·배포·복구 | [보안·운영](references/operations.md) |
| 코드/설계/설명 검토·원인 조사·정확성/완료 주장 | [진단·검증](references/diagnosis.md) |

- 새 경계는 행 재계산. 미확인→해당 없음 축소 금지. 표 밖 도메인·안전 계약은 공식 기준 추가 조회
- 단순 확정 수정: G1 기존 결정, G2 변경 경계만. 규모·인프라 질문·전체 설계 재수행 금지
- 전체 참조 선독 금지. 같은 문맥의 변경 없는 원문 재사용. 압축 후 현재 단계 필수 규칙 재조회, 읽음 표시는 대체 불가
- 압축 시 조건·예외·검사 보존. 바이트 감소와 실제 토큰·비용 절감 구분

## 출력과 검증

- 선택 제안: `결정/이유 → 확인된 조건·미확인 → 대안별 결과·비용·실패 → 추천·바뀌는 조건 → 제안/선택/위임 상태·구현 범위`
- 실제 값 하나의 정상 경로와 조건 하나 변경 시 차이 설명. 오해한 반응은 교정 후 선택 연결. 필요하면 최소 코드·도식, 모든 작업의 시험·강의 강제 금지
- 제출 직전 초안 대조: 결론 전 대조의 근거·보류 범위와 전체 설명 일치 확인. `같은 입력/계약 결과/실제 처리/조건 하나 변경`을 분리해 계산 도구·최소 실행과 대조; 불가하면 전개식과 미검증 범위 표시
- 수치·배치·도구 선택은 조사 후 근거 있는 안 제시. 한 후보의 권장값/배치를 필수로 승격하거나 임의 숫자 선택을 사용자에게 전가 금지
- 다음 행동을 바꾸는 결정부터 질문. 전체 점검표 전가·기존 결정 재질문 금지
- 단계 경계: `G번호: 통과/대기 — 결과·근거 — 다음 행동`. 종료: `요구→구현 위치→실제 검사`와 보존·미검증
- 실행 지침의 필수/차단과 호스트의 강제 기능 구분. Markdown만으로 자동 로드·도구 차단 보장 금지
- 타입·스키마·린트·빌드·동작 검사는 프로젝트 도구로 실행. 미실행 검사·미설치 훅을 적용으로 표시 금지
- 의미 정확성은 요청·실제 코드·독립 기대 결과로 확인. 자기 검토·다른 모델의 동의·검사 개수로 대체 금지
