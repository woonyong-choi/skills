# Developer Thinking

- 우선순위: 해당 주제의 사용자 지시 → 저장소 규칙 → 이 스킬. 중복 규칙은 머리에 연결한 정본 스킬 적용
- 범위: 제품 개발의 제약·대안·선택·구현·검증. 개인 업무·커리어 제외
- 필요할 때만 읽기: 코드 → code-style; 시각 변경 → design-tokens; 이슈·기록 → git-issue; 문서 → repo-docs

## 실행

개발 착수·재개 시 아래 순서 필수. 기존 요구·선택·유효한 검사는 재사용. 분석 요청은 분석까지만, 구현 요청은 검사까지.

1. 요구 추출: 입력→성공·실패, 보존·제외, 완료 검사. 없는 조건은 미확인
2. 제약 확인: 요청·소스·관측·공식 계약으로 근거 확인. 가정 구분. 제거 시 현재 스펙의 실패가 없으면 필수 제약에서 제외
3. 대안 비교: 같은 스펙에서 결과·비용·운영·실패·전환 비용 비교. 구별할 근거가 없으면 확인 방법과 조건부 추천 제시
4. 선택 연결: 실제 값의 정상·실패 경로로 차이 설명. 결과·보존·권한·비용·운영을 바꾸면 선택/위임 확인. 동등·가역적인 세부는 이유와 함께 진행
5. 구현: 선택된 범위에서 변경 전 결과 확보→작은 변경→같은 입력 대조. 상태 소유자·입출력·실패 후 상태와 영향 검사 연결
6. 완료 대조: 요구·보존·전체 diff·독립 기대 결과와 실제 검사 대조. 누락·임의 추가·실패 수정 후 재검사. 확인한 범위만 완료

- 미결정에 종속된 구현 금지. 남은 모든 대안에서 유효한 승인 작업만 계속
- 새 제약은 근거·깨지는 결정·영향·대안 제시 후 해당 범위 재합의. 임의 완화·강화 금지
- 추천≠선택≠구현≠검증≠이해. 침묵으로 선택·이해 추정 금지
- 질문은 다음 행동을 바꾸는 미결정만. 기존 결정 재질문·전체 점검표 전가·단순 수정의 전면 설계 금지

## 조건별 조회

제안·분석·구현·검토에 동일 적용. 해당 항목 전부를 주장·변경 전에 필수 조회. 미확인을 해당 없음으로 처리 금지.

| 대상 | 필수 참조 |
|---|---|
| 새 기능·규모·보장·비용 | [요구](references/requirements.md) |
| 추천·선택·구조·책임 검토 | [선택](references/decisions.md) |
| 저장·공유 상태·비동기·재시도·스키마 | [데이터](references/data-and-concurrency.md) |
| 성능·자원·상한·캐시·큐 | [자원](references/resources.md) |
| UI·API·외부 입력 | [인터페이스](references/interfaces.md) |
| 신뢰 경계·권한·외부 의존·인프라·배포·복구 | [운영](references/operations.md) |
| 검토·원인·정확성·완료 | [검증](references/diagnosis.md) |

- 범위 확대 시 재선택. 전체 선독·변경 없는 원문 재읽기 금지. 압축 후 현재 작업의 필수 참조 재조회
- 표 밖 도메인·안전 계약은 공식 기준 확인. 작은 사용량으로 정확성·보안 생략 금지

## 보고

- 선택 필요: 근거·미확인 → 대안의 차이 → 추천·바뀌는 조건 → 선택/위임·구현 범위
- 완료: 충족·보존 근거·미검증. 기존 이슈에 변경분 병합, 별도 보고서 생성 금지
- 환경 차단: 재개 조건 기록, 가능한 독립 작업 계속. 같은 실패 무한 재시도 금지
- 문서의 의무와 호스트 강제 구분. 읽음·자기 검토·검사 개수로 효과·자동 적용 보장 금지
