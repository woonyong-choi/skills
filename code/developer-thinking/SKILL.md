# Developer Thinking

- 우선순위: 해당 주제의 사용자 지시 → 저장소 규칙 → 이 스킬. 중복 규칙은 머리에 연결한 정본 스킬 적용
- 범위: 제품 개발의 제약·대안·선택·구현·검증. 개인 업무·커리어 제외
- 필요할 때만 읽기: 코드 → code-style; 시각 변경 → design-tokens; 이슈·기록 → git-issue; 문서 → repo-docs

## 먼저 읽기

착수 전 `python3 <이 스킬 폴더>/scripts/read_rules.py <해당 분류...>` 필수 실행. 본문만으로 제안·분석·구현·검토 금지.

| 요청의 판단·변경 대상 | 분류 | 규칙 |
|---|---|---|
| 신규 제품·전체 설계 | `product` | 아래 전체 |
| 기존 기능의 스펙·규모·보장·예산 | `spec` | [스펙](references/requirements.md) |
| 추천·선택·구조·책임 검토 | `choice` | [선택](references/decisions.md) + 스펙 |
| 저장·공유 상태·비동기·재시도·스키마 | `data` | [데이터](references/data-and-concurrency.md) |
| 성능·자원·상한·캐시·큐 | `resources` | [자원](references/resources.md) + 스펙 |
| 화면·사용자 행동·상태·모션 | `interface` | [인터페이스](references/interfaces.md) |
| API·권한별 요청·외부 입력 | `external` | 인터페이스 + 운영 |
| SaaS·구매/구축·호스팅·인프라·비용 | `infrastructure` | [인프라·비용](references/infrastructure-cost.md) + 선택·스펙·운영 |
| 신뢰 경계·권한·외부 의존·배포·복구 | `operations` | [운영](references/operations.md) |
| 주장·결과 검토 | `review` | [검증](references/diagnosis.md), 항상 포함 |

- Python 3.9 이상·표준 라이브러리. 복수 분류는 합집합. stdout 원문, 입력 오류 2·읽기 실패 1. 쓰기·네트워크 없음
- 실행 불가 시 참조·의존 원문 직접 조회. 누락·실패 시 영향 범위 보류, 미확인을 해당 없음으로 처리 금지
- 유효한 조회 재사용, 범위 확대 시 재선택·압축 후 필수 참조 재조회. 무관한 선독 금지
- 표 밖 도메인·안전 계약은 공식 기준 확인. 규모로 정확성·보안 생략 금지
- 제품·공급자·프레임워크 기본값 금지. 현재 스펙으로 후보 조사·비교, 기존 합의 스택은 해당 범위에서 재사용

## 실행

착수·재개 시 아래 순서 적용. 기존 결정·유효한 검사 재사용. 분석은 분석까지, 구현은 검사까지.

1. 확인: 입력·사용량→성공/실패·보존·제외·예산·검사 추출. 수치는 대상·단위·기간·근거 연결. 확정 요구는 유지, 기존 사실 미조회는 조사, 새 정책 미결정은 비교로 연결. 조사 불가를 새 정책 결정으로 전환 금지
2. 비교·선택: 같은 스펙의 실제 후보를 위임 시에도 비교·제시. 미확인은 확인 방법·조건부 추천. 결과·보존·권한·비용·운영 변경은 선택/위임 확인, 동등·가역적 세부는 이유와 함께 진행
3. 구현: 선택 범위의 변경 전 결과→작은 변경→같은 입력 대조. 상태 소유자·입출력·실패 후 상태·영향 검사 연결
4. 검증: [완료 차단·결과 대조](references/diagnosis.md#완료-차단-검사) 적용. 실패 교정 뒤 영향 재검사, 확인 범위만 완료

- 미결정에 종속된 구현 금지. 남은 모든 대안에서 유효한 승인 작업만 계속
- 제약은 근거·위반 피해 확인, 가정 구분. 지킬 요구 없는 제약의 필수화 금지. 새 제약은 깨지는 결정·영향·대안 제시 후 재합의, 임의 완화·강화 금지
- 추천≠선택≠구현≠검증≠이해. 침묵으로 선택·이해 추정 금지
- 질문은 다음 행동을 바꾸는 미결정만. 기존 결정 재질문·점검표 전가·단순 수정의 전면 설계 금지

## 보고

- 결정에 필요한 요구(원근거)·관측(범위)·제안(대안·전제·대가·변경 조건)·미확인(영향·확인 방법)만 구분. 근거는 같은 문장/행에 연결, 빈 항목·전체 표 강제 금지
- 특정 방식은 명시 계약 또는 다른 방식의 요구 위반 근거가 있어야 의무, 나머지는 제안
- 완료: 충족·보존 근거·미검증을 기존 이슈에 병합. 별도 보고서·조회/검토 과정 나열 금지
- 차단: 재개 조건 기록. 근거 없는 반복 재시도 금지
- 문서 의무≠호스트 강제, 조회≠이해·준수. 읽음·자기 검토·검사 개수로 효과·자동 적용 보장 금지
