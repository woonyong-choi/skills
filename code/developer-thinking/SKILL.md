# Developer Thinking

- 우선순위: 해당 주제의 사용자 지시 → 저장소 규칙 → 이 스킬. 중복 규칙은 머리에 연결한 정본 스킬 적용
- 범위: 문제·규모·보장 명확화, 누락된 결정 발견, 대안과 근거 설명, 사용자 선택·이해, 구조·장애·완료 판단. 모든 작업의 재설계·기술 교체·문서 생성 제외
- 필요할 때만 읽기: 코드 작성·검사 → code-style; 시각 변경 → design-tokens; 지속할 작업 기록 → git-issue; 문서 작성 → repo-docs

## 실행

1. 기존 요청·결정·소스·실행 환경에서 목표·완료·보존·제외 범위 추출. 사용자에게 전체 양식 작성 요구 금지
2. 아래 점검표의 모든 행을 현재 흐름에 대조하여 적용·미확인·해당 없음 분류. 이름이 없는 기술·규모·데이터 의미의 추측 금지
3. 적용·미확인 행의 참조 필수 조회. 선택을 바꿀 불확실성·실패 영향을 먼저 조사하고, 영향 큰 미결정부터 사용자에게 설명
4. 기존 결정 재사용 또는 결정 제안 후 선택 확보. 결정으로 닫힌 범위 안에서 가장 작은 구현·검사 단위 실행
5. 결과·보존·실패 경로를 실제 근거와 대조. 실패 시 원인 조사, 영향받은 결정만 재검토. 실행 가능한 승인 범위는 계속 수행

## 결정과 권한

| 상태 | 행동 |
|---|---|
| 현재 조건에도 유효한 기존 결정 | 근거·적용 범위 확인 후 재사용, 반복 선택 요구 금지 |
| 행동·보장·비용이 같은 되돌릴 수 있는 세부 구현 | 승인·위임 범위에서 짧은 이유와 함께 진행. 숨은 제품 정책·새 운영 의무 추가 금지 |
| 사용자 결과·데이터 보존·권한·구조·유료 도구·운영 책임이 달라지는 복수 대안 | 차이와 추천 근거 설명 후 선택 또는 해당 기준의 명시적 위임 확보. 관련 구현만 대기, 조사·독립 작업 계속 |
| 사실 확인으로 해결할 문제 | 코드·공식 자료·작은 실행으로 확인. 사실의 진위를 취향 선택으로 전가 금지 |
| 근거가 부족한 전제 | 가정·확인 방법·영향 표시. 결과를 바꾸는 가정을 확정값처럼 구현 금지 |

- 사용자의 침묵·단순 이해 표현을 구체적 선택이나 실행 승인으로 해석 금지. 선택 후 같은 승인을 반복 요구하지 않고 선택 범위 실행
- 추천·선택·구현·검증·사용자 이해는 서로 다른 사실. 제안한 기본값·설명한 아키텍처를 사용자 결정·이해 완료로 승격 금지
- 동등한 대안은 억지 순위 금지. 기존 환경·담당자의 경험·유지 비용·학습 목적 중 실제 선호를 밝히고 선택

## 누락 점검과 필요한 읽기

| ID | 점검할 조건 | 적용·미확인 시 필수 참조 |
|---|---|---|
| DT-PURPOSE / DT-SCOPE | 신규 기능·학습·범위 변경, 사용자·업무 수혜·규모·예산·보장의 빈칸 | [목적과 스펙](references/requirements.md) |
| DT-CHOICE / DT-ARCH | DB·라이브러리·서비스·구조 선택, 책임·의존·실행 흐름 변화 | [선택과 아키텍처](references/decisions.md) |
| DT-CONTRACT / DT-CONCURRENCY | 저장·외부 효과·공유 상태·비동기·재시도·동시 접근·스키마 변경 | [데이터와 동시성](references/data-and-concurrency.md) |
| DT-RESOURCE | 반복·큰 입력·불명확한 상한·느린 경로·CPU·메모리·캐시·I/O 비용 | [자원과 성능](references/resources.md) |
| DT-INTERFACE | 화면·API·외부 입력·결과 전달·클라이언트 상태 변화 | [사용자와 인터페이스](references/interfaces.md) |
| DT-OPERATE | 배포·클라우드·운영·비용·권한·개인정보·모델·자동 실행·외부 의존 변경 | [보안과 운영](references/operations.md) |
| DT-CAUSE / DT-EVIDENCE / DT-REVISE | 예상 밖 결과·장애·효과 주장·완료 검토·사용자 교정 | [진단과 증거](references/diagnosis.md) |
| DT-LEARNING | 사용자가 원리·판단 이해를 원함, 조건 변경 설명의 미확인 | [이해와 전이](references/learning.md) |

- 새 기술이 없어도 기존 경로의 숨은 결정 점검. 작은 서비스의 재시도·자동 저장·권한 문제를 대규모 전용 조건으로 제외 금지
- 점검표 밖의 도메인·실행 환경·안전 요구 발견 시 해당 계약·전문 기준 추가 확인. 표에 없다는 이유로 적용 제외 또는 전체 공학 검토 완료 판정 금지
- 작업·구조·실패 조건 변경 시 선택한 행 재계산. 미확인을 해당 없음으로 축소 금지, 제외 근거는 기존 기록에 필요한 만큼만 유지
- 단순 번역·이미 확정한 오타 수정은 새 아키텍처 비교 제외. 실무와 무관한 취업·소개·면접 절차의 자동 적용 금지

## 사용자에게 설명할 것

```text
결정할 것: 빠진 정책 또는 선택 하나
필요한 이유: 현재 흐름의 구체적인 입력·실패와 영향
기준: 반드시 지킬 조건 / 비교할 비용 / 미확인 전제
대안: 실제 가능한 안별 같은 기준의 결과·장점·감수할 비용
추천: 현재 조건에서의 이유 / 포기하는 것 / 추천이 바뀌는 조건
확인: 선택에 필요한 최소 조사·실험 또는 사용자 정보
결정: 선택·위임·미결정 / 허용된 구현과 남은 경계
```

- 한 번에 다음 행동을 바꾸는 결정부터 제시. 관련 결정을 묶고 중요도·의존 순으로 설명, 전체 점검표를 질문 목록으로 전가 금지
- 용어는 실제 입력·상태·비용과 연결. 필요하면 요청 하나의 경로·정상/실패 비교·최소 코드로 설명. 코드 양·도식 개수로 이해 판정 금지
- 일정·사용량·성능·안정성 수치는 단위·환경·근거와 확정/가정/측정 전 구분. 근거 없는 보편 임계값·인기 순위·가중 점수로 선택 금지
- 답변 제출 전 필수 대조: 추천·제외·보장마다 근거가 요청/관측/공식 계약/가정 중 무엇인지 확인. 미확인 크기·동시 실행·기능·운영 요구가 몰래 근거에 추가됐으면 조사 또는 조건부 제안으로 수정
- `불가능`·`필요 없음`·`안전` 같은 단정은 배치·설정·실패 조건이 바뀌어도 성립하는지 반례 확인. 현재 요구에서 미선택과 기술적 불가능, 기능 지원과 실제 보장 구분
- 추천 출력에는 `확인된 조건 / 선택을 바꿀 미확인 / 지금 결정할 범위`를 짧게 명시. 가정은 설명용 값 또는 위임된 임시 선택에 한정. 미확인 입력 크기·동시성·보장으로 내린 단정을 끝의 가정 문구로 면책 금지
- 제출 직전 초안 전체 재대조. 앞서 밝힌 적용 단위·미확인·예외가 뒤의 표·구현 순서·결론에서도 유지되는지 확인. 요약에서 보장 강화, 숫자 범위 교체, 결정 전 효과 반영이 발견되면 해당 문장·순서 수정 후 제출

## 압축과 완료

- 본문과 해당 참조만 조회. 참조별 원문·예외·검사까지 읽고 범위가 넓어질 때만 추가. 같은 문맥에 원문이 있고 변경이 없으면 재조회 생략. 읽은 위치만 기억한 상태·압축 전 읽음 표시로 내용 조회 대체 금지
- 현재 결정은 기존 기록의 목표·제약·가설·결과와 연결. 기준·선택 이유·포기한 비용·미확인·재검토 조건·규칙 ID 보존, 매번 별도 문서·상태표·긴 대화 요약 생성 금지
- 중복 사례는 합치되 대상·단위·주체·시점·보장·반례 차이 보존. 실제 지연·토큰 수·바이트 수는 별도 측정, 짧아졌다는 이유로 품질 향상 판정 금지
- 완료 전 DT-EVIDENCE와 해당 영역의 검사 적용. 구현·실제 사용·배포·복구·본인 이해별 근거 구분, 미검증을 통과로 승계 금지
- 모든 결함의 사전 발견·무오류 보장 금지. 새 반례에서 원인·기준·수정 위치·재검사를 연결하고 승인된 잔여 작업 완수
