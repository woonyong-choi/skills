# Developer Thinking

- 우선순위: 사용자 지시 → 저장소 규칙 → 이 스킬. 범위 밖은 명시한 소유 스킬 적용
- 범위: 개발 실행 순서·규칙 선택·재개 위치. 개인 업무·커리어 제외

## 실행 순서

1. 연결: 상위 지침·필수 링크 → git-issue 과업 연결 → 요청·작업본 대조. 작업 경계 기록은 git-issue 과업 연결과 기록 절의 결정 기록
2. 조회: 훅이 출력한 명령 실행으로 누락 보완 → 조회 절의 미조회 원문 → 제안·변경. 대상 본문 선행 로드 금지
3. 결정·구현: 조회한 설계 선택 → 승인 범위 구현. 문서·Git·리팩터링은 해당 소유 스킬 추가
4. 검증: 출력의 검증 절로 요구·보존·근거 대조
5. 종료: git-issue의 상태·완료 규칙 적용 → 사용자에게 작업 보고(작업 보고 절)

- 산출물·쓰기 범위 준수. 유효 결정·결과 재사용
- 실패·새 사실은 영향 단계로 복귀. 하위 스킬에서 루트 전체 재호출 금지
- 확인 질문 없이 합리적 가정으로 끝까지 진행, 가정은 보고 끝 한 줄. 질문은 되돌릴 수 없고 해석이 둘 이상일 때만
- Git·GitHub 작업은 에이전트가 직접: 커밋·push·PR·머지(git-branch), 이슈(git-issue)

## 조회

- 코드 편집 전 규칙: just-do 훅이 편집하는 파일 종류·내용에 맞는 원칙 파일·code-style 절·언어별 스킬을 미전달분만 전달. 거부 안내의 `--pending` 명령 실행으로 보완
- 직접 조회: `python3 <just-mode 스킬 폴더>/scripts/rules/read_rules.py <파일...>` 또는 `--ids <ID...>`. Python 3.9+·표준 라이브러리, 오류 2·부분 출력 없음
- 기능·규모·보장, 미확정 대안, 구매·구축은 repo-docs-design 원문 직접 확인
- 같은 문맥·원문·단계의 완독 절·포함 참조 재사용, 파일·기반 스킬 재조회 금지
- 원문 변경·압축·재개는 현재 단계 필수 원문 재조회. 검색 발췌·제목·해시·읽음 표시로 대체 금지

## 작업 보고

```text
{결론 한 문장: 무엇이 끝났고 무엇이 달라졌는지}
할 일: {사용자만 할 수 있는 것. 없으면 "없음"}

바뀐 것
- {바뀐 것}: {예: 실제 이름·값·화면}

확인한 것
- {무엇을}: {어떻게 확인했고 결과가 어땠는지}

못 한 것
- {무엇}: {이유}. {다음에 누가 하는지}

자세히
- {PR 번호, 커밋, 파일 경로, 시험 수, 바이트 변화 같은 근거}

가정: {진행하며 정한 해석 한 줄. 없으면 생략}
```

- 맨 앞 두 줄만 읽어도 다음 행동 파악 가능. 근거는 자세히 칸에만
- 정할 것: 할 일 칸에 선택지와 각 선택의 결과를 한 줄씩. "A로 하면 ~, B로 하면 ~"
- 쉬운 설명 규칙 전체와 낯선 말 목록(repo-docs `references/plain-language.md`) 적용. 결론 맨 앞 규칙은 위 틀의 첫 두 줄
- 해당 칸이 없으면 칸째 생략
