## 테스트

- 목표: 근거 있는 최소 집합. 커버리지·테스트 개수 목표 금지

항목 → 규칙:

- 근거 → 테스트마다 하나 이상 필수: 설계 문서 요구사항 표의 행, 재현된 버그의 이슈 번호, 공개 계약(입출력 형식·호환·CLI), 지켜야 하는 규칙(접근성 대비 등). 이름이나 바로 위 한 줄 주석에 근거 식별자·경로 기록. 근거 없는 추가 금지
- 추가 전 → 기존 검사 실행·테스트 수정·입력 추가 우선. 새 테스트는 기존 검사로 잡지 못하는 회귀 위험에만 최소 추가, 이유 보고
- 근거 검증 → 근거 존재 여부와 테스트의 실제 검증 내용 별도 확인
- 기대값 → 사용자 확정값·접근성 임계값·공개 계약의 기대값은 구현 토큰과 독립된 근거 필수. 구현값을 그대로 읽는 자기 비교를 결정 보존의 증거로 사용 금지
- 병합 → 같은 동작의 입력 차이는 입력·기대값 표 기반 테스트 하나로 병합. 같은 규칙의 여러 파일 중복 검증 금지
- 검증 대상 → 사용자에게 보이는 결과나 공개 API만. 비공개 함수의 반환 모양, 생성 코드·CSS 문자열 일부, 내부 자료 구조 검증 금지. 문자열 형식 자체가 공개 계약일 때만 문자열 검증 허용
- 리팩터링 → 리팩터링 커밋에 테스트 추가 금지. 동작을 고정하는 테스트가 없으면 리팩터링 전 별도 커밋으로 추가
- 정리 → 요구사항 삭제·계약 폐기 등으로 근거가 사라진 테스트는 같은 PR에서 삭제
- 시간·성능 → 시간·성능 기준 테스트는 CI 금지, 로컬 측정 스크립트로 분리. 결과가 흔들리는 테스트는 근거 있는 테스트로 인정 금지

- 성공·실패는 자동 판정
- 새 테스트·변경한 검증: 통과하면 안 되는 입력 하나의 실패 확인
- 테스트마다 테스트 데이터 새로 생성. 테스트끼리 상태 공유 금지
- 입력 선정: 근거에 해당하는 경계값·빈 값·잘못된 입력. 버그 수정 전 재현 실패 확인
- 수정 전 실패: 동작이 틀려 실패한 경우만 인정. 테스트가 새로 만든 이름을 불러와 생긴 불러오기 오류는 제외. 새 이름만 대체물로 바꿔 동작 실패 확인
- 수정 전 코드로 실행할 수 없는 테스트: 새 내부 함수를 직접 부르는 단위 테스트 등은 별도 분류·보고. 공개 명령·공개 API 계약 테스트는 수정 전후 같은 테스트로 비교
- 끝없는 반복·메모리 폭증 재현: 생성 횟수 상한, 자식 프로세스 메모리 상한, 제한 시간으로 중단. 실제 메모리 부족 유발 금지
- 이름: `대상_조건_결과`. 대상은 공개 API나 사용자 동작, 조건이 없으면 생략: `parse_empty_input_returns_error`. 실제 검증 범위보다 넓은 이름 금지
- 본문은 준비 → 실행 → 확인 순서. 단계 사이 빈 줄
- 테스트 하나에 동작 하나. assert 여러 개는 같은 동작 확인 때만
- 테스트 위치는 언어 관례 (언어별 스킬)
