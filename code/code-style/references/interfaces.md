# 화면 · API

화면과 API를 바꿀 때 구현 전에 정할 것과 반드시 검사할 것을 조건별로 정한다.

## 조건별 확정과 검사

- 사용자 행동을 바꾸면 처음 사용, 반복 사용, 수정, 취소, 복구마다 입력, 요청과 권한, 응답, 상태, 완료 신호가 어떻게 이어지는지 정한다. 실제 과업이 끝나는지와 실패 뒤 복구되는지 검사한다.
- 상태는 정상, 로딩, 빈 결과, 오류, 부분 결과, 권한 없음, 저장 중, 성공 후를 정한다. 빈 결과와 읽기 실패를 다르게 다루고, 완료 표시와 영속화 성공을 다르게 다룬다.
- 클라이언트 데이터는 서버 정본, 편집 중인 값, 일시적인 UI 상태마다 소유자를 하나로 정하고, 낙관적 갱신의 실패, 취소, 충돌 정책을 정한다. 연속 입력, 중복 제출, 응답 역전, 화면 이탈을 검사한다.
- API는 타입, 단위, 입력 검증, 객체 권한, 오류, 재시도, 페이지와 정렬, 버전, 호환해야 할 소비자를 정한다. 형식과 업무상 정답을 따로 대조한다. HTTP 성공만으로 결과가 완전하다고 판정하지 않는다.
- 지원 환경은 연결 끊김, 재연결, 오프라인 수정, 기기 저장소와 권한, 백그라운드 수명을 정한다. 개발 환경에서의 성공을 다른 환경의 성공으로 넘겨받지 않는다.
- 구성 요소는 기존 컴포넌트, 토큰, 역할별 변형을 먼저 쓰고, 새 역할과 기존 상태를 구분한다. 같은 역할의 표현, 상태, 모션이 일치하는지 검사한다.
- 시각과 접근성은 작은 화면, 확대, 키보드, 초점, 대비, 테마, 긴 내용 중 지원할 조건을 정한다. 실제 크기와 상태로 렌더해 대조하고, 빌드나 토큰이 일치한다는 것만으로 통과시키지 않는다.
- 모션은 목적, 속성, 시간, 곡선, 중단, 연속 입력, 로딩, 모션 줄이기를 정한다. 상태, 초점, 사용자 행동을 막지 않는지 검사한다.
- 기존 UI를 개선할 때는 의미, 실루엣, 정보 위계, 색 역할을 보존한다. 같은 크기와 상태의 대표 화면을 전후로 대조한 뒤 범위를 넓힌다.

## 공통 규칙

- 파일, URL, 쿼리, 명령처럼 신뢰 경계를 넘어오는 외부 입력을 처리하기 전에 반드시 [보안 · 운영](operations.md)을 읽는다.
- 잘림, 누락, 전송 중단, 연결 재개 상태를 대조한다. 시안 범위의 요청은 시안으로 끝내고 실제 제품이 완료됐다고 주장하지 않는다.
- 용어, 단위, 오류 위치, 복구 행동을 확인한다. 내부 구현을 알아야만 쓸 수 있는 제품 흐름은 고친다.
