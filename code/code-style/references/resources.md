# 자원 · 성능

성능과 자원에 닿는 변경에서 반드시 할 일과 검사, 차단 기준을 조건별로 정한다.

## 조건별 행동과 검사

- 부하와 자원 한도는 평균과 순간 최대, 지속 시간, 동시 수, 입력 분포, 결과 크기, 느린 소비자를 확인한다. 하루 건수나 사용자 수만으로 용량과 성능이 충분하다고 판정하지 않는다. 과한 구조를 도입할 근거가 없다는 것과 지금 구성이 성능을 통과한다는 것을 구별한다.
- 계측 범위는 대기, 초기화, 처리, 외부 호출, 전송, 전체를 나누고 요청, 풀, 프로세스, 복제본, 전체를 나눈다. 설정값, 예약값, 실사용량, 관측 최고를 구분한다. 일부의 개선을 전체 개선으로 넓히지 않는다.
- CPU는 실제 알고리즘, 반복, 직렬화, 압축, 복사, 경합 경로를 프로파일한다. 입력이 바뀔 때 비용이 어떻게 바뀌는지 대조한다. 언어 탓으로 확정하기 전에 아래 공통 규칙대로 원인을 나눈다.
- 메모리는 보관 값, 버퍼, 재할당 전후 공존, 결과, 캐시, 관리 정보의 수명과 동시 합계를 본다. 요청별 메모리 한도를 RSS나 RSS 증가분과 같게 보지 않는다. 같은 대상을 재는지 먼저 확인한다.
- I/O는 호출 수, 묶음 크기, 순차와 임의 접근, 왕복, 재전송, bytes를 본다. 대상별 지연, 전체 지연, 완전성을 대조한다.
- 캐시는 정본, 키, 범위, 갱신과 무효화, 허용하는 오래됨, 퇴출, 민감 데이터를 정한다. 적중률 말고도 전체 지연, 메모리, 갱신, 재시작, 폭주를 대조한다.
- 동시 처리와 stream은 직렬 구간, 외부 한도, 작업 수, 생산과 소비 속도, 버퍼, 취소, 역압을 정한다. 처리량, 긴 지연, 실패율, 쌓이는 메모리, 순서, 완전성을 대조한다.

## 공통 규칙

- 상한을 넘으면 대기, 거절, 분할, 외부 저장 중에서 비용과 업무 결과를 보고 고른다. 조용한 잘림, 부분 성공, 무제한 재시도를 두지 않는다.
- 사용자 목적에 없는 대규모 목표나 안전 비율을 강요하지 않는다.
- 캐시는 반복 비용과 최신성 요구를 확인한 뒤 도입한다. 캐시가 없어도 복제, snapshot, 동시 갱신 때문에 최신성이 보장되지 않는다.
- TTL은 항목의 수명이다. 원본보다 얼마나 늦을 수 있는지는 채운 값의 시점, 갱신 경로, 재삽입 경로까지 대조한 뒤 판정한다.
- 원인은 언어, 컴파일러 옵션, 런타임과 할당기, 자료 배치와 알고리즘, OS와 장치, 계측으로 나눈다. 같은 언어 안의 대안을 확인하기 전에 다른 언어로 다시 쓰지 않는다.

## 측정 통과

1. 질문, 예측, 반증 조건, 고정 조건, 반복 횟수, 중단 기준을 정한다.
2. 의미, 결과, 내구성, 자원, 초기 상태가 같은 기준 실행을 확보한다. 차이가 있으면 비교 범위를 좁힌다.
3. 바꾼 비용 원인과 결과를 대조한다. 여러 변경의 총효과를 변경별 기여율로 지어내지 않는다.
4. 정확성과 복구가 보존됐는지, 병목이 옮겨 갔는지 확인한다. 다음 최적화를 시작할 관측 조건을 적는다.

- 숫자를 믿거나 보고하기 전에 제한 요인과 다른 것을 쟀을 가능성을 배제한다. 방법은 **principle-explain-the-number** 스킬을 따른다.
- 0이나 빈 지표는 필드, 단위, 집계, 스키마까지 확인한다. 샘플링한 최고를 절대 최고로 확정하지 않는다.
- CPU cache, DB buffer, OS page cache를 구분한다. 재시작했다고 모든 것이 cold 상태라고 추정하지 않는다.
- bytes, 문자, 토큰을 구분하고 누적, 현재, 최대를 구분한다. 직렬화 크기, 전송 크기, 저장 크기를 구분한다.
