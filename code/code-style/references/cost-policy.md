## 비용 주석

비용이 코드에서 드러나지 않는 알고리즘, 병목, 외부 호출 경계의 시간·메모리·호출 비용 기록. 개선 대상 선택과 변경 전후 비교에 사용

- 대상: 비용이 코드에서 드러나지 않는 알고리즘, 프로파일링으로 확인한 병목, 파일·네트워크·프로세스·모델 호출 경계만
- 함수 안에서 비용이 다른 대상 단계가 둘 이상이면 단계 바로 위에도 기록. 함수 위 값은 전체
- 위치: 선언 바로 위, 문서 주석·attribute·애노테이션·데코레이터보다 위. 주석 기호는 언어의 한 줄 주석
- 비용 주석 대상 함수 작성·변경·검토 전 [비용 해석·예·측정](cost.md) 필수 확인
- 키는 영어 고정, 설명 글은 주석 언어
- 린터 줄 길이를 넘는 줄: 같은 키로 다음 줄에 이어 기록

줄 → 쓰는 때 → 값:

- `cost` → 대상일 때 → `time`, `heap`, `stack` 순서의 O 표기. 0이 아닐 때만 `alloc`(할당 횟수), `io`(파일·네트워크·프로세스 호출 수), `tokens`(모델 호출의 입력 + 출력 토큰) 추가
- `mem` → 크기 식을 세울 수 있을 때 → 최대 피크 바이트 식. 변수와 `size(타입)`, 스택은 `frame`(프레임 하나) 기호: `stack ≈ d·frame`
- `vars` → `cost`·`mem`에 변수가 있을 때 → 한 글자·여러 글자 변수 모두 정의: `n = entries.len()`, `d = 트리 깊이`. 여럿이면 `, `로 연결
- `basis` → 대상일 때 → `estimate`(코드를 읽고 추산) 또는 `measured {벤치마크·테스트 이름}`
- `alt` → 비용이 다른 대안을 알 때 → 대안 이름, 그 `cost`·`mem`, `잃는 것`

- 대상 코드 변경 시 같은 커밋에서 비용 주석 갱신. 반복 수가 상수에서 입력·시간 비례로 바뀌면 변수 정의·상위 호출 비용 함께 갱신. `basis measured`는 재측정 또는 `estimate`로 교체
- 누락·위치 검사: `python3 <code-style 스킬 폴더>/scripts/check_cost_comments.py <소스 폴더>`. 검사는 정적으로 식별 가능한 외부 호출 경계만. 비용이 드러나지 않는 알고리즘·병목은 코드 검토로 확인
- 검사 오탐: 비용 주석 추가 대신 패턴·검사 범위 수정. 수정 뒤 출력 `total 0` 확인. 존재 검사 통과를 비용 정확성으로 보고 금지
- 개선: `cost`·`alt` 비교로 후보 선택. 적용은 성능 원칙(프로파일링으로 확인한 병목)
- Kotlin: ktlint 연속 주석 규칙 때문에 비용 주석과 KDoc 사이 빈 줄
