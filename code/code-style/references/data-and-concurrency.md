# 데이터 · 동시성

데이터와 공유 상태를 바꿀 때 구현 전에 정할 것과 반드시 대조하거나 막을 것을 조건별로 정한다.

## 조건별 확정과 대조

- 값과 경계를 다루면 구현 전에 타입, 단위, 범위, NULL, 기본값, 정밀도, 시간대, 인코딩, 길이, 직렬화를 정한다. 호출하는 쪽과 제공하는 쪽이 같은 입력을 같은 뜻으로 읽는지 대조한다. 문자 수, byte 수, 저장 공간을 섞지 않는다.
- 결과와 정본을 다루면 완전성, 페이지와 종료 신호, 오류를 정하고 정본, 색인, 캐시의 소유자와 갱신·삭제 전파를 정한다. 빈 값, 읽기 실패, 잘린 결과를 구분한다. 일부만 바뀔 수 있으면 무변경, 부분 성공, 보상 중 어떤 계약인지 확인한다.
- 저장소를 고를 때는 관계, 접근 패턴, 성장, 갱신, 내구성, 운영 조건을 정한다. 저장할 수 있다는 것만으로 DB를 확정하지 않는다.
- 스키마를 이전할 때는 기존 데이터, 신구 소비자, 배포 순서, 되돌릴 수 없는 변환, 복원을 정한다. 이전 데이터와 버전이 섞인 입력으로 대조하고, 백업이 있다는 것과 복원에 성공한 것을 구분한다.
- 재전송과 중복을 다루면 중복 정책을 정한다. 식별해야 하면 식별자의 생성 주체, 범위, 수명, 내용 충돌, 진행과 실패 상태까지 정한다. 같은 이벤트의 재전송과 정상적인 반복 요청을 구분하고, 내용 해시만으로 중복을 지우지 않는다.
- 공유 효과를 다루면 실행권, 원자성 경계, 외부 효과가 불확실한 상태를 정하고, 식별할 때는 내용이 일치하는지도 정한다. 두 요청이 엇갈려 실행되는 경우와 효과가 난 뒤 기록 전에 멈춘 경우를 대조한다. 실행권을 얻기 전에 공유 파일이나 외부 효과를 바꾸지 않는다.
- 순서와 버전을 다루면 전체 순서, 대상별 순서, 순서 무관 중 무엇인지와 오래된 응답, 시계 차이, 누락 처리를 정한다. 역전, 지연, 재시작 뒤의 최신 상태와 허용 순서를 대조한다.
- 읽은 뒤 쓰는 경우에는 충돌 검출, 재시도, 덮어쓰기를 정한다. 두 요청이 같은 이전 값을 읽는 경우의 계약을 대조한다.
- 잠금과 비동기를 다루면 잠금 대상, 획득 순서, 해제와 상태 소유자, 수명, 완료 전달을 정한다. 대기, 취소, 오류, 잠금 중 외부 I/O, 화면 이탈, 연속 입력을 대조한다.
- 재시도와 큐를 다루면 안전한 효과, 오류 종류, 상한, 지연, 중단과 큐 용량, 소비 속도, 재처리를 정한다. 응답 소실, 반복 실패, 불량 항목, 밀림, 종료를 대조한다.

## 공통 규칙

- 중복 정책은 매번 실행, 기존 결과 반환, 거절, 상태 갱신 중에서 업무 의미로 고른다. 호출, 효과, 성공 기록을 구별한다.
- 실행권을 얻기 전에 요청별로 격리된 준비를 하는 것은 괜찮다. 다만 최종 반영과 나눈다. DB 제약이나 큐 보장으로 외부 효과가 정확히 한 번 일어난다고 보장하지 않는다.
- 응답이 사라졌으면 효과는 미확인이다. 가능한 수단으로 효과를 대조하고, 대조할 수 없으면 미확인으로 둔다. 효과가 불명확한 작업을 무조건 다시 실행하지 않는다.
- timeout만으로 교착을 확정하지 않는다. 소유자, 대기 관계, 진행 조건을 확인한다. 프로세스 안의 잠금을 여러 프로세스 사이의 보장으로 넓히지 않는다.
- 순차, 동시, 중단 뒤 재개 검사를 나눈다. 겹칠 경로가 없다는 근거가 있을 때만 동시 조건을 뺀다.
- 큐는 처리량 말고도 지연 허용, 실패 격리, 영속 대기 요구로 판단한다. 사용량이 작다는 것을 중복, 권한, 정확성 검사를 생략하는 근거로 쓰지 않는다.
