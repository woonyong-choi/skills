## 오류와 로그

실패 종류별 처리:

경우 → 처리:

- 입력·파일·네트워크·외부 프로세스처럼 일어날 수 있는 실패 → 오류 값·예외로 호출하는 쪽에 전달
- 코드에 버그가 없으면 일어날 수 없는 경우 → 단언(assert)으로 중단. 메시지에 성립해야 하는 이유
- 테스트 → 단언 실패로 중단 허용

- 테스트 밖에서 구현을 미룬 채 실패하는 자리표시 코드 금지
- 예외: 여러 작업이 함께 쓰는 공개 계약을 검토하는 초안 PR의 미완성 자리표시. `TODO(#{번호})`로 이슈를 남기고, PR 준비 완료 전 0개. 언어별 자리표시 문법은 언어별 스킬
- 오류 전파 시 무엇을 하다 실패했는지 추가: `failed to read config file`
- 라이브러리 공개 API: 호출하는 쪽이 경우별로 처리할 수 있는 오류 종류 반환. 모든 오류를 한 타입으로 묶는 방식은 실행 파일(앱) 코드에서만
- 오류는 한 곳에서 한 번만 처리: 로그 기록이나 전파 중 하나. 로그는 최종 처리하는 곳에서
- 오류를 무시하면 이유를 주석으로. 빈 catch 금지

메시지:

- 오류·로그 메시지는 영어로 짧게. 대소문자·마침표는 언어 관례 (언어별 스킬)
- 관련 값(경로, id) 포함. 비밀번호·토큰·API 키·개인정보 포함 금지

로그 레벨:

레벨 → 쓰는 때:

- error → 작업 실패로 사람의 확인 필요
- warn → 실패는 아니지만 예상 밖. 재시도·기본값 대체로 진행
- info → 시작·종료·설정 적용처럼 드문 주요 상태 변화
- debug → 문제 원인을 찾을 때 필요한 값
- trace → 함수 진입, 반복마다의 세부 흐름 정보

- 반복마다 찍히는 로그는 debug 이하
- 진단 메시지는 로그 라이브러리로. CLI 도구: 로그는 stderr, stdout은 프로그램 결과에만
