# 코드 구조

함수와 파일의 크기, 이름, 조건식, 선언 순서, 공개 범위와 주석을 정한다.

## 수치 기준

- 표의 값은 허용하는 최대다.
- 권장 최대를 넘으면 원칙에 따라 나눌지 판단한다. 나누지 않으면 이유를 PR 본문에 적는다.
- 절대 최대를 넘으면 반드시 나눈다. 린터로 강제할 수 있으면 설정하고, 설정 방법은 언어별 스킬에 있다.

| 대상 | 권장 최대 | 절대 최대 | 대응 |
|---|---|---|---|
| 함수 길이(빈 줄과 주석 제외) | 40줄 | 100줄 | 함수 추출, 처리 단계 분리 |
| 함수 매개변수(`self`, `this` 제외) | 3개 | 7개 | 매개변수 묶음 타입 도입, 객체 통째로 전달 |
| bool 매개변수 | 0개 | 3개 | bool 플래그 인자 제거 |
| 중첩 깊이(함수 본문 안의 if, for, while, switch) | 2단 | 3단 | early return, 조건문을 함수로 분리, 함수 추출 |
| 조건식 하나의 `&&`, `\|\|` 개수 | 2개 | 3개 | 조건을 이름 있는 변수나 함수로 추출 |
| 인지 복잡도 | 없음 | 15 | 함수 추출, 조건문을 함수로 분리 |
| 같은 enum이나 타입 코드의 분기 | 1곳 | 2곳 | 분기를 다형성으로 |
| 파일 길이(같은 파일 안 테스트 제외) | 300줄 | 750줄 | 타입 분리, 함수 이동 |

## 이름

| 대상 | 규칙 | 예 |
|---|---|---|
| 타입 | 명사 | `Session`, `ProviderConfig` |
| 함수, 메서드 | 동사로 시작한다. 접근자, 생성, 변환은 언어 관례를 따르고 관례는 언어별 스킬에 있다 | `load_config`, `send_message` |
| bool을 돌려주는 함수 | `is`, `has`, `can`으로 시작하거나 3인칭 동사를 쓴다 | `is_empty`, `has_token`, `contains`, `starts_with` |
| bool 변수, 필드 | `is`, `has`, `can`, `should`로 시작한다 | `is_ready`, `should_retry` |
| 컬렉션 | 복수형 | `sessions`, `pending_jobs` |
| 약어 | 한 단어처럼 쓴다. 언어 관례가 먼저다 | `HttpClient`, `http_client` |
| 단위 | 시간 간격 같은 단위 타입을 먼저 쓰고, 숫자면 단위 접미사를 붙인다 | `timeout_ms`, `size_bytes` |
| 파일, 모듈 | 역할 명사. 금지 이름은 [folder-naming](../../folder-naming/SKILL.md)의 모듈 이름과 금지 규칙을 따른다 | `paths`, `retry` |

- 한 개념에는 한 단어를 쓴다. `fetch`, `get`, `retrieve`를 섞지 않고 저장소에서 이미 쓰는 단어를 쓴다.
- 반대 동작은 정해진 짝을 쓴다: add/remove, begin/end, create/destroy, first/last, get/set, increment/decrement, insert/delete, lock/unlock, min/max, next/previous, old/new, open/close, show/hide, source/target, start/stop.
- 줄임말은 `id`, `url`, `http`, `db`, `max`, `min`, `len`처럼 널리 쓰는 것만 쓴다. `mgr`, `svc`, `usr`처럼 글자를 뺀 줄임말을 쓰지 않는다.
- 이름에 타입을 붙이지 않는다(`name_string`, `UserStruct`).

## 조건식

비교는 다음 순서로 쓴다.

- `판단 대상 연산자 기준값` 순서로 쓴다(`count > 0`, `state == READY`, `elapsed > timeout`).
- 상수를 왼쪽에 두는 비교(`0 == x`)를 쓰지 않는다. 실수로 하는 대입(`if (x = 0)`)은 컴파일러나 린터로 막는다.
- 범위 검사만 예외로 수직선 순서를 쓴다(`min <= x && x < max`). `>`, `>=`로 뒤집지 않는다.
- bool은 그대로 쓴다(`if is_ready`, `if !is_ready`). `== true`, `== false`를 쓰지 않는다.
- 이중 부정을 쓰지 않는다. `!is_not_empty` 대신 `is_empty`를 쓴다.
- if와 else가 모두 있으면 긍정 조건을 if에 둔다.

`&&`, `||`로 잇는 조건은 다음 순서로 둔다.

1. 뒤 조건의 전제가 되는 검사를 먼저 둔다(`i < size && items[i] > 0`).
2. 그다음 싼 검사를 먼저 둔다. 변수와 필드, 순수 함수 호출, I/O와 잠금 순서다.
3. 부작용이 있는 호출은 조건식에 넣지 않는다. 단락 평가 때문에 실행 여부가 달라진다.

- `&&`와 `||`를 섞으면 반드시 괄호를 쓴다(`(a && b) || c`).
- 예외와 오류 경우는 early return으로 먼저 처리하고, 정상 흐름은 들여쓰기 없이 쓴다.
- switch와 match 분기는 enum 선언 순서로 두고 default는 마지막에 둔다.

## 선언 순서

포매터가 바꾸지 않는 순서는 직접 지킨다. 새 선언은 끝에 덧붙이지 않고 아래 순서의 제자리에 둔다. 없는 항목은 건너뛴다.

파일은 다음 순서로 쓴다.

1. 파일 설명 주석
2. import. 언어의 정렬 도구가 순서를 정하면 그 순서를 따른다. 없으면 표준 라이브러리, 외부 라이브러리, 같은 프로젝트 순서로 두고 그룹 사이에 빈 줄을 둔다.
3. 하위 모듈 선언(언어에 있으면)
4. 상수와 정적 변수
5. 타입. 공개 타입을 먼저 둔다. 타입 정의와 그 메서드 구현은 붙여 둔다.
6. 자유 함수. 공개 함수, 비공개 함수 순서다.
7. 같은 파일 안 테스트(언어 관례가 그렇다면)

타입 안은 다음 순서로 쓴다.

1. 상수(`MAX_RETRY`)
2. 정적 필드(`static`)
3. 불변 필드(`final`, `readonly`, `val`)
4. 가변 필드
5. 생성자와 팩토리
6. 프로퍼티와 접근자. get, set 순서로 두고 필드 선언 순서를 따른다.
7. 생명주기 메서드. `init`, `update`, `close`처럼 불리는 순서로 둔다.
8. 공개 메서드. 주요 로직이다.
9. 비공개 헬퍼. 처음 호출되는 순서로 둔다.
10. 검증(`validate_*`, `check_*`, `ensure_*`)

- 같은 순서 안에서는 공개, 비공개 순서로 둔다.
- 이름이 이어지는 함수(`parse`, `parse_with`)는 붙여 둔다.

인터페이스와 트레잇은 다음 순서로 쓴다.

1. 연관 타입과 상수
2. 구현해야 하는 메서드
3. 기본 구현이 있는 메서드

- 구현하는 쪽도 인터페이스의 선언 순서를 따른다.

## 공개 범위와 주석

- 공개 범위는 가장 좁게 시작해 필요한 만큼만 넓힌다. 비공개, 패키지나 모듈 안, 외부 순서다.
- 필드도 가장 좁은 공개 범위에서 시작한다. 밖에서 읽고 쓰는 방식(접근 메서드, 프로퍼티)은 언어 관례를 따르고, 관례는 언어별 스킬에 있다.
- 주석은 기본으로 쓰지 않는다. 코드가 보여 줄 수 없는 뻔하지 않은 이유만 주석으로 쓴다. 이름과 타입으로 전달되면 쓰지 않고, 공개 API도 같은 기준을 따른다.
- 뻔하지 않은 이유의 예는 불변 조건, 외부 제약, 단위와 범위, 실패 조건(돌려주는 오류, 던지는 예외, 중단 조건)이다.
- 주석은 쓰면서 깨끗하게 둔다. 위임받은 서브에이전트의 diff를 포함해 모든 파일에 적용한다.
- 주석은 한 줄, 한 문장으로 쓴다. 설계 문서 내용을 옮겨 쓰지 않는다. 근거가 별도 설계 문서에 있으면 해당 절 링크 하나만 단다.
- 이름 반복(`/// 채팅 id.`), 화면 문구나 키 목록 나열, 다음 상태 목록, 호출 흐름 서술을 주석에 쓰지 않는다.
- 검증 스크립트와 테스트 스크립트에 단계 설명 주석(`// Phase 1: add cards`)을 쓰지 않는다. 단언과 로그 문자열이 단계를 설명한다(`assert(ok, 'persisted across restart')`).
- 파일 설명 주석은 한 줄로 쓴다. 설계 문서 경로는 덧붙여도 된다.
- 주석 언어는 저장소의 기존 주석을 따른다. 기존 주석이 없으면 README 언어를 쓴다.
- TODO는 이슈 번호와 함께 쓴다(`TODO(#12): 재시도 횟수를 설정으로 이동`). 이슈 없는 TODO를 쓰지 않는다.
- 주석에 AI 작성 표시를 넣지 않는다.
