## 수치 기준

값: 허용 최대

- 권장 최대 초과: 원칙에 따라 분할 판단. 나누지 않으면 이유를 PR 본문에 기록
- 절대 최대 초과: 분할 필수. 린터로 강제할 수 있으면 설정 (언어별 스킬)

대상 → 권장 최대 → 절대 최대 → 대응:

- 함수 길이 (빈 줄·주석 제외) → 40줄 → 100줄 → 함수 추출, 처리 단계 분리
- 함수 매개변수 (`self`·`this` 제외) → 3개 → 7개 → 매개변수 묶음 타입 도입, 객체 통째로 전달
- bool 매개변수 → 0개 → 3개 → bool 플래그 인자 제거
- 중첩 깊이 (함수 본문 안의 if·for·while·switch) → 2단 → 3단 → early return, 조건문을 함수로 분리, 함수 추출
- 조건식 하나의 `&&`·`||` 개수 → 2개 → 3개 → 조건을 이름 있는 변수·함수로 추출
- 인지 복잡도 → - → 15 → 함수 추출, 조건문을 함수로 분리
- 같은 enum·타입 코드 분기 → 1곳 → 2곳 → 분기를 다형성으로
- 파일 길이 (같은 파일 안 테스트 제외) → 300줄 → 750줄 → 타입 분리, 함수 이동

## 이름

대상 → 규칙 → 예:

- 타입 → 명사 → `Session`, `ProviderConfig`
- 함수·메서드 → 동사로 시작. 접근자·생성·변환은 언어 관례 (언어별 스킬) → `load_config`, `send_message`
- bool 반환 함수 → `is`·`has`·`can`으로 시작, 또는 3인칭 동사 → `is_empty`, `has_token`, `contains`, `starts_with`
- bool 변수·필드 → `is`·`has`·`can`·`should`로 시작 → `is_ready`, `should_retry`
- 컬렉션 → 복수형 → `sessions`, `pending_jobs`
- 약어 → 한 단어처럼 표기(언어 관례 우선) → `HttpClient`, `http_client`
- 단위 → 단위 타입(시간 간격 등) 우선, 숫자면 단위 접미사 → `timeout_ms`, `size_bytes`
- 파일·모듈 → 역할 명사와 금지 이름: (folder-naming 모듈 이름, 금지) → `paths`, `retry`

- 한 개념에 한 단어. `fetch`·`get`·`retrieve` 혼용 금지, 저장소에서 이미 쓰는 단어 사용
- 반대 동작은 정해진 짝: add/remove, begin/end, create/destroy, first/last, get/set, increment/decrement, insert/delete, lock/unlock, min/max, next/previous, old/new, open/close, show/hide, source/target, start/stop
- 줄임말은 널리 쓰는 것만: `id`, `url`, `http`, `db`, `max`, `min`, `len`. `mgr`·`svc`·`usr`처럼 글자를 뺀 줄임말 금지
- 이름에 타입 붙이기 금지: `name_string`, `UserStruct`

## 조건식

비교 순서:

- `판단 대상 연산자 기준값`: `count > 0`, `state == READY`, `elapsed > timeout`
- 상수를 왼쪽에 두는 비교(`0 == x`) 금지. 실수로 인한 대입(`if (x = 0)`)은 컴파일러·린터로 차단
- 범위 검사만 예외로 수직선 순서: `min <= x && x < max`. `>`·`>=`로 뒤집기 금지
- bool은 그대로: `if is_ready`, `if !is_ready`. `== true`·`== false` 금지
- 이중 부정 금지: `!is_not_empty` 대신 `is_empty`
- if·else가 모두 있으면 긍정 조건을 if에

`&&`·`||` 순서:

1. 뒤 조건의 전제가 되는 검사 먼저: `i < size && items[i] > 0`
2. 그다음 싼 검사 먼저: 변수·필드 → 순수 함수 호출 → I/O·잠금
3. 부작용 있는 호출은 조건식에 넣기 금지 (단락 평가로 실행 여부 변동)

- `&&`와 `||`를 섞으면 괄호 필수: `(a && b) || c`
- 예외·오류 경우는 early return으로 먼저 처리, 정상 흐름은 들여쓰기 없이
- switch·match 분기는 enum 선언 순서. default는 마지막

## 선언 순서

포매터가 바꾸지 않는 순서: 직접 유지. 새 선언은 끝에 덧붙이지 않고 아래 순서의 자리에. 없는 항목은 생략

파일:

1. 파일 설명 주석
2. import. 언어의 정렬 도구가 순서를 정하면 그 순서. 없으면 표준 라이브러리 → 외부 라이브러리 → 같은 프로젝트, 그룹 사이 빈 줄
3. 하위 모듈 선언 (언어에 있으면)
4. 상수·정적 변수
5. 타입. 공개 먼저. 타입 정의와 그 메서드 구현은 붙여 배치
6. 자유 함수. 공개 → 비공개
7. 같은 파일 안 테스트 (언어 관례가 그렇다면)

타입:

순서 → 대상 → 예·기준:

- 1 → 상수 → `MAX_RETRY`
- 2 → 정적 필드 → `static`
- 3 → 불변 필드 → `final`, `readonly`, `val`
- 4 → 가변 필드
- 5 → 생성자·팩토리
- 6 → 프로퍼티·접근자 → get → set, 필드 선언 순서대로
- 7 → 생명주기 메서드 → `init` → `update` → `close`, 불리는 순서대로
- 8 → 공개 메서드 → 주요 로직
- 9 → 비공개 헬퍼 → 처음 호출되는 순서대로
- 10 → 검증 → `validate_*`, `check_*`, `ensure_*`

- 같은 순서 안에서는 공개 → 비공개
- 이름이 이어지는 함수(`parse`, `parse_with`)는 붙여 배치

인터페이스·트레잇:

1. 연관 타입·상수
2. 구현해야 하는 메서드
3. 기본 구현이 있는 메서드

- 구현하는 쪽도 인터페이스 선언 순서

## 공개 범위와 주석

- 가장 좁은 공개 범위부터, 필요한 만큼만 확대: 비공개 → 패키지·모듈 안 → 외부
- 필드도 가장 좁은 공개 범위부터. 밖에서 읽고 쓰는 방식(접근 메서드·프로퍼티)은 언어 관례 (언어별 스킬)
- 주석은 기본 없음. 코드가 보여 줄 수 없는 뻔하지 않은 이유만 주석으로. 이름과 타입으로 전달되면 생략, 공개 API도 같은 기준
- 뻔하지 않은 이유의 예: 불변 조건, 외부 제약, 단위·범위, 실패 조건(돌려주는 오류·던지는 예외·중단 조건)
- 쓰면서 깨끗하게. 위임받은 서브에이전트의 diff를 포함한 모든 파일에 적용
- 한 줄, 한 문장. 설계 문서 내용 전재 금지. 근거가 별도 설계 문서에 정의되어 있으면 해당 절 링크 하나만
- 금지: 이름 반복(`/// 채팅 id.`), 화면 문구·키 목록 나열, 다음 상태 목록, 호출 흐름 서술
- 검증·테스트 스크립트의 단계 설명 주석(`// Phase 1: add cards`) 금지. 단언·로그 문자열이 단계 설명: `assert(ok, 'persisted across restart')`
- 파일 설명 주석: 한 줄. 설계 문서 경로 덧붙이기 허용
- 주석 언어: 저장소의 기존 주석. 기존 주석이 없으면 README 언어
- TODO는 이슈 번호와 함께: `TODO(#12): 재시도 횟수를 설정으로 이동`. 이슈 없는 TODO 금지
- 주석에 AI 작성 흔적 금지
