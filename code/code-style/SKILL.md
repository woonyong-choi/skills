# Code Style

- 우선순위: 사용자 지시 → 저장소 규칙 → 이 스킬. 범위 밖은 명시한 소유 스킬 적용
- 범위: 원칙 스킬(just의 `principle-*`)에 없는 코드 공통 세부의 정본. 언어별 스킬은 언어별 스킬 절의 항목만 정하고, 그 밖에서 상충하면 이 스킬 우선
- 필요할 때만 읽기: 결과가 다른 미확정 설계 선택 → repo-docs-design; 리팩터링 기법 선택 → code-refactoring; 파일·모듈 이름 결정 → folder-naming; UI 시각·모션 변경 → design-tokens; CSS 변경 → code-style-css

## 조건별 읽기

- 판단 기준(최소 변경, 검증, 테스트 방식, 경계, 동시성, 근본 원인)은 원칙 스킬이 정본. 이 스킬은 그 밖의 수치·이름·순서·오류 형식·데이터·운영 세부
- 편집 전 훅이 편집하는 파일 종류와 내용 조건에 맞는 원칙 파일, 아래 절, 언어별 스킬을 함께 전달. 대응표 정본: just-mode `scripts/rules/rule-map.json`
- 직접 조회: `python3 <just-mode 스킬 폴더>/scripts/rules/read_rules.py <파일...>`(편집할 파일 기준 선택) 또는 `--ids <ID...>`. Python 3.9+·표준 라이브러리, 오류 2·부분 출력 없음
- 작은 수정에도 해당 오류·검사·예외 규칙 제외 금지. 새 함수는 이름·수치·선언·공개 범위와 실제 변경 조건 모두 적용

ID → 적용 조건 → 정본:

- CS-CORE → 모든 코드 작성·검토 → 이 문서의 머리와 원칙 절
- CS-VERIFY → 모든 코드 작성·검토 → 이 문서의 검증 절
- CS-FAILURE → 결함·장애 원인과 복구 → 이 문서의 실패 처리 절
- CS-LANGUAGE → 모든 코드 작성·검토 → [언어별 스킬](references/language.md)
- CS-SIZE → 함수·타입·분기·매개변수·파일 크기 변경 → [수치 기준](references/structure.md#수치-기준)
- CS-NAME → 이름 추가·변경 → [이름](references/structure.md#이름)
- CS-CONDITION → 조건식·분기 변경 → [조건식](references/structure.md#조건식)
- CS-ORDER → 선언 추가·이동 → [선언 순서](references/structure.md#선언-순서)
- CS-VISIBILITY → 공개 범위·필드·주석 추가·변경 → [공개 범위와 주석](references/structure.md#공개-범위와-주석)
- CS-ERROR → 실패 가능한 입력·외부 경계·오류·로그 변경 → [오류와 로그](references/errors.md)
- CS-TEST → 테스트 선택·추가·변경 → [테스트](references/testing.md)
- CS-DATA → 데이터·공유 상태·비동기 변경 → [데이터 · 동시성](references/data-and-concurrency.md)
- CS-RESOURCES → 성능·자원·캐시·큐 변경 → [자원 · 성능](references/resources.md)
- CS-INTERFACES → 화면·API 변경 → [화면 · API](references/interfaces.md)
- CS-OPERATIONS → 신뢰 경계·외부 입력·권한·의존·배포·복구 변경 → [보안 · 운영](references/operations.md)

## 원칙

원칙 → 규칙:

- 표기와 포맷 → 대소문자 표기·포맷은 언어 공식 관례와 포매터. 예시 이름의 snake_case·PascalCase는 설명용
- 클래스 없는 언어 → 클래스 → struct·trait·module, 상속 → 조합·인터페이스로 바꿔 적용
- 리팩터링 시점 → 기능 추가 직전, 코드를 이해하는 중, 작업하다 발견한 문제, 코드 리뷰 중
- 리팩터링 제외 → 앞으로 고칠 일 없는 코드, 재작성·이전·재검증 총비용이 리팩터링 비용보다 작다는 비교 근거가 있는 코드
- 공개 API 변경 → 외부 사용자 때문에 호출하는 쪽을 한 번에 못 바꾸면: 새 함수 추가 → 기존 함수는 새 함수 호출 + deprecated 표시 → 호출하는 쪽 이전 → 기존 함수 삭제
- 성능 → 프로파일링으로 확인한 병목만 최적화
- 이름 → 역할이 드러나게. 쓰는 범위가 넓을수록 구체적으로, 짧은 루프 변수 같은 좁은 범위는 짧게 허용. 세부: 이름 절
- 함수 크기 → 설명이 필요한 덩어리는 함수로 추출. 수치는 목표 아닌 경고선, 범위 안이라는 이유로 품질 판정 금지. 수치: 수치 기준 절
- 주석 → CS-VISIBILITY의 주석 조건·형식 적용

## 검증

- 요구마다 구현 위치·독립 기대 결과·실행 입력·명령·환경·관측과 통과/실패/미검증 연결
- 추천·탈락·필수 조건·완료 주장도 원요구·공식 계약·소스·관측과 대조. 값·주체·전체/부분 범위·시점·확실성 변경 금지. 의무 근거가 없으면 제안으로 분리
- 수치·명시적 조건은 기존 계산 도구로 검사. 입력 작성·원문 대조는 실행자 책임, 의미 해석·근거 진위·누락까지 검증됐다고 표시 금지
- 도구 부재 시 `python3 <code-style 스킬 폴더>/scripts/check_decisions.py` 사용. Python 3.9 이상·표준 라이브러리, 쓰기·네트워크·모델 호출 없음. 최초 사용 전 `--help`의 입력·오류·한계 확인
- HEAD·관련 미커밋 입력·명령·도구·환경이 같은 유효 결과 재사용. 관련 조건 변경은 영향 검사 재실행, 영향 불명확이면 전체 검사
- 원실패·새 사례·적용 제외·기존 정상 대조. 취향 변화와 결함 구분, 한 사례의 교정을 전체 금지로 일반화 금지
- 공통 패키지는 정본·생성물·실제 소비 버전·동작 연결. 해시·설치·import만으로 소비 동작 판정 금지
- 화면 검사는 현재 전경·초점·입력 제한 준수. 방해 금지 시 숨김 검사, 미확인 실제 입력·초점은 미검증 유지
- 제출 전 필수 참조·전체 diff·본문·코드·결론의 단위·주체·시점·예외와 요청 범위 대조. 부분 반영·외부 차단·남은 작업은 보고에 명시. 별도 보고서 파일 강제 금지

## 실패 처리

1. 현재 영향·진행 작업 확인. 허용된 피해 제한, 원본·미전송·근거 보존
2. 원인 찾기와 수정은 원칙 스킬(principle-fix-root-causes, principle-attack-the-premise)
3. 원실패·인접 경계·기존 정상·실패 후 다음 요청·복구 데이터 재검사

- 효과가 불명확한 외부 작업 재실행, 무관한 변경 일괄 복귀 금지
- 시간 초과만으로 교착·효과 실패 확정 금지. 긴급 복구와 장기 개선 분리
