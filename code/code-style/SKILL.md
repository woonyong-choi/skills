# Code Style

- 우선순위: 해당 주제의 사용자 지시 → 저장소 규칙 → 이 스킬. 중복 규칙은 머리에 연결한 정본 스킬 적용
- 범위: 코드 공통 규칙의 정본. 언어별 스킬은 언어별 스킬 절의 항목만 정하고, 그 밖에서 다르면 이 스킬 우선
- 필요할 때만 읽기: 결과가 다른 미확정 설계 선택 → repo-docs-design; 리팩터링 기법 선택 → code-refactoring; 파일·모듈 이름 결정 → folder-naming

## 조건별 읽기

- 변경 전 해당 ID의 절 전체 필수 확인. 범위 확대 시 아래 조건의 합집합 재선택

ID → 적용 조건 → 정본:

- CS-LANGUAGE → 작업 언어의 스킬 선택·변경 → [언어별 스킬](references/language.md)의 해당 절
- CS-SIZE → 함수·타입·분기·매개변수·파일 크기 변경 → [수치 기준](references/structure.md)의 해당 절
- CS-NAME → 이름 추가·변경 → [이름](references/structure.md)의 해당 절
- CS-CONDITION → 조건식·분기 변경 → [조건식](references/structure.md)의 해당 절
- CS-ORDER → 선언 추가·이동 → [선언 순서](references/structure.md)의 해당 절
- CS-VISIBILITY → 공개 범위·필드·주석 추가·변경 → [공개 범위와 주석](references/structure.md)의 해당 절
- CS-ERROR → 실패 가능한 입력·외부 경계·오류·로그 변경 → [오류와 로그](references/errors.md)의 해당 절
- CS-COST → I/O·프로세스·모델 호출·비용 대상 변경 → [비용 주석](references/cost-policy.md)의 해당 절
- CS-TEST → 테스트 선택·추가·변경 → [테스트](references/testing.md)의 해당 절

- 조회: Python 3.9+·표준 라이브러리의 `python3 <이 스킬 폴더>/scripts/read_rules.py --ids CS-CONDITION CS-ERROR --text`. 출력: 조건·출처·원문, 내부 해시 검증. `--text` 생략 시 해시 포함 JSON, `--catalog`는 조건 목록. 오류 종료 2. 전체 파일 대신 대상 절 필수 확인
- 필수 조건이 둘 이상이면 합집합 조회. 작은 수정에도 해당 오류·검사·예외 규칙 제외 금지. 새 함수는 이름·수치·선언·공개 범위와 실제 변경 조건 모두 적용

- 데이터·공유 상태·비동기 변경: [data-and-concurrency.md](references/data-and-concurrency.md) 필수 확인
- 성능·자원·캐시·큐 변경: [resources.md](references/resources.md) 필수 확인
- 화면·API 변경: [interfaces.md](references/interfaces.md) 필수 확인
- 신뢰 경계·외부 입력·권한·의존·배포·복구 변경: [operations.md](references/operations.md) 필수 확인
- UI 시각·모션 변경은 design-tokens, CSS 변경은 code-style-css 필수 확인. UI 없는 서버 작업은 제외

## 원칙

원칙 → 규칙:

- 표기와 포맷 → 대소문자 표기, 포맷: 언어 공식 관례와 포매터. 이 스킬은 그 밖의 것
- 클래스 없는 언어 → 클래스 → struct·trait·module, 상속 → 조합·인터페이스로 바꿔 적용
- 예시 이름 → snake_case·PascalCase 표기. 실제 표기는 언어 관례
- 하는 때 → 기능 추가 직전, 코드를 이해하는 중, 작업하다 발견한 문제, 코드 리뷰 중. 같은 코드가 3곳이면 정리
- 하지 않는 때 → 앞으로 고칠 일 없는 코드, 재작성·이전·재검증 총비용이 리팩터링 비용보다 작다는 비교 근거가 있는 코드
- 공개 API 변경 → 호출하는 쪽을 한 번에 못 바꾸면: 새 함수 추가 → 기존 함수는 새 함수 호출 + deprecated 표시 → 호출하는 쪽 이전 → 기존 함수 삭제
- 최소 코드 → 선택한 계약 안에서 기존 코드 제거·재사용·표준 기능·설치된 의존성을 검토하고 최소 추가. 보안·오류 처리·접근성·가독성 보존, 몇 줄을 위한 의존성·래퍼 추가 금지
- 성능 → 먼저 읽기 쉽게 작성. 프로파일링으로 확인한 병목만 최적화
- 이름 → 역할이 드러나게. 쓰는 범위가 넓을수록 구체적으로, 짧은 루프 변수 같은 좁은 범위는 짧게 허용. 세부: 이름 절
- 함수 크기 → 설명이 필요한 덩어리는 함수로 추출. 수치는 목표 아닌 경고선, 범위 안이라는 이유로 품질 판정 금지. 수치: 수치 기준 절
- 주석 → 기본은 주석 없음. 이유, 불변 조건, 외부 제약, 단위·범위, 실패 조건만 한 줄로. 공개 범위와 주석 절. 비용: 비용 주석 절

## 구현

1. 변경 경로의 호출자·상태 소유자·기존 검사에서 정상 기준 또는 재현 실패 확인
2. 선택한 계약을 만족하는 작은 변경 적용. 기능 변경과 리팩터링 분리
3. 같은 입력에서 요구 결과·보존 조건·관련 실패 경로 대조 후 범위 확대

- 필요한 선행 리팩터링은 동작 보존 확인 후 분리 커밋
- 확인한 문제 없이 재설계하거나 현재 쓰임 없는 계층·설정·추상화 추가 금지
- 테스트 선택·추가·변경은 [testing.md](references/testing.md)의 적용 조건과 예외 확인
- 종료 전 잔여 조건을 실행 가능·외부 의존·사용자 판단·범위 밖으로 분류. 승인된 실행 가능 작업 계속, 독립 작업까지 중단 금지
- 실행할 일이 남으면 진행 약속만으로 종료 금지. 의존 작업은 대기 도구로 확인, 위임·실행 중을 결과로 대체 금지

## 검증

- 요구마다 구현 위치·독립 기대 결과·실행 입력·명령·환경·관측과 통과/실패/미검증 연결
- 추천·탈락·필수 조건·완료 주장도 원요구·공식 계약·소스·관측과 대조. 값·주체·전체/부분 범위·시점·확실성 변경 금지. 의무 근거가 없으면 제안으로 분리
- 중요한 미확인 판정은 종속 구현 보류. 교정 뒤 추천·구현 범위와 나머지 제약 재대조
- 기대 결과를 구현값·같은 계산식·모델 답변에서 복제 금지. 독립 기준이 없으면 미검증
- 수치·명시적 조건은 기존 계산 도구로 검사. 입력 작성·원문 대조는 실행자 책임, 의미 해석·근거 진위·누락까지 검증됐다고 표시 금지
- 도구 부재 시 `python3 <이 스킬 폴더>/scripts/check_decisions.py` 사용. Python 3.9 이상·표준 라이브러리, 쓰기·네트워크·모델 호출 없음. 최초 사용 전 `--help`의 입력·오류·한계 확인
- 빈 결과·0 지표는 입력·필터·기간·권한·읽기·계측의 양성 대조부터 확인. 일부 검색 미발견을 전체 부재로 확대 금지
- 저장소·언어의 필수 빌드·테스트·포맷·린트 적용. 미해결 실패·경고를 완료로 처리 금지
- HEAD·관련 미커밋 입력·명령·도구·환경이 같은 유효 결과 재사용. 관련 조건 변경은 영향 검사 재실행, 영향 불명확이면 전체 검사
- 원실패·새 사례·적용 제외·기존 정상 대조. 취향 변화와 결함 구분, 한 사례의 교정을 전체 금지로 일반화 금지
- 공통 패키지는 정본·생성물·실제 소비 버전·동작 연결. 해시·설치·import만으로 소비 동작 판정 금지
- 화면 검사는 현재 전경·초점·입력 제한 준수. 방해 금지 시 숨김 검사, 미확인 실제 입력·초점은 미검증 유지
- 호출·응답·효과·영속화·재시작과 구현·실사용·배포·복구를 각각 확인한 범위로 보고. 모의 성공·형식 통과·검사 개수·검토자 동의로 대체 금지
- 표본·분모·버전·환경 보존. 미실행을 성공 분모에서 제외하거나 일부 성공을 전체 완료로 확대 금지
- 제출 전 필수 참조·전체 diff·본문·코드·결론의 단위·주체·시점·예외와 요청 범위 대조. 부분 반영·외부 차단·남은 작업 구분. 별도 보고서 강제 금지
- 모델 검토도 원요구·직접 근거로 재검사. 확신·요약·해시의 순환 인용 금지

## 실패 처리

1. 현재 영향·진행 작업 확인. 허용된 피해 제한, 원본·미전송·근거 보존
2. 입력·버전·설정·최근 변경·실행 경로로 기대와 실제 결과 고정
3. 원인 후보를 구분할 최소 검사 실행. 직접 원인과 가설 구분
4. 깨진 가정·현재 계약·불변식에 맞는 국소 수정. 새 요구·구조 선택은 결정 단계로 반환
5. 원실패·인접 경계·기존 정상·실패 후 다음 요청·복구 데이터 재검사

- 새 근거 없는 동일 재시도, 효과가 불명확한 외부 작업 재실행, 무관한 변경 일괄 복귀 금지
- 시간 초과만으로 교착·효과 실패 확정 금지. 긴급 복구와 장기 개선 분리
