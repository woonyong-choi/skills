# 디자인 토큰

화면 값을 정본 토큰 파일 하나에 정의해 코드가 토큰으로만 쓰게 하고, 하드코딩을 검사하고, 시각 변경을 전후 비교로 검수한다.

## 원칙

- 하드코딩하지 않는다. 색, 글꼴, 글자 크기, 줄 높이, 자간, 간격, 반지름, 테두리 두께, 그림자, 투명도, z-index, 시간, 이징, 크기, breakpoint 값은 토큰으로만 쓴다. 예외는 아래 토큰 대상 제외, 외부 라이브러리 고정 값, 토큰 없이 써도 되는 값, `@media`와 `@container` 조건(`var()`를 쓸 수 없어 breakpoint 토큰과 같은 숫자를 쓴다)뿐이다.
- 손으로 고치는 파일은 기본값을 담은 `tokens.json`과 테마에서 바뀌는 값을 담은 `tokens.dark.json` 같은 테마 파일이다. 다른 파일은 이 파일들로 생성하거나 토큰을 참조한다.
- 먼저 만들고 쓴다. 맞는 토큰이 없으면 코드에 값을 적지 않고 정본에 토큰을 더한 뒤 쓴다.
- 의미로 쓴다. 색과 그림자는 의미 토큰만 쓴다. 그 밖의 분류(간격, 크기, 반지름, 글자 크기, 시간 등)는 기본 토큰을 써도 된다.
- 테마는 의미 층에서 바꾼다. 다크 모드와 고대비는 의미 토큰 값만 바꾼다. 토큰 파일 밖에서 테마를 분기하지 않는다. 테마 전환 코드(사용자 선택 읽기와 저장)는 그 줄에 `tokens-allow: {이유}`를 단다.

토큰 없이 써도 되는 값은 `0`, `1`(flex 비율, 불투명), `auto`, `none`, `inherit`, `initial`, `unset`, `currentColor`, `transparent`, 배치 비율 `%`와 `fr`, `100vh`, `100vw`다.

- 도형 좌표, 경로, 데이터에서 계산한 크기는 토큰 대상이 아니다.
- 문서 그림의 토큰, 색 역할, 대비는 **repo-docs-figures** 스킬의 도구와 파일 절이 맡는다. 이 스킬의 토큰을 그림 원본에 복제하지 않는다.
- 외부 라이브러리가 요구하는 고정 값은 그 줄에 `tokens-allow: {이유}` 주석을 단다. 이유 없이 허용하지 않는다.

## 세 층

| 층 | 역할 | 이름 예 | 참조하는 쪽 |
|---|---|---|---|
| 기본(primitive) | 쓸 수 있는 값 목록이다. 뜻은 없다 | `color.blue.600`, `space.4`, `size.text.md` | 의미 토큰. 색과 그림자 밖의 분류는 코드도 참조한다 |
| 의미(semantic) | 용도다. 테마마다 값이 바뀐다 | `color.accent`, `color.text.muted`, `space.card.pad` | 구성 요소 토큰, 코드 |
| 구성 요소(component) | 한 구성 요소만의 값이다. 없어도 된다 | `button.height`, `tab.gap` | 그 구성 요소 코드 |

- 구성 요소 토큰은 한 구성 요소의 값만 바꾸고 다른 구성 요소의 값은 그대로 둬야 할 때만 둔다. 그 밖에는 의미 토큰을 바로 쓴다.
- 직접 값(DTCG 색 객체, dimension 등)은 기본 토큰에만 둔다. 의미 토큰과 구성 요소 토큰의 값은 다른 토큰을 참조한다(`{color.blue.600}`).

## 이름

- 형식은 `{분류}.{용도}.{변형}.{상태}`이고 점으로 나눈다. 겹치지 않게 용도와 상태를 가려낼 칸만 쓴다.
- CSS 이름은 점을 `-`로 바꾼다(`--color-accent-hover`). JavaScript 이름은 같은 경로의 객체다(`tokens.color.accent.hover`).
- 낱말은 소문자 kebab-case로 쓴다. 색 이름(`blue`)은 기본 층에만 쓰고, 의미 층에는 용도 이름(`accent`, `danger`)을 쓴다.
- 토큰 분류나 단계를 새로 만들거나 바꿀 때는 [references/categories.md](references/categories.md)를 반드시 읽는다.

## 정본과 생성물

| 파일 | 내용 | 손으로 고치기 |
|---|---|---|
| `tokens.json` | 정본이다. DTCG(Design Tokens Community Group) 2025.10 형식(`$value`, `$type`, `$description`)으로 쓴다 | 고친다 |
| `tokens.dark.json` | 다크 모드에서 바뀌는 의미 토큰만 담는다 | 고친다 |
| `tokens.css` | 생성물이다. `:root`의 CSS 사용자 정의 속성과 다크 모드 덮어쓰기를 담는다 | 고치지 않는다 |
| `tokens.js` | 생성물이다. 토큰 경로 객체(값은 `var(--…)`)와 계산용 숫자를 담는다 | 고치지 않는다 |

생성은 다음 명령으로 한다. Python 3.9 이상과 표준 라이브러리로 돈다.

```sh
python3 <이 스킬 폴더>/scripts/build_tokens.py tokens.json --out <생성 폴더>
```

- 저장소에 화면 코드가 한 곳이면 그 소스 루트에, 여럿이면 공유 폴더 하나에 둔다. 생성물은 커밋한다.
- 생성물 첫 줄에는 정본 경로와 `생성물, 손으로 고치지 않음` 주석을 둔다.
- 생성물은 실제 생성 파일 경로로 포매터와 린터에서 뺀다(`.prettierignore`, ESLint `ignores`, Stylelint `ignoreFiles`).
- 글자 크기 정본은 반드시 `rem` dimension으로 쓴다. 단위 없는 수는 `px`로 생성되므로 쓰지 않는다.
- 다크 모드는 `@media (prefers-color-scheme: dark)`와 `[data-theme='dark']` 두 곳에 같은 값으로 생성한다. `[data-theme='light']`는 밝은 값을 강제한다.

## 쓰는 방법

| 자리 | 쓰는 방법 | 예 |
|---|---|---|
| CSS | `var(--토큰)` | `padding: var(--space-4);` |
| CSS 계산 | `calc()` 안에 토큰 | `calc(var(--space-4) * 2)` |
| `@media` 조건 | breakpoint 토큰과 같은 숫자를 쓴다. `var()`는 쓸 수 없다 | `@media (min-width: 768px)` |
| JavaScript가 만드는 CSS, 인라인 style, SVG 속성 | `tokens.js`의 값(`var(--…)` 문자열) | `` `fill="${tokens.color.accent}"` `` |
| JavaScript 배치 계산 | `tokens.js`의 `values` 숫자 | `values.space['4']` |

- 이미지로 넣는 SVG에서는 `var()` 값이 사라진다. 인라인 SVG와 `currentColor`를 먼저 쓴다. 그럴 수 없으면 빌드가 `tokens.css`를 `<style>`에 넣고 첫 줄에 생성물 표시를 달아 출력한다. 손으로 복사하지 않는다.

## 새 값이 필요할 때

1. 색과 그림자는 같은 용도의 의미 토큰을 찾는다. 없으면 의미와 대비 조건을 채우는 기본 색 단계로 의미 토큰을 더한다.
2. 그 밖의 분류는 기본 단계에서 고른다.
3. 기존 단계로 채울 수 없는 조건과 적용 화면을 기록하고 기본 토큰을 더한다.
4. 정본을 고친 뒤 생성 스크립트를 돌리고 생성물과 함께 커밋한다.

- 코드에 값을 먼저 적고 나중에 토큰으로 바꾸지 않는다.
- 한 번만 쓴다는 이유로 직접 값을 쓰지 않는다.
- 토큰 값과 같은 숫자를 복사해 쓰지 않는다.

## 시각 변경 검수

- 토큰이 맞는다고 시각 품질이 합격한 것은 아니다. 기존 형태, 의미, 색 역할을 개선하라는 요청이면 지킬 대상과 확인된 결함부터 짚는다. 전체를 다시 설계하라는 뜻으로 짐작하지 않는다.
- 아이콘이나 삽화를 바꾸기 전에 대상 저장소의 제작 규칙과 실제 참고 이미지를 조회한다. 바꾸는 이유를 결함과 잇고, 같은 크기와 배경의 전후 비교에서 해결, 보존, 새 결함을 각각 판정한다.
- 작은 크기, 밝음과 어두움, 색과 단색, 실사용 상태 가운데 해당하는 조건을 검사한다. 조건을 빼면 쓰임 근거를 밝힌다. 확인하지 않은 것을 통과로 처리하지 않는다.
- 많이 바꿀 때는 서로 다른 대표 유형에서 방향을 검증한 뒤 넓힌다. 항목마다 의미와 비례 검수를 빠뜨리지 않는다. 기존 승인이나 위임 범위 안의 국소 수정에는 다시 승인을 받으라고 강요하지 않는다.
- 사용자가 불합격시킨 원인은 다음 수정의 보존 조건과 금지 조건에 넣는다. 검사 통과, 같은 해시, 생성 성공을 사용자의 시각 승인으로 대신하지 않는다.

## 검사

다음 명령으로 검사한다. Python 3.9 이상과 표준 라이브러리로 돈다. 출력이 `total 0`이 될 때까지 고친다. 0이 아니면 1로 끝난다.

```sh
python3 <이 스킬 폴더>/scripts/check_tokens.py <검사할 폴더>
```

- 찾는 것은 hex 색, 색 함수(`rgb()`, `oklch()` 등), 단위가 붙은 길이와 시간, 단위 없는 굵기, 줄 높이, 투명도, z-index, 자간, 크기를 나타내는 속성의 숫자(`rx`, `stroke-width` 등), 글꼴 이름, 토큰 파일 밖의 사용자 정의 속성 값, breakpoint 토큰에 없는 `@media`와 `@container` 숫자, 색과 그림자 기본 토큰의 직접 참조, 토큰 파일 밖의 테마 분기(`prefers-color-scheme`, `[data-theme`), 스타일 객체의 숫자(`{ fontWeight: 600 }`)다.
- CSS 계열은 주석 밖 전체를 본다. 마크업 계열(`.html`, `.svg`, `.vue`, `.svelte`)은 `<style>`, `style` 속성, 표현 속성만 본다. JavaScript 계열은 주석 밖 모든 문자열의 색을 보고, CSS나 마크업 모양 문자열과 값 하나뿐인 문자열(`'12px'`)에는 나머지 규칙도 본다. 코드의 토큰 경로(`tokens.color.blue['600']`)와 스타일 객체(`style`, `sx`, `css`) 안의 숫자도 본다.
- `tokens.json`, `tokens.dark.json`, 첫 줄에 생성물 표시가 있는 파일, `node_modules`, `dist`, `build`, `coverage`, `.git`, 비어 있지 않은 이유가 붙은 `tokens-allow:` 줄은 보지 않는다.
- 이징 함수(`cubic-bezier()`, `ease` 등), 토큰 이름이 용도를 드러내는지, 구성 요소 토큰이 필요한지([세 층](#세-층) 절 기준), `style`, `sx`, `css` 밖 이름의 스타일 객체 숫자는 직접 확인한다.
- 화면 구현값의 하드코딩과 테스트 기대값을 구분한다. 테스트 기대값의 근거는 code-style `references/testing.md`를 반드시 읽고 확인한다.

## 답변

- 검사했으면 `total` 값과 남은 위반 위치를 적는다.
- 토큰을 더하거나 바꿨으면 바꾼 토큰 이름과 생성물 갱신 여부를 적는다.
- 시각 변경을 검수했으면 조건마다 해결, 보존, 새 결함, 미확인을 나눠 적는다.

## 구분

- 결과가 달라지는 정해지지 않은 디자인 선택은 **repo-docs-design** 스킬이 맡는다.
- CSS 작성은 **code-style-css** 스킬이 맡는다.
- JavaScript와 TypeScript 작성은 **code-style-typescript** 스킬이 맡는다.
- 문서 그림의 색, 글꼴, 크기는 **repo-docs-figures** 스킬이 맡는다.
