# Git Commit

- 우선순위: 사용자 지시 → 저장소 규칙 → 이 스킬. 범위 밖은 명시한 소유 스킬 적용
- 범위: 커밋 메시지, 커밋 분리, 커밋 절차
- 필요할 때만 읽기: 커밋 메시지 작성·검토 → repo-docs `references/writing.md` 필수 확인; 커밋 전 검사 → code-style

## 형식

- 정본: [commit-template.txt](references/commit-template.txt). 채운 파일로 `git commit --cleanup=strip -F {파일}`(`#` 줄 삭제). squash 머지 메시지도 같은 방법
- 설명·본문은 기본 한글, type·scope는 영어 소문자. 언어 변경은 머리의 우선순위 적용
- 코드, 도구, 파일 이름: 원문 그대로 (`tokio`, `rustfmt`, `user_name`)

## scope

- 변경이 속한 패키지·crate 단위 모듈 이름, 프로젝트 접두사 제외: `{프로젝트}-core` → `core`
- 모듈 밖 변경: `repo`(저장소 전체 설정·여러 모듈에 걸친 구조), `deps`(의존성), `readme`, `docs`(docs 폴더, `AGENTS.md`, `llms.txt` 같은 루트 문서), `release`(버전·배포)
- 모듈 안 하위 폴더, 파일, 클래스, 함수 이름 금지
- 서로 독립된 변경이 여러 모듈에 있으면 모듈별로 커밋 분리. 이슈 단위 브랜치(git-branch)를 쓰는 저장소면 이슈부터 분리
- 한 변경이 여러 모듈에 걸쳐 나눌 수 없으면 생성물·잠금 파일 제외 추가+삭제 줄 수가 가장 큰 모듈. 동률·공통 계약 변경·저장소 전반이면 `repo`

## 설명

끝말 → 뜻:

- 추가 → 없던 것 생성
- 제거 → 있던 것 삭제
- 수정 → 잘못된 동작 고치기(fix)
- 변경 → 값·동작·이름 바꾸기
- 개선 → 동작 유지, 품질 향상
- 분리 → 하나를 여럿으로
- 통합 → 여럿을 하나로
- 이동 → 위치만 옮기기
- 정리 → 동작 변화 없는 정돈
- 갱신 → 버전·내용을 최신으로
- 적용 → 설정·규칙·도구 반영
- 도입 → 새 도구·라이브러리 첫 사용
- `되돌림` → revert

- 결과만, 과정·시도("~하려고", "~시도") 금지
- `수정`·`변경` 단독 금지. 대상 명시
- 파일명 나열 금지

## 꼬리말

- `Closes:`·`Refs:` 선택 기준: (git-issue 닫기). 이슈 생략 조건: (git-issue 과업 연결과 기록)

## 절차

1. `git status --short`, `git diff`, `git diff --staged`로 변경 확인
2. 함께 되돌릴 변경끼리 커밋 분리. 사용자가 따로 한 변경과 섞기 금지
3. 요청 범위 파일만 stage
4. 커밋 전 검사와 통과 증거 재사용: (code-style 검증). 실패·경고가 남으면 커밋 없이 보고

## 금지

- 작성 표시. 도구 기본 꼬리말 지시에도 적용, 목록 정본은 repo-docs references/writing.md 문체
- 작성자 변경(사용자 Git 설정 그대로)
- 메시지만 요청받았는데 commit·push·amend 실행
- 요청 없는 rebase·force push·과거 커밋 재작성
