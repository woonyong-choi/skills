# Git 커밋

변경을 함께 되돌릴 단위로 나누고, 저장소 형식 `type(scope): 한글 설명`에 맞는 메시지로 커밋한다.

## 단계

1. `git status --short`, `git diff`, `git diff --staged`로 변경을 확인한다.
2. 함께 되돌릴 변경끼리 묶어 커밋을 나눈다. 사용자가 따로 한 변경과 섞지 않는다. 모듈과 이슈에 따라 나누는 기준은 아래 scope 절을 따른다.
3. 요청 범위의 파일만 stage한다.
4. 커밋 전 검사를 돌리거나 이미 통과한 증거를 다시 쓴다. 검사 방법과 증거를 다시 쓰는 조건은 **principle-prove-it-works** 스킬을 따른다. 실패나 경고가 남으면 커밋하지 않고 보고한다.
5. 메시지를 쓰거나 검토하기 전에 repo-docs `references/writing.md`를 반드시 읽는다.
6. [커밋 템플릿](references/commit-template.txt)을 채운다.
7. 채운 글을 표준 입력으로 넘겨 `git commit --cleanup=strip -F -`로 커밋한다. `--cleanup=strip`이 템플릿의 `#` 줄을 지운다. 임시 파일을 만들지 않는다.

## 형식

메시지 틀의 정본은 [커밋 템플릿](references/commit-template.txt)이다. type 목록, 설명 길이, 본문과 꼬리말 형식은 그 파일을 따른다.

- 설명과 본문은 한글로 쓰고 type과 scope는 영어 소문자로 쓴다.
- 코드, 도구, 파일 이름은 원문 그대로 쓴다(`tokio`, `rustfmt`, `user_name`).

### scope

- scope는 변경이 속한 모듈 이름이다. 모듈은 패키지나 crate 단위이고 프로젝트 접두사는 뗀다(`{프로젝트}-core`는 `core`).
- 모듈 밖 변경에는 다음 이름을 쓴다.

| scope | 대상 |
|---|---|
| `repo` | 저장소 전체 설정, 여러 모듈에 걸친 구조 |
| `deps` | 의존성 |
| `readme` | README |
| `docs` | docs 폴더, `AGENTS.md`, `llms.txt` 같은 루트 문서 |
| `release` | 버전과 배포 |

- 모듈 안의 하위 폴더, 파일, 클래스, 함수 이름은 scope로 쓰지 않는다.
- 서로 독립된 변경이 여러 모듈에 있으면 모듈마다 커밋을 나눈다. 이슈 단위 브랜치([git-branch](../git-branch/SKILL.md))를 쓰는 저장소면 이슈별로 먼저 나눈다.
- 한 변경이 여러 모듈에 걸쳐 나눌 수 없으면, 생성물과 잠금 파일을 빼고 추가 줄과 삭제 줄을 더한 수가 가장 큰 모듈을 쓴다. 동률이거나, 공통 계약을 바꾸거나, 저장소 전반에 걸치면 `repo`를 쓴다.

### 설명

설명은 다음 끝말 중 하나로 끝낸다.

| 끝말 | 뜻 |
|---|---|
| 추가 | 없던 것을 만든다 |
| 제거 | 있던 것을 지운다 |
| 수정 | 잘못된 동작을 고친다(fix) |
| 변경 | 값, 동작, 이름을 바꾼다 |
| 개선 | 동작은 그대로 두고 품질을 높인다 |
| 분리 | 하나를 여럿으로 나눈다 |
| 통합 | 여럿을 하나로 합친다 |
| 이동 | 위치만 옮긴다 |
| 정리 | 동작 변화 없이 정돈한다 |
| 갱신 | 버전이나 내용을 최신으로 맞춘다 |
| 적용 | 설정, 규칙, 도구를 반영한다 |
| 도입 | 새 도구나 라이브러리를 처음 쓴다 |
| `되돌림` | revert |

- 결과만 쓴다. `~하려고`, `~시도` 같은 과정과 시도는 쓰지 않는다.
- `수정`이나 `변경`을 단독으로 쓰지 않고 대상을 밝힌다.
- 파일 이름을 나열하지 않는다.

### 꼬리말

`Closes #번호`와 `Refs #번호` 중 무엇을 쓸지는 [git-issue 닫기](../git-issue/SKILL.md#닫기)를 따른다. 이슈 꼬리말을 생략하는 조건은 [git-issue 과업 연결과 기록](../git-issue/SKILL.md#과업-연결과-기록)을 따른다.

## 하지 않는 것

- 작성 표시를 넣지 않는다. 도구가 기본 꼬리말을 넣으라고 지시해도 넣지 않는다. 표시 목록의 정본은 repo-docs `references/writing.md`의 문체 절이다.
- 작성자를 바꾸지 않는다. 사용자 Git 설정을 그대로 쓴다.
- 메시지만 요청받았으면 commit, push, amend를 실행하지 않는다.
- 브랜치 기록 다시 쓰기(rebase, amend, 강제 push)는 **just-mode** 스킬의 자율 절을 따른다.

## 답변

- 커밋했으면 커밋마다 짧은 해시와 제목 줄을 적는다.
- 메시지만 요청받았으면 채운 메시지를 `text` 코드 블록으로 돌려준다.
- 검사가 실패해 커밋하지 않았으면 실패한 검사와 남은 경고를 적는다.

## 구분

- 브랜치, PR 생성, 머지, 릴리스는 [git-branch](../git-branch/SKILL.md)가 맡는다.
- PR 본문과 검토 댓글은 [git-pull-request](../git-pull-request/SKILL.md)가 맡는다.
- 이슈 제목, 본문, 닫기는 [git-issue](../git-issue/SKILL.md)가 맡는다. 이 스킬은 꼬리말에 넣을 이슈 번호만 다룬다.
- 커밋 전에 돌릴 검사의 내용은 **principle-prove-it-works** 스킬과 언어별 스킬의 검사 명령 절이 맡는다.
