# Git 풀 리퀘스트

PR의 종류를 정하고, 틀에 맞춰 증거가 있는 본문을 쓰고, 검토와 머지 조건으로 머지할 수 있는지 판정한다.

## 쓰기 전에 읽을 것

- 제목, 본문, 댓글을 쓰거나 검토하기 전에 repo-docs `references/writing.md`를 반드시 읽는다.
- PR 본문, 리뷰, 댓글을 게시하기 전에 git-issue `references/public-links.md`를 반드시 읽는다.

## 종류

| 종류 | 담는 것 | 올리는 방식 |
|---|---|---|
| 설계 | docs만 담는다. 설계 이슈의 결정 반영, 실험 사전 등록, 실험 결과 | 바로 검토를 받는다 |
| 계약 | 여러 작업이 함께 쓰는 공개 프로토콜과 API. trait, 공유 타입, 오류 타입과 필요한 문서 주석을 담고, 본문이 필요한 함수는 뺀다 | 구현 전에 바로 검토를 받는다. 머지한 뒤 구현 작업을 시작한다 |
| 구현 | 구현, 테스트, 설계 문서 갱신 | 한 이슈 안에서만 쓰는 시그니처는 같은 PR에서 구현과 함께 바꾼다 |

- 초안 PR의 미완성 자리표시는 **code-style** 스킬의 오류와 로그 절을 따른다.

## 본문

- 틀은 [references/pull-request.md](references/pull-request.md)의 코드 블록 안이다. 채워서 `gh pr create --body-file -`로 표준 입력에 넘긴다. 임시 파일을 만들지 않는다.
- 올리기 전에 주석과 해당 없는 항목을 지운다. 저장소별 `.github` 틀을 만들지 않는다.
- 절 다섯 개의 이름과 순서를 그대로 둔다.
- 가정(이슈나 설계에 없어 작성자가 정한 전제)은 `왜 필요한가`에 쓴다. 문서 변경과, 생성물을 뺀 소스 변경 범위는 `무엇이 달라지나`에 쓴다.
- 결과는 "전 → 후"로 쓴다. `개선`이나 `정리`만 쓰지 않는다.
- 첫 줄의 `Closes #번호`와 `Refs #번호` 가운데 무엇을 쓸지는 [git-issue 닫기](../git-issue/SKILL.md#닫기)를 따른다. 이슈를 만들지 다시 쓸지는 [git-issue 과업 연결과 기록](../git-issue/SKILL.md#과업-연결과-기록)을 따른다.
- 체크 항목마다 증거(테스트 이름, 명령과 결과 숫자, 경로)를 붙인다. 실행하지 않은 검증은 `실행 안 함: {이유}`로 쓴다. 테스트를 더하거나 지운 근거는 **code-style** 스킬의 테스트 절을 따른다.
- 정해지지 않은 결정을 찾으면 그 결정에 기대는 변경만 보류한다. 선택은 **repo-docs-design** 스킬이, 이슈 분리는 [git-issue 과업 연결과 기록](../git-issue/SKILL.md#과업-연결과-기록)이 맡는다.

### 화면·움직임 변경

마지막 커밋으로 띄운 실제 화면으로 판정한다. 중간 커밋의 캡처나 테스트 통과로 대신하지 않는다.

- 전후 캡처 표는 데스크톱 1280px과 모바일 390px을 한 줄씩 둔다. 같은 줄은 같은 화면, 스크롤 위치, 크기로 찍는다. 캡처마다 번호를 붙인다. 칸 너비를 정하려고 틀의 HTML 표를 쓴다.
- 확인 기준 표의 기준은 이슈 완료 조건과 바꾼 화면에서 뽑고, 증거는 캡처 번호로 적는다. 움직임도 같은 표에 넣고 증거는 녹화로 적는다.
- 모형이나 합성 화면이면 alt와 결과 칸에 `모형`이라고 적는다.

캡처 파일은 다음처럼 다룬다.

- 작업 브랜치와 기본 브랜치에 커밋하지 않는다. 저장소의 `pr-assets` 브랜치(기본 브랜치와 기록을 공유하지 않는 orphan)에 `{PR 번호}/{번호}-{전|후}-{폭}.png`로 올린다.
- 주소는 `https://github.com/{owner}/{repo}/blob/pr-assets/{경로}?raw=true`다.
- 브랜치가 없으면 첫 캡처 때 `git switch --orphan pr-assets`로 만들고, 빈 첫 커밋 없이 캡처 커밋부터 쌓는다.
- 다시 찍으면 같은 경로를 덮어쓴다. 머지된 PR의 폴더는 지우지 않는다.
- 로컬 캡처 파일은 저장소 `.local/media/`에 두고 올린 뒤 지운다.

## 문서 동반

- 동작, 계약, 설정을 바꾸는 PR은 같은 PR에서 설계 문서를 고친다. 고칠 것이 없으면 `무엇이 달라지나`에 이유를 적는다.
- 계약 PR이면 설계 문서의 인터페이스 절을 코드 위치로 바꾼다(**repo-docs-design** 스킬).
- 실험 결과가 설계를 바꾸면 실험 문서와 설계 문서를 같은 PR에서 고친다.
- 새 문서를 만들지와 승인은 **repo-docs** 스킬의 새 문서 절을 따른다.
- 결정 기록 대상 표에 맞는 `design` 이슈의 결정은 같은 PR에 공개 결정 기록으로 남긴다(**repo-docs-decision** 스킬의 대상 절).
- 그림 원본이나 입력 JSON을 바꾸면 산출물을 함께 올리고 변환을 검증한다(repo-docs-figures `references/validation.md`의 검사).
- README나 `docs/` 문서를 바꾸면 llms 파일의 생성 조건을 보고 함께 갱신한다(**repo-docs-llms** 스킬의 만들기 절). full 파일은 이미 있거나 요청된 경우만 만든다.
- 릴리스 PR은 `CHANGELOG.md`를 같은 PR에서 고친다(**repo-docs-root** 스킬).

## 크기

- PR 하나는 사용자 결과 하나와 그 검증까지 담는다. 제목으로 설명되지 않는 독립 결과는 이슈와 PR을 따로 낸다.
- 바뀐 줄은 400줄 안팎으로 둔다. 생성 파일과 잠금 파일은 세지 않는다. 넘으면 이슈를 나눌지 검토하라는 신호다.
- 계약 PR은 계약 하나의 묶음과 소비자 영향만 담는다. 따로 승인할 수 있는 계약은 나눈다. 400줄을 넘으면 나눌지 검토한 근거를 기록한다.

## 검토

규칙이나 설계를 검토하거나 검토 댓글을 쓰기 전에 [references/review.md](references/review.md)를 반드시 읽는다.

## 머지 조건

셋을 모두 채우면 머지한다. 막히면 결정 기록에 `결정 필요`로 적고 다음 일로 넘어간다.

1. `watch-pr` 판정이 `READY`다. CI와 리뷰 상태를 포함한다(**just-mode** 스킬 `scripts/watch-pr`).
2. 남은 P1과 P2가 0개다([references/review.md](references/review.md)의 등급).
3. 검증 판정이 지금 patch에 유효하다. 판정한 커밋과 현재 head의 `git patch-id`를 비교한다(**just-mode** 스킬 `playbooks/shipping.md` 3단계).

- PR 본문의 체크 항목은 기록용이고 머지 조건이 아니다.
- 계약 PR은 사람의 계약 승인이 있어야 `READY`가 된다([종류](#종류) 절).

## 하지 않는 것

- 작성 표시는 [git-commit 하지 않는 것](../git-commit/SKILL.md#하지-않는-것)을 따른다.
- 실행하지 않은 검증을 기록하거나 증거 없이 항목을 체크하지 않는다.
- 비공개 기록의 링크나 내용을 넣지 않는다.

## 답변

- 만들거나 고친 PR의 번호와 주소를 적는다.
- 검토했으면 리뷰 요약 첫 줄(P1~P5 개수)과 축별 발견을 적는다.
- 머지 조건을 판정했으면 세 조건 각각의 결과와 막힌 조건을 적는다.

## 구분

- 브랜치와 머지 절차는 [git-branch](../git-branch/SKILL.md)가 맡는다.
- PR 제목 형식은 [git-commit](../git-commit/SKILL.md)이 맡는다.
- 구현 검증의 내용은 **principle-prove-it-works** 스킬이 맡는다.
- 그림 원본, 입력, 산출물의 형식은 **repo-docs-figures** 스킬이 맡는다.
