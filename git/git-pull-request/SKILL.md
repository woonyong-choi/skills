# Git Pull Request

- 우선순위: 사용자 지시 → 저장소 규칙 → 이 스킬. 범위 밖은 명시한 소유 스킬 적용
- 범위: PR 종류, 본문, 계약 검토, 문서 동반, 검토 댓글, 머지 조건. 브랜치·머지 절차(git-branch), 제목 형식(git-commit) 제외
- 필요할 때만 읽기: 제목·본문·댓글 작성·검토 → repo-docs `references/writing.md` 필수 확인; 구현 검증·머지 조건 확인 → code-style; 그림 원본·입력·산출물 변경 → repo-docs-figures; PR 본문·리뷰·댓글 게시 전 → git-issue `references/public-links.md` 필수 확인

## 종류

종류 → 담는 것 → 올리는 방식:

- 설계 → docs만: 설계 이슈 결정 반영, 실험 사전 등록, 실험 결과 → 바로 검토
- 계약 → 여러 작업이 함께 쓰는 공개 프로토콜·API. trait·공유 타입·오류 타입과 필요한 문서 주석, 본문이 필요한 함수 제외 → 구현 전 바로 검토. 머지 뒤 구현 작업 시작
- 구현 → 구현, 테스트, 설계 문서 갱신 → 단일 이슈 안에서만 쓰는 시그니처는 같은 PR에서 구현과 함께 변경

- 초안 PR의 미완성 자리표시: (code-style 오류와 로그)

## 본문

- 틀: [pull-request.md](references/pull-request.md)의 코드 블록 안. 채워서 `gh pr create --body-file -`(표준 입력, 임시 파일 금지). 올리기 전 주석과 해당 없는 항목 삭제. 저장소별 `.github` 틀 생성 금지
- 절 다섯 개, 이름·순서 그대로. 가정(이슈·설계에 없어 작성자가 정한 전제)은 `왜 필요한가`, 문서 변경과 생성물 제외 소스 변경 범위는 `무엇이 달라지나`에. 결과는 "전 → 후", `개선`·`정리`만 쓰기 금지
- 첫 줄 `Closes:`·`Refs:` 선택: (git-issue 닫기). 이슈 생성·재사용: (git-issue 과업 연결과 기록)
- 체크 항목마다 증거(테스트 이름, 명령과 결과 숫자, 경로). 실행하지 않은 검증은 `실행 안 함: {이유}`. 테스트 추가·삭제 근거: (code-style 테스트)
- 미결정 발견 시 종속 변경만 보류. 선택은 (repo-docs-design 선택), 이슈 분리는 (git-issue 과업 연결과 기록)

### 화면·움직임 변경

마지막 커밋으로 띄운 실제 화면으로 판정. 중간 커밋 캡처·테스트 통과로 대체 금지

- 전/후 캡처 표: 데스크톱 1280px·모바일 390px 한 줄씩, 같은 줄은 같은 화면·스크롤 위치·크기. 캡처마다 번호. 칸 너비 지정을 위해 틀의 HTML 표 사용
- 확인 기준 표: 기준은 이슈 완료 조건과 바꾼 화면에서, 증거는 캡처 번호. 움직임도 같은 표, 증거는 녹화
- 모형·합성 화면: alt와 결과 칸에 `모형`

캡처 파일:

- 작업 브랜치·기본 브랜치 커밋 금지. 저장소의 `pr-assets` 브랜치(기본 브랜치와 기록을 공유하지 않는 orphan)에 `{PR 번호}/{번호}-{전|후}-{폭}.png`
- 주소: `https://github.com/{owner}/{repo}/blob/pr-assets/{경로}?raw=true`
- 브랜치가 없으면 첫 캡처 때 `git switch --orphan pr-assets`, 빈 첫 커밋 없이 캡처 커밋부터
- 다시 찍으면 같은 경로 덮어쓰기. 머지된 PR 폴더 삭제 금지
- 로컬 캡처 파일은 저장소 `.local/media/`에 두고 올린 뒤 삭제

## 문서 동반

- 동작, 계약, 설정을 바꾸는 PR: 같은 PR에서 설계 문서 수정. 고칠 것이 없으면 `무엇이 달라지나`에 이유.
- 계약 PR: 설계 문서의 인터페이스 절을 코드 위치로 교체 (repo-docs-design)
- 실험 결과가 설계를 바꾸면 실험 문서와 설계 문서를 같은 PR에서
- 결정 기록 대상 표에 맞는 `design` 이슈 결정: 같은 PR에 결정 기록 (repo-docs-decision 대상)
- 그림 원본·입력 JSON 변경 시 산출물 동반과 변환 검증: (repo-docs-figures references/validation.md 검사)
- README나 `docs/` 문서 변경 시 생성 조건·동반 갱신: (repo-docs-llms 만들기). full은 기존 파일이 있거나 요청된 경우만
- 릴리스 PR: `CHANGELOG.md`를 같은 PR에서 (repo-docs-root)

## 크기

- 한 PR: 한 사용자 결과와 그 검증까지. 제목으로 설명되지 않는 독립 결과는 별도 이슈·PR로 분리
- 바뀐 줄 400줄 안팎. 생성 파일, 잠금 파일 제외. 넘으면 이슈 분할 필요성을 검토하는 신호
- 계약 PR: 단일 계약 집합과 소비자 영향만 포함. 별도 승인 가능한 계약은 분리. 400줄 초과 시 분리 검토 근거 기록

## 검토

규칙·설계 검토 수행 또는 검토 댓글 작성 전 [review.md](references/review.md) 필수 확인

## 머지 조건

셋 모두 충족 시 머지. 막히면 결정 기록에 `결정 필요`, 다음 일로 이동

1. `watch-pr` 판정 `READY`(CI·리뷰 상태 포함, just-mode `scripts/watch-pr`)
2. 남은 P1·P2 0개 (review.md 등급)
3. 검증 판정이 지금 patch에 유효: 판정 커밋과 현재 head의 `git patch-id` 비교(just-mode `playbooks/shipping.md` 3단계)

- PR 본문 체크 항목: 기록용, 머지 조건에서 제외
- 계약 PR: 사람의 계약 승인이 `READY` 전제(종류 절)
