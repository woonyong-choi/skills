# Git Pull Request

- 우선순위: 해당 주제의 사용자 지시 → 저장소 규칙 → 이 스킬. 중복 규칙은 머리에 연결한 정본 스킬 적용
- 범위: PR 종류, 본문, 계약 검토, 문서 동반, 검토 댓글, 머지 조건. 제목, 브랜치, 머지 절차(git-branch)와 제목 형식(git-commit) 제외
- 필요할 때만 읽기: 제목·본문·댓글 작성·검토 → repo-docs `references/writing.md` 필수 확인; 테스트 변경 근거 확인 → code-style; 그림 원본·입력·산출물 변경 → repo-docs-figures
- 필요할 때만 읽기: PR 본문·리뷰·댓글의 파일·문서·코드 링크 작성·검토 → git-issue `references/public-links.md` 필수 확인
- PR 생성·머지 전 [판 상태 절차](../git-issue/references/project-status.md) 필수 확인

## 종류

| 종류 | 담는 것 | 올리는 방식 |
|---|---|---|
| 설계 | docs만: 설계 이슈 결정 반영, 실험 사전 등록, 실험 결과 | 바로 검토 |
| 계약 | 여러 작업이 함께 쓰는 공개 프로토콜·API. trait·공유 타입·오류 타입과 필요한 문서 주석, 본문이 필요한 함수 제외 | 구현 전 바로 검토. 머지 뒤 구현 작업 시작 |
| 구현 | 구현, 테스트, 설계 문서 갱신 | 단일 이슈 안에서만 쓰는 시그니처는 같은 PR에서 구현과 함께 변경 |

- 초안 PR의 미완성 자리표시: code-style 오류와 로그 절

## 본문

- 이슈·PR·댓글을 올리기 전에 [git-issue 공개 웹 링크](../git-issue/references/public-links.md)의 규칙과 스크립트로 검사, 리뷰 댓글에도 동일 적용
- 절 이름, 순서 그대로. 빈 절은 `없음`

```text
Closes: #{번호} 또는 Refs: #{번호}

## 변경
- {결과 중심, 필요한 줄. 3~7줄은 검토 신호, 파일 나열 금지}

## 문서
- {고친 문서와 절} 또는 `없음: {이유}`

## 검증
- `{실제로 실행한 명령}`: {결과}
- 테스트 변경: {추가·삭제한 테스트 이름과 각각의 근거} 또는 `없음`

## 가정
- {이슈·설계에 없어서 작성자가 정한 것} 또는 `없음`

## 확인할 곳
- {사람이 직접 볼 파일과 이유: 보안, 데이터 손실, 동시성, 공개 계약} 또는 `없음`
```

- 이슈 연결이 있으면 첫 줄: `Closes: #{번호}` 또는 `Refs: #{번호}`. 독립 추적이 필요 없는 작은 정리는 이 줄 생략
- `Closes:`와 `Refs:` 판단 기준: git-issue 닫기 절
- 검증: 실제로 실행한 것만. 실행하지 못한 것은 `실행 안 함: {이유}`
- 테스트 변경 근거: (code-style 테스트). 삭제는 근거 폐기·중복 병합 등 삭제 이유 포함
- 가정: 작은 선택도 기록(기본값, 오류 메시지, 이름). 설계를 바꾸는 선택이면 PR 중단, 설계 이슈 생성

## 문서 동반

- 동작, 계약, 설정을 바꾸는 PR: 같은 PR에서 설계 문서 수정. 고칠 것이 없으면 문서 절에 이유
- 계약 PR: 설계 문서의 인터페이스 절을 코드 위치로 교체 (repo-docs-design)
- 실험 결과가 설계를 바꾸면 실험 문서와 설계 문서를 같은 PR에서
- 결정 기록 대상 표에 맞는 `design` 이슈 결정: 같은 PR에 결정 기록 (repo-docs-decision 대상)
- 그림 원본·입력 JSON 변경 시 산출물 동반과 변환 검증: (repo-docs-figures references/validation.md 검사)
- README나 `docs/` 문서 변경 시 생성 조건·동반 갱신: (repo-docs-llms 만들기). full은 기존 파일이 있거나 요청된 경우만
- 릴리스 PR: `CHANGELOG.md`를 같은 PR에서 (repo-docs-root)

## 크기

- 한 PR: 한 사용자 결과와 그 검증까지. 제목으로 설명되지 않는 독립 결과는 별도 이슈·PR로 분리
- 바뀐 줄 400줄 안팎. 생성 파일, 잠금 파일 제외. 넘으면 이슈 분할 필요성을 검토하는 신호
- 본문 `변경` 절: 생성물을 제외한 소스 변경 범위 기록
- 계약 PR: 단일 계약 집합과 소비자 영향만 포함. 별도 승인 가능한 계약은 분리. 400줄 초과 시 분리 검토 근거 기록

## 검토

규칙·설계 검토 수행 또는 검토 댓글 작성 전 [review.md](references/review.md) 필수 확인

## 머지 조건

- CI가 있으면 CI 통과, 없으면 로컬 검사 통과. 검사 범위·증거 재사용: (code-style 검증 증거)
- 검토 `필수` 0개
- 완료 조건 모두 체크
- 화면·움직임 변경: 최종 HEAD의 실제 출력으로 판정한 수용표 필수. 기준·캡처·성능 측정 뒤 해당 경로 변경 시 영향 증거 갱신
- 계약이 있으면 사람이 계약 승인
- 머지 주체: 요청이 있을 때만 AI 머지 (git-branch 머지)

## 금지

- 제목·본문·댓글의 작성 표시 금지 항목: (git-issue 금지)
- 실행하지 않은 검증 기록
- 비공개 기록 링크나 내용
- 절 빼기, 빈 절 두기
