# 검토

검토자: 작성 결론 전제 금지, diff·계약·시험 증거 직접 대조. 규칙·설계 두 축 독립 검토

축 → 기준 → 보는 것:

- 규칙 → 저장소 규칙, code-style과 언어별 스킬 → 이름, 구조, 오류 처리, 테스트, 금지 항목
- 설계 → 이슈 완료 조건, 설계 문서 → 빠진 조건, 범위 밖 변경, 설계와 다른 동작, 문서 동반, 가정, 확인 절 증거

등급 → 처리 → 예:

- P1 → 꼭 반영 → 데이터 손실, 보안, 잘못된 결과
- P2 → 반영 또는 근거 답글로 반박 → 요구·테스트 누락
- P3 → 반영 또는 후속 이슈 링크 → 유지보수 비용 증가
- P4 → 작성자 판단 → 취향
- P5 → 작성자 판단 → 사소한 의견

- 줄 단위 댓글 맨 앞 `[P1]`~`[P5]`와 근거(규칙·조건)
- 리뷰 요약 첫 줄 `P1 0 · P2 1 · P3 2 · P4 0 · P5 1`, 이어서 축별 발견. 없으면 `발견 없음`
- 해결: 첫 리뷰어와 다른 2차 리뷰어가 수정 커밋으로 판정하고 해결된 의견에 `반영 확인: {커밋 7자리}` 답글. 작성자 자기 판정 금지. 2차 확인은 최대 2번, 미합의는 사용자 결정
