# 검토

PR을 규칙과 설계 두 축으로 독립 검토하고, 지적마다 등급을 매겨 반영 여부를 판정한다.

## 방법

- **interrogate** 스킬로 다른 회사 모델 둘 이상이 독립적으로 검토하고, 지적마다 아래 P1~P5 등급을 매긴다.
- 검토자는 작성자의 결론을 전제로 두지 않고 diff, 계약, 시험 증거를 직접 대조한다.
- 규칙과 설계 두 축을 따로 검토한다.

| 축 | 기준 | 보는 것 |
|---|---|---|
| 규칙 | 저장소 규칙, **code-style** 스킬과 언어별 스킬 | 이름, 구조, 오류 처리, 테스트, 금지 항목 |
| 설계 | 이슈 완료 조건, 설계 문서 | 빠진 조건, 범위 밖 변경, 설계와 다른 동작, 문서 동반, 가정, 확인 절의 증거 |

## 등급

| 등급 | 처리 | 예 |
|---|---|---|
| P1 | 반드시 반영한다 | 데이터 손실, 보안, 잘못된 결과 |
| P2 | 반영하거나 근거를 단 답글로 반박한다 | 요구나 테스트 누락 |
| P3 | 반영하거나 후속 이슈 링크를 단다 | 유지보수 비용 증가 |
| P4 | 작성자가 판단한다 | 취향 |
| P5 | 작성자가 판단한다 | 사소한 의견 |

## 공개 피드백 형식

- 이슈와 PR의 일반 댓글, 줄 단위 댓글, 리뷰 본문에 검토·검증 결과를 쓸 때 반드시 이 절을 따른다. 결정·질문·범위 변경·완료 댓글은 **git-issue** 스킬의 해당 틀을 따른다.
- 첫 줄은 `## 검토 결과` 또는 `## 검증 결과`로 쓴다. 제목에 영문 판정이나 등급 집계를 넣지 않는다.
- 첫 문단에는 실제 판정을 `통과했습니다.`, `주의사항을 포함해 통과했습니다.`, `통과하지 못했습니다.` 중 하나로 쓴다. 실행 없이 검토만 했다면 통과를 단정하지 않고 실제 발견을 한 문장으로 쓴다.
- 판정 뒤에는 `## 발견 사항`, `## 확인한 내용`, `## 한계와 미확인 사항` 순서로 쓴다. 해당 사실이 없는 절은 지운다. 형식을 채우려고 발견이나 한계를 만들지 않는다.
- 발견에는 등급, 실제 영향, 근거와 반영·검토·참고·기각 중 처리 판단을 적는다. 줄 단위 댓글도 같은 형식을 쓰고 지적 앞에 `[P1]`~`[P5]`를 붙인다.
- 등급을 집계했다면 `## 발견 사항` 아래 본문에 `P1 0 · P2 1 · P3 2 · P4 0 · P5 1` 형식으로 둔다. 기각한 지적은 집계에서 빼고 기각 이유는 남긴다. 새 검토에서 발견이 없으면 집계를 생략하고 첫 문단에 `검토한 범위에서 발견 사항이 없습니다.`라고 쓴다. 기존 댓글을 바꿀 때는 0건 집계도 숫자를 보존해 본문으로 옮긴다.
- 확인한 내용에는 대상 커밋, 범위, 실행한 명령·입력과 실제 결과를 적는다. 수치, 커밋·댓글·테스트 식별자, 근거 링크를 보존한다. API와 코드가 노출된 변경이면 코드별 조건과 예외도 대조한다.
- 한계와 미확인 사항에는 실행하지 않은 검사, 외부 검토 차단과 확인 범위를 적는다. 형식 검사 통과를 행동 검증이나 독립 검토 통과로 넓히지 않는다.
- 공개 검증 판정은 기존 `PASS`를 `통과했습니다.`, `PASS+NOTES`를 `주의사항을 포함해 통과했습니다.`, `FAIL`을 `통과하지 못했습니다.`로 쓴다. 영문 판정을 단독 표기로 쓰거나 한글 뒤에 되붙이지 않는다. GitHub API의 실제 상태 값, 내부 워커 프로토콜, 명령 출력, 인용 원문은 그대로 둔다. 이를 공개 결과로 요약할 때만 위 한글 판정으로 쓴다.
- 기존 댓글의 형식만 바꿀 때는 판정, 발견, 기각, 반영 여부, 제한, 수치, 식별자와 근거를 바꾸지 않는다. 새 검증을 한 것처럼 시점을 바꾸지 않는다.

```markdown
## 검증 결과

주의사항을 포함해 통과했습니다.

## 확인한 내용

- 확인한 커밋과 실행한 검사, 실제 결과

## 한계와 미확인 사항

- 실행하지 못한 검사와 이유
```

## 반영 확인

- 그 코드를 쓴 작성 에이전트가 아닌 다른 에이전트가 수정 커밋을 보고 판정한다. 해결된 의견에는 위 공개 피드백 형식으로 답글을 단다. 첫 문단에 실제로 확인한 반영 결과를 쓰고, `## 확인한 내용` 아래에 `반영 확인: {커밋 7자리}`와 확인 근거를 적는다.
- 작성자가 스스로 판정하지 않는다.
- 확인은 최대 2번까지 되풀이한다. 합의하지 못하면 결정 기록에 `결정 필요`로 적는다.
