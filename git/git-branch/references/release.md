# 릴리스

태그로 버전을 매기고, 지난 메이저의 수정은 `v{major}` 브랜치로 내보낸다.

## 태그와 버전

- 태그는 기본 브랜치에 `v{X}.{Y}.{Z}` 형식으로 붙인다. 요청이 있을 때만 붙인다.
- 어느 자리를 올릴지는 마지막 태그 이후의 커밋으로 정한다. 앞자리를 올리면 뒷자리는 0으로 돌린다.

| 올릴 자리 | 커밋 | 뜻 |
|---|---|---|
| X | `!`이나 `BREAKING CHANGE` 커밋 | 쓰는 쪽 코드를 고쳐야 하는 호환성 파괴 |
| Y | `feat` 커밋 | 기존 사용법을 그대로 둔다 |
| Z | `fix`만 있음 | 기존 동작을 고친다 |

- `0.y.z`에서는 Y를 올릴 때도 호환성이 깨질 수 있다.

## 지난 메이저 수정

- 필요할 때만 그 메이저의 마지막 태그에서 `v{major}` 브랜치(예: `v1`)를 만든다.
- 급한 수정도 `fix/` 브랜치와 PR로 한다. 예외는 없다.

1. 기본 브랜치에 먼저 PR을 낸다.
2. 원래 이슈를 참조하는 백포트 이슈를 만든다.
3. 그 이슈의 브랜치를 `v{major}`에서 분기해 PR을 낸다.
4. 머지한 뒤 새 태그를 붙인다.
