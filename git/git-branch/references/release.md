# 릴리스

- 태그: 기본 브랜치에 `v{X}.{Y}.{Z}`. 요청이 있을 때만
- 올릴 자리: 마지막 태그 이후 커밋 기준. 앞자리를 올리면 뒷자리는 0
- X 올림: `!` 또는 `BREAKING CHANGE` 커밋. 쓰는 쪽 코드 수정이 필요한 호환성 파괴
- Y 올림: `feat` 커밋. 기존 사용법 유지
- Z 올림: `fix`만. 기존 동작 수정
- `0.y.z`: Y 올림에도 호환성 파괴 가능
- 지난 메이저 수정: 그 메이저의 마지막 태그에서 `v{major}` 브랜치(예: `v1`) 생성. 필요할 때만
- 수정 순서: 기본 브랜치에 먼저 PR → 원 이슈를 참조하는 백포트 이슈 → 그 이슈 브랜치를 `v{major}`에서 분기해 PR → 머지 후 새 태그
- 급한 수정도 `fix/` 브랜치 + PR. 예외 없음
