# 새 저장소 보드 초기화

새 저장소의 작업 보드를 만들고, 자동화를 설정하고, 실제로 동작하는지 확인한다.

## 범위

- 개발 요청에는 그 저장소의 작업 보드를 만들고 설정하는 일까지 든다. 따로 설정 요청을 기다리지 않는다.
- GitHub 원격이 없거나 사용자가 생략하라고 했으면 하지 않는다([과업 연결](../SKILL.md#과업-연결과-기록)).
- 소유 조직의 금지 정책이나 권한 부족을 우회하지 않는다.

## 스크립트

처음에는 다음 명령을 실행한다.

```sh
python3 <이 스킬 폴더>/scripts/project_bootstrap.py --repo owner/name
```

- macOS나 Linux, Python 3.9 이상, 표준 라이브러리, 인증된 gh와 프로젝트 쓰기 권한이 필요하다.
- 출력 JSON의 project.number와 url을 쓴다. 번호를 짐작하지 않는다.
- 보드가 없으면 비공개 프로젝트를 만들고, 저장소에 잇고, 다섯 상태와 BOARD, 완료 제외 필터를 설정한다. 기존에 연결된 보드가 하나면 다시 쓰고, 여럿이거나 닫힌 보드면 `--project`로 고른다. 기존 보드의 값과 뷰를 마음대로 초기화하지 않는다.
- 다시 실행하면 `~/.config/skills/project-locks`의 저장소별 잠금 안에서 원격을 다시 조회한다. 만든 직후 연결에 실패하면 출력 URL을 확인해 복구하고 새 보드를 다시 만들지 않는다. 다른 호스트에서 동시에 만드는 것은 막지 못하므로 만드는 담당을 하나로 둔다.
- 제한된 CLI에서는 잠금 디렉터리와 현재 작업 기록 경로에만 쓴다. 샌드박스 전체를 풀거나 권한 거부를 우회하지 않는다.
- `--audit`는 원격을 읽기만 하고 잠금 파일을 만들지 않으며 오류면 2로 끝난다.
- 0으로 끝난 것은 구조 조회와 설정이 성공했다는 뜻일 뿐이다. `automation_verified=false`는 브라우저 검증을 마치지 않았다는 뜻이므로 전체 준비가 끝났다고 보지 않는다.

## 브라우저 설정

- 실행자가 출력 URL을 인증된 브라우저 도구로 열고 아래 설정과 재조회를 한다. 사용자에게 넘기거나 수동 명령만 내놓고 완료라고 하지 않는다.
- 브라우저 도구가 없으면 미완료로 기록하고, 쓸 수 있는 연결이 생기면 그 자리에서 이어서 설정한다.
- 호스트 연결은 지금 도구 목록의 브라우저 도구를 실제로 한 번 불러서 확인한다. MCP 목록만 보고 접근할 수 있다거나 없다고 단정하지 않는다.
- 사이트 승인이나 인증이 거부되면 실패한 동작과 이유를 보고하고 승인을 요청한다. 다른 도구로 우회하지 않는다.

| 위치 | 반드시 할 설정과 재조회 |
|---|---|
| 지정 작업 뷰 | Board, Group by Status, 보류 표시, 완료 제외 필터를 저장한다 |
| Workflows의 Auto-add to project | 저장소를 정확히 고르고 `is:open` 필터와 Enabled를 둔다. Save한 뒤 다시 열어 저장소, 필터, Enabled를 확인한다 |
| Item added to project | 이슈와 PR 모두, Status 대기, Enabled로 둔다 |
| Item closed | 이슈와 PR 모두, Status 완료, Enabled로 둔다 |
| Pull request merged | Status 완료, Enabled로 둔다 |
| Auto-close issue | Disabled로 둔다. 카드 이동으로 완료를 판정하거나 이슈를 닫지 않는다 |

- 브라우저 UI에서 지금 보이는 이름과 대상을 조회해서 조작한다. 비공개 API, 쿠키 추출, 고정 좌표 짐작, 워크플로 이름만 보는 것으로 설정 확인을 대신하지 않는다.

## 실제 검증

1. 처음 여는 이슈를 만든다.
2. set, bind, `check --fix` 없이 자동으로 올라가 대기가 됐는지 조회한다.
3. 착수해 bind한다.
4. 상태마다 set한다.
5. 완료 근거를 기록하고 닫는다.
6. 손으로 보정하지 않고 자동으로 완료가 됐는지 조회한다.

- 실패하면 설정 위치로 돌아간다. `check --fix`로 고친 결과를 자동화가 통과했다고 표시하지 않는다.
- 검증용 독립 이슈는 실제 보드 동작을 관측하는 조건으로 쓰고, 성공 근거를 남긴 뒤 닫는다. 다시 실행하면 열린 검증 이슈를 다시 쓴다. 업무와 관계없는 운영 이슈를 시험 대상으로 바꾸지 않는다.
- 기존 저장소에서 자동화가 없어지거나 동작하지 않으면 같은 절차를 다시 한다. 브라우저 전체 검사는 처음 설정, 변경, 실패 때만 하고 상태 전환마다 되풀이하지 않는다.
