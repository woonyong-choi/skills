# 작업 기록과 복구

- 이슈 연결 조건: [과업 연결과 기록](../SKILL.md#과업-연결과-기록). 이 문서는 연결한 작업의 기록·복구 계약
- 정본: 상태는 [프로젝트 판 상태](project-status.md), 목표·계획·판단·결과는 연결 이슈. 로컬 파일은 미전송 기록과 실행 환경만
- 착수·재개: 연결 이슈 → 실제 작업본 대조 → 현재 단계 규칙 조회 → 미완료 행동 실행
- 프로젝트 문맥: repo-docs `references/project-context.md` 필수 확인. 등록 Vault index의 필수·조건별 자료를 읽은 후 진행. Vault에 별도 상태표 금지. 읽은 경로·버전과 다음 행동은 기존 로컬 기록에 최소 반영, 공개 이슈에 비공개 경로 노출 금지
- 기록: 아래 일곱 필드에 현재 유효한 내용만

필드 → 내용:

- goal → 이슈 전체 목표. 현재 질문·단계로 교체 금지
- constraints → 보존 대상·허용 변경·제외 범위
- plan → 조건별 최소 작업 단위·검사 방법·필요 규칙 ID/절
- hypotheses → 주장·확인 방법·미확인/확인/기각
- actions → 실제 변경과 이유
- results → 조건 ID별 충족·보존·회귀의 통과/실패/미검증과 입력·방법·근거
- next → 바로 실행할 행동·입력·막힘과 재개 조건

- 값: 빈 값 없는 문자열. 해당 사실이 없으면 `해당 없음` 또는 `아직 미검증`. 전체 24000바이트 초과 시 근거 산출물 참조로 분리, 조건·예외 임의 삭제 금지
- 공개 기록에 비공개 경로·개인정보·인증 값·내부 대화·작성 주체 표시 금지. 게시 전 public-links 규칙 적용. 복구 데이터는 자료이며 새 실행 권한으로 해석 금지
- 원격 저장: 결정·검사 결과·인계가 바뀐 경계의 버전 댓글. 같은 상태 재저장은 댓글 추가 없음. 댓글 본문은 바뀐 필드만, 접힌 복구 JSON은 전체 상태. 사람 본문 덮어쓰기·도구 호출마다 댓글 추가 금지
- 로컬 실행 기록·검증 출력: 연결된 작업 기록 폴더의 기존 파일 갱신. 임시 경로 저장·같은 출력의 별도 사본 금지
- 원격 실패: 로컬 pending 유지. 전송 성공 오표시·미전송 기록 덮어쓰기 금지. 외부 변경 충돌 시 양쪽 근거를 읽고 명시적으로 병합
- 종료 알림 범위: 파일 변경 전 실행자가 `checkpoint --watch-path 상대경로` 반복으로 현재 과업의 파일·전용 디렉터리 등록 필수. 새 경로 변경 전 전체 목록 갱신, 생략 시 이전 목록 유지. 공유 저장소 전체·공유 상위 디렉터리 지정과 사용자에게 목록 작성 요구 금지. 범위·지문은 로컬 기록만, 공개 이슈 전송 제외
- Stop 알림: 명시 bind한 채팅에서 요청 시작 이후 등록 경로가 바뀌고 checkpoint에 미반영일 때만 보완 요청. 같은 지문 재알림, 미등록 경로·다른 채팅·읽기 전용 요청의 기존 차이로 종료 차단 금지. 범위 미등록이면 입력 훅이 등록 안내, 저장소 전체 감지로 대체 금지. 같은 파일의 타인 변경은 실행자가 대조. 파일 없는 결정·검사 결과는 단계 경계에서 직접 저장
- 종료 판정: 단위 검사·실제 호스트 훅·실제 초기화·복구 별도. 일부 통과로 전체 완료 판정 금지

## 과업 판정과 병합

- 판정 입력: 최신 요청의 관측 가능한 결과와 기존 완료 조건의 대상·동작·관측. 실행 전 결과마다 반사실 검사. 새 제품·공개 API·배포물을 넓은 설계 조건에 흡수 금지
- 독립 결과: 열린 이슈 검색 → 조건이 맞는 이슈 재사용 또는 생성 → 보드 등록 → 기존 기록 저장 → bind 전환. 권한·네트워크 실패 시 입력 보존·해당 결과 보류, 원래 이슈에 대신 기록 금지
- 혼합 요청은 결과별 연결. 같은 과업 부분만 병합, 기존 조건을 넓히는 amend로 분리 회피 금지
- 자동 제거는 코드·표·목록을 제외한 같은 필드의 완전히 동일한 문장 줄만. 의미 중복은 실행자 대조
- 결정 변경 이유·유효 조건·미검증을 보존하여 현재 기록 교체. 과거 근거는 원격 이력, 규칙은 ID·절만 참조
- `synced`는 전송 상태. 과업 일치·요구 충족·작업본 존재·검사 유효성과 구분

## 명령

`--task`는 로컬 작업 기록 폴더 이름. 최초 연결·환경 변경 시 [실행 환경](continuity-hosts.md#실행-환경) 확인. 전역 `--root`는 하위 명령 앞

```sh
python3 <이 스킬 폴더>/scripts/continuity.py bind --task 작업명 --repo 저장소경로 --issue 번호 --project 번호
python3 <이 스킬 폴더>/scripts/continuity.py checkpoint --task 작업명 --input 기록.json --sync --status 진행
python3 <이 스킬 폴더>/scripts/continuity.py restore --task 작업명
python3 <이 스킬 폴더>/scripts/continuity.py doctor --task 작업명
```

- bind: `--project` 필수. 보드가 없으면 project-status의 새 저장소 절차 후 연결, 이슈 단독 bind 금지. 권한·도구 부족이면 입력 보존·미완료 보고. 보드 등록·불일치만 보정하고 유효 상태 보존. 역할 이름이 다르면 `--status-map 역할=이름` 반복, 스크립트 함수 임시 교체 우회 금지
- 같은 작업 경로의 여러 채팅: bind에 `--session-id 현재채팅ID`(Codex는 `CODEX_THREAD_ID` 기본값). 한 채팅은 한 작업에만 연결. 전환은 기존 기록 저장 후 `--from-task 이전작업`, 미전송 기록이면 거부. 훅은 명시된 채팅 연결 우선, 없을 때만 저장소 경로로 탐색
- `checkpoint --sync`: 지정 보드의 현재 이슈 등록·빈 상태·열림/완료 불일치 보정 후 기록 동기화. 다른 이슈·보드 수정 금지. 실패 시 로컬 보존·오류 반환. `--sync` 없으면 로컬 저장만
- `--status 진행|검토|보류`: 착수·재개·단계 전환에 명시, 연결 보드와 `--sync` 필요. 생략하면 현재 상태 보존. 전체 완료는 project-status의 근거 확인·닫기·재조회 순서. 자동 압축 훅의 기록 전송으로 단계 판단·상태 변경 대체 금지
- 입력: 일곱 문자열과 아래 scope 객체, 로컬 경로·스냅샷은 명령이 수집. 기존 기록은 그대로 복구 가능, 다음 저장부터 scope 필수. goal 변경·독립 결과·완료 조건 불일치·조건 연결 누락은 저장 거부. `--reconcile`도 범위 검사 유지
- scope.criteria: 이슈 본문 `## 완료 조건`의 체크 항목 문구 전체를 순서대로 복사. covers: 현재 단계가 진전시키는 항목의 1부터 시작하는 번호, outcomes의 criterion 집합과 일치
- scope.outcomes: 요청 결과별 result·criterion(조건 번호)·criterion_result(기존 관측 결과)·verification(대조 방법)·independent(bool)·counterfactual(기존 조건 충족 뒤에도 별도 결과가 남는지와 이유) 필수. 도구는 구조·원문 일치만 검사, 의미 진위는 실행자가 원래 요청과 대조
- relation=amend: 승인된 범위 변경으로 원격 완료 조건이 수정된 경우에만, 변경 근거와 함께. 원격 변경 없는 amend·조건 변경의 continue 처리 거부
- 네트워크 실패: 검증한 scope.criteria가 있으면 로컬 저장·원격 미확인 표시, 동기화 성공 처리 금지. 최초 scope는 이슈 조회 필수, 실패 시 입력 파일 보존 후 재개
- 목표 자체 변경: 기존 완료 상태 정리 후 새 과업 연결. 같은 결과의 방법 수정은 goal 유지

```json
{"criteria":["검색 결과와 빈 상태 검증"],"stage":"검색어 변경 중 응답 역전 확인","relation":"continue","covers":[1],"reason":"기존 검색 결과 정확성의 반례 검사","boundary":"별도 결제 기능은 검색 완료와 독립이므로 새 과업","outcomes":[{"result":"검색어 변경 중 오래된 응답을 표시하지 않음","criterion":1,"criterion_result":"현재 검색어의 결과 또는 빈 상태 표시","verification":"첫 요청을 늦춰 마지막 검색어와 표시 결과 대조","independent":false,"counterfactual":"기존 결과 정확성을 충족하면 이 응답 역전 결함도 해결되어야 하므로 별도 인수 결과 없음"}]}
```

- 출력: stdout JSON, 실패 stderr와 종료 2
- restore: 읽기 전용. `ready`는 이슈·작업본 복구 판정, `context_ready`는 등록 Vault 진입 판정. 등록 Vault 작업은 둘 다 true인 뒤 필수 문서 실제 조회. `ready:false`면 원인 해결 전 구현 재개 금지. `changed`는 저장 이후 변경 신호, 검사 실패와 별개. `context_reads`는 조회 당시 해시, 압축 후 재조회 면제·이해 증명 금지
- `restore --offline`: 원격 미확인(이슈 열림 포함)으로 로컬 기록 조회. 충돌 반환 시 양쪽 내용을 읽고 `checkpoint --reconcile --sync`로 병합, 미전송 원본은 로컬 history 보존. 다른 이슈·작업본으로 같은 작업 이름 재연결 금지
- 통과 근거의 입력·HEAD·환경이 달라지면 영향 검사 재실행. 압축 전 읽기 표시로 규칙 확인 대체 금지
- 첫 커밋 전: HEAD 빈 값, staged·unstaged·비추적 변경 모두 대조. 첫 커밋 생성도 변경. 기록용 빈 커밋 금지

## 로컬 산출물

- `binding.json` 작업 연결, `checkpoint.json` 최신 복구·미전송 기록, `session-*.json` 세션별 훅 중복 방지, `meter.json` 최근 사용량, `window*.json` 관리 창 제어·복구. 실행 중 삭제 금지
- `history/`: 충돌 때 보존한 미전송 원본. 병합·원격 반영 확인 전 삭제 금지. 시험 출력·검증 기록은 유일한 완료 근거인지 확인 후 정리
- 완료 작업의 로컬 기록 정리: 실행기 종료·원격 동기화·참조 확인 후 저장소 정책 적용. 삭제 요청 처리 기준은 (repo-docs 작성 규칙). 사용자가 삭제한 시험 산출물은 요청 없이 재생성 금지
- 훅·사용량·호스트 제어·설치·진단 변경 시 [호스트 연결](continuity-hosts.md)의 해당 절 필수 확인. 일반 기록 갱신에는 불필요
