# 공개 웹 링크

GitHub에 게시하는 글의 파일과 코드 위치는 공개 웹 링크로 쓰고, 공개되지 않은 위치는 드러내지 않는다.

## 적용 범위

- GitHub 이슈, PR 본문, 리뷰, 댓글에 쓰는 파일, 문서, 코드 위치에 적용한다.
- 저장소 안 문서끼리의 상대 링크에는 적용하지 않는다.

## 링크 규칙

- 파일과 문서 위치는 짧은 경로나 이름을 링크 글자로 쓰고 웹 주소를 건다.
- 코드 줄은 `https://github.com/{소유자}/{저장소}/blob/{커밋 SHA}/{경로}#L{시작}-L{끝}`로 건다. 계속 바뀌는 문서는 기본 브랜치 주소를 쓴다. 기본 브랜치는 저장소를 조회해서 얻는다.
- 공개되지 않은 위치에는 링크를 걸지 않고 경로도 적지 않는다. 로컬 폴더, 홈 폴더, 저장소 밖 작업 폴더(worktree의 `{이름}.wt` 등), 커밋하지 않는 폴더(`.local` 등)가 여기에 든다. 근거가 있다는 것만 밝혀야 하면 `비공개 원자료`처럼 존재만 적고, 공개해도 되는 내용만 본문에 요약한다.
- 비공개 저장소 링크는 같은 저장소의 이슈, PR, 리뷰, 댓글에서만 쓴다. 다른 저장소에서는 참조하지 않는다.
- `github.com`과 `www.github.com`의 `user-attachments/assets/`와 `user-attachments/files/` 아래 첨부 주소는 저장소 주소로 조회하지 않고 보존한다. 첨부의 존재나 접근 권한을 확인하는 검사는 아니다.
- 같은 호스트의 `advisories/GHSA-xxxx-xxxx-xxxx` 보안 권고 주소도 저장소로 조회하지 않는다. 권고 내용이나 영향 버전을 확인하는 검사는 아니다.

## 경로 판정

- 절대 경로, 홈 경로, Windows 경로, file URL은 토큰 시작에서만 비공개 경로로 판정한다. 토큰 시작은 줄 시작, 공백, 여는 괄호, 여는 대괄호, 여는 중괄호, 따옴표, 백틱, `<` 뒤를 말한다.
- 상대 경로 낱말 중간의 `/`는 판정하지 않는다. `.local` 경로 요소와 토큰 시작의 `../`는 계속 막는다.
- HTML 닫는 태그는 경로로 검사하지 않는다.
- 인라인 코드 전체가 `GET /query/x`, `POST /query`처럼 대문자 HTTP 메서드와 `/`로 시작하는 요청 경로이면 보존한다. 메서드는 `GET`, `HEAD`, `POST`, `PUT`, `DELETE`, `OPTIONS`, `TRACE`, `PATCH`이고 사이에는 공백 하나를 쓴다. 경로에 공백이 있거나 `//`로 시작하면 이 예외를 적용하지 않는다. `.local`과 worktree 경로 마디는 요청 경로에서도 계속 막는다. 메서드 없는 `/query/x`는 절대 파일 경로와 구별할 수 없어 계속 막는다.
- worktree 경로는 같은 토큰 시작 경계에서 `{이름}.wt/`로 시작하거나 경로 마디 하나가 정확히 `{이름}.wt`이면 막는다. 이름은 한 글자 이상이다. 백틱 안과 밖, 링크 대상에 모두 적용한다.
- `a.wt.md`, `docs/x.wtf/a.md`, `foo.wtx/a`처럼 `.wt` 뒤에 마디 이름이 이어지면 worktree 규칙을 적용하지 않는다.

## 검사

이슈, PR, 리뷰, 댓글을 게시하기 전에 다음 검사로 위반이 0개인지 반드시 확인한다. 본문은 표준 입력(heredoc 등)으로 넘긴다.

```sh
python3 <이 스킬 폴더>/scripts/public_links.py --repo <게시 대상 저장소 루트> -
python3 <이 스킬 폴더>/scripts/public_links.py --repo <게시 대상 저장소 루트> --fix -
```

- Python 3.9 이상, 표준 라이브러리, Git, 인증된 `gh`가 필요하다. 원격 `--remote`(기본 origin)의 공개 여부와 기본 브랜치는 `gh repo view`로 조회한다.
- 입력은 표준 입력(`-`이나 생략)이나 UTF-8 파일이다. `--repo`의 기본값은 현재 디렉터리이고, 저장소 상대 경로는 이 루트를 기준으로 푼다.
- 검사 결과는 줄 번호와 함께 표준 출력에 낸다. `--fix`는 고친 본문만 표준 출력에 내고 남은 위반은 표준 오류에 낸다. 원본 파일을 덮어쓰지 않는다.
- 고친 결과는 게시 도구의 본문 인자로 넘기거나 구조화된 파일 도구로 승인된 경로에 저장한다. `>`로 파일에 리디렉션하지 않는다.
- `--fix` 결과는 다시 검사한 뒤 게시한다.
- 종료 코드는 통과하거나 모든 위반을 고치면 0, 위반이 남으면 1, 입력이나 Git이나 공개 여부 조회가 실패하면 2다.

## 진단과 자동 수정

- 링크 규칙 진단은 `relative repository link: replace with a public web link`와 `repository path in code text: replace with a public web link`다. HEAD에 있는 저장소 파일의 상대 링크와 코드 표기는 공개 웹 링크로 바꿀 대상이다. 상대 경로 자체는 게시 금지 대상이 아니다.
- 게시 금지 진단은 `private path`, `path outside repository`, `unpublished file` 뒤에 `do not publish; summarize without its location`이 붙는다. 비공개 위치는 공개 링크로 바꾸지 않고 위치를 뺀 내용만 요약한다. 다른 비공개 저장소는 `private repository: do not publish; summarize without its address`다.
- 자동 수정은 HEAD에 든 저장소 파일만 웹 링크로 바꾼다. 줄 번호가 있으면 현재 HEAD SHA로 고정한다. 비공개 경로와 다른 비공개 저장소 주소는 원문을 그대로 두고 위반만 보고한다.
- 첫 커밋 전에는 일반 이슈 본문 검사를 할 수 있고, 모든 파일을 아직 발행하지 않은 것으로 다룬다. 존재하지 않는 커밋이나 기본 브랜치의 URL을 만들지 않는다.
