# Git Issue

- 우선순위: 해당 주제의 사용자 지시 → 저장소 규칙 → 이 스킬. 중복 규칙은 머리에 연결한 정본 스킬 적용
- 범위: 이슈 종류, 라벨, 제목, 본문 틀, 묶음, 상태, 닫기. 브랜치와 PR 흐름(git-branch), PR 본문(git-pull-request), 커밋 형식(git-commit) 제외
- 필요할 때만 읽기: 제목·본문·댓글 작성·검토 → repo-docs `references/writing.md` 필수 확인; 공통 끝말의 뜻이나 영역 라벨의 scope 단어 → git-commit

## 종류

| 종류 라벨 | 쓰는 때 | 제목 | 예 |
|---|---|---|---|
| `design` | 정해야 할 질문 | `{대상} 결정` | `끊긴 요청 재전송 정책 결정` |
| `build` | 만들 것 확정 | `{대상} {추가/구현/변경}` | `토큰 만료 시 자동 재발급 추가` |
| `bug` | 설계·기대와 다른 동작 | `{대상} {증상} 수정` | `대기 요청 재연결 뒤 중복 전송 수정` |
| `experiment` | 측정·실측 필요 | `{대상} 측정` | `한국어 입력 분류 오류율 측정` |
| `docs` | 문서만 수정 | `{대상} 문서 갱신` | `설치 방법 문서 갱신` |

- 생성 때 라벨: 종류·영역·우선순위 각 하나. 영역은 `area:{scope}`, scope는 커밋 scope 단어
- 제목: 한글, 공백 포함 Unicode 문자 수 20자 이내, 대상이 맨 앞, 종류는 표의 끝말로 표시. 마침표·물음표·라벨 이름·번호 금지. 공통 끝말 뜻: (git-commit 설명), `결정`·`구현`·`측정`은 이슈 전용

### 제목 검사

- 게시 전 `python3 <이 스킬 폴더>/scripts/issue_title.py --kind bug <제목 파일>` 통과 필수. 대상 선두·bug 증상 포함은 직접 확인

- 실행 조건: Python 3.9 이상, 표준 라이브러리. 시험: `python3 -m pytest <이 스킬 폴더>/tests/test_issue_title.py` (pytest 필요)
- 입력: `--kind`는 종류 라벨, 제목은 UTF-8 한 줄 파일(생략·`-`: 표준 입력). 끝 개행 하나 제외한 길이·끝말·대상 검사. 빈 제목·여러 줄·끝말만 있는 제목은 위반
- 출력·종료 코드: 통과는 무출력·0, 위반은 줄 번호와 표준 출력·1, 입력 오류는 표준 오류·2. 원본 수정·GitHub 호출 없음

## 본문

- 작성·검토 전 종류별 틀 필수 확인. 절 이름·순서 유지. 내용 없으면 생략: `원인`, `범위 밖`, `관련`만
- 틀 파일: `.github/ISSUE_TEMPLATE/{종류 라벨}.md`. 파일 머리 `---` 사이에 GitHub 틀 머리말 `name: {종류 라벨}`, `about: {쓰는 때}`, `labels: [{종류 라벨}]`

| 종류 | 하위 문서 |
|---|---|
| design | [design.md](references/design.md) |
| build·docs | [build.md](references/build.md) |
| bug | [bug.md](references/bug.md) |
| experiment | [experiment.md](references/experiment.md) |

- `docs` 이슈: build 틀에서 `계약` 절 제외
- 관련 절: 막는 이슈, 막히는 이슈, 상위 이슈, 설계 문서 링크

## 공개 웹 링크

- 이슈·PR·리뷰·댓글 작성·게시 전 [공개 웹 링크](references/public-links.md)의 규칙과 검사 명령 필수 확인, 위반 0개와 수정 결과 재검사 후 게시

## 우선순위

| 라벨 | 색 | 기준 |
|---|---|---|
| `P0` | `B60205` | 이미 쓰는 기능의 장애: 데이터 손실, 보안·권한 우회, 같은 작업 두 번 실행, 사용자 몰래 진행, 멈춤·실행 불가 |
| `P1` | `D93F0B` | 프로젝트의 지금 목표(README나 마일스톤에 적힌 핵심 흐름)를 끝까지 동작하지 못하게 하는 문제 |
| `P2` | `FBCA04` | 공개·배포에 꼭 필요함, 또는 README 핵심 사용 경로 또는 저장소의 사용 빈도 기준에 해당하는 기능의 품질 저하 |
| `P3` | `C5DEF5` | 개선, 측정, 정리, 나중에 필요할 때 할 일 |

- 기준 둘 이상: 높은 우선순위
- 막는 이슈: 막히는 이슈 중 가장 높은 우선순위. `design`, `experiment` 이슈는 결정이 막는 작업의 우선순위
- 작업 순서: 높은 우선순위 먼저. 같으면 다른 이슈를 막는 것 먼저. 그것도 같으면 오래된 것 먼저
- 다시 매기기: 막힘 관계 변경, 목표 변경, 장애 새 확인

## 묶음과 순서

- 큰 작업(설계 문서 둘 이상 변경, 공개 계약 변경, 이슈 셋 이상): 마일스톤 하나(목표 한 문장·성공 기준). 우선순위와 별개
- 나눈 작업: GitHub 하위 이슈. 순서 제약: GitHub 막힘 관계, 기능이 없으면 관련 절에 `막힘: #번호`
- 한 이슈 = 독립적으로 완료·검증·되돌릴 수 있는 사용자 결과 하나. 독립된 결과는 하위 이슈로 분할 (git-branch 작업 단위)

## 상태

상태 표시: GitHub로만. 이슈 본문, 문서에 상태 기록 금지.

| 상태 | 표시 |
|---|---|
| 할 일 | 열림, 담당자 없음 |
| 진행 중 | 담당자 지정 + 작업 브랜치 (git-branch) |
| 막힘 | 막힘 관계 |
| 끝 | 닫힌 이슈(completed) |
| 안 함 | 닫힌 이슈(not planned) + 이유 댓글 |

## 프로젝트 판 상태

이슈 생성·착수·결과 제출·결정 대기·막힘·재개·닫기, PR 생성·머지 또는 판 초기 설정·검사 전 [프로젝트 판 상태](references/project-status.md) 필수 확인. 사건별 등록·상태 이동과 실패 처리는 이 문서가 정본

## 범위 변경

- 완료 조건의 범위 변경: 이슈 댓글의 남은 작업표 갱신: 남은 작업·바뀐 조건·실행/대기/재작업별 시간 추정과 단위. 작업일은 하루 작업 시간 명시

## 닫기

| 경우 | 연결·닫는 방법 |
|---|---|
| PR로 이슈 완료 조건 모두 충족·체크 | PR에 `Closes: #번호` |
| 관련 작업, 일부 완료 | PR에 `Refs: #번호` |
| 다른 PR로 이미 완료 | `완료 근거: #{PR 번호}`, `닫는 이유: {조건 충족 이유}` 댓글 뒤 수동 닫기 |
| design | 결정 댓글 뒤 완료 조건을 충족한 PR로 닫기 |
| 안 함 | 이유 한 문장. 중복이면 `#번호와 중복` |

- 독립 추적이 필요 없는 형식, 주석, 죽은 코드, 문서 동기화 정리: 이슈 없이 PR 허용

결정 댓글. 구현 규칙을 바꾸지 않는 결정만 `동작 계약` 생략 가능

```text
## 결정

{고른 선택지 한 문장}

## 이유

{정하는 기준에 비춰 한두 문장}

## 동작 계약

{구현 의미·경계: 순서·실패·기존 동작 유지·금지. 작업자에게 맡길 이름·구체 문법·기본값 명시}

## 완료 조건

- [ ] {충족할 조건} (확인: {시험 이름·명령·관측 대상 중 하나})

## 반영

{갱신할 설계 문서·후속 이슈·이 이슈를 닫는 시점}. 결정 뒤 같은 질문으로 사용자 선택을 다시 기다리지 않는다.
```

- 닫은 이슈 재오픈 금지. 같은 문제 재발 시 새 이슈에 이전 이슈 링크

## 금지

- 한 이슈에 종류 둘 이상, 다른 이슈 작업 섞기
- 우선순위 라벨 없는 열린 이슈, 우선순위 라벨 둘 이상
- 완료 조건 없는 이슈
- 실제 근거 없이 완료 조건 체크
- 결정 댓글 없이 design 닫기
- 본문, 댓글에 비공개 기록 링크나 내용
- 제목·본문·댓글의 AI 흔적: `Co-Authored-By`, `Generated with`, 로봇 이모지(`U+1F916`), 모델 이름을 붙인 작성 표시, 생성 문구, 세션 링크
