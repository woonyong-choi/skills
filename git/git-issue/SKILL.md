# Git Issue

- 우선순위: 사용자 지시 → 저장소 규칙 → 이 스킬. 범위 밖은 명시한 소유 스킬 적용
- 범위: 이슈 종류, 제목, 본문 틀, 다음 작업, 묶음, 상태, 닫기. 브랜치와 PR 흐름(git-branch), PR 본문(git-pull-request), 커밋 형식(git-commit) 제외
- 필요할 때만 읽기: 제목·본문·댓글 작성·검토 → repo-docs `references/writing.md` 필수 확인; 공통 끝말의 뜻 → git-commit

## 과업 연결과 기록

- 작업 착수·결정·구현 단위·검사 종료·압축·재개 전 [작업 기록과 복구](references/continuity.md) 필수 확인
- 개발 조사·기능·수정·리팩터링·UI 개선: 작업 전 이슈 연결 필수. 단순 질의응답 제외
- GitHub 원격 없음 또는 사용자 생략 지시: 이슈·판 연결 생략, 결과에 보고, 작업 계속
- 요청 결과를 기존 이슈 완료 조건과 결과별 대조. 미확정 설계 선택은 repo-docs-design 소유
- 과업: 이슈 하나의 완료 조건으로 추적하는 작업. 기존 조건을 모두 충족해도 별도 완료 결과가 남으면 독립 과업. 열린 이슈 재사용 또는 생성·보드 등록 후 bind(로컬 작업 기록과 이슈·보드 연결)
- 기존 결과의 방법 비교·반례·설명·결함 수정·작은 정리는 같은 과업. 같은 저장소·주제라는 이유만으로 병합 금지
- 전체 goal 유지. 현재 단계·조건 연결·분리 근거는 scope에 기록
- 결정·구현 단위·검사 종료 때 유효한 계획·가설·처리·결과·다음 행동을 checkpoint(작업 기록 저장)에 병합. 가설을 사실로, 계획을 처리로 승격 금지

## 종류

종류 → 쓰는 때 → 제목 → 예:

- `design` → 정해야 할 질문 → `{대상} 결정` → `끊긴 요청 재전송 정책 결정`
- `build` → 만들 것 확정 → `{대상} {추가/구현/변경}` → `토큰 만료 시 자동 재발급 추가`
- `bug` → 설계·기대와 다른 동작 → `{대상} {증상} 수정` → `대기 요청 재연결 뒤 중복 전송 수정`
- `experiment` → 측정·실측 필요 → `{대상} 측정` → `한국어 입력 분류 오류율 측정`
- `docs` → 문서만 수정 → `{대상} 문서 갱신` → `설치 방법 문서 갱신`

- 종류 구분: 제목 끝말과 고른 틀. 라벨 미사용
- 제목: 한글, 공백 포함 Unicode 문자 수 20자 이내, 대상이 맨 앞, 종류는 위 목록의 끝말로 표시. 마침표·물음표·번호 금지. 공통 끝말 뜻: (git-commit 설명), `결정`·`구현`·`측정`은 이슈 전용

### 제목 검사

- 게시 전 `printf '%s\n' '<제목>' | python3 <이 스킬 폴더>/scripts/issue_title.py --kind <종류> -` 통과 필수. 대상 선두·bug 증상 포함은 직접 확인
- 실행 조건: Python 3.9 이상, 표준 라이브러리
- 입력: `--kind`는 종류, 제목은 표준 입력(`-`·생략) 또는 UTF-8 한 줄 파일. 끝 개행 하나 제외한 길이·끝말·대상 검사. 빈 제목·여러 줄·끝말만 있는 제목은 위반
- 출력·종료 코드: 통과는 무출력·0, 위반은 줄 번호와 표준 출력·1, 입력 오류는 표준 오류·2. 원본 수정·GitHub 호출 없음

## 본문

- 종류별 틀(코드 블록 안)을 채워 `gh issue create --body-file -`(표준 입력, 임시 파일 금지). 절 이름·순서 유지. 올리기 전 주석과 해당 없는 절 삭제
- 틀 정본: 아래 파일만. 저장소별 `.github` 틀·계정 `.github` 저장소 생성 금지
- 이슈 연결: GitHub 하위 이슈·막힘 관계

종류 → 틀:

- design → [design.md](references/design.md)
- build → [build.md](references/build.md)
- bug → [bug.md](references/bug.md)
- experiment → [experiment.md](references/experiment.md)
- docs → [docs.md](references/docs.md)

- 댓글 틀(결정·범위 변경): 채워서 `gh issue comment --body-file -`. 개조식 명사 끝, 처리 확인 항목은 체크박스와 증거(경로·#번호·링크), 주석과 해당 없는 줄 삭제

## 공개 웹 링크

- 이슈·PR·리뷰·댓글 작성·게시 전 [공개 웹 링크](references/public-links.md)의 규칙과 검사 명령 필수 확인

## 다음 작업

고르는 순서: 사용자가 지정한 이슈 → 다른 이슈를 막는 이슈 → 대기 중 가장 오래된 이슈

순서 제안 기준(사용자에게 순서를 제안할 때만, 위가 높음):

1. 이미 쓰는 기능의 장애: 데이터 손실, 보안·권한 우회, 같은 작업 두 번 실행, 사용자 몰래 진행, 멈춤·실행 불가
2. 프로젝트의 지금 목표(README나 상위 이슈에 적힌 핵심 흐름)를 끝까지 동작하지 못하게 하는 문제
3. 공개·배포에 꼭 필요함, 또는 README 핵심 사용 경로 또는 저장소의 사용 빈도 기준에 해당하는 기능의 품질 저하
4. 개선, 측정, 정리, 나중에 필요할 때 할 일

## 묶음과 순서

- 큰 작업(설계 문서 둘 이상 변경, 공개 계약 변경, 이슈 셋 이상): 상위 이슈 하나 아래 GitHub 하위 이슈로 분할. 순서 제약: GitHub 막힘 관계
- 상위 이슈: 작업 종류의 틀, 완료 조건은 `- [ ] 하위 이슈 전부 완료` 한 줄. 하위 이슈 목록 본문 기재 금지
- 한 이슈 = 독립적으로 완료·검증·되돌릴 수 있는 사용자 결과 하나. 독립된 결과는 하위 이슈로 분할 (git-branch 작업 단위)

## 상태

상태(대기·진행·검토·보류·완료)의 들어가는 조건·머무는 동안·나가는 조건과 닫는 기준 정본: [프로젝트 판 상태](references/project-status.md) 상태표. 이슈 본문·문서에 현재 상태 중복 기록 금지

## 프로젝트 판 상태

판(저장소에 연결한 GitHub Projects v2 보드). 이슈 생성·착수·결과 제출·결정 대기·막힘·재개·닫기, PR 생성·머지 또는 판 초기 설정·검사 전 [프로젝트 판 상태](references/project-status.md) 필수 확인. 사건별 등록·상태 이동과 실패 처리는 이 문서가 정본

## 범위 변경

- 완료 조건: 사용자 결과별 관측·근거 연결. 구현 수단·검사 명령으로 결과 대체 금지
- 완료 조건의 범위 변경: [scope-change.md](references/scope-change.md) 댓글. 시간 추정 미기재

## 닫기

경우 → 연결·닫는 방법:

- PR로 이슈 완료 조건 모두 충족·체크 → PR·커밋에 `Closes: #번호`
- 관련 작업, 일부 완료 → PR·커밋에 `Refs: #번호`
- 다른 PR로 이미 완료 → `완료 근거: #{PR 번호}`, `닫는 이유: {조건 충족 이유}` 댓글 뒤 수동 닫기
- design → [decision.md](references/decision.md) 결정 댓글 뒤 반영 PR로 닫기. 결정으로 생기는 구현 조건은 후속 build 이슈의 완료 조건
- 완료·안 함의 닫는 기준: (프로젝트 판 상태 닫는 기준)

- 정상 완료 뒤 같은 문제 재발은 새 이슈에 이전 이슈 링크

## 금지

- 한 이슈에 종류 둘 이상, 다른 이슈 작업 섞기
- 완료 조건 없는 이슈
- 실제 근거 없이 완료 조건 체크
- 결정 댓글 없이 design 닫기
- 본문, 댓글에 비공개 기록 링크나 내용
- 작성 표시: (git-commit 금지)
