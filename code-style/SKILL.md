# Code Style

- 저장소 안에 같은 역할의 규칙이 있으면 그것 우선. 없으면 이 스킬이 다른 규칙보다 우선
- 범위: 코드 공통 규칙의 정본. 언어별 스킬은 언어별 스킬 절의 항목만 정하고, 그 밖에서 다르면 이 스킬 우선
- 필요할 때만 읽기: 리팩터링 기법 선택 → code-refactoring

## 언어별 스킬

- 작업 언어의 스킬이 있으면 함께 적용. 없으면 이 스킬과 그 언어의 공식 스타일 가이드
- 이름: `code-style-<언어>`. 절 이름은 이 스킬과 같게, 공통 규칙 재기술 금지

언어별 스킬이 정하는 항목. 그 밖의 차이: 언어별 스킬 쪽 수정 대상 오류

- 대소문자 표기와 포맷
- 언어 관례가 있는 이름 형식: 접근자, 생성, 변환, 반복자
- 문법이 언어마다 다른 것: 에러 값·예외·단언, 공개 범위 키워드, 필드 접근 방식(접근 메서드·프로퍼티), 문서 주석 형식, import·모듈 선언
- 에러·로그 메시지의 대소문자·마침표
- 선언 순서에서 언어 문법·공식 규칙 때문에 달라지는 부분: 불변·가변 구분이 없는 필드, 공식 규칙이 위치를 정한 항목(Kotlin companion object 등), import 정렬 도구의 순서
- 테스트 위치
- 라이브러리 기본값: 로그, 에러 타입
- 린터 설정과 검사 명령
- CSS만: 선택자, 값과 단위, 반응형·접근성

| 언어 | 스킬 | 다루는 것 |
|---|---|---|
| Rust | `code-style-rust` | 이름 형식, 에러 처리(thiserror·anyhow), 로그(tracing), 공개 범위·문서 주석, 파일 구성, 테스트 위치, clippy 설정·검사 명령 |
| Kotlin | `code-style-kotlin` | 이름 형식, 에러 처리, 로그(SLF4J), 공개 범위·KDoc, 파일·클래스 구성, 테스트 위치, detekt·ktlint 설정·검사 명령 |
| Python | `code-style-python` | 이름 형식, 예외 처리, 로그(logging), 공개 범위·docstring, 모듈·클래스 구성, 테스트 위치, ruff·mypy 설정·검사 명령 |
| JavaScript | `code-style-javascript` | 이름 형식, 모듈(ESM), 에러 처리, 로그, 공개 범위·JSDoc, 테스트 위치(node:test), ESLint·Prettier 설정·검사 명령 |
| CSS | `code-style-css` | class 이름, 파일 구성, 속성 순서, 선택자, 값과 단위, 반응형·접근성, Stylelint 설정·검사 명령. 함수·에러·로그 항목은 해당 없음 |

## 원칙

| 원칙 | 규칙 |
|---|---|
| 표기와 포맷 | 대소문자 표기, 포맷: 언어 공식 관례와 포매터. 이 스킬은 그 밖의 것 |
| 클래스 없는 언어 | 클래스 → struct·trait·module, 상속 → 조합·인터페이스로 바꿔 적용 |
| 예시 이름 | snake_case·PascalCase 표기. 실제 표기는 언어 관례 |
| 기능 변경과 리팩터링 분리 | 동작 변경과 구조 변경 동시 진행 금지. 커밋도 분리 (`feat`·`fix` / `refactor`) |
| 작은 단계 | 동작이 그대로인 작은 변경마다 테스트. 실패하면 직전 단계로 복귀 |
| 하는 때 | 기능 추가 직전, 코드를 이해하는 중, 작업하다 발견한 문제, 코드 리뷰 중. 같은 코드가 3곳이면 정리 |
| 하지 않는 때 | 앞으로 고칠 일 없는 코드, 새로 짜는 게 더 빠른 코드 |
| 공개 API 변경 | 호출하는 쪽을 한 번에 못 바꾸면: 새 함수 추가 → 기존 함수는 새 함수 호출 + deprecated 표시 → 호출하는 쪽 이전 → 기존 함수 삭제 |
| YAGNI | 지금 쓰는 곳 없는 추상화·설정·계층·인터페이스 금지. 필요해지면 그때 추가 |
| 성능 | 먼저 읽기 쉽게 작성. 프로파일링으로 확인한 병목만 최적화 |
| 이름 | 역할이 드러나게. 쓰는 범위가 넓을수록 구체적으로, 짧은 루프 변수 같은 좁은 범위는 짧게 허용. 세부: 이름 절 |
| 함수 크기 | 설명이 필요한 덩어리는 함수로 추출. 수치: 수치 기준 절 |
| 주석 | 무엇을 하는지는 코드와 이름으로. 일반 주석은 이유, 불확실한 점, 외부 제약에만. 문서 주석: 공개 범위와 주석 절. 비용: 비용 주석 절 |

## 수치 기준

값: 허용 최대

- 권장 최대 초과: 원칙에 따라 분할 판단. 나누지 않으면 이유를 PR 본문에 기록
- 절대 최대 초과: 분할 필수. 린터로 강제할 수 있으면 설정 (언어별 스킬)

| 대상 | 권장 최대 | 절대 최대 | 대응 |
|---|---|---|---|
| 함수 길이 (빈 줄·주석 제외) | 40줄 | 100줄 | 함수 추출, 처리 단계 분리 |
| 함수 매개변수 (`self`·`this` 제외) | 3개 | 7개 | 매개변수 묶음 타입 도입, 객체 통째로 전달 |
| bool 매개변수 | 0개 | 3개 | bool 플래그 인자 제거 |
| 중첩 깊이 (함수 본문 안의 if·for·while·switch) | 2단 | 3단 | early return, 조건문을 함수로 분리, 함수 추출 |
| 조건식 하나의 `&&`·`\|\|` 개수 | 2개 | 3개 | 조건을 이름 있는 변수·함수로 추출 |
| 인지 복잡도 | - | 15 | 함수 추출, 조건문을 함수로 분리 |
| 같은 코드 | 1곳 | 2곳 | 함수 추출 |
| 같은 enum·타입 코드 분기 | 1곳 | 2곳 | 분기를 다형성으로 |
| 파일 길이 (같은 파일 안 테스트 제외) | 300줄 | 750줄 | 타입 분리, 함수 이동 |

## 이름

| 대상 | 규칙 | 예 |
|---|---|---|
| 타입 | 명사 | `Session`, `ProviderConfig` |
| 함수·메서드 | 동사로 시작. 접근자·생성·변환은 언어 관례 (언어별 스킬) | `load_config`, `send_message` |
| bool 반환 함수 | `is`·`has`·`can`으로 시작, 또는 3인칭 동사 | `is_empty`, `has_token`, `contains`, `starts_with` |
| bool 변수·필드 | `is`·`has`·`can`·`should`로 시작 | `is_ready`, `should_retry` |
| 컬렉션 | 복수형 | `sessions`, `pending_jobs` |
| 약어 | 한 단어처럼 표기 | `HttpClient`, `http_client` (`HTTPClient` X) |
| 단위 | 단위를 담는 타입(시간 간격 타입 등) 우선. 숫자 타입이면 단위 접미사 | `timeout_ms`, `size_bytes` |
| 파일·모듈 | 역할 명사. `utils`, `common`, `helpers`, `misc` 금지 (folder-naming과 같은 기준) | `paths`, `retry` |

- 한 개념에 한 단어. `fetch`·`get`·`retrieve` 혼용 금지, 저장소에서 이미 쓰는 단어 사용
- 반대 동작은 정해진 짝: add/remove, begin/end, create/destroy, first/last, get/set, increment/decrement, insert/delete, lock/unlock, min/max, next/previous, old/new, open/close, show/hide, source/target, start/stop
- 줄임말은 널리 쓰는 것만: `id`, `url`, `http`, `db`, `max`, `min`, `len`. `mgr`·`svc`·`usr`처럼 글자를 뺀 줄임말 금지
- 이름에 타입 붙이기 금지: `name_string`, `UserStruct`

## 조건식

비교 순서:

- `판단 대상 연산자 기준값`: `count > 0`, `state == READY`, `elapsed > timeout`
- 상수를 왼쪽에 두는 비교(`0 == x`) 금지. 실수로 인한 대입(`if (x = 0)`)은 컴파일러·린터로 차단
- 범위 검사만 예외로 수직선 순서: `min <= x && x < max`. `>`·`>=`로 뒤집기 금지
- bool은 그대로: `if is_ready`, `if !is_ready`. `== true`·`== false` 금지
- 이중 부정 금지: `!is_not_empty` 대신 `is_empty`
- if·else가 모두 있으면 긍정 조건을 if에

`&&`·`||` 순서:

1. 뒤 조건의 전제가 되는 검사 먼저: `i < size && items[i] > 0`
2. 그다음 싼 검사 먼저: 변수·필드 → 순수 함수 호출 → I/O·잠금
3. 부작용 있는 호출은 조건식에 넣기 금지 (단락 평가로 실행 여부 변동)

- `&&`와 `||`를 섞으면 괄호 필수: `(a && b) || c`
- 예외·오류 경우는 early return으로 먼저 처리, 정상 흐름은 들여쓰기 없이
- switch·match 분기는 enum 선언 순서. default는 마지막

## 선언 순서

포매터가 바꾸지 않는 순서: 직접 유지. 새 선언은 끝에 덧붙이지 않고 아래 순서의 자리에. 없는 항목은 생략

파일:

1. 파일 설명 주석
2. import. 언어의 정렬 도구가 순서를 정하면 그 순서. 없으면 표준 라이브러리 → 외부 라이브러리 → 같은 프로젝트, 그룹 사이 빈 줄
3. 하위 모듈 선언 (언어에 있으면)
4. 상수·정적 변수
5. 타입. 공개 먼저. 타입 정의와 그 메서드 구현은 붙여 배치
6. 자유 함수. 공개 → 비공개
7. 같은 파일 안 테스트 (언어 관례가 그렇다면)

타입:

| 순서 | 대상 | 예·기준 |
|---|---|---|
| 1 | 상수 | `MAX_RETRY` |
| 2 | 정적 필드 | `static` |
| 3 | 불변 필드 | `final`, `readonly`, `val` |
| 4 | 가변 필드 | |
| 5 | 생성자·팩토리 | |
| 6 | 프로퍼티·접근자 | get → set, 필드 선언 순서대로 |
| 7 | 생명주기 메서드 | `init` → `update` → `close`, 불리는 순서대로 |
| 8 | 공개 메서드 | 주요 로직 |
| 9 | 비공개 헬퍼 | 처음 호출되는 순서대로 |
| 10 | 검증 | `validate_*`, `check_*`, `ensure_*` |

- 같은 순서 안에서는 공개 → 비공개
- 이름이 이어지는 함수(`parse`, `parse_with`)는 붙여 배치

인터페이스·트레잇:

1. 연관 타입·상수
2. 구현해야 하는 메서드
3. 기본 구현이 있는 메서드

- 구현하는 쪽도 인터페이스 선언 순서

## 에러와 로그

실패 종류별 처리:

| 경우 | 처리 |
|---|---|
| 입력·파일·네트워크·외부 프로세스처럼 일어날 수 있는 실패 | 에러 값·예외로 호출하는 쪽에 전달 |
| 코드에 버그가 없으면 일어날 수 없는 경우 | 단언(assert)으로 중단. 메시지에 성립해야 하는 이유 |
| 테스트 | 단언 실패로 중단 허용 |

- 테스트 밖에서 구현을 미룬 채 실패하는 자리표시 코드 금지
- 에러 전파 시 무엇을 하다 실패했는지 추가: `failed to read config file`
- 라이브러리 공개 API: 호출하는 쪽이 경우별로 처리할 수 있는 에러 종류 반환. 모든 에러를 한 타입으로 묶는 방식은 실행 파일(앱) 코드에서만
- 에러는 한 곳에서 한 번만 처리: 로그 기록이나 전파 중 하나. 로그는 최종 처리하는 곳에서
- 에러를 무시하면 이유를 주석으로. 빈 catch 금지

메시지:

- 에러·로그 메시지는 영어로 짧게. 대소문자·마침표는 언어 관례 (언어별 스킬)
- 관련 값(경로, id) 포함. 비밀번호·토큰·API 키·개인정보 포함 금지

로그 레벨:

| 레벨 | 쓰는 때 |
|---|---|
| error | 작업 실패로 사람의 확인 필요 |
| warn | 실패는 아니지만 예상 밖. 재시도·기본값 대체로 진행 |
| info | 시작·종료·설정 적용처럼 드문 주요 상태 변화 |
| debug | 문제 원인을 찾을 때 필요한 값 |
| trace | 함수 진입, 반복마다의 세부 흐름 정보 |

- 반복마다 찍히는 로그는 debug 이하
- 진단 메시지는 로그 라이브러리로. CLI 도구: 로그는 stderr, stdout은 프로그램 결과에만

## 공개 범위와 주석

- 가장 좁은 공개 범위부터, 필요한 만큼만 확대: 비공개 → 패키지·모듈 안 → 외부
- 필드도 가장 좁은 공개 범위부터. 밖에서 읽고 쓰는 방식(접근 메서드·프로퍼티)은 언어 관례 (언어별 스킬)
- 공개 API는 문서 주석 필수. 첫 줄은 한 줄 요약, 빈 줄 뒤에 자세한 설명
- 문서 주석에 실패 조건(돌려주는 에러·던지는 예외·중단 조건) 기록
- 비공개 항목의 문서 주석은 선택
- 주석 언어: 저장소의 기존 주석. 기존 주석이 없으면 README 언어
- TODO는 이슈 번호와 함께: `TODO(#12): 재시도 횟수를 설정으로 이동`. 이슈 없는 TODO 금지
- 주석에 AI 작성 흔적 금지

## 비용 주석

함수와 알고리즘 단계의 시간·메모리·호출 비용 기록. 개선 대상 선택과 변경 전후 비교에 사용

- 대상: 모든 함수. 생략 조건: 시간 O(1), 힙 할당 없음, 재귀 없음, I/O·모델 호출 없음. 생략은 이 값이라는 뜻
- 함수 안에서 비용이 다른 단계가 둘 이상이면 단계 바로 위에도 기록. 함수 위 값은 전체
- 위치: 선언 바로 위, 문서 주석·attribute·애노테이션·데코레이터보다 위. 주석 기호는 언어의 한 줄 주석
- 키는 영어 고정, 설명 글은 주석 언어
- 린터 줄 길이를 넘는 줄: 같은 키로 다음 줄에 이어 기록

```rust
// cost: time O(n log n), heap O(n), stack O(1), alloc 1
// mem: heap ≈ n·size(Entry)
// vars: n = entries.len()
// basis: estimate
// alt: HashMap 색인. time O(n), heap ≈ n·(size(Key) + size(Entry)). 잃는 것: 정렬 순서
```

| 줄 | 쓰는 때 | 값 |
|---|---|---|
| `cost` | 항상 | `time`, `heap`, `stack` 순서의 O 표기. 0이 아닐 때만 `alloc`(할당 횟수), `io`(파일·네트워크·프로세스 호출 수), `tokens`(모델 호출의 입력 + 출력 토큰) 추가 |
| `mem` | 크기 식을 세울 수 있을 때 | 최대 피크 바이트 식. 변수와 `size(타입)`, 스택은 `frame`(프레임 하나) 기호: `stack ≈ d·frame` |
| `vars` | `cost`·`mem`에 변수가 있을 때 | 변수 정의: `n = entries.len()`, `d = 트리 깊이`. 여럿이면 `, `로 연결 |
| `basis` | 항상 | `estimate`(코드를 읽고 추산) 또는 `measured {벤치마크·테스트 이름}` |
| `alt` | 비용이 다른 대안을 알 때 | 대안 이름, 그 `cost`·`mem`, `잃는 것` |

- 시간: 최악 기준. 평균이 다르면 `time O(n) avg, O(n²) worst`
- `heap`: 이 함수가 새로 할당해 동시에 살아 있는 최대 크기. 입력으로 받은 것 제외, 반환값 포함
- `stack`: 재귀 깊이와 큰 지역 배열 기준. 없으면 O(1)
- 숫자 바이트: 크기가 정해진 타입(`u64` = 8바이트 등)이나 측정값만. 그 밖에는 기호 식(지어낸 수치 방지)
- 코드를 바꾸면 같은 커밋에서 비용 주석 갱신. `basis measured`는 다시 측정하거나 `estimate`로 교체
- 누락·위치 검사: `python3 <이 스킬 폴더>/scripts/check_cost_comments.py <소스 폴더>`, 출력 `total 0`까지 수정. 반복·순회, 재귀, I/O가 보이는 함수만 검사. 잘못 잡힌 함수는 실제 비용(`time O(1)` 등) 기재
- 개선: `cost`·`alt` 비교로 후보 선택. 적용은 성능 원칙(프로파일링으로 확인한 병목)
- Kotlin: ktlint 연속 주석 규칙 때문에 비용 주석과 KDoc 사이 빈 줄

## 테스트

- 성공·실패는 자동 판정
- 새 테스트는 일부러 한 번 실패시켜 제대로 검사하는지 확인
- 테스트마다 테스트 데이터 새로 생성. 테스트끼리 상태 공유 금지
- 경계값, 빈 값, 잘못된 입력 테스트
- 버그 발견 시 재현 테스트부터 작성
- 커버리지·테스트 개수는 목표 아님. 위험한 곳 테스트
- 이름: `대상_조건_결과`. 대상은 테스트하는 함수 이름, 조건이 없으면 생략: `parse_empty_input_returns_error`
- 본문은 준비 → 실행 → 확인 순서. 단계 사이 빈 줄
- 테스트 하나에 동작 하나. assert 여러 개는 같은 동작 확인 때만
- 테스트 위치는 언어 관례 (언어별 스킬)

## 절차

1. 바꿀 동작과 실패하는 경우 결정. 호출하는 쪽, 상태를 가진 쪽, 테스트 읽기
2. 테스트가 없으면 현재 동작을 고정하는 테스트부터 추가
3. 리팩터링이 필요하면 먼저 적용하고 커밋, 그 뒤 기능 변경 시작
4. 끝나면 바꾼 코드를 이름, 조건식, 선언 순서, 에러와 로그, 공개 범위와 주석, 비용 주석 기준으로 확인, 언어별 스킬의 검사 명령과 비용 주석 누락 검사 실행

## 금지

- 테스트 없이 큰 구조 변경
