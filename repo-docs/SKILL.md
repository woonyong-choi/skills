# Repo Docs

- 저장소 안에 같은 역할의 규칙이 있으면 그것 우선. 없으면 이 스킬이 다른 규칙보다 우선
- 범위: 저장소 문서 공통 규칙의 정본. 종류별 스킬은 템플릿, 절 규칙, 그 종류에만 있는 규칙만 정하고, 그 밖에서 다르면 이 스킬 우선(종류별 스킬 쪽이 고칠 오류)
- 필요할 때만 읽기: 코드 주석 → code-style; 커밋, PR, 이슈, 브랜치 → git-* 스킬; 그림 파일, 대체 글 → repo-docs-figures

## 문서 목록

저장소 문서: 아래 표의 파일만. 표에 없는 파일이 필요하면 새 파일 대신 가장 가까운 파일의 절이나 행으로 추가

- `docs/requirements.md`부터 `docs/experiments/README.md`까지 행 순서: `docs/README.md` 표 순서

- 비공개: `docs/archive/**`만. 공개 문서에서 `docs/archive` 링크와 내용 전재 금지
- 파일 문체: 합쇼는 루트 `README.md`, `CHANGELOG.md`, `.github/CONTRIBUTING.md`, `.github/SECURITY.md`. `llms*.txt`는 원본 문서 그대로, `docs/assets/**`는 해당 없음, 나머지 평서
- 제목 칸 `템플릿`: 그 스킬 템플릿의 제목
- 그림 파일 위치: `docs/assets/`와 실험 폴더의 `results/figures/`만. 파일 이름: 영어 소문자 kebab-case

## 템플릿 사용

1. 종류별 스킬의 템플릿 그대로 복사
2. `{...}` 자리에 값 기입. 문장 자리 끝: 마침표. 저장한 문서에 `{`, `}` 잔존 금지(코드 블록 제외)
3. 템플릿 절 조건 표에서 조건이 거짓인 절: 제목까지 삭제
4. 템플릿에 없는 제목, 절, 문단 추가 금지
5. 절 순서 변경 금지
6. 조건이 있는 절: 조건이 참일 때만. 조건이 없는 절: 항상
7. 템플릿 칸을 채울 사실이 없으면 문서 저장 금지, 채우지 못한 칸 목록을 사용자에게 보고. 지어낸 내용 금지. 자리표시 표에 있는 경우만 예외
8. `준비 중`, `추후 작성` 같은 빈자리용 문장 금지

## 문체

파일 문체: 문서 목록의 파일 문체 규칙. 한 파일에 한 문체만

| 문체 | 자리 | 문장 끝 | 예 |
|---|---|---|---|
| 합쇼 | 합쇼 파일의 문단 | `-ㅂ니다`, `-습니다`, `-입니다` | `대화를 SQLite에 저장합니다.` |
| 합쇼 요청 | 합쇼 파일에서 독자에게 하라고 하는 문장 | `-세요` | `다음 명령으로 설치하세요.` |
| 평서 | 평서 파일의 문단 | `-다` | `설정 파일은 홈 폴더에 둔다.` |
| 평서 과거 | 평서 파일의 끝난 일(실험 방법·결과, 결정 기록의 배경, 판단 기록) | `-했다`, `-였다` | `문장 400개를 측정했다.` |
| 명사형 | 모든 파일의 제목, 목록 항목, 표 칸 | 명사구. 종결어미와 마침표 없음 | `- 작업 기록 저장` |

- 절차(번호 목록): 명사구. 주체가 있으면 `{주체}: {동작}`: `1. 서버: 요청 저장`
- 한 문장 표 칸: 템플릿이 `문장 열`로 지정한 표 열만, 그 파일 문체
- 평서 파일: 요청 문장 금지. 할 일은 `-한다` 문장: `다음 명령으로 재현한다.`
- 쓰지 않는 종결: `-해요`, `-십시오`, `-함`, `-음`, `-임`, `-ㄹ 것이다`, `-게 된다`, 합쇼 파일의 `-다`, 평서 파일의 `-니다`와 `-세요`
- 한 목록 안 명사구와 문장 혼용 금지. 문장이 필요한 내용은 문단으로
- 명사구의 동작: 동작 명사. 명사형 어미 `-ㅁ`, `-기` 금지: `찾음` 대신 `검색`, `멈춤` 대신 `중지`
- 문장을 명사구로 바꿀 때 끝 변환: `{명사}한다` → `{명사}`, `같다` → `동일`, `다르다` → `상이`, `있다` → `존재`, `없다` → `없음`(서식 6 표기라 `-ㅁ` 금지의 예외), `할 수 있다` → `가능`, `할 수 없다` → `불가`, 그 밖의 동사: 같은 뜻 동작 명사(`쓴다` → `기록`, `고친다` → `수정`, `둔다` → `배치`). 앞 낱말 그대로, 바로 앞 조사 `이`, `가`, `은`, `는` 삭제: `두 수명이 같다` → `두 수명 동일`
- 질문문, 느낌표, 줄임표 금지
- 인용, 코드, 명령 출력: 문체 규칙 밖
- 평서 원본을 합쇼 파일로 옮길 때: 문장 끝만 변경: `저장한다.` → `저장합니다.`, `없다.` → `없습니다.`, `이다.` → `입니다.` 다른 글자 변경 금지

## 문장

- 한 문장에 사실 하나. 80자 이내
- 주어와 동작 명시: `최적화 수행` 대신 `캐시로 조회 수를 줄인다.`
- 형용사 대신 동작과 수치: `빠른 검색` 대신 `색인으로 검색한다.`
- 같은 대상: 문서 전체에서 같은 이름. 이름 기준: `docs/glossary.md`, 없으면 `docs/architecture.md`
- 사용자가 준 사실, 저장소 원문을 옮길 때: 원문 낱말 그대로. 동의어 교체, 어순 변경 금지. 예외: 용어 표의 교체, 같은 대상 이름 통일, 문체와 명사형을 맞추는 끝 변환
- 이유: 규칙 바로 뒤 한 문장: `{규칙}. {막는 일}을 막기 위해서다.`

## 용어

| 쓰는 말 | 쓰지 않는 말 |
|---|---|
| 로드맵 | 계획, 예정, 향후, TBD, TODO |
| 사용자 | 유저, 고객 |
| 저장소 | 레포, 리포지토리, 레포지토리 |
| 명령 | 커맨드 |
| 설정 | 컨피그, 옵션(명령 옵션은 옵션) |
| 오류 | 에러(코드 식별자 제외) |
| 실행 | 구동 |
| 측정 전 | 미측정, 측정 예정 |
| 합성 데이터 | 더미 데이터, 목업 데이터 |

- 쓰지 않는 수식어: `강력한`, `혁신적`, `쉽게`, `손쉽게`, `간단히`, `간단하게`, `다양한`, `효율적`, `원활`, `최적의`, `완벽한`, `매끄러운`, `차세대`
- 쓰지 않는 연결어: 문장 첫머리 `또한`, `이를 통해`, `이에 따라`, `결론적으로`, `요약하면`, `참고로`, `기본적으로`
- 쓰지 않는 추측: `~것 같다`, `~로 보인다`, `아마`
- 인라인 코드로 쓰는 것: 명령, 경로, 파일 이름, 코드 식별자, 패키지와 crate 이름, 설정 키와 값, 메서드 이름. 예: `cargo test`, `Cargo.toml`, `tokio`, `session/start`
- 일반 글자로 쓰는 것: 제품, 서비스, 언어, 운영체제, 표준 이름. 예: Rust, SQLite, GitHub, JSON-RPC, macOS
- 약어 풀이 금지. 프로젝트가 만든 약어: `docs/glossary.md`에

## 서식

1. 제목: `#` 형식. 문서당 `#` 하나. 단계 생략 금지. 제목 끝 문장부호 없음
2. 블록 사이 빈 줄 하나. 빈 줄 연속 금지. 줄 끝 공백 금지. 파일 끝: 줄바꿈 하나
3. 문단은 한 줄. 문장 중간 줄바꿈 금지
4. 비순서 목록 `- `, 순서 목록 `1.`, `2.`처럼 실제 번호. 목록 중첩 금지
5. 표: 머리 행과 `|---|` 구분 행 필수. 칸 앞뒤 공백 하나. 칸 안 줄바꿈 금지
6. 빈 칸 표기: 값이 0개면 `없음`, 항목이 이 대상에 적용되지 않으면 `해당 없음`. 정하지 않아서 모르는 칸 금지(템플릿 사용 7)
7. 코드 블록: 백틱 세 개와 언어 태그: `sh`, `text`, 또는 코드 언어 이름(`rust`, `toml`, `json`, `python`). 명령 앞 `$` 금지
8. 그림: 이미지 한 줄: `![{대체 글}]({상대 경로})`. 그림 파일이 아직 없으면 그 줄 삭제, 그림을 만들 때 추가. 파일과 대체 글(repo-docs-figures). mermaid와 텍스트 그림 금지(`docs/ui.md` 배치 그림만 예외)
9. 저장소 안 링크: 상대 경로. 링크 글자: 문서 제목, 파일 이름, 또는 템플릿이 정한 문서 종류 이름(`결정 기록`). `여기`, `이 링크` 금지
10. 굵게, 기울임, 이모지, HTML 태그, 각주, 배지 금지
11. 인용 블록: GitHub 알림 두 가지만: `> [!NOTE]`(알아 둘 사실), `> [!WARNING]`(어기면 데이터나 동작을 잃는 규칙). 다음 줄 `> {문장}` 한 줄
12. 숫자와 단위 사이 공백 없음: `5초`, `400줄`, `1MB`. 날짜: `YYYY-MM-DD`
13. 조사: 영문과 코드 바로 뒤, 공백 없음: `tokio를`, `SQLite에`

## 사실 상태

기능과 수치를 문서에 쓰기 전 상태 결정. 상태별로 쓸 수 있는 자리: 종류별 스킬

| 상태 | 근거 |
|---|---|
| 로드맵 | `docs/requirements.md`에 있고 확인 방법의 테스트가 아직 없거나 미통과 |
| 구현 | `main`에 코드가 있고 확인 방법의 테스트 통과 |
| 사용 가능 | 사용자가 실행하는 명령을 실제로 실행해 기대한 출력 확인 |

- 근거 우선순위: 실행 결과 > 코드와 테스트 > 설계 문서 > 대화
- 수치: 실험 결과(`results/summary.json`)나 실행 출력이 있을 때만. 설정 기본값처럼 설계로 정한 값은 예외
- 외부 도구의 버전, 가격, 지원 여부: 확인한 날짜 필수: `(2026-09-30 확인)`
- 근거를 찾지 못한 주장 금지

## 자리표시

아직 없는 것: 아래 표의 것으로만 대체. 가짜 수치, 가짜 화면을 실제처럼 제시 금지

| 아직 없는 것 | 대신 두는 것 | 표시 |
|---|---|---|
| 실행 화면 | 구조도 | 대체 글 앞 `설계:` |
| 모든 기능이 동작하는 화면 | 합성 데이터로 녹화한 데모 | 대체 글 앞 `합성 데이터:`, 화면 안 `합성 데이터` 글자 |
| 측정값 | 값 칸을 `측정 전`으로 둔 표 | 표 바로 위 `> [!NOTE]` |
| 결과 차트 | 예시 데이터 차트 | 파일 이름 끝 `-illustrative`, 차트 부제 앞 `예시 데이터.`, 대체 글 앞 `예시 데이터:` |
| 벤치마크 결과 | 실험 `design.md`와 결과 칸이 `측정 전`인 표 | 표 바로 위 `> [!NOTE]` |

- 알림 문장. 평서: `측정 전 값이다. 측정 방법은 [{실험 제목}]({design.md 경로})에 있다.` 합쇼: `측정 전 값입니다. 측정 방법은 [{실험 제목}]({design.md 경로})에 있습니다.`
- 실제 값이 생기면 표시와 알림 삭제, 값으로 교체

## 저장 전 검사

저장한 파일마다: 저장소 루트에서 상대 경로로 아래 명령 실행, 출력이 없을 때까지 수정. 검사 뒤 절 이름과 순서를 템플릿과 한 줄씩 대조

```sh
python3 <이 스킬 폴더>/scripts/check_doc.py README.md
```

- `<이 스킬 폴더>`: 이 SKILL.md가 있는 폴더. 스크립트 본문은 읽지 않고 실행만. Windows에서 `python3`가 없으면 `py -3`
- 실행 조건: Python 3.9 이상, 표준 라이브러리만. 줄바꿈 CRLF도 같은 규칙. 오류가 있으면 종료 코드 1
- 합쇼 파일: 루트 `README.md`, `CHANGELOG.md`, `.github/CONTRIBUTING.md`, `.github/SECURITY.md`. 나머지는 평서로 검사
- 문체 검사 대상: 문단 끝, 표 칸, 목록 항목 끝. `아니다`, `없음`, `다음`, `포함`, `결함`은 제외. 다른 명사가 걸리면 그대로 유지
- 스크립트 밖이라 손으로 확인: 문장 80자, 목록 안 문장과 명사구 혼용, 명사형 어미 `-ㅁ`, `-기`
- 비공개 경로: 대소문자 무시. `docs/archive`, 링크 대상의 상대 경로 `archive/`, `../archive/`
- 코드 블록: 여는 펜스보다 짧은 펜스는 닫는 줄 아님. 안 닫힌 펜스는 오류. 블록 안 내용은 비공개 경로만 검사
- `llms.txt`, `llms-full.txt`, 그림 원본: 검사 제외(생성 함수의 산출물)

## 교정

교정: 뜻 유지, 규칙에 어긋난 곳만 수정

| 그대로 두는 것 | 예 |
|---|---|
| 사실, 수치, 날짜, 단위 | `171개`, `2026-09-29` |
| 조건과 부정의 범위 | `~일 때만`, `~는 아니다` |
| 인용, 코드, 명령, 출력, 링크 대상 | 해당 없음 |
| 사용자가 확정한 문장 | 해당 없음 |

1. 사실 상태 재결정, 상태와 맞지 않는 문장 이동이나 삭제
2. 템플릿과 절 이름, 순서 일치
3. 문체, 용어, 서식 수정
4. 저장 전 검사 실행

보고: 고친 파일 경로, 사실 상태 때문에 옮기거나 지운 문장만
