# Repo Docs

- 저장소 안에 같은 역할의 규칙이 있으면 그것 우선. 없으면 이 스킬이 다른 규칙보다 우선
- 범위: 저장소 문서 공통 규칙의 정본. 종류별 스킬은 절 이름 목록, 필수 절, 그 종류에만 있는 규칙만 정하고, 그 밖에서 다르면 이 스킬 우선(종류별 스킬 쪽이 고칠 오류)
- 필요할 때만 읽기: 코드 주석 → code-style; 커밋, PR, 이슈, 브랜치 → git-* 스킬; 그림 파일, 대체 글 → repo-docs-figures

## 원칙

1. 독자 우선: 문서마다 정해진 독자와 답할 질문(문서 목록 표). 형식을 지켜도 질문에 답하지 못하면 실패
2. 예시 우선: 개념 설명 전에 동작 장면이나 예시
3. 정직한 상태: 없는 파일, 테스트, 명령, 화면을 있는 것처럼 쓰기 금지. 미정은 미정으로 표시
4. 적고 정확하게: 같은 사실은 한 파일에만, 낡은 문서 삭제, 만드는 조건이 안 된 문서 생성 금지
5. 이름과 자리로 통일: 같은 내용이면 같은 절 이름, 같은 순서, 같은 용어, 같은 상태 표기. 절의 유무, 길이, 예시 수는 문서마다 자유

## 문서 목록

저장소 문서: 아래 표의 파일만. 표에 없는 파일이 필요하면 새 파일 대신 가장 가까운 파일의 절로 추가

| 위치 | 독자 | 답할 질문 | 만드는 조건 | 스킬 `repo-docs-*` |
|---|---|---|---|---|
| `README.md` | 처음 온 사람 | 무엇인가, 왜 필요한가, 어떻게 쓰이나, 지금 쓸 수 있나, 어디서 더 보나 | 항상. 영어 원본 | readme |
| `README.ko.md` | 한국어 독자 | `README.md`와 동일 | 항상. `README.md`의 한국어 번역 | readme |
| `AGENTS.md`, `CLAUDE.md`(링크) | 코딩 에이전트 | 무엇이 어디에 있나, 무엇을 지켜야 하나 | 항상 | root |
| `CHANGELOG.md`, `.github/CONTRIBUTING.md`, `.github/SECURITY.md` | 사용자, 기여자 | 무엇이 바뀌었나, 어떻게 기여하나, 취약점은 어디로 알리나 | README 단계별(repo-docs-root 파일 표) | root |
| `LICENSE` | 모두 | 어떤 조건으로 쓸 수 있나 | 라이선스를 정했을 때(repo-docs-root 파일 표) | root |
| `llms.txt` | LLM 도구 | 어떤 문서가 있나 | `docs/README.md`가 있을 때 | llms |
| `docs/README.md` | 기여자 | 어떤 문서를 어떤 순서로 읽나 | `docs/`에 문서가 둘 이상 | design |
| `docs/architecture.md` | 기여자 | 코드가 어떻게 나뉘나, 무엇이 어디서 일어나나, 깨면 안 되는 조건은 | 항상. 설계 단계 포함 | design |
| `docs/design/{주제}.md` | 기여자, 검토자 | 왜 필요한가, 어떻게 동작하나, 무엇이 아직 미정인가 | 기능이나 동작을 설계할 때, 주제마다 하나 | design |
| `docs/glossary.md` | 모두 | 이 프로젝트만의 말이 무슨 뜻인가 | 프로젝트 고유 용어가 다섯 개 이상 | design |
| `docs/protocol.md`, `docs/cli.md`, `docs/ui.md`, `docs/data.md`, `docs/configuration.md`, `docs/errors.md` | 사용자, 연동 개발자 | 정확한 형식과 값은 무엇인가 | 그 인터페이스가 `main` 코드에 들어간 뒤. 그 전에는 `docs/design/{주제}.md` | spec |
| `docs/decisions/README.md`, `docs/decisions/**` | 기여자 | 왜 이렇게 정했나, 무엇을 버렸나 | 결정 기록이 하나 이상 | decision |
| `docs/experiments/README.md`, `docs/experiments/**` | 기여자 | 설계 값을 어떻게 확인했나 | 실험이 하나 이상 | experiment |
| `docs/notes/**` | 기여자 | 개발 중 무엇을 알게 됐나 | 기록할 insight나 reference가 있을 때 | note |
| `docs/assets/**` | 해당 없음 | 해당 없음 | 문서에 그림이 있을 때 | figures |
| `.local/journal/**`, `.local/stories/**`, `.local/principles.md` | 본인 | 무엇을 왜 판단했나 | 기록할 판단, 큰 작업, 교훈이 있을 때 | journal |
| `.local/promo/**` | 본인 | 무엇을 어떻게 찍나 | 홍보 영상 촬영 준비 때 | promo |
| `.local/reports/{YYYY-MM-DD}-{주제}/` | 본인 | 그림으로 무엇을 결정하거나 확인했나 | 프로젝트 보고서가 있을 때 | html-report |

- `docs/README.md` 표 순서: `architecture.md`, `design/` 문서(읽는 순서), `glossary.md`, spec 문서(위 표 순서), `decisions/README.md`, `experiments/README.md`
- 비공개: `.local/**`만. 저장 전 `git check-ignore .local`로 git 제외를 확인. 제외되지 않으면 저장 금지, 보고
- 공개 문서에서 `.local` 링크와 내용 전재 금지
- 비공개 설계서를 공개 문서로 옮길 때: 확인된 사실만 골라 새로 작성, 원문 문장과 내부 기호 복사 금지
- 그림 파일 위치: `docs/assets/`와 실험 폴더의 `results/figures/`만. 파일 이름: 영어 소문자 kebab-case

## 언어

| 파일 | 언어 |
|---|---|
| `README.md` | 영어. 원본 |
| `README.ko.md` | 한국어. `README.md`의 번역 |
| `CHANGELOG.md`, `.github/**`, `LICENSE` | 영어 |
| `AGENTS.md`, `llms.txt` 밖의 `docs/**` | 작업 언어 하나. `docs/README.md` 첫 문단에 명시 |
| `.local/**` | 한국어 |

- 번역본: 원본과 절, 순서, 목록 항목 수, 그림, 링크, 코드 블록 일대일. 원본을 고치는 PR에서 번역본도 수정
- 언어 전환 줄: 제목 바로 아래 한 줄. 원본 `English | [한국어](README.ko.md)`, 번역본 `[English](README.md) | 한국어`
- 영어 README에서 작업 언어가 영어가 아닌 문서 링크: 문서 절 첫 문장에 언어 표시(repo-docs-readme 문서)

## 절 구성

1. 종류별 스킬의 절 이름 목록에서 필요한 절만 골라 목록 순서대로 배치
2. 필수 절: 종류별 스킬이 단계별로 지정. 필수 절을 채울 사실이 없으면 문서 저장 대신 사용자에게 보고. 설계 문서는 `미해결 질문` 절에 이슈 링크
3. 목록에 없는 절: 독자 질문에 필요할 때만 추가. 위치는 목록에서 내용이 가장 가까운 절 바로 뒤. 여러 저장소에서 반복되면 종류별 스킬 목록에 추가
4. 같은 내용의 절: 목록 글자 그대로. 동의어 금지
5. 절 길이, 예시 수, 그림 수: 독자 질문에 필요한 만큼
6. 빈 절, `준비 중`, `추후 작성`, 지어낸 내용 금지
7. 종류별 스킬의 코드 블록 예시: 절 구성과 문체를 보여 주는 표본. 글자 복사 대상 아님

## 한국어 문체

| 문체 | 자리 | 문장 끝 | 예 |
|---|---|---|---|
| 합쇼 | `README.ko.md` 문단 | `-ㅂ니다`, `-습니다`, `-입니다` | `대화를 SQLite에 저장합니다.` |
| 합쇼 요청 | `README.ko.md`에서 독자에게 하라고 하는 문장 | `-세요` | `다음 명령으로 설치하세요.` |
| 평서 | 그 밖 한국어 문서의 문단과 절차 | `-다` | `엔진은 입력을 먼저 저장한다.` |
| 명사형 | 제목, 표 칸, 한 줄짜리 대등한 나열 목록 | 명사구. 종결어미와 마침표 없음 | `- 입력 기록 보존` |

- 설명과 절차: 완결된 문장. 번호 목록의 단계도 문장: `1. 엔진이 입력을 기록 저장소에 저장한다.`
- 명사형: 표 칸과 한 줄짜리 대등한 나열에만. 한 목록 안 명사구와 문장 혼용 금지
- 시제: 현재형. 과거형은 끝난 일(실험 방법과 결과, 판단 기록)에만
- 쓰지 않는 종결: `-해요`, `-십시오`, `-함`, `-음`, `-임`, `-ㄹ 것이다`, `-게 된다`, 합쇼 파일의 `-다`, 평서 파일의 `-니다`와 `-세요`
- 질문문, 느낌표, 줄임표 금지
- 인용, 코드, 명령 출력: 문체 규칙 밖

## 영어 문체

- 현재형, 능동태. 독자에게 하라고 하는 문장: 명령형 `Run the following command.`
- 제목: 첫 글자만 대문자(sentence case) `How it works`
- 축약형 금지: `do not`, `it is`
- 쓰지 않는 말: `blazing`, `powerful`, `seamless`, `simply`, `easy`, `easily`, `revolutionary`, `next-generation`, `cutting-edge`, `world-class`, `best-in-class`
- 쓰지 않는 연결어: 문장 첫머리 `Additionally`, `Furthermore`, `In conclusion`, `Basically`
- 질문문, 느낌표, 줄임표 금지. 인용, 코드, 명령 출력: 문체 규칙 밖

## 문장

- 한 문장에 사실 하나. 한국어 80자, 영어 25단어 이내
- 주어와 동작 명시: `최적화 수행` 대신 `캐시로 조회 수를 줄인다.`
- 형용사 대신 동작과 수치: `빠른 검색` 대신 `색인으로 검색한다.`
- 이유: 규칙 바로 뒤 한 문장. `{규칙}. {막는 일}을 막기 위해서다.`
- 기호와 변수: 처음 나오는 문장에서 정의. `활성 맥락 크기 A가 기준 T 이상이면 새 세션을 연다.`
- 설계로 정한 수치: 결정 기록이나 실험 이슈가 있으면 링크. 측정으로 확인해야 하는데 실험이 없는 값은 `미해결 질문`에
- 사용자가 확정한 문장과 인용: 원문 그대로

## 용어

- 기술 용어: 원어 기본. 업계가 원어로 쓰는 말은 한국어 문서에서도 원어: provider, engine, session, TUI, CLI, subagent
- 번역어를 쓸 때: 처음 나오는 곳에 원어 병기 `판단기(judge)`. 번역어와 원어 중 하나를 문서 전체에서 같게
- 구성 요소와 모듈 이름: 코드 식별자와 같은 글자(`core`, `engine`)
- 같은 대상: 저장소 전체에서 같은 이름. 기준은 `docs/glossary.md`, 없으면 `docs/architecture.md` 코드 지도
- 프로젝트 고유 용어: `docs/glossary.md`. 업계 일반 용어 제외
- 약어: 업계에서 널리 쓰는 약어(API, CLI, JSON, TUI, HTTP) 그대로. 프로젝트가 만든 약어는 처음 나오는 곳에서 풀이

| 쓰는 말 | 쓰지 않는 말 |
|---|---|
| 사용자 | 유저, 고객 |
| 저장소 | 레포, 리포지토리, 레포지토리 |
| 명령 | 커맨드 |
| 설정 | 컨피그 |
| 오류 | 에러(코드 식별자 제외) |
| 실행 | 구동 |
| 측정 전 | 미측정 |
| 합성 데이터 | 더미 데이터, 목업 데이터 |

- 쓰지 않는 수식어: `강력한`, `혁신적`, `쉽게`, `손쉽게`, `간단히`, `간단하게`, `다양한`, `효율적`, `원활`, `최적의`, `완벽한`, `매끄러운`, `차세대`
- 쓰지 않는 연결어: 문장 첫머리 `또한`, `이를 통해`, `이에 따라`, `결론적으로`, `요약하면`, `참고로`, `기본적으로`
- 쓰지 않는 추측: `~것 같다`, `~로 보인다`, `아마`, `TBD`, `TODO`
- 인라인 코드로 쓰는 것: 명령, 경로, 파일 이름, 코드 식별자, 패키지와 crate 이름, 설정 키와 값, 메서드 이름. 예: `cargo test`, `Cargo.toml`, `tokio`, `session/start`
- 일반 글자로 쓰는 것: 제품, 서비스, 언어, 운영체제, 표준 이름. 예: Rust, SQLite, GitHub, JSON-RPC, macOS

## 서식

1. 제목: `#` 형식. 문서당 `#` 하나. 단계 생략 금지. 제목 끝 문장부호 없음
2. 블록 사이 빈 줄 하나. 빈 줄 연속 금지. 줄 끝 공백 금지. 파일 끝: 줄바꿈 하나
3. 문단은 한 줄. 문장 중간 줄바꿈 금지
4. 비순서 목록 `- `, 순서 목록 `1.`, `2.`처럼 실제 번호. 목록 중첩 금지
5. 표: 머리 행과 `|---|` 구분 행 필수. 칸 앞뒤 공백 하나. 칸 안 줄바꿈 금지
6. 빈 칸 표기: 값이 0개면 `없음`, 항목이 이 대상에 적용되지 않으면 `해당 없음`
7. 코드 블록: 백틱 세 개와 언어 태그 `sh`, `text`, 또는 코드 언어 이름(`rust`, `toml`, `json`, `python`). 명령 앞 `$` 금지
8. 그림: 이미지 한 줄 `![{대체 글}]({상대 경로})`. 다크 모드 그림이 따로 있으면 `<picture>` 블록. 그림 파일이 없으면 그 줄 삭제(repo-docs-figures). mermaid와 텍스트 그림 금지(`docs/ui.md`와 `docs/design/` 화면 배치 그림만 예외)
9. 저장소 안 링크: 상대 경로. 링크 글자: 문서 제목, 파일 이름, 또는 문서 종류 이름(`결정 기록`). `여기`, `이 링크`, `here` 금지
10. 굵게, 기울임, 이모지, 각주, 배지 금지. HTML은 `<picture>`, `<source>`, `<img>`, `<details>`, `<summary>`와 README 머리의 `<p align="center">`, `<h1 align="center">`, `<a>`, `<br>`만
11. 인용 블록: GitHub 알림 두 가지만. `> [!NOTE]`(알아 둘 사실), `> [!WARNING]`(어기면 데이터나 동작을 잃는 규칙). 다음 줄 `> {문장}` 한 줄
12. 숫자와 단위: 한국어는 붙여 쓰기 `5초`, `1MB`, 영어는 띄어 쓰기 `5 s`, `1 MB`. 날짜 `YYYY-MM-DD`
13. 조사: 영문과 코드 바로 뒤, 공백 없음 `tokio를`, `SQLite에`

## 사실 상태

기능, 동작, 수치를 쓰기 전 상태 결정. 상태별로 쓸 수 있는 자리: 종류별 스킬

| 상태 | 근거 | 표시 |
|---|---|---|
| 미정 | 선택지가 남은 `design` 이슈 | 설계 문서 `미해결 질문` 절의 이슈 링크 |
| 결정 | 결정 기록이나 `design` 이슈 결정 댓글, 코드 없음 | 설계 문서 상태 `결정`, README 로드맵 |
| 구현 | `main`에 코드와 통과한 테스트 | 설계 문서 상태 `구현`, README 기능 |
| 사용 가능 | 사용자가 실행하는 명령을 실제로 실행해 기대 출력 확인 | README 설치, 사용법 |

- 근거 우선순위: 실행 결과 > 코드와 테스트 > 결정 기록 > 설계 문서 > 대화
- 아직 없는 테스트: `검증 계획` 칸에 테스트가 확인할 내용만. 파일 경로와 테스트 이름은 테스트가 생긴 뒤 기입
- 수치: 실험 결과(`results/summary.json`)나 실행 출력이 있을 때만. 설계로 정한 값은 근거 링크와 함께
- 외부 도구의 버전, 가격, 지원 여부: 확인한 날짜 필수 `(2026-09-30 확인)`, 영어 `(checked 2026-09-30)`
- 근거를 찾지 못한 주장 금지

## 자리표시

아직 없는 것: 아래 표의 것으로만 대체. 가짜 수치, 가짜 화면을 실제처럼 제시 금지

| 아직 없는 것 | 대신 두는 것 | 표시 |
|---|---|---|
| 실행 화면 | 구조도나 흐름 그림 | 대체 글 앞 `Design:`, 한국어 `설계:` |
| 모든 기능이 동작하는 화면 | 합성 데이터로 녹화한 데모 | 대체 글 앞 `Synthetic data:`, 한국어 `합성 데이터:`, 화면 안 `합성 데이터` 글자 |
| 측정값 | 값 칸을 `측정 전`으로 둔 표 | 표 바로 위 `> [!NOTE]` |
| 결과 차트 | 예시 데이터 차트 | 파일 이름 끝 `-illustrative`, 차트 부제 앞 `예시 데이터.`, 대체 글 앞 `예시 데이터:` |
| 벤치마크 결과 | 실험 `design.md`와 결과 칸이 `측정 전`인 표 | 표 바로 위 `> [!NOTE]` |

- 알림 문장. 평서: `측정 전 값이다. 측정 방법은 [{실험 제목}]({design.md 경로})에 있다.` 합쇼: `측정 전 값입니다. 측정 방법은 [{실험 제목}]({design.md 경로})에 있습니다.` 영어: `Not measured yet. The method is in [{실험 제목}]({design.md 경로}).`
- 실제 값이 생기면 표시와 알림 삭제, 값으로 교체

## 저장 전 검사

저장한 파일마다 두 가지 검사

1. 기계 검사: 저장소 루트에서 상대 경로로 아래 명령 실행, 출력이 없을 때까지 수정
2. 독자 검사: 문서 목록 표의 `답할 질문`에 이 문서만 읽고 답해 보기. 맥락 없는 새 에이전트를 띄울 수 있으면 문서만 주고 질문. 답이 비거나 틀린 질문의 절 수정

```sh
python3 <이 스킬 폴더>/scripts/check_doc.py README.md README.ko.md
```

- `<이 스킬 폴더>`: 이 SKILL.md가 있는 폴더. 스크립트 본문은 읽지 않고 실행만. Windows에서 `python3`가 없으면 `py -3`
- 실행 조건: Python 3.9 이상, 표준 라이브러리만. 오류가 있으면 종료 코드 1
- 기계 검사 항목: 서식, 문장 끝, 쓰지 않는 말, 비공개 경로, 절 이름 순서(종류별 스킬 목록에 있는 절끼리), `README.md`와 `README.ko.md`의 절 대응
- 영어 파일 판정: 한글이 거의 없는 파일. 영어 문체 규칙으로 검사
- 합쇼 파일: `README.ko.md`. 그 밖 한국어 파일은 평서로 검사
- 스크립트 밖이라 손으로 확인: 문장 길이, 목록 안 문장과 명사구 혼용, 명사형 어미 `-ㅁ`, `-기`, 번역본 문장의 뜻
- `llms.txt`, 그림 원본: 검사 제외(생성 함수의 산출물)

3. 문체, 용어, 서식 수정
4. 저장 전 검사 실행
